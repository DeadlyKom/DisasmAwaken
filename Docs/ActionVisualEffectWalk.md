# Кадровый обход визуальных эффектов ACTION

[Обход 6D38](../Source/Action/UpdateVisualEffects.asm) вызывается из
[UpdateFrame](../Source/Action/UpdateFrame.asm) после смещения рабочего вектора.
При выключенном операнде `#6D39` он сразу возвращается. При включённом
уменьшает операнд `#6D3D`. При переходе из единицы в ноль снимает разрешение
на следующий кадр, но выполняет обход на текущем. Входное значение ноль
при включённом разрешении переходит в `#FF`.

Первый `ADD IX, DE` сдвигает `#A783` на `#12` к записи `#A795`.
В оригинале физически помещены восемь записей по 18 байтов.
В [VisualEffects.asm](../Source/Action/Data/VisualEffects.asm) они оформлены
как экземпляры `FVisualEffect`. Следом за ними идут только первые восемь
байтов маркера, `State` по `#A82C` равен `#FF`.
Отрицательное состояние завершает обход до чтения остальных полей.
Нулевое состояние пропускает запись. Положительное уменьшается на единицу,
при этом запись обрабатывается и на кадре, в котором счётчик стал нулём.
[AllocateEffect](../Source/Voxel/AllocateEffect.asm) заполняет записи того же формата.

| Смещение | Действие обходчика |
|---|---|
| `04`, `00`, `02` | Старые слова передаются в операнды `#AF69`, `#AF48`, `#AF56`. В самой записи из них вычитаются слова `#E5ED`, `#E5B3`, `#E5D2` соответственно, с переносом по модулю `#10000`. |
| `08` `FramePointer` | Текущий адрес ресурса. В эту позицию пишется адрес следующей фазы или начальный адрес. |
| `0A` `FirstFrame` | Адрес, восстанавливаемый при истечении счётчика ресурса. При выделении записи оба адреса равны. |
| `0C` `FrameCount`, `0D` `FrameReload` | Текущий счётчик и значение перезагрузки. Если после уменьшения `0C` равен нулю, он получает `0D`. |
| `0E` `FrameStride` | 16-разрядный шаг, прибавляемый к текущему адресу при ненулевом счётчике после уменьшения. |

Перед переходом в [ComputePatchedVector](../Source/Action/ComputePatchedVector.asm)
обходчик записывает настоящий `SP` по `#6DD2` и передаёт адрес продолжения
`#6DD1` в `IY`. [Продолжение](../Source/Action/ResumeVisualEffect.asm)
восстанавливает `SP`. Оно возвращается к следующей
записи при установленном `P/V` или при неположительном слове `#D7A2`.
В остальных случаях подготавливает параметры, выбирает страницу 3 вызовом
`#AB1B` с `A = #13`, сохраняет `IX` на стеке и вызывает `#FA3A`. После возврата
восстанавливает `IX`, выбирает страницу 0 и снова выставляет шаг обхода `#12`.

[Сквозная модель](../Tools/Disasm/Research/CheckActionVisualEffectTransfer.py)
проверила 8846 сценариев с настоящим `AF43` и реальным `OUT` в модели восьми
страниц. В 3164 сценариях с положительной глубиной проверены страница 3,
рамка стека, режим в `A` и параметры `FA3A`. В `HL` и `DE` приходят
координаты с вычтенными половинами размеров из `FrameWidth` (`10`) и `FrameHeight` (`11`).
В `BC` приходит глубина, в `DE'` текущий адрес ресурса, в `HL'` оба
исходных размера. При переполнении или неположительной глубине обработчик
возвращается без записи в порт. Все входы в страницу 3 выполнены до
возврата из обходчика с восстановлением страницы 0 и стека. Сверены все
3072 байта буфера на оригинальных ресурсах `#D800` и `#C400`.
В 332 случаях буфер изменился, в 2832 сохранился.
[Результаты](../Tools/Disasm/Reports/ActionVisualEffectTransferVerification.json)

Модель [полного списка](../Tools/Disasm/Research/CheckActionVisualEffectList.py)
также создаёт оба варианта оригинальным кодом VOXAL в первой и последней
записях. Первый обход уменьшает начальный `FrameCount = 1`, возвращает
`FramePointer` к `FirstFrame` и загружает `FrameReload`.
Затем малый эффект перебирает 13 кадров от `#D800` до `#E100`
с шагом `#00C0`, большой перебирает восемь от `#C400` до `#D580`
с шагом `#0280`. В каждом сценарии дважды пройден весь цикл.
Сверены 88 активных обновлений с растровой записью и четыре обхода,
в которых уже погашенная запись пропускается. Отдельно отслежены
обращения к банку 3 по `#E1C0..#E4FF`, в этих сценариях их не было.
[Происхождение хвоста HIPERJMP](VoxelPhysicalResources.md) установлено отдельно.
[Результаты](../Tools/Disasm/Reports/ActionVisualEffectListVerification.json)

## Проекция в странице 3

По оригинальным байтам VOXAL вход `#FA3A` записывает `6 − A` по модулю 256
в два операнда `JR` по `#F9FA` и `#FA1D`. Для входного `A` от 0 до 6
переходы оставляют по `A + 3` удвоения перед добавлением координат.
Изначально операнды равны `#FE` и замыкают переходы на самих себя.
Первый и второй вызовы `#F9E9` используют разные поправки. Перед первым
обе байтовые половины `HL'` удваиваются одной 16-разрядной инструкцией
и по отдельности меняют знак. Перед вторым обе половины снова меняют знак.
Второй вызов выполняется только при сброшенном `P/V` после первого.

В [ProjectEffectPoint](../Source/Voxel/ProjectEffectPoint.asm) по `#F9E9` при отрицательном `DE` срабатывает ранний отказ. Иначе
вычисляются две координаты. В числитель первого
[логарифмического деления](../Source/Action/DivideScaledLogarithmic.asm)
входит `BC` и масштабированный знаковый `H'`. Во второе деление поступает
исходный `HL` с поправкой из масштабированного знакового `L'`.
К результатам добавляются `#0030` и `#0080` соответственно. При успехе
первый результат возвращается в `DE`, второй в `HL`. Сложение второго
результата с `#0080` может само установить `P/V`. При переносе из первого
деления отказ возвращает исходный `HL`. При переносе из второго деления
отказ возвращает в `HL` результат первой проекции с прибавленным `#0030`.
В обоих случаях отказ устанавливает `A = #03` и `P/V = 1`.

[Модель F9E9](../Tools/Disasm/Research/CheckVoxelEffectProjection.py)
проверила эти результаты в 11652 сценариях для всех режимов от 0 до 6.
Выполнялись исходные байты страницы 3 и настоящее логарифмическое деление.
Сверены регистры на возврате, R дополнительно проверен после каждой инструкции, а также значения и порядок
записей в код и в шесть рабочих байтов стека в модели Z80. [Результаты](../Tools/Disasm/Reports/VoxelEffectProjectionVerification.json)

В [DrawProjectedEffect](../Source/Voxel/DrawProjectedEffect.asm) после двух проекций со сброшенным `P/V` вычисляются разности
`dx = x₂ − x₁` и `dy = y₂ − y₁` по модулю 65536. Каждая должна
лежать в диапазоне 1…1023 до логического сдвига на два бита.
В [ClipSprite](../Source/Voxel/ClipSprite.asm) по `#EC7F` передаются
`HL = x₁ >> 2`, `DE = y₁ >> 2` со знаковым сдвигом,
`B = dy >> 2` и `C = dx >> 2` с логическим сдвигом.
Размеры 1…3 в исходном масштабе проходят эти проверки и дают нулевую
высоту или ширину на входе `ClipSprite`, где срабатывает отдельный отказ.
Перед переходом обе половины `HL'` сдвигаются вправо отдельно.

[Модель FA3A](../Tools/Disasm/Research/CheckVoxelEffectDrawEntry.py)
проверила 3938 сценариев, в том числе 395 переходов к отсечению.
Сверены границы размеров, входные регистры отсечения и состояние SP.
Модель сверяет все записи вне стека, включая два смещения переходов
и три слова исходных компонент для второго вызова. Записи в стек
ограничены двенадцатью байтами под входным SP. [Результаты](../Tools/Disasm/Reports/VoxelEffectDrawEntryVerification.json)

Для результатов сквозной проверки применяется модель
[выбора кодов и отрисовки](VoxelSpriteClipBounds.md). Первый сквозной прогон
использует одну активную запись.

[Модель полного списка](../Tools/Disasm/Research/CheckActionVisualEffectList.py)
прошла 384 сценария. В них сверены все восемь записей, общий счётчик,
накопленный буфер после 1400 банковых вызовов рисователя, порядок OUT и SP.
Побочные записи вне списка и буфера, точные итоговые регистры и нативное
выполнение этой моделью не проверялись.
[Результаты](../Tools/Disasm/Reports/ActionVisualEffectListVerification.json)

[Модель префикса](../Tools/Disasm/Research/CheckActionVisualEffectWalk.py)
сравнила полное 64-килобайтное окно памяти в 4096 сценариях на оригинальном
коде. Проверены выключение, остановка на маркере, сброс и продвижение ресурса.
Проверены также адрес передачи управления, положение стека и значения
`IX` и `IY` при входе в вычислитель. Модель останавливается до его первой
инструкции. [Результаты](../Tools/Disasm/Reports/ActionVisualEffectWalkVerification.json)


При отрицательной глубине `ProjectEffectPoint` сохраняет исходные
HL, DE, BC и AF'. При переносе из первого деления HL и DE возвращаются
из сохранённых слов, а BC и AF' остаются от первого деления. При переносе
из второго деления HL получает первую проекцию со смещением `#0030`,
а DE, BC и AF' остаются от второго деления. Все три отказа возвращают
`AF=#0304`. При обычном завершении BC получает `#0080`, A и AF'
остаются от второго деления, а F соответствует прибавлению `#0080`
к горизонтальной проекции с предварительно сброшенным Carry.


## Обновление R в проекторе точки

В [модели ProjectEffectPoint](../Tools/Disasm/Research/CheckVoxelEffectProjection.py) отдельно сверены исходные 81 байт #F9E9..#FA39 из VOXAL и 208 байт делителя #AE73..#AF42 из ACTION с физическими байтами TRD. После настройки относительных переходов проектор исполняется вместе с действительным делителем. Записи в операнды и стек по-прежнему сопоставляются с независимым числовым эталоном.

Пусть m — входной режим от 0 до 6, q1 и q2 — числа M1 первого и второго вызовов DivideScaledLogarithmic из его независимого эталона. Для самого ProjectEffectPoint получены четыре формулы, включая внешний RET и оба префиксных M1 инструкции BIT:

| Ветвь | Полное число M1 |
| --- | --- |
| Отрицательная глубина | 8 |
| Carry первого деления | 26 + m + q1 |
| Carry второго деления | 46 + 2m + q1 + q2 |
| Оба деления завершились без Carry | 48 + 2m + q1 + q2 |

Последняя ветвь включает случай, когда последующее ADC HL,#0080 выставляет P/V. Это отдельный признак для вызывающего DrawProjectedEffect, при подсчёте M1 сам путь не меняется. Формулы сравниваются с независимым подсчётом префиксов реально исполненных инструкций, после каждого шага R сверяется с увеличением младших семи битов по модулю 128 при сохранённом бите 7.

В 11652 сценариях получены 3782 отказа по отрицательной глубине, 2100 отказов первого деления, 296 отказов второго и 5474 прохождения обоих делений. Все 256 исходных значений R распределены между сценариями, полный декартов перебор R со всеми входами не выполнялся. Для наблюдённых входов стоимости остальных ветвей составили 66..120, 125..254 и 114..362 M1 соответственно, это диапазоны выборки, не универсальные границы.

[Отчёт](../Tools/Disasm/Reports/VoxelEffectProjectionVerification.json) сохраняет проверку полного рисователя как незавершённую. IRQ и нативный запуск не моделируются. [Договор исходника](../Source/Voxel/ProjectEffectPoint.asm) и [канонический реестр процедуры](../Tools/Disasm/Research/VoxelEffectProjectionFacts.py) согласованы без изменения инструкций.


## Обновление R в обёртке двух проекций

[Проверка DrawProjectedEffect](../Tools/Disasm/Research/CheckVoxelEffectDrawEntry.py) дополнительно сверяет исходные 142 байта #FA3A..#FAC7 с VOXAL из образа. Сохраняется прежний набор 3938 входов и четыре класса результата, в том числе 395 передач в ClipSprite. Для каждого входа теперь проверяется R после каждой инструкции и сопоставляется число M1 с формулой, не использующей внутренний счётчик симулятора.

Обозначим p1 и p2 полными стоимостями вызванных ProjectEffectPoint по формулам предыдущего раздела, включая их RET. Собственные стоимости обёртки включают условные RET независимо от исхода, инструкции со служебными префиксами и финальный JP, при этом ClipSprite не исполняется:

| Первый достигнутый результат | Число M1 до остановки |
| --- | --- |
| P/V после первой проекции | 29 + p1 |
| P/V после второй проекции | 49 + p1 + p2 |
| dx = 0 | 53 + p1 + p2 |
| dx ≥ 1024, разность по модулю 65536 | 60 + p1 + p2 |
| dy = 0 при допустимом dx | 72 + p1 + p2 |
| dy ≥ 1024 при допустимом dx | 79 + p1 + p2 |
| Передача в ClipSprite | 113 + p1 + p2 |

Все семь путей присутствуют в выборке. Последний дополнительный RET NZ после логического уменьшения dy не создаёт восьмую ветвь при исходных инструкциях, предыдущая проверка уже требует dy < 1024, поэтому H после двух логических сдвигов равен нулю.

С BC′=#A55A, DE′=#D800, IX=#1357, IY=#5C3A, I=#3C и IM=2 проверено их сохранение на собственных выходах и перед отсечением, IFF остаётся сброшен. HL′ меняется исходным удвоением слова и последующими побайтовыми операциями. Перенос из младшего байта в старший при первоначальном ADD HL,HL не подменяется независимым удвоением двух полуразмеров.

Входные R=0..255 распределены по сценариям, полного декартова перебора со всеми параметрами нет. Проверка заканчивается перед ClipSprite или на внешнем возврате, договор последующего рисования и нативный запуск этим не расширены. [Отчёт](../Tools/Disasm/Reports/VoxelEffectDrawEntryVerification.json), [исходник](../Source/Voxel/DrawProjectedEffect.asm), [канонический договор](../Tools/Disasm/Research/VoxelEffectProjectionFacts.py).
