# Кадровый обход визуальных эффектов ACTION

[Обход 6D38](../Source/Action/UpdateVisualEffects.asm) вызывается из
[UpdateFrame](../Source/Action/UpdateFrame.asm) после смещения рабочего вектора.
При выключенном операнде `#6D39` он сразу возвращается. При включённом
уменьшает операнд `#6D3D`. При переходе из единицы в ноль снимает разрешение
на следующий кадр, но выполняет обход на текущем. Входное значение ноль
при включённом разрешении переходит в `#FF`.

Первый `ADD IX, DE` сдвигает `#A783` на `#12` к записи `#A795`.
В оригинале физически помещены восемь записей по 18 байтов.
В [VisualEffects.asm](../Source/Action/Data/VisualEffects.asm) они оформлены
как экземпляры `FVisualEffect`. Следом за ними идут только первые восемь
байтов маркера, `State` по `#A82C` равен `#FF`.
Отрицательное состояние завершает обход до чтения остальных полей.
Нулевое состояние пропускает запись. Положительное уменьшается на единицу,
при этом запись обрабатывается и на кадре, в котором счётчик стал нулём.
[AllocateEffect](../Source/Voxel/AllocateEffect.asm) заполняет записи того же формата.

| Смещение | Действие обходчика |
|---|---|
| `04`, `00`, `02` | Старые слова передаются в операнды `#AF69`, `#AF48`, `#AF56`. В самой записи из них вычитаются слова `#E5ED`, `#E5B3`, `#E5D2` соответственно, с переносом по модулю `#10000`. |
| `08` | Текущий адрес ресурса. В эту позицию пишется адрес следующей фазы или начальный адрес. |
| `0A` | Адрес, восстанавливаемый при истечении счётчика ресурса. При выделении записи оба адреса равны. |
| `0C`, `0D` | Текущий счётчик и значение перезагрузки. Если после уменьшения `0C` равен нулю, он получает `0D`. |
| `0E` | 16-разрядный шаг, прибавляемый к текущему адресу при ненулевом счётчике после уменьшения. |

Перед переходом в [ComputePatchedVector](../Source/Action/ComputePatchedVector.asm)
обходчик записывает настоящий `SP` по `#6DD2` и передаёт адрес продолжения
`#6DD1` в `IY`. [Продолжение](../Source/Action/ResumeVisualEffect.asm)
восстанавливает `SP`. Оно возвращается к следующей
записи при установленном `P/V` или при неположительном слове `#D7A2`.
В остальных случаях подготавливает параметры, выбирает страницу 3 вызовом
`#AB1B` с `A = #13`, сохраняет `IX` на стеке и вызывает `#FA3A`. После возврата
восстанавливает `IX`, выбирает страницу 0 и снова выставляет шаг обхода `#12`.

[Сквозная модель](../Tools/Disasm/Research/CheckActionVisualEffectTransfer.py)
проверила 8846 сценариев с настоящим `AF43` и реальным `OUT` в модели восьми
страниц. В 3164 сценариях с положительной глубиной проверены страница 3,
рамка стека, режим в `A` и параметры `FA3A`. В `HL` и `DE` приходят
координаты с вычтенными половинами размеров из полей `10` и `11`.
В `BC` приходит глубина, в `DE'` текущий адрес ресурса, в `HL'` оба
исходных размера. При переполнении или неположительной глубине обработчик
возвращается без записи в порт. Все входы в страницу 3 выполнены до
возврата из обходчика с восстановлением страницы 0 и стека. Сверены все
3072 байта буфера на оригинальных ресурсах `#D800` и `#C400`.
В 332 случаях буфер изменился, в 2832 сохранился.
[Результаты](../Tools/Disasm/Reports/ActionVisualEffectTransferVerification.json)

## Проекция в странице 3

По оригинальным байтам VOXAL вход `#FA3A` записывает `6 − A` по модулю 256
в два операнда `JR` по `#F9FA` и `#FA1D`. Для входного `A` от 0 до 6
переходы оставляют по `A + 3` удвоения перед добавлением координат.
Изначально операнды равны `#FE` и замыкают переходы на самих себя.
Первый и второй вызовы `#F9E9` используют разные поправки. Перед первым
обе байтовые половины `HL'` удваиваются одной 16-разрядной инструкцией
и по отдельности меняют знак. Перед вторым обе половины снова меняют знак.
Второй вызов выполняется только при сброшенном `P/V` после первого.

В `#F9E9` при отрицательном `DE` срабатывает ранний отказ. Иначе
вычисляются две координаты. В числитель первого
[логарифмического деления](../Source/Action/DivideScaledLogarithmic.asm)
входит `BC` и масштабированный знаковый `H'`. Во второе деление поступает
исходный `HL` с поправкой из масштабированного знакового `L'`.
К результатам добавляются `#0030` и `#0080` соответственно. При успехе
первый результат возвращается в `DE`, второй в `HL`. Сложение второго
результата с `#0080` может само установить `P/V`. При переносе из первого
деления отказ возвращает исходный `HL`. При переносе из второго деления
отказ возвращает в `HL` результат первой проекции с прибавленным `#0030`.
В обоих случаях отказ устанавливает `A = #03` и `P/V = 1`.

[Модель F9E9](../Tools/Disasm/Research/CheckVoxelEffectProjection.py)
проверила эти результаты в 11652 сценариях для всех режимов от 0 до 6.
Выполнялись исходные байты страницы 3 и настоящее логарифмическое деление.
Сверены значения на возврате, положение стека и память вне шести рабочих
байтов стека. [Результаты](../Tools/Disasm/Reports/VoxelEffectProjectionVerification.json)

После двух проекций со сброшенным `P/V` вычисляются разности
`dx = x₂ − x₁` и `dy = y₂ − y₁` по модулю 65536. Каждая должна
лежать в диапазоне 1…1023 до логического сдвига на два бита.
В [ClipSprite](../Source/Voxel/ClipSprite.asm) по `#EC7F` передаются
`HL = x₁ >> 2`, `DE = y₁ >> 2` со знаковым сдвигом,
`B = dy >> 2` и `C = dx >> 2` с логическим сдвигом.
Размеры 1…3 в исходном масштабе проходят эти проверки и дают нулевую
высоту или ширину на входе `ClipSprite`, где срабатывает отдельный отказ.
Перед переходом обе половины `HL'` сдвигаются вправо отдельно.

[Модель FA3A](../Tools/Disasm/Research/CheckVoxelEffectDrawEntry.py)
проверила 3938 сценариев, в том числе 395 переходов к отсечению.
Сверены границы размеров, входные регистры отсечения, стек и оба изменяемых
смещения. [Результаты](../Tools/Disasm/Reports/VoxelEffectDrawEntryVerification.json)

Для результатов сквозной проверки применяется модель
[выбора кодов и отрисовки](VoxelSpriteClipBounds.md). Первый сквозной прогон
использует одну активную запись.

[Модель полного списка](../Tools/Disasm/Research/CheckActionVisualEffectList.py)
прошла 384 сценария. В них сверены все восемь записей, общий счётчик,
накопленный буфер после 1400 банковых вызовов рисователя, порядок OUT и SP.
Побочные записи вне списка и буфера, точные итоговые регистры и нативное
выполнение этой моделью не проверялись.
[Результаты](../Tools/Disasm/Reports/ActionVisualEffectListVerification.json)

[Модель префикса](../Tools/Disasm/Research/CheckActionVisualEffectWalk.py)
сравнила полное 64-килобайтное окно памяти в 4096 сценариях на оригинальном
коде. Проверены выключение, остановка на маркере, сброс и продвижение ресурса.
Проверены также адрес передачи управления, положение стека и значения
`IX` и `IY` при входе в вычислитель. Модель останавливается до его первой
инструкции. [Результаты](../Tools/Disasm/Reports/ActionVisualEffectWalkVerification.json)
