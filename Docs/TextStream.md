# Управляющий текстовый поток

[PrintText](../Source/Station/PrintText.asm), #BD08..#BDA5,
читает поток по HL и вызывает DrawGlyph для обычных кодов.
[RecoverTextX](../Source/Station/RecoverTextX.asm), #BD01..#BD07,
является дополнительным входом восстановления физического X.
Он может продолжиться прямо в PrintText, поэтому их include имеют порядок (0), (1).

## Коды и изменяемые операнды

| Код | Действие |
| ---: | --- |
| 0 | Переход в MeasureTextRun на остатке потока, затем возврат непосредственно вызывающей стороне |
| 1 | Выход, код потреблён, AF=#0044 |
| 2..6 | Присвоение CursorX из одного из пяти операндов, затем продолжение чтения |
| 10, LF | Выход, код потреблён, AF=#0A4A |
| 13, CR | CursorY+8 по модулю 256, при допустимой высоте CursorX=0 и продолжение |
| остальные 7..255 | Вызов DrawGlyph, включая код 7 и исключая отдельно обработанные LF, CR |

Код 0 не является обычным нулевым ограничителем строки. После него
MeasureTextRun получает HL на следующем байте, сохраняет BC и DE,
ищет CR, LF либо разделитель B, возвращает ширину и положение ограничителя.
Насыщение может вернуть позицию ещё не принятого символа. См. [Font](Font.md).

| Символ | Адрес байта | Управляющий код |
| --- | --- | ---: |
| TextStreamState.Column2X | #BD73 | 2 |
| TextStreamState.Column3X | #BD7E | 3 |
| TextStreamState.Column4X | #BD89 | 4 |
| TextStreamState.Column5X | #BD94 | 5 |
| TextStreamState.Column6X | #BD9F | 6 |

Это пять отдельных непосредственных операндов LD A,nn в исполняемом коде,
а не непрерывный массив координат. Они задают пиксельный X относительно
TextWindow. Код команды не забирает следующий байт потока как координату.

TextWindow.Style по #BD26 также является непосредственным операндом.
Разряды 7..0 здесь образуют одно значение, проверяется равенство всего байта нулю.
Значение 00000000 выбирает отбрасывание остатка строки при отказе по ширине
или физическому X. Любое другое значение выбирает перенос по ширине
либо пропуск отдельного символа при отказе физического X.
Независимых флагов или доказанного значения отдельных битов у этого поля нет.

## Отказы и положение HL

При успехе DrawGlyph обработчик читает следующий символ. При отказе
HL сначала уменьшается, снова указывая на отказавший символ.

| A отказа DrawGlyph | Продолжение |
| ---: | --- |
| 0, физический X | RecoverTextX, при Style=0 поиск CR/LF, иначе пропуск одного символа |
| 1, физический Y | Выход AF=#0041, HL остаётся на символе |
| 2, относительная высота | Выход AF=#0041, HL остаётся на символе |
| 3, ширина либо переполнение X | Style=0 ищет CR/LF, иначе новый Y и повтор того же символа |

Поиск CR/LF не обрабатывает встреченные управляющие коды. LF потребляется
и завершает поток. CR возвращается в обычный цикл и обрабатывается как перенос.
Ветви явного CR и автоматического переноса физически дублируются в оригинале,
одна не заменена вызовом другой.

### Временный возврат после CR

TextStreamState.LineEndCode по #BD4F содержит код исходного JP PrintText.Entry.
Обработчик центрирования по #C2DF временно пишет вместо #C3 код RET #C9,
а общий выход по #C341 восстанавливает #C3. Два байта адреса JP остаются
нетронутыми, при временном RET они не исполняются.

В этом режиме принятый явный CR продвигает Y, сбрасывает X и возвращает
AF=#0044, HL уже после CR. Это позволяет вызывающему коду вычислить центр
следующей строки отдельно. Отказ переноса по высоте по-прежнему возвращает
Carry, а автоматический перенос ширины использует JP по #BD69 и продолжает
поток. Подмена относится только к одному из двух физических хвостов.
Полный разбор вызывающего обработчика центрирования ещё продолжается.

Если новый Y не меньше высоты, он не записывается. A содержит новый Y,
Carry установлен. S, Z, PV взяты от CP(новый Y,высота), биты 5 и 3 от
нового Y, H=N=0. При явном CR HL уже за ним, при автоматическом переносе
HL остаётся на повторяемом символе. Исходные BC и DE сохранены.

Рост Y имеет байтовое переполнение. Например, при ширине 0, высоте 255,
Style=1, CursorY=0 и обычном символе перенос перебирает 0,8,...,248,0.
Ни один новый Y не достигает 255, поэтому код повторяет тот же глиф без выхода.
Исправление этого алгоритма изменило бы оригинал. Для высот 249..255 цикл
возможен при остатке Y modulo 8 меньше Height-248.

## Проверка

[CheckTextStream.py](../Tools/Disasm/Research/CheckTextStream.py) проверяет
268944 завершающихся потока. Проверены все 65536 сочетаний Y/Height на CR,
все 65536 сочетаний первого кода и байта Style для обычного и временного RET,
1800 сочетаний геометрии
и входа восстановления, 5000 воспроизводимых смешанных потоков.
Сверяются полный AF, HL, сохранённые регистры, SP, курсор и последовательность
попыток глифа. Дополнительно 28 циклических сочетаний высоты и остатка Y
подтверждены повторением состояния после двух полных оборотов.
R и счётчик времени при сравнении цикла исключены, этот код не читает R.

DrawGlyph исполняется в своём исходном режиме без записи пикселей,
его реализация не подменена заглушкой. Прерывания отключены.
Модель не подтверждает нативный запуск или игровой процесс.
Отчёт [TextStreamVerification.json](../Tools/Disasm/Reports/TextStreamVerification.json).
