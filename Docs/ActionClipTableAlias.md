# Байты таблицы отсечения CF08

В ACTION банка 0 диапазон CF08..CF0A содержит F3 AF C9. Эти байты являются младшими частями трёх настоящих указателей таблицы CF00/D000, используемых диспетчерами отсечения. Индексы 08, 09 и 0A допустимы для исходных кодов областей. [Проверка](../Tools/Disasm/Research/CheckActionClipTableAlias.py) сверяет каждую пару страниц с зарегистрированной целью, [отчёт](../Tools/Disasm/Reports/ActionClipTableAliasVerification.json) сохраняет адреса и значения.

Тот же диапазон опубликован как [UnknownCF08](../Source/Action/UnknownCF08.asm), поскольку F3 AF C9 декодируется как DI, XOR A, RET. Наличие такого декодирования не доказывает вызов процедуры. Табличное использование тоже не исключает исполнения тех же байтов. Вход в этот фрагмент пока не доказан, его контракт и статус Unknown сохраняются. Байты, адреса и существующее размещение не изменяются.

Распознаватель Analyze.py принудительно включает этот диапазон в кандидаты кода. Это решение распознавателя следует отличать от доказательства фактического входа. Для окончательного решения нужен установленный вызывающий путь либо достаточно полный анализ всех способов образования адреса исполнения.

Проверка также просмотрела непосредственные обращения к `#CF08`,
`#CF09` и `#CF0A` в инструкциях всех 20 декодированных областей.
Совпадений нет. Табличное чтение адресуется через регистр, поэтому
этот результат ожидаем и для известного чтения. Сквозная проверка
косвенных переходов, модифицируемых адресов и вычисляемых возвратов
остаётся отдельным условием для исключения входа исполнения.
