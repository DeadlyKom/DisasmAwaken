# Композиция карты C000

[DrawMapScene](../Source/Map/DrawMapScene.asm) занимает исходные C000..C230 банка KARTA. Процедура последовательно инвертирует экран, поэтому повторный вызов с теми же данными снимает те же пиксели только при неизменности всех слоёв и таблиц. Это свойство XOR, оно не означает, что состояние дуги или регистры сохраняются.

## Порядок слоёв

Сначала входной A сохраняется в операнде ModeControl. Из слова по 988E выбирается старший байт, если он ненулевой, иначе целая половина младшего. Утроение выбранного байта по модулю 256 задаёт Radius. Игровая роль самого слова 988E ещё не установлена. Полные мировые координаты основного ключа преобразуются в знаковые смещения относительно начала и половины окна. Грубое отбрасывание использует полные модули, а диспетчер дуги получает только их младшие байты. Формулы, переносы и границы усечения описаны в [ArcWorkspace](ArcWorkspace.md), последующий выбор краёв — в [ArcDispatcher](ArcDispatcher.md).

После дуги идут следующие вызовы [XorMapPointMarker](../Source/Map/XorMapPointMarker.asm).

| Источник ключа | Ресурс | Правило обхода |
| --- | --- | --- |
| Основной ключ 983F..9842 | Primary | Один вызов |
| MapSelection 9844..9847 | Selected | Один вызов |
| Запись по SecondaryPointState.Cursor | Cursor | Пропуск только при первом байте FF |
| Первый сохранённый список 990A | Stored | FF пропускает запись, 80..FE заканчивает список |
| Ключи 997B и общие коды 99A3 | ActiveAux | 0 пропускает, 1..127 рисует, 80..FF заканчивает |
| Второй сохранённый список 993D | Secondary | Любой первый байт 80..FF заканчивает список |

Ресурсы имеют восемь фаз и разобраны в [MapMarkerSprites](MapMarkerSprites.md). Чтение обоих сохранённых списков имеет шаг пять, пятый байт при рисовании маркера не используется. У дополнительных ключей шаг четыре. Кодовая проверка ёмкости у них отсутствует. Одиннадцатый исходный код равен нулю и пропускает уже перекрывающую коды позицию IX. Следующий отрицательный байт 81 физически принадлежит InterfaceChoices и завершает исходный проход. Подробности общего хранения и оставшиеся неизвестные роли кодов даны в [AuxiliaryMapPoints](AuxiliaryMapPoints.md).

Если первый байт второго списка меньше 80, [DrawMapPointChain](../Source/Map/DrawMapPointChain.asm) строит цепочку по StoredMapOrder. Затем выполняется настоящий HALT. Процедура не включает прерывания перед ним. Способ пробуждения задаётся окружающим игровым кодом и аппаратным окружением.

## Секторные точки и самомодификация

После пробуждения SP сохраняется в операнде C22E. EXX меняет набор общих регистров. Width записывается в два прямых сравнения X, (1-Width)&FF — в два обратных. Height и (1-Height)&FF записываются в младшие байты двух загрузок BC. Все семь операндов именованы в MapScenePatch. Это существующие адреса исходного кода.

SP получает F1FE. Первое POP пропускает предшествующее слово масок, затем четыре цикла по 128 слов читают F200..F5FF. Младший байт каждого слова — X, старший — Y. Прямое направление принимает разность raw-origin без займа и меньше размера. Обратное направление принимает origin-raw без займа и не меньше (1-размер)&FF. Принятая обратная разность меняет знак по модулю 256. Направления страниц совпадают с [BuildVisibleMapPoints](../Source/Map/BuildVisibleMapPoints.asm).

Для каждой принятой точки RowHigh и RowLow дают адрес строки, ColumnByte добавляет колонку, PixelMask задаёт один инвертируемый бит. Секторные данные и списки не изменяются. Атрибуты этот проход не записывает. Отсутствие отдельной проверки размера окна компенсируется только требованиями к подготовленным таблицам, произвольные несогласованные таблицы безопасными не объявляются.

В конце восстанавливается SP и выполняется RET. Обратного EXX после C150 нет. Поэтому основной HL содержит последнее исходное слово F5FE, DE — OriginLow, B равен нулю, C равен (1-Height)&FF. Carry равен нулю, если последнее слово принято, иначе единице. Это следствие последней проверки, последующих DJNZ, LD SP и RET, а не отдельный статус успеха сцены.

При наличии принятой точки альтернативный HL равен F100+X последней точки, DE содержит адрес её экранного байта, B равен X. Альтернативный C остаётся значением основного C перед C150. Если ни одной точки не принято, альтернативные общие пары сохраняют основные значения перед этим обменом. IX остаётся результатом обходов и цепочки, входной IX не сохраняется. IY и I сохраняются инструкциями процедуры и разобранных помощников. Реальный ISR может иметь дополнительный контракт.

## Проверка и границы доказательства

[CheckMapScene.py](../Tools/Disasm/Research/CheckMapScene.py) исполнил 1024 сцены исходного C000 вместе с настоящими вызовами дуги, шести маркеров и цепочки. Независимая композиционная модель сравнила весь bitmap и атрибуты для окон 128×96 и 208×112, пустых списков, пропусков FF, четырёх стилей цепочки и оборачивающихся координат начала. В 64 случаях использован исходный снимок общих кодов с отрицательной границей в соседних данных интерфейса. Проверены изменяемые операнды, сохранность исходных списков и секторных слов, возвращаемые пары и Carry.

Пробуждение HALT выполнено явно моделью без ISR. Индивидуально отсечённые рёбра цепочки в этой композиционной проверке не перебирались. Другие геометрические проверки остаются отдельными свидетельствами. Сборка, аппаратные прерывания, нативный запуск и полный игровой цикл этим отчётом не подтверждаются. Неизвестные игровые роли слова 988E, части общих кодов и конечных байтов фаз маркеров остаются открытыми.
