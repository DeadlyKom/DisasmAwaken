# Инвертирование масштабированных компонент

[ReverseScaledVector](../Source/Action/ReverseScaledVector.asm) занимает 6EDE..6F1C перенесённого ядра ACTION. Три раздельные компоненты находятся в непосредственных словах операндов по E5B3, E5D2 и E5ED. Общая величина SpeedWord по A78F также используется [шестой шкалой](ActionPanelGauges.md) и [StepNearZeroWord](ActionNearZeroWord.md). Её полный игровой смысл и физические единицы пока не доказаны.

## Точный порядок

Сначала EnabledCode по 6EAD получает 1, разрешая последующую обработку StepNearZeroWord. Вызова этой процедуры здесь нет, запрос шестой шкалы непосредственно не записывается.

Затем Component0, Component2 и Component1 в таком физическом порядке меняют знак по модулю 65536. Их величина **не делится пополам**. При входном 8000 отрицание остаётся 8000. После этих трёх записей отдельно вычисляется новое SpeedWord:

```
negated = (-old_word) mod 65536
new_word = (arithmetic_shift_right(signed16(negated), 1) + 1) mod 65536
```

Сначала происходит оборачивание отрицания, затем знаковый сдвиг. Поэтому для исходного 8000 результат равен C001, а не положительной половине математического отрицания. При старом 0 получается 1, при старом 1 получается 0, при FFFF получается 1. Насыщения, проверки переполнения и исправлений алгоритма нет.

В коде по 6E6C три настоящих MultiplySignedScaled используют SpeedWord с коэффициентами CBD8, CBEE и CC09 и сохраняют результаты в этих трёх компонентах. Это устанавливает их общий числовой источник. Однако данная процедура только инвертирует уже готовые компоненты, а новое SpeedWord будет учтено при другом последующем вычислении. Немедленного пересчёта компонент на половину новой величины здесь нет.

## Регистры и изменяемый код

HL содержит записанное новое SpeedWord, DE и BC сохраняются. A равен инверсии старшего байта исходного SpeedWord. F остаётся от RR L перед последним INC HL, Carry совпадает с младшим битом исходного слова. Z и Sign не являются проверкой окончательного HL. Например, для исходного 0 записывается HL=1 при установленном Z, для исходного 1 записывается HL=0 при сброшенном Z.

Альтернативные регистры, IX, IY, I, IM и IFF сохраняются. SP увеличивается на два из-за RET, дополнительных записей CPU-стека нет. R получает 44 M1. Существующие слова операндов названы в ActionScaledVectorState, новая RAM и искусственная непрерывная структура вместо раздельных операндов не добавляются. EnabledCode и SpeedWord используют уже существующие имена. Четыре писателя кода описаны в [ModifiedCode](ModifiedCode.md), SpeedWord является обычным состоянием.

## Проверка

[CheckActionVectorReverse.py](../Tools/Disasm/Research/CheckActionVectorReverse.py) сравнивает исходные инструкции с независимыми формулами отрицания и арифметического сдвига. [Отчёт](../Tools/Disasm/Reports/ActionVectorReverseVerification.json) содержит 263025 сценариев, все слова каждой компоненты и SpeedWord по отдельным сечениям, все входные флаги и 625 совместных крайних сочетаний четырёх слов.

Проверяются регистры, флаги, R, SP, вся RAM и кратность девяти записей. Полный декартов перебор четырёх слов не заявляется. Контекст обработки близкого объекта по E506 требует отдельного разбора, прерывания, весь игровой кадр и нативная реакция этой локальной моделью не подтверждаются. Сборка Codex не выполняется.
