# Начальное заполнение случайных потоков ACTION

[InitializeRandomStates](../Source/ActionBoot/InitializeRandomStates.asm)
исполняется по #4306 после выбора банка 0. Код берётся из смещений
#0149..#0197 исходного ACTION. Он использует настоящий
[NextRandomWord0](../Source/Action/NextRandomWord0.asm) и общее ядро
[StepFoldedRandom](../Source/Action/StepFoldedRandom.asm).
[Числовая рекурсия и границы её проверки](ActionFoldedRandom.md).

Сначала HL=#C9F1 записывается по #5CC2. Это две команды POP AF и RET
системного переходника. LD A,R считывает R после четырёх M1 от входа,
затем LD L,A заменяет только младший байт HL. Начальный LowWord
Stream0 равен #C900 + считанный R. Его FoldByte не обнуляется,
а берётся из уже загруженной физической записи.

Число прогревочных вызовов N равно `(считанный R AND 3)+1`.
После N обновлений Stream0 последнее слово записывается в Stream3.
Затем семь следующих результатов того же потока заполняют остальные
указанные ниже младшие слова. Отдельного девятого результата до
первого копирования нет.

| Порядок копирования | Назначение LowWord | Адрес | Номер обновления Stream0 |
|---|---|---|---|
| 0 | Stream3 | #EBDB | N |
| 1 | Stream4 | #EBFF | N+1 |
| 2 | Stream1 | #EC02 | N+2 |
| 3 | Stream5 | #EC05 | N+3 |
| 4 | Stream8 | #EBE1 | N+4 |
| 5 | Stream9 | #EBE4 | N+5 |
| 6 | Stream10 | #EBE7 | N+6 |
| 7 | Stream2 | #EBEA | N+7 |

FoldByte всех восьми получателей сохраняются. Состояния потоков
6, 7, 11, 12, 13 и 14 не меняются. В конце
ActionOverlayModeState.Mode получает 1, что выбирает режим без
наложения, а ActionPanelGaugesState.ThirdValue получает #2E.
Адреса соответствуют существующим операндам, новая память не вводится.

Основной DE сохраняется, B возвращается нулевым, C сохраняется.
HL содержит последний результат Stream0. A=#2E, F остаётся от
последнего StepFoldedRandom. Альтернативный HL указывает на Stream0,
альтернативный DE содержит новое слово, B′=0, C′ содержит младший
байт последней смеси n. AF′, IX, IY, I, IM, IFF и страница сохраняются
при отсутствии вмешательства IRQ.

## R и временный стек

До прогрева выполняется девять M1. Одна прогревочная итерация содержит
PUSH BC, CALL, 66 M1 настоящего генератора, POP BC и DJNZ, всего
70 M1. Восемь записей результатов, семь последующих CALL с их
генераторами и пять конечных инструкций дают ещё 482 M1.
Итого `491 + 70×N`, то есть 561, 631, 701 либо 771 M1.
R меняется по модулю 128 в младших семи битах, бит 7 сохраняется.

На прогревочном участке PUSH BC, адрес возврата CALL и временное слово
ядра занимают шесть байтов ниже входного SP. Последующие вызовы без
PUSH BC требуют только четыре. При SP=#BFFE минимум равен #BFF8,
после окончательного RET SP=#C000. Содержимое всех шести временных
байтов также проверяется, они не объявляются восстановленными.

## Проверка

[CheckActionBootRandomInitialization](../Tools/Disasm/Research/CheckActionBootRandomInitialization.py)
исполнил 512 вызовов исходных инструкций. Все 256 начальных R
проверены с исходными состояниями, затем с отдельным ненулевым
заполнением всех 15 записей. Числовая модель рекурсии вычисляет
ожидаемые состояния независимо от последовательности Z80-команд.

Сверены регистры кроме T, R после каждого шага, все 65536 байтов
памяти и кратность записей по каждому адресу. I, IM и IFF варьируются
с R, это не полное декартово произведение входов.
[Результат](../Tools/Disasm/Reports/ActionBootRandomInitializationVerification.json).

Полный 24-битный домен начального Stream0 не перебран. Период,
равномерность, все игровые роли потоков, IRQ и нативная загрузка
этой проверкой не установлены. Сборка не запускалась.
