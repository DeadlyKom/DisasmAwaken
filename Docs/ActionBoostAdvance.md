# Общий хвост ускорения

[AdvanceBoost](../Source/Action/AdvanceBoost.asm) занимает исходные `7504..754B`, 72 байта. В него ведёт JR из [RequestBoost](ActionBoostCommand.md) при свободном пространстве. [Факты и договор](../Tools/Disasm/Research/ActionBoostAdvanceFacts.py), [независимая модель](../Tools/Disasm/Research/ReferenceActionBoostCommand.py), [проверка](../Tools/Disasm/Research/CheckActionBoostCommand.py).

Сначала вызывается [SelectFuelStock](../Source/Action/SelectFuelStock.asm). Ненулевой Preferred выбирается вместе со своим адресом, иначе читается Fallback. Команда помещает выбранный байт A в C и уменьшает C. Знак результата определяет отказ, поэтому допускаются исходные значения 1..128. Значения 0 и 129..255 приводят в ReleaseBoostDebrisRecords. Простая проверка «байт ненулевой» изменила бы исходный алгоритм.

| Существующий операнд | Начальное значение | Действие |
| --- | --- | --- |
| FastPhase, 750D | 00 | INC по модулю 256, только ноль допускает следующий шаг |
| SlowPhase, 7515 | 00 | INC и AND 07, только ноль допускает расход |
| FirstRotation, 752C | 11 | RRCA, старый бит 0 разрешает второе вращение |
| SecondRotation, 7534 | 88 | RRCA, старый бит 0 разрешает создание класса 20 |

Когда обе фазы дают ноль, выбранный физический байт получает C. Current по `9BD2` уменьшается по модулю 256, ноль превращается в FF. SecondRequest по `665C` получает 1. Старшие биты исходной SlowPhase отбрасываются только на реально достигнутом шаге, начальные произвольные значения не нормализуются заранее.

Первое вращение выполняется на каждом допущенном пути независимо от расхода. Второе выполняется только при старом бите 0 первого. При единичном старом бите 0 второго вызывается настоящий [CreateBoostDebrisRecord](../Source/Action/CreateBoostDebrisRecord.asm). Это устанавливает подтверждённого вызывающего уже разобранного создателя. Неудача поиска свободной записи не отменяет дальнейшие шаги ускорения. Авторское T_TRASH и текущая модель TRASH устанавливают назначение класса 14 как мусора форсажа, см. [подтверждение](ActionClass20Spawn.md#авторское-назначение-и-текущий-вызывающий-код).

Затем существующий операнд LimitWord по `7693` получает `1000`. Цикл B=16 сохраняет BC и вызывает [IncreaseGaugeWord.MotionGate](../Source/Action/IncreaseGaugeWord.asm) по `7685`. Вход пропускает проверку SkipDetail основного входа `7680`, но сохраняет требование MotionOpcode `3A`. При другом опкоде шестнадцать вызовов не изменяют SpeedWord. При допуске каждый вызов рассчитывает SpeedWord+8 и проверяет знак обёрнутой разности с LimitWord. Успешные изменения ставят SixthRequest по `669F`, отдельный от SecondRequest при расходе.

Цикл не заменён сложением 128 и насыщением. Каждый промежуточный знаковый отказ, переполнение и запрос сохраняются. BC вокруг каждого вызова восстанавливается, на обычном завершении B=0. Вспомогательные структуры, коэффициенты и стек остаются на существующих адресах.

69728 сквозных сценариев проверяют настоящий поиск, освобождение, поток 8, транспонированное преобразование и шестнадцать отдельных вызовов шкалы. Сверяются регистры кроме R и тактов, восемь банков RAM и кратность записей вне 32 временных байтов стека. Наблюдаемый дополнительный стек в этой серии — 10 байтов. Полное произведение входов не исчерпано. Сборка, IRQ и нативный игровой процесс не исполнялись.
