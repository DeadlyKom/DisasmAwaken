# Косвенные выборки текстуры через стек указателей

[RunTextureSampler](../Source/Intro/RunTextureSampler.asm), вход `6BE3`,
сохраняет CPU SP в исходном операнде `6BF3`, затем использует SP для чтения
строк по 64 слова. Число строк задаёт IXL, адрес назначения задаёт BC.
H принудительно равен 93, это страница таблицы замены младшего адреса.

Цепочка `9100..9281` создаётся
[InitializeLookupEffect](../Source/Intro/InitializeLookupEffect.asm) из 64 копий
[PointerSample](../Source/IntroTemplates/PointerSample.asm).
Последний INC C заменяется трёхбайтовым JP на
[NextTextureSampleRow](../Source/Intro/NextTextureSampleRow.asm), вход `6BED`.
Его нельзя вызывать обычным CALL, адрес возврата берётся из сохранённого
CPU-стека основного входа.

Каждая выборка читает слово через POP DE. Его младший байт выбирает элемент
таблицы `9300..93FF`, прочитанное значение заменяет E. D остаётся старшим
байтом исходного слова. Байт по новому адресу DE записывается в BC.
Таким образом, таблица преобразует младшую координату, старшая остаётся
в слове входного потока.

Первые 63 выборки строки увеличивают **только C**, без переноса в B.
В продолжении после последней записи выполняется `INC BC`.
При выравнивании C на 64 результат совпадает с прибавлением 64 к BC.
При произвольном C перенос, произошедший внутри первых 63 записей,
теряется. Это исходная особенность адресации, она сохранена.
Повторение уменьшает IXL, B не является счётчиком строк.

После последней строки HL имеет H=93 и L, равный исходному младшему байту
последнего слова. DE содержит последний преобразованный адрес, A содержит
последний выбранный байт, F=42 OR входной Carry. IXH сохранён, IXL=0,
альтернативные регистры и IY сохранены. SP восстанавливается, конечный
RET снимает внешний адрес возврата. В CPU-стек процедура не записывает.

[Проверка](../Tools/Disasm/Research/CheckIntroPointerSampler.py) получает
реальную цепочку исполнением построителя до таблиц фаз и ожиданий IRQ,
затем сравнивает её с формой исходного шаблона. Сам выборщик исполняется
вместе с продолжением на оригинальных байтах. Числовая модель отдельно
вычисляет адреса, регистры, все физические записи и их кратность.

1824 сценария покрывают длины 1..38 строк, четыре выровненных C, четыре
перестановки таблицы и три положения CPU-стека. Ещё 1024 сценария покрывают
все значения C на длинах две и пять строк с двумя вариантами таблицы.
Зафиксированы 882 потерянных переноса C. Основные игровые вызовы используют
13 и 25 строк, их длины входят в проверенный диапазон.

[Отчёт](../Tools/Disasm/Reports/IntroPointerSamplerVerification.json)
подтверждает регистры кроме R, все восемь банков RAM и кратность записей.
Нулевой IXL означал бы 256 строк, этот случай не доказан. Произвольные
перекрытия, время, аппаратные IRQ и нативный показ эффекта не проверялись.
