# Вывод объекта после чтения узла

[RenderQueuedObject](../Source/Action/RenderQueuedObject.asm) занимает 36 исходных байтов E4DB..E4FE ACTION банка 0. [Полный договор и композиционная проверка](ActionQueuedObject.md) описаны отдельно. Цепочка использует [коэффициенты C99B](ActionRenderCoefficients.md), [композицию CB23](ActionRenderMatrix.md), [проход вершин D5C9](ActionObjectVertices.md), [сканер кодов DEF3](ActionVertexCodes.md), [RenderInsideRecords](ActionPacketRenderer.md) и [RenderClippedRecords](ActionClippedPacketRenderer.md). Все адреса относятся к ACTION банка 0.

После первых четырёх вызовов Z сканера означает маркер отказа перспективы 80xx и пропускает рисование. Нулевой старший бит общего кода означает, что все точки лежат снаружи одной границы, такой объект тоже пропускается. Иначе ненулевая младшая тетрада выбирает DBBD для точек снаружи границ, нулевая выбирает DD23 для всех точек внутри. Общий хвост восстанавливает HL со стека, читает Next узла и последовательно исполняет выбор следующего узла по E4FF.

Начальный указатель узла сохраняет [ReadRenderQueue](ActionRenderQueueControl.md), разметка узла описана в [InsertRenderQueue](ActionRenderQueueInsert.md). В 1920 сценариях на всех исходных чётных индексах моделей сверены все физические банки, кратность записей, регистры кроме R и OUT 7FFD=14/10. Подготовители выполняются также в эталоне, новая независимая математика подготовки не заявляется. Последующий селектор, все игровые состояния, IRQ, сборка и нативный игровой процесс не доказаны.
