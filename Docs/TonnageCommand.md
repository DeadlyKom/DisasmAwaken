# Команда T и взвешенная сумма

[RecomputeTonnage](../Source/Text/RecomputeTonnage.asm) вызывает [ComputeWeightedLoad](../Source/Text/ComputeWeightedLoad.asm), сохраняет итоговый A по 9850 и переходит к следующей команде. Формулы, байтовые переполнения, инвертируемые веса и ограничения единиц разобраны в [WeightedLoad](WeightedLoad.md).

Входной HL команда сама не меняет. В штатном пути DispatchToken перед JP (HL) загружает HL адресом обработчика, то есть C0DB. Вычислитель превращает его в адрес `(9852+2*C0DB) AND FFFF = 1A08`. Он не совпадает ни с одной из 30 строк 9852..988C. Поэтому при обычном чтении команды T ни одна строка не получает дополнительную единицу. Прямой вызов с индексом 0..29 может её добавить. Нельзя автоматически подставлять текущий выбранный товар вместо фактического HL.

Начальный LD DE,67AE не меняет этот вывод, вызываемый вычислитель загружает DE=9852 до первого использования. Исправлять эту особенность исходника не требуется, байты оставлены без изменений.

[Модель](../Tools/Disasm/Research/CheckTonnageCommand.py) проверяет 256 прямых входов и 256 проходов через реальную таблицу команд и полный вычислитель, без заглушек. Все байты дополнительного выбора 984A включены. Проверяются физическая запись 9850, SelectedRow, результат, флаги, регистры и стек. [Отчёт](../Tools/Disasm/Reports/TonnageCommandVerification.json). Сборка, прерывания и нативный игровой запуск не выполнялись.
