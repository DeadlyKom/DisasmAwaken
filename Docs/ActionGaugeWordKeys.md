# Клавиатурное изменение слова шестой шкалы

[IncreaseGaugeWord](../Source/Action/IncreaseGaugeWord.asm), 7680..76A2,
и [DecreaseGaugeWord](../Source/Action/DecreaseGaugeWord.asm), 76A3..76C6,
находятся в фиксированном банке 5. Их оригинальные адреса присутствуют
в таблице клавиатурных указателей. Они изменяют SignedWord по A78F и
создают запрос SixthRequest=1 после записи. Игровые единицы слова пока
не установлены, назначение его шестой шкале подтверждено потребителем.

Оба входа допускают изменение только при нулевом SkipDetail по 6F59
и MotionOpcode=3A по 6E72. Этот байт является настоящим опкодом
LD A,(CBD8) в начале координатной цепочки, остальные значения не допускают
изменение. Увеличение сначала проверяет SkipDetail через OR, уменьшение
сначала проверяет опкод и затем SkipDetail через AND. Поэтому ранние
возвраты имеют разные A/F, даже при одинаковом запрете.

Увеличение вычисляет candidate=(SignedWord+8) AND FFFF. Из него с
очищенным Carry вычитается изменяемый LimitWord по 7693, исходно 0088.
Затем LimitWord прибавляется обратно, восстанавливая candidate в HL.
Этот ADD сохраняет S/Z/PV от SBC, поэтому RET P проверяет знак обёрнутой
разности candidate-LimitWord, а не знак candidate. При S=0 запись
отклоняется, при S=1 SignedWord получает candidate и запрос шкалы единицу.
На обычном неотрицательном диапазоне и LimitWord=0088 это строгая граница
candidate<0088. Для полного слова это не универсальное насыщение,
знаковые переполнения и переход через FFFF сохранены.

При достижении арифметики увеличение возвращает HL=candidate, DE=LimitWord.
A=3A при отказе или 1 при записи. Пусть difference=(candidate-LimitWord)
AND FFFF. S/Z/PV берутся из SUB16(candidate, LimitWord), биты 3/5 из
старшего байта candidate, N=0, H равен переносу из разряда 11 при
difference+LimitWord, Carry равен переносу из разряда 15 этого сложения.
Исходный SBC поэтому определяет знак, а последующий ADD меняет часть
прочих флагов. BC сохраняется.

Уменьшение читает SignedWord в HL и устанавливает DE=8. Для неотрицательного
слова сразу выполняется вычитание. Для отрицательного проверяется бит 4
младшего байта L. Если бит нулевой, возврат сохраняет слово, HL=прежнее
значение, DE=8, A=0 и F=54 OR (L AND 28). Если бит установлен, вычитается
8. Нет проверки обычного минимального signed16. Запись даёт
HL=(SignedWord-8) AND FFFF, A=1 и флаги SBC с исходным Carry=0. Нулевое
слово может перейти в FFF8, эта особенность не исправляется.

Все альтернативные регистры, IX/IY, I, IM, IFF и страница сохраняются.
SP после RET получает два байта внешнего возврата, CPU-стек не записывается.
Для увеличения точные M1 равны 3 при первом запрете, 6 при втором,
15 при знаковом отказе и 19 при записи. Для уменьшения это 3, 6, 14
при отказе отрицательного слова по биту 4, 18 при записи неотрицательного
слова и 21 при записи отрицательного. R сохраняет бит 7. Точные T не
проверялись.

[Независимая модель](../Tools/Disasm/Research/ReferenceActionGaugeWordKeys.py)
и [проверка исходных инструкций](../Tools/Disasm/Research/CheckActionGaugeWordKeys.py)
прошли 729088 сценариев. Проверены все пары запрета и опкода для обоих
входов, все слова уменьшения, все слова увеличения при семи границах,
все значения самой границы и 8192 смешанных случая. Сопоставлены регистры
включая R, все записи и восемь банков RAM. Полное произведение слова
и границы, IRQ, сборка и нативный игровой запуск не выполнялись.
