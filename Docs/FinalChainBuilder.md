# Контракт построителя тела финальной цепочки

[BuildDisplayChain](../Source/Final/BuildDisplayChain.asm) создаёт тело
цепочки, без заголовка сохранения SP и завершающих LD SP,nn и RET.
Эти части добавляет PrepareFrame. Начало тела передаётся в HL.

Один знакоместный ряд содержит восемь bitmap-шаблонов по 52 байта
и один атрибутный шаблон длиной 23 байта, всего 439 байтов.
24 ряда дают 10536 байтов команд. После рядов 10 и 18 построитель
пропускает по четыре байта, не меняя их содержимое. Поэтому полный
занятый диапазон тела равен 10544 байтам, `#2930`.

При начале start указатель AfterRow10 получает start+`#1126`, а
AfterRow18 получает start+`#1EE2`, включая первый пропуск.
Для штатного start=`#8004` это адреса `#912A` и `#9EE6`.
Исходные поля описаны в [разборе синхронизации](FinalSyncAndPreviewRecord.md).

Конечные HL=`#5B20`, DE=start+`#2930`, B=0, C сохраняется.
AF=`#019B`, A получает последний счётчик 1, флаги оставляет CP `#0F`.
DJNZ и RET их не меняют. Альтернативные и индексные регистры
сохраняются, как и I, IM и IFF при отсутствии вмешательства IRQ.
Шаблоны остаются подготовленными для строки после последней,
пять операндов равны `#D800`, `#5810`, `#D810`, `#5820`, `#5B20`.

При входном SP=s максимальная глубина составляет восемь байтов.
Внешнее слово возврата по s не перезаписывается, RET снимает его.
Остаточные слова после завершения:

| Адрес | Слово | Последняя запись |
| --- | --- | --- |
| s−8 | `#622C` | второй CALL NextBitmapLine в последней bitmap-строке |
| s−6 | `#61E9` | CALL EmitBitmapLine последней bitmap-строки |
| s−4 | `#61EF` | CALL EmitAttributeRow последнего знакоместного ряда |
| s−2 | `#0100` с входным C в младшем байте | PUSH BC последнего внешнего счётчика |

[Композиционная модель](../Tools/Disasm/Research/CheckFinalBuildDisplayChain.py)
исполняет исходный вход отдельно от PrepareFrame в 272 сценариях.
Для `#8004` проверены все 256 значений C, ещё по восемь значений
для начал `#7000` и `#9000`. Геометрический эталон создаёт каждый
экземпляр шаблона по формуле раскладки экрана, не вызывая исходные
генераторы. Проверены все 64 КБ итоговой памяти, конечные регистры
кроме R/T и число записей по каждому адресу.
[Отчёт](../Tools/Disasm/Reports/FinalBuildDisplayChainVerification.json).

Каждый сценарий содержит 13756 записей. Из них 10536 приходятся
на тело цепочки, 1584 на операнды шаблонов, четыре на указатели
синхронизации и 1632 на восемь байтов CPU-стека. Восемь байтов
пропусков сохраняют контрольное заполнение. Проверка не исполняет
результирующую цепочку, не подтверждает перекрытия и не включает IRQ.
Исполнение всей цепочки проверено отдельно в [разборе финала](Final.md).
