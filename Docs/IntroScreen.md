# Экранный распаковщик вступления

[UnpackScreen](../Source/IntroUnpack/UnpackScreen.asm) занимает 154 байта
исходной записи AWAKEN, смещения `2631..26CA`. Загрузчик переносит его
из `8931` в `6E31`, поток начинается сразу после кода по `6ECB`.
Синтетическая модель не заменяет показ этого экрана в эмуляторе.

## Получение адреса потока

`LD DE,008E / INC E` даёт DE=008F и гарантирует Z=0.
CALL по `1FC6` попадает в настоящие ROM-байты `E1 C8 E9`.
POP HL снимает адрес продолжения `6E3C`, RET Z не срабатывает,
JP (HL) возвращает исполнение на ADD HL,DE.
Сумма `6E3C+008F=6ECB` задаёт поток без передаваемого указателя.
CPU SP после этого трюка снова указывает на внешний возврат.

## Общий поток байтов и битов

Первый байт всегда литерал. Следующий управляющий бит, читаемый от
старшего к младшему, выбирает литерал при единице и пакет ссылки при нуле.
Литералы, расширения длины, младшие смещения и битовые байты используют
один продвигаемый курсор. Резервуар D содержит ещё не выбранные биты
и единичный маркер. Пополнение происходит только при следующем запросе
бита после исчерпания прежнего байта.

Переменная группа имеет маску `56`, то есть `01010110`.
Буквы a, b, c, d обозначают отдельные биты значения.

| Последовательность битов | Значение группы |
| --- | --- |
| `1` | FF |
| `0 a 1` | FD+a |
| `0 a 0 b 1` | F9+2a+b |
| `0 a 0 b 0 c d` | E9+8a+4b+2c+d |

Всего имеется 23 кода E9..FF. Одна и та же группа используется для длины
и старшего байта отрицательного смещения.

## Длина и направление ссылки

| Код длины g | Число байтов до поправки дальности |
| --- | --- |
| E9..F8 | 256−g, от 23 до 8 |
| FA..FF | 257−g, от 7 до 2 |
| F9 и ненулевое расширение e | 257−e, от 256 до 2 |
| F9 и расширение 0 | Конец потока |

Далее читаются группа старшего смещения, бит направления и младший байт
смещения. Полное смещение — отрицательное 16-битное слово E900..FFFF,
от −5888 до −1. Нулевой бит направления читает историю вперёд, единичный
читает её назад. Новые записанные байты доступны следующим выборкам
прямой перекрывающейся ссылки.

Если старший байт смещения меньше FD, отрицательный счётчик IXL уменьшается
ещё на один. Обычно это увеличивает длину на один. Счётчик восьмибитный,
поэтому длина 256 с этой поправкой превращается в **1**, а не в 257.
Исходное оборачивание сохранено и проверено отдельными синтетическими
потоками. Никаких проверок корректности ссылки или границ результата
в исходном коде нет.

## Логический экран и физическая адресация

Выходной DE линейно проходит `4000..5AFF`. Для пиксельного смещения o
от 0 до 6143 порядок соответствует байтовой колонке `(o >> 6) AND 31`
и строке `(o AND 63) OR ((o >> 11) << 6)`.
Физический адрес вычисляется по обычному размещению bitmap Spectrum.
Такой порядок проходит по 64 пиксельным строкам одной байтовой колонки,
затем по следующей колонке и следующей трети экрана.

Одинаковая перестановка применяется к курсору истории HL и назначению DE.
После логического адреса 5800 атрибуты читаются и пишутся линейно.
Сохранённый через EX AF,AF' Carry задаёт направление ссылки. Carry,
возникающий при перестановке адресных битов, хранится отдельно и не
подменяет направление.

Общий хвост адресов атрибутов использует Carry=1 для источника и Carry=0
для назначения. PUSH AF и POP AF сохраняют этот признак вокруг исходного
ADD A,00. У этой версии нулевая поправка старшей страницы остаётся
исходной, писатель другого значения не установлен.

## Результат и проверка

Исходный поток даёт 6912 байтов, 662 литерала и 338 ссылок.
217 ссылок прямые, 121 обратная, 46 используют расширение длины.
Из потока прочитаны 1440 байтов. Вместе со 154 байтами кода это 1594
из 1743 байтов оставшейся части исходного файла. Последние 149 байтов
сохранены, их назначение не считается установленным.

После исходного экрана HL=5AFF, DE=5B00, BC=5AFF, AF=FFA8.
Альтернативные HL'=2758, DE'=108F, BC'=00C0, AF'=5A50.
IXH сохранён, IXL=FF, IY и I/IM/IFF сохраняются. Конечный RET снимает
внешний возврат. Назначение фиксированного выходного слова 2758 у всех
потребителей ещё не установлено, само значение подтверждено.

[Независимый декодер](../Tools/Disasm/Research/IntroScreenCodec.py) описывает
битовую грамматику, прямые и обратные ссылки без исполнения Z80.
[Проверка](../Tools/Disasm/Research/CheckIntroScreen.py) сравнивает с ним
исходный Z80-код и настоящие три инструкции локальной 48K ROM.
Исследовательский сценарий принимает ROM аргументом, путь к внешнему
каталогу в проект не записан. ROM и Python не требуются обычной сборке.

1322 сценария включают восемь исходных экранов с разным контекстом,
один литерал, 1058 сочетаний всех кодов длины и старшего смещения
в обоих направлениях, 255 ненулевых расширений длины.
Все значения входного F встречаются в совокупности сценариев.
Независимо сверены регистры кроме R, вся логическая RAM, временные
байты CPU-стека и кратность каждой записи.

Хеш физического экрана SHA-256 равен
`3bb10a9f778e0da7f2529d5572ec5c0146f275746a6ac001670eb377ad01d58b`.
[Отчёт](../Tools/Disasm/Reports/IntroScreenVerification.json)
содержит хеш проверенной ROM. Повреждённые потоки, отдельная модель всех
физических банков, R/T, аппаратные IRQ и нативный показ не доказаны.
