# Адресные страницы отсечения предпросмотра

[Младшие байты](../Source/D3D/Data/PreviewClipTargetLow.asm) лежат в
CC00..CCFF, [старший префикс](../Source/D3D/Data/PreviewClipTargetHigh.asm)
в CD00..CDAF. Это исходные смещения 0C00..0DAF записи D3D, банк 4.
Каждая физическая строка занимает 16 байтов.

Первый код стороны выбирает строку через старшую тетраду индекса,
второй выбирает поле End0..EndF через младшую. Допустимые коды обеих
точек равны 0, 1, 2, 4, 5, 6, 8, 9, A. Для всех 81 сочетаний младший
и старший байт выражены через имена 71 действительной цели.
Это включает пустой RET и общие хвосты.

[ClipPreviewPolygon](../Source/D3D/ClipPreviewPolygon.asm) берёт коды
в исходном порядке и кладёт перед переходом один адрес продолжения.
[DispatchPreviewClipSegment](../Source/D3D/DispatchPreviewClipSegment.asm)
может переставить концы и кладёт три одинаковых слова. Оба читают
две страницы по одному индексу. Полный граф обработчиков и его
проверка описаны в [табличных решениях](PreviewClipCases.md).

Все байты вне обычных кодов сохранены буквально. На старшей странице
индексы B0..FF продолжают чтение уже в соседних физических данных,
начиная с [пиксельных масок](../Source/D3D/Data/PreviewPixelMasks.asm).
Исходный lookup не проверяет корректность индекса.
[Проверка](../Tools/Disasm/Research/CheckPreviewClipTablePages.py) исполнила
обе исходные последовательности до JP (HL) при всех 256 индексах.
Сверены адрес назначения и содержимое подставных кадров.
Обработчики для искусственных индексов не исполнялись.
[Отчёт исполнения](../Tools/Disasm/Reports/PreviewClipTablePagesVerification.json)
и [сверка физических байтов](../Tools/Disasm/Reports/PreviewClipTablePagesClassification.json).
