# Начальные записи ACTION и известные поля

Исходные байты записи 17 ACTION по смещениям 4100..477F задают
25 слотов по 64 байта от A100 до A700 и отдельную запись-маркер
по A740. В первых 25 слотах первый компонент равен 8000,
у маркера равен 8080, остальные исходные байты нулевые.
После маркера по A780 начинается соседнее состояние, в массив оно
этой разметкой не включается. Это физическая начальная раскладка,
не доказательство неизменного предела всех возможных состояний игры.

Физические экземпляры находятся в
[ObjectRecords](../Source/Action/Data/ObjectRecords.asm), каждый FActionRecord
занимает ровно 40 байтов в шестнадцатеричной записи.
FActionComponents содержит три вложенных FActionWord, у каждого Low и High.
Новые адреса и память не выделяются, исходные значения сохраняются.

| Смещение | Поле | Доказанный смысл |
|---|---|---|
| 00..05 | Components | Три little-endian слова, создаваемая ракета получает результаты TransformVectorTransposed |
| 06 | ModelOffset | Байтовое смещение таблицы указателей моделей 9E00 |
| 07 | OffsetPhase0 | Байтовый индекс первой фазовой пары вычислителя смещения |
| 08 | OffsetPhase1 | Байтовый индекс второй фазовой пары, подготовитель добавляет 128 |
| 09 | OffsetPhase2 | Байтовый индекс третьей фазовой пары вычислителя смещения |
| 0A | StateCode | Байтовый код диспетчера ObjectStateHandlers |
| 0B | LinkedIndex | У цели 60AE записывает индекс созданной ракеты |
| 0C | LinkFlags | Четыре контекстных признака в битах 0..3, старшие четыре бита не установлены |
| 0D | Phase0OrLink | Первая локальная фаза либо байтовый индекс связанной опоры |
| 0E | LocalPhase1 | Вторая локальная фаза, потребитель добавляет `#80` по модулю байта |
| 0F | Phase2OrTarget | Третья локальная фаза, индекс цели или порог счётчика |
| 10 | OffsetScaleLow | Младший байт масштаба в общем расчёте, полный беззнаковый масштаб в локальном |
| 11 | Unknown11 | Счётчик, порог, количество либо признак уведомления в зависимости от обработчика |
| 12 | ClassCode | Полный код для FindRecordByCode, создаваемая ракета получает 11 |
| 13 | EffectReserve | Текущий запас для проверки эффекта и связанных состояний |
| 14 | MissileRepeatDelay | Счётчик допуска создания записи класса 17 |
| 15 | LinkOverride | Индекс подстановки LinkedIndex, FF запрещает, ноль разрешён |
| 16 | SavedStateCode | Код состояния для восстановления в обработчиках хода и ожидания |
| 17 | PhaseMoveTimer | Байтовый таймер вызовов обработчиков хода первой фазы |
| 18 | ReuseByte | FF заставляет FindReusableRecord очистить байт и пропустить запись в этом проходе |
| 19 | TimedResumeCode | Полный прежний StateCode, возвращаемый при истечении таймера состояния `#10` |
| 1A..1F | ViewPosition | Знаковые слова X, Y и глубины после преобразования для текущего кадра |
| 20 | ProximityIndex | Полный байтовый индекс записи для проверки близости |
| 21 | ProximityClass | Требуемый полный класс выбранной записи |
| 22 | ReserveCeiling | Параметр предела восстановления запаса, используется уменьшенный на единицу |
| 23 | PickupKind | Байт вида подбора для класса `#13`, индекс груза и правила |
| 24 | OffsetScaleHigh | Старший байт масштаба смещения и фазовый счётчик ожидания |
| 25 | TargetCodeStep | Числовой шаг подвода фазовых кодов, не набор флагов |
| 26 | WideTargetIndex | Полный байтовый индекс строки широкой цели с шагом 12 байтов |
| 27..3F | Unknown27..Unknown3F | 25 исходных нулевых байтов в каждом физическом экземпляре |

Для диапазона `#27..#3F` проверены 26 физических хвостов и 25 699
декодированных инструкций ACTION, загрузчика, 3DPART, VOXAL и CONTROL.
В этих инструкциях нет операндов IX/IY с указанными смещениями.
Трасса инициализации ACTION и 64 полётных кадров видит чтения и записи
рабочих полей, а к хвостам в этом профиле обращений нет. Другие
сценарии и способы косвенной адресации остаются открытыми.
[Модель](../Tools/Disasm/Research/CheckActionRecordTail.py) ·
[Результат](../Tools/Disasm/Reports/ActionRecordTailVerification.json)

В шумовом цикле отдельно подтверждены условные обращения ROM к трём
этим байтам при подготовленном старшем разряде R, см. раздел ниже.

Единицы и полный пространственный смысл трёх компонентов ещё не объявляются
установленными. Итератор использует старший байт Component0 равный 80
для проверки пропуска, а младший байт 80 при этом задаёт маркер конца.
Это специальные коды в полях компоненты, отдельный флаг занятости
в дополнительной памяти не создаётся.

Индекс и класс для проверки близости записывает [создатель детей класса 9](ActionChildSpawn.md).
[Резервный поиск](ActionSelectClass8.md) может обновить только индекс.
Отдельное поле WideTargetIndex записывает [планировщик](ActionSelectWideTarget.md).
State01 читает его как индекс строки по формуле `#9B27 + 12 × индекс`,
включая исходный случай `#FF` без проверки границ массива.

При [входе во временное состояние `#11`](ActionEnterTimedState.md) прежний
код записывается в TimedResumeCode. Истечение первого таймера переводит
запись в [состояние `#10`](ActionTimedLinkedState.md) на 70 тиков.
Только после второго истечения восстанавливается сохранённый код.
OffsetScaleHigh увеличивается только при значении ниже 15 в
[фазовом ожидании](ActionObjectPhaseWait.md). [Подготовитель смещения](ActionObjectOffsetTransfer.md)
передаёт этот байт в D, после условного обнуления для классов ниже 16
вне состояния `#13`. Слово DE применяется как знаковый масштаб
трёх компонент [смещения](ActionObjectOffsetVector.md). E получает
OffsetScaleLow до условного инкремента, поэтому новое значение влияет
только на последующие расчёты. [Локальный вход](ActionLocalOffsets.md)
читает OffsetScaleLow в E и устанавливает D=0. State00 уменьшает младший
байт на два при ненулевом значении, а State07 делит его на два без знака
при продолжающемся таймере.

[Обход объектов](ActionObjectWalk.md) восстанавливает EffectReserve
для классов ниже 16. При проверке порога эффект запускается, если запас
меньше выбранного порога. Иначе [диспетчер](ActionRecordEffectResume.md)
записывает остаток после вычитания. State02 и State05 также сравнивают
запас с `#23` перед случайным выбором следующих действий.

[Проверка окна создания](ActionSpawnWindow.md) требует нулевой MissileRepeatDelay
и после попытки записывает байт по полному коду класса, даже если свободного
слота не оказалось. В [State02](ActionLinkedTargetState.md) и
[State05](ActionLinkedPhaseState.md) результат DEC со сброшенным знаком
записывается обратно. Переход с единицы на ноль вызывает создатель.
Вход `#80` даёт `#7F`, а входы `#00` и `#81..#FF` сохраняются
на этой ветви.

## Позиция после преобразования

FActionViewPosition занимает шесть байтов по #1A..#1F. В начале просмотра записи #E0EC пишет #80 в ViewPosition.X.High. После успешного ComputePatchedVector исходные PUSH по #E160, #E164 и #E169 записывают Depth, Y и X в обратном порядке. При раннем пропуске и арифметическом переполнении значение #80 остаётся признаком отсутствия свежей позиции, остальные байты могут хранить прежний результат. [Писатель](../Source/Action/RenderSceneFrame.asm) · [Подготовка кадра](ActionRenderFrameSetup.md)

Радар читает только старшие байты. X задаёт горизонтальное положение, Depth участвует в вертикальном положении основания метки, Y задаёт высоту её линии. Обработчики связанного контура и противоракетного режима используют целые слова. [Радар](../Source/Controls/DrawRadar.asm) · [Чтение связанной записи](ActionLinkedVectors.md)

Трасса 32 входов в исходный полётный кадр сверила 24 записи всех трёх слов с выходами преобразователя и 24 чтения каждого старшего байта радаром. Размер записи #40 и смещения следующих полей сохранены во всех 26 физических экземплярах. Единицы координат остаются открытыми. [Трасса](../Tools/Disasm/Reports/ActionRecordViewPositionVerification.json) · [Сверка физической разметки](../Tools/Disasm/Reports/ActionRecordViewPositionClassification.json)

## Разряды LinkFlags

Разряды 7..0 имеют схему `? ? ? ? P H R B`. Это независимые признаки в опубликованных контекстах, назначение разрядов 7..4 не выдумывается.

| Бит и маска | Доказанный писатель и условие |
| --- | --- |
| 0, B, 01 | [CheckAndToggleLinkedOverlay](ActionLinkedOverlay.md) устанавливает перед обратной записью LinkedIndex, если прочитанный R не меньше порога. ApplyPendingRecordLink устанавливает перед заменой LinkedIndex на 1A. |
| 1, R, 02 | Ракетная атака цели. [CreateLinkedMissileRecord](ActionClass17Spawn.md) устанавливает при создании связи цели с ребёнком, [State08](ActionArrivalState.md) до проверки активности выбранной цели |
| 2, H, 04 | Ракетное поражение цели. State08 устанавливает после нулевого накопителя остаточных старших байтов, то есть попадания в его ближнюю область |
| 3, P, 08 | ActivateAntimissileSystem устанавливает перед проверками вектора вместе с битом 0. CheckRecordEffectThreshold читает для выбора базового порога либо порога с учётом PS1 и PS2. |

Авторский `EQUS.a` из `awk1.trd` задаёт `ACTN EQU 12`, то есть нынешнее поле `LinkFlags` по смещению #0C. Комментарий к нему прямо называет бит 1 `ROKET ATACK`, бит 2 `ROKET KILLED YOU`. Эти значения сопоставлены с текущей записью класса #11 по #6127 и исходными писателями #613B, #F585 и #F62C. [Проверка архивных определений и текущих байтов](../Tools/Disasm/Research/ControlsObjectGlyphData.py) сохраняет исходный текст в [отчёте](../Tools/Disasm/Reports/ArchivedObjectGlyphRolesVerification.json). Установка бита поражения не означает обязательного освобождения цели, точные условия State08 описаны отдельно.

Старшие четыре бита имеют неустановленные отдельные роли, но не являются
игнорируемыми. [UpdateObjects.CheckLinks](../Source/Action/UpdateObjects.asm)
сначала проверяет весь байт через AND A. Значения #10, #20, #40 или
#80 при нулевых младших битах проходят ненулевой путь. При классе #0F
это вход CheckRecordEffectThreshold вместо прямого CallHandler.
При классе #12 исполняется счётчик связей и, если их меньше двух,
записывается StateCode=#0B. Нулевой байт сразу обходит эти действия.

[Модель обхода](../Tools/Disasm/Research/CheckActionObjectWalk.py)
проверяет все байты LinkFlags. В [отчёт](../Tools/Disasm/Reports/ActionObjectWalkVerification.json)
добавлены 32 явных профиля, оба класса при всех 16 старших тетрадах
и нулевых младших битах. Они подтверждают влияние на нулевую проверку,
а не собственные назначения битов 7..4 или достижимость таких значений
в нативной игре. Исходные маски, имена неизвестных ролей и нулевой
инициализатор сохранены.

Числовые индексы этих двух признаков заданы как
`ActionLinkFlagsConst.BackLinkBit` и `ActionLinkFlagsConst.AntimissileBit`.
Обход объектов использует существующий `ActionArrivalConst.RocketAttackBit`.
Проверка исходников восстанавливает прежние опкоды из именованных операндов.
[Константы](../Includes/Const/Include.inc) ·
[Противоракетная команда](ActionAntimissileCommand.md) ·
[Преобразование ожидающей записи](ActionRecordLinkEvent.md)

Бит 0 записывается до проверок знаков и переполнений, их отказ его не отменяет. Бит 1 State08 ставится даже у записи, которая затем окажется недоступной. Бит 2 ставится и при StateCode цели FF, это значение запрещает только освобождение текущей записи. Поэтому ни один из трёх битов сам по себе не доказывает наличие доступной живой цели.

Полный ноль сбрасывает четыре известных признака и четыре неизвестных разряда. Создатели могут записать весь нулевой байт при инициализации. Полный разбор всех игровых потребителей остаётся отдельной задачей. Физический формат FActionRecord, все 26 экземпляров и 1664 исходных байта сохранены.

При создании ракеты известны также записи 90 по 06, нулей по 07..09,
08 по 0A, 1A по 0D, 01 по 11, выбранного 0A либо 32 по 13 и 02 по 25.
Неустановленные поля сохраняют Unknown, StateCode выделен по доказанному потребителю.
Все не затронутые инициализатором байты сохраняются, нулевое исходное
заполнение не считается доказательством их невостребованности.

## Связанные алгоритмы

[Адресные преобразователи](ActionRecordIndex.md) задают шаг 64.
[FindReusableRecord](ActionRecordSearch.md) ищет доступную запись,
очищая ReuseByte в проверяемых строках. [Итератор и фильтр](ActionRecordIterator.md)
используют те же первые два байта и полный ClassCode.
Начальное содержимое не доказывает всех инвариантов игрового исполнения.

Проверка сравнивает каждый из 1664 байтов физического источника,
вложенные смещения и все именованные экземпляры. Сборку выполняет
пользователь, статическая разметка не объявляется нативным запуском.

## Дополнительный потребитель ReuseByte

[CheckCloseRecordComponents](ActionCloseRecord.md) проверяет только бит 4 ReuseByte, ноль направляет в общий хвост инверсии, единица допускает проверку старших байтов компонент. Другие потребители продолжают использовать полный байт, в том числе код FF. Это не переименование всего поля в набор независимых флагов.

## StateCode

[DispatchObjectState](../Source/Action/DispatchObjectState.asm) читает байт
по смещению #0A, удваивает его с оборачиванием байта и выбирает слово
из ObjectStateHandlers. Это числовой код, а не независимые флаги.
Все разряды 7..0 принадлежат одному байту кода, при формировании индекса
старший разряд теряется. Нулевой код выбирает State00. Исходная таблица
имеет 22 физических указателя на обработчики, проверки верхней границы на этом
входе нет. Допустимость остальных игровых значений этим не доказывается.
Смещение #0A, размер FActionRecord и все физические байты сохранены.

## ModelOffset

По смещению #06 хранится байтовое смещение таблицы 9E00, читаемое
[ReadObjectHeaderWord](../Source/Action/ReadObjectHeaderWord.asm).
Нулевое значение выбирает первую пару таблицы и само по себе не
означает отсутствие модели. Для обычных чётных значений номер пары
равен ModelOffset/2, но поле не переименовано в порядковый индекс.
Сам читатель не проверяет чётность, нечётное смещение и FF сохраняют
своё описанное физическое поведение. Разряды 7..0 образуют числовое
смещение, независимые флаги здесь не назначаются.

[PrepareRecordScale](../Source/Action/PrepareRecordScale.asm),
[FinishSpawnRecord](../Source/Action/FinishSpawnRecord.asm) и
[PrepareLargeEffect](../Source/Action/PrepareLargeEffect.asm) передают
поле одному читателю заголовка. Установленные писатели используют
разобранные таблицы шаблонов, пары моделей, выборку потока либо
константу #90 при создании ракеты. Конкретные игровые наименования
всех моделей этим именем не утверждаются.

## Фазовые индексы 07..09

OffsetPhase0, OffsetPhase1 и OffsetPhase2 задают три индекса исходной
256-байтовой синусоиды 9900. Единица поля соответствует одному индексу
страницы, арифметика оборачивается по модулю 256. Все разряды 7..0
образуют одно число, независимые флаги не назначаются. Нулевое значение
выбирает индекс ноль, на исходной странице его синус равен нулю.

[PrepareObjectOffsetTransform](../Source/Action/PrepareObjectOffsetTransform.asm)
передаёт первое и третье поля прямо, ко второму добавляет 128.
[BuildObjectOffsetCoefficients](../Source/Action/BuildObjectOffsetCoefficients.asm)
читает для каждого индекса пару значений с расстоянием 64 и вычисляет
три коэффициента. Имена пространственных осей не установлены и полям
не приписываются. [StepRecordTargetCodes](../Source/Action/StepRecordTargetCodes.asm)
подводит второе и третье поля к двум рассчитанным кодам по своим
различным правилам ограничения шага. [Физические шаблоны](ActionSpawnPhysicalRows.md)
содержат начальный OffsetPhase1. Разметка подтверждает использование
полей на разобранных путях, а не завершённость всех игровых классов.

## Восстанавливаемое состояние и числовые счётчики

SavedStateCode по 16 хранит код состояния, возвращаемый в StateCode
после хода либо ожидания. Его прямо читают
[AdvanceObjectOffsetFall](../Source/Action/AdvanceObjectOffsetFall.asm) и
[AdvanceObjectPhaseWait](../Source/Action/AdvanceObjectPhaseWait.asm).
[ConfigureClass9Link](../Source/Action/ConfigureClass9Link.asm) отдельно
распознаёт полный код 0D. Это один числовой код, а не независимые флаги,
нулевое значение при прямом восстановлении выбирает State00.
Полный игровой смысл всех кодов и всех классов этим не устанавливается.

PhaseMoveTimer по 17 уменьшается при каждом вызове двух обработчиков
хода. Смена состояния происходит при исходном таймере 1. Исходный ноль
не означает немедленное завершение, он оборачивается в FF. При переходе
из нарастания в спад записывается 1E, то есть 30 вызовов обработчика.
Единица здесь является вызовом соответствующего обработчика, перевод
в миллисекунды либо фиксированную частоту игровых кадров не утверждается.
Все восемь разрядов составляют числовой таймер.

TargetCodeStep по 25 задаёт предельный байтовый шаг
[StepRecordTargetCodes](../Source/Action/StepRecordTargetCodes.asm).
Два поля используют разные условия уменьшения шага и пропуска записи,
[точный алгоритм](ActionRecordCodeStep.md) сохраняет эти различия.
Нулевой шаг может приводить к записи прежнего значения, а не к пропуску
обработчика. Все разряды 7..0 относятся к числу. Создание ракеты пишет
02, подготовитель обычной записи выбирает 01 либо 02 по заголовку модели.
Адреса, физический размер записи и значения инициализации не изменены.

## Установленные контексты разрядов ReuseByte

Физический байт по 18 совмещает полный код однократного пропуска и
поля отдельных алгоритмов. Он не переименован в восемь независимых
флагов. Для контекстов опубликованных ниже процедур схема разрядов:

```text
разряд       7 6 5 4 3 2 1 0
назначение   ? ? ? E ? S N N
```

`NN`, маска 03, число оставшихся попыток создания класса 19 по
[CreateCargoAndUpdateList](ActionClass19Spawn.md). Ноль запрещает попытку,
1..3 уменьшаются до поиска места с сохранением остальных шести битов.
Это одно двухбитовое число. Отказ поиска не восстанавливает попытку.

`S`, бит 2, маска 04, [SpawnLinkedClass9Records](ActionChildSpawn.md)
проверяет его как уже инициированный запрос. Ноль допускает случайную
проверку, единица возвращает управление без обновления потока. Бит
устанавливается после случайного допуска, до поиска места и остаётся
установленным при отказе выделения. Его явно сбрасывает
[HandleSelectedRecordProximity](ActionSelectedRecordProximity.md) у
выбранной ближней записи до освобождения текущей.

`E`, бит 4, маска 10, создатель класса 19 устанавливает его при
нормализованном коде x<5, иначе обнуляет весь ReuseByte ребёнка.
[State0E](ActionLinkedProximity.md) использует исходный бит 4 выбранной
ближней записи для допуска большого эффекта, затем весь байт уже
заменён FF пометкой освобождения. Другой установленный потребитель
[CheckCloseRecordComponents](ActionCloseRecord.md) также проверяет
этот разряд в собственном контексте. Общее игровое имя флага не назначено.

Знаки `?` означают, что общий смысл разрядов 7, 6, 5 и 3 этой разметкой
не установлен. Заполнение нулями само по себе не доказывает их отсутствия.
Полный FF продолжает означать однократный пропуск для
[FindReusableRecord](ActionRecordSearch.md), когда первая компонента
записи допускает просмотр как свободной. Поиск обнуляет байт и пропускает
его в этом проходе. Нельзя трактовать FF только как одновременную установку
всех независимых признаков. Полный ноль означает нулевой счётчик и
сброшенные опубликованные разряды, доступность самой записи определяется
отдельно по Component0 и маркеру.

Физические 26 экземпляров, структура FActionRecord, все размеры,
смещения и исходные 1664 байта сохранены. Уточнены только комментарии.

### Авторское поле LZS у ракеты

`EQUS.a` задаёт `LZS EQU 17`, то есть нынешний Unknown11 по смещению #11. Отдельное пояснение к ракетам определяет ноль как ракету персонажа, неноль как ракету игрока. В текущих байтах [CreateMissileForTarget](../Source/Action/CreateMissileForTarget.asm) по #60D7..#60D9 передаёт A′=1, а [CreateMissileFromCurrentLink](../Source/Action/CreateMissileFromCurrentLink.asm) по #F26C..#F26E обнуляет A′. Общий создатель записывает его по #6124 в Unknown11 ракеты класса #11 и состояния #08. Его последующие проверки нуля управляют сообщениями игроку при потере и достижении цели.

[Реестр ролей байта](../Tools/Disasm/Research/CheckActionRecordByte11Roles.py) сверяет точную архивную строку, смещение и семь текущих инструкций с исходным ACTION. [Отчёт](../Tools/Disasm/Reports/ActionRecordByte11RolesVerification.json) отделяет это подтверждение происхождения ракеты от таймеров, вероятностных порогов и количества груза. Оно не превращает поле во всеобщий флаг и не доказывает отсутствия других косвенных употреблений. Поэтому общее Unknown11 пока сохранено.

## Авторский порядок координат и открытый масштаб

EQUS.a задаёт XW=0, YW=2, ZW=4. Эти определения поясняют порядок трёх координатных слов, в FActionComponents ему соответствуют Component0, Component1 и Component2. Добавлены адресные ASSERT на смещения 0, 2, 4. Они фиксируют физический порядок, не назначают новую систему координат и не устанавливают единицу расстояния.

[Проверка авторских определений и обозначений единиц](../Tools/Disasm/Research/InspectArchivedCoordinateUnits.py) просмотрела 160 исходников в шести TRD, 129 общим читателем и ещё 31 структурным читателем STORM из [расширенного реестра](AuthorSourceInventory.md). В STORM проверены 1512 комментариев, 39 строковых литералов и 5027 вхождений имён после декодирования, поиск не применяется к его двоичным кодам чисел как к обычному тексту. Для явно указанного набора слов найдено одно употребление «секунду» в BRAINPRO.a, в описании режима отлёта. Оно не определяет масштаб скорости или координат и не является измерением времени текущей игры. Слова «параметров» не считаются употреблением «метров», поиск ведётся по границам целых слов. Иные обозначения, упакованные руководства и внешние документы поиском не исключены. [Отчёт](../Tools/Disasm/Reports/ArchivedCoordinateUnitsInspection.json). Единицы у трёх полей сохраняются открытыми.

## Условные IRQ-псевдонимы хвостов записей

[Модель](../Tools/Disasm/Research/CheckActionNoiseObjectRecordAliases.py) проходит исходную инициализацию ACTION и один полётный кадр, затем пороговую ветвь к шуму. В двух ROM в первом копировании подготовлено R=#95. Настоящий CopyViewportToScreen получает из последних двух байтов шумового кадра IY=#A72B. На втором IRQ выполняются исходные команды ROM. Во втором кадре R развивается естественно и не переназначается, младшее слово FRAMES подготовлено к переполнению, нажатие A задано во второй клавиатурной матрице.

| Адрес и физическое поле | Подтверждённая операция ROM |
| --- | --- |
| #A72C, Record18.Unknown2C | #02FF читает флаги клавиатуры, #030B читает байт и ставит бит 5, результат #20. ROM 128K также читает бит 4 по #3870 |
| #A732, Record18.Unknown32 | #02FC читает исходный ноль как клавиатурный режим |
| #A76B, EndMarker.Unknown2B | #0045 увеличивает исходный ноль до единицы вместо старшего байта штатного FRAMES |

Все три обращения относятся к фиксированному физическому банку 2, независимо от страницы окна #C000. Оба варианта ROM дали точную ожидаемую последовательность чтений и записей. [Отчёт](../Tools/Disasm/Reports/ActionNoiseObjectRecordAliasesVerification.json). Исходные нули не заменяются результатами исполнения в образе. Комментарии трёх физических экземпляров отмечают условный псевдоним, общие имена Unknown2C/Unknown32/Unknown2B сохранены.

Условие R=#95 существенно: оно требует установленного бита 7. Для всех 128 исходных значений с битом 7, равным нулю, адреса IY+1, IY+7, IY+#30 и IY+#40 не попадают в хвосты этих записей. Достижимость нужного старшего бита в нативном запуске текущего Awaken не доказана. Наблюдаемая роль ROM не устанавливает первоначальное игровое назначение полей и не превращает весь хвост записи в клавиатурное состояние. Это отдельная проверка от 64 обычных полётных кадров без таких обращений.


## Последовательное заполнение и повторное использование исходного массива

[CheckActionRecordPoolLifecycle.py](../Tools/Disasm/Research/CheckActionRecordPoolLifecycle.py) исполняет настоящий CreateMissileForTarget, геометрию, поиск и инициализацию без сброса памяти между последовательными вызовами. Начальные 25 слотов и 64 байта маркера сверены с ACTION и полным оригинальным TRD. Смещения EffectReserve, ClassCode и ReuseByte сверены с реальной структурой. Наблюдатель записей подтверждён отдельной инструкцией CPU.

В 50 профилях каждый из 25 исходных слотов поочерёдно задаётся активной целью, отдельно проверяются Fallback и Preferred. Прочие 24 слота заполняются последовательно, в порядке от младшего свободного. Два следующих вызова возвращают отсутствие слота, IY=A740, AF=8042, весь массив остаётся побайтово прежним и записей CPU в него нет. Запас ракет не уменьшается, созданный EffectReserve равен 0A либо 32.

Затем фикстура освобождает первый и последний чужие слоты, задавая Component0=8000 и ReuseByte=FF. Первый вызов очищает только ReuseByte и пропускает запись, затем достигает маркера. Второй вызов уже принимает тот же слот и инициализирует новую запись. Освобождение здесь выполняет фикстура, проверка реальной игровой процедуры освобождения этим не заменяется.

Суммарно исполнено 1500 вызовов, 1300 созданий, 200 отказов, из них 100 с однократным пропуском FF. Все 64 байта EndMarker сохраняются после каждого вызова, записей CPU в A740..A77F нет. Исходный возврат и поля запаса сверены. [Отчёт](../Tools/Disasm/Reports/ActionRecordPoolLifecycleVerification.json) сохраняет порядок вызовов каждого профиля.

Этот результат подтверждает устойчивость маркера в конкретной последовательности создания и повторного использования. Все произвольные писатели, остальные способы создания, игровое освобождение, IRQ, разные матрицы и положения стека не охвачены, полный динамический предел игры по-прежнему не доказан. Сборка и нативный запуск не выполнялись.


### Повторение с настоящими процедурами освобождения

Режим --game-release той же [модели жизненного цикла](../Tools/Disasm/Research/CheckActionRecordPoolLifecycle.py) заменяет ручные три записи настоящими MarkRecordForReuse по F394 и MarkIYRecordForReuse по F03D. Первый чужой слот помечается через IX, последний через IY. Проверены все 13 исходных байтов каждого входа относительно ACTION, весь массив RAM до и после, точный порядок трёх записей и все регистры кроме T, включая семь M1 и сохранность бита 7 R.

В 50 профилях выполнено 100 таких пометок и прежние 1500 вызовов создания. После каждого настоящего освобождения поиск очищает ReuseByte=FF и отказывает на полном остальном массиве, следующий вызов создаёт запись в освобождённом слоте. Все 64 байта маркера остаются прежними, собственных записей в него нет. Параметры Fallback/Preferred и исходный возврат по-прежнему сохраняются. [Отчёт реального освобождения](../Tools/Disasm/Reports/ActionRecordPoolRealReleaseVerification.json) отделён от прежнего режима ручной фикстуры.

Выбор слота и момент вызова пометчика остаются действиями сценария модели. Реальная цепочка инструкций освобождение → поиск → создание исполнена без заглушек, но её достижимость из полного игрового кадра и поведение всех остальных писателей этим не доказаны. Аппаратные IRQ и нативное исполнение не выполнялись, глобальный динамический предел массива остаётся открытым.


## Циклы создания и массового освобождения класса 14

[CheckActionClass14PoolCycle.py](../Tools/Disasm/Research/CheckActionClass14PoolCycle.py) связывает настоящие CreateBoostDebrisRecord по 617D и ReleaseBoostDebrisRecords по 6172. Название создателя использует десятичное 20, записываемый ClassCode равен 14 шестнадцатерично. После начальной подготовки единичной матрицы, потока Stream8 и режима по 6E75 модель не меняет классы и не освобождает слоты вручную.

В каждом из десяти профилей выполняются три последовательных цикла. Создатель заполняет все 25 исходных слотов, следующее создание отказывает на A740 без записи массива и без шага генератора. ReleaseBoostDebrisRecords сама находит все записи класса 14 через настоящие поиск и итератор, вызывает MarkIYRecordForReuse и оставляет Component0=8000, ReuseByte=FF. Сверены полный массив и точная последовательность 75 записей, по три на запись. Кроме них записываются только временные адреса CALL по BFFA..BFFD.

Первый последующий CreateBoostDebrisRecord очищает ReuseByte всех 25 строк, каждую пропускает и возвращает отказ по маркеру. Генератор не продвигается. Следующий цикл вновь заполняет слоты от нулевого, без восстановления исходного снимка и без сброса генератора либо матрицы. Сверены компоненты созданной записи с реальным выходом преобразования, ClassCode=14, EffectReserve=FA, нулевой ReuseByte и неизменность остальных слотов.

[Отчёт](../Tools/Disasm/Reports/ActionClass14PoolCycleVerification.json) содержит 750 созданий, 60 отказов, 30 массовых освобождений и 750 очисток отложенного пропуска. Все 64 байта маркера сохраняются после каждого вызова, CPU не пишет в A740..A77F. Внешний возврат сохраняется, SP восстанавливается. Варьируются пять начальных слов Stream8 и два знаковых режима третьей компоненты.

Это полный последовательный протокол названных процедур, вызовы выбирает сценарий модели. Достижимость создания из исходного главного цикла, все матрицы и писатели, полный R, IRQ, нативный запуск и глобальный динамический предел пула не доказаны. Сборка не выполнялась.

## Общий тип компонент и разные владельцы

Смещения Component0/1/2 объектной записи совпадают с определениями XW/YW/ZW архивного EQUS, полная пространственная интерпретация этим совпадением не доказывается. Писатель F45E задаёт 46 одновременно с StateCode=02, поэтому на локальном сравнении State02 это порог младшего байта потока 0, а не уменьшаемый таймер. Имя соответствующей константы уточнено как ActionPeriodicClass3Const.LinkedThreshold. [Цепочка создания и границы проверки](ActionPeriodicClass3State.md#начальный-порог-состояния-02). Константа ActionChildSpawnConst.InitialParam11 описывает начальное значение, не навязывая ему таймерную роль во всех состояниях.
