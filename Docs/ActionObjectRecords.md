# Начальные записи ACTION и известные поля

Исходные байты записи 17 ACTION по смещениям 4100..477F задают
25 слотов по 64 байта от A100 до A700 и отдельную запись-маркер
по A740. В первых 25 слотах первый компонент равен 8000,
у маркера равен 8080, остальные исходные байты нулевые.
После маркера по A780 начинается соседнее состояние, в массив оно
этой разметкой не включается. Это физическая начальная раскладка,
не доказательство неизменного предела всех возможных состояний игры.

Физические экземпляры находятся в
[ObjectRecords](../Source/Action/Data/ObjectRecords.asm), каждый FActionRecord
занимает ровно 40 байтов в шестнадцатеричной записи.
FActionComponents содержит три вложенных FActionWord, у каждого Low и High.
Новые адреса и память не выделяются, исходные значения сохраняются.

| Смещение | Поле | Доказанный смысл |
|---|---|---|
| 00..05 | Components | Три little-endian слова, создаваемая ракета получает результаты TransformVectorTransposed |
| 06 | ModelOffset | Байтовое смещение таблицы указателей моделей 9E00 |
| 07 | OffsetPhase0 | Байтовый индекс первой фазовой пары вычислителя смещения |
| 08 | OffsetPhase1 | Байтовый индекс второй фазовой пары, подготовитель добавляет 128 |
| 09 | OffsetPhase2 | Байтовый индекс третьей фазовой пары вычислителя смещения |
| 0A | StateCode | Байтовый код диспетчера ObjectStateHandlers |
| 0B | LinkedIndex | У цели 60AE записывает индекс созданной ракеты |
| 0C | LinkFlags | Бит 1 устанавливается при этой записи связи, остальные разряды пока неизвестны |
| 0F | TargetIndex | У создаваемой ракеты содержит входной код цели |
| 12 | ClassCode | Полный код для FindRecordByCode, создаваемая ракета получает 11 |
| 16 | SavedStateCode | Код состояния для восстановления в обработчиках хода и ожидания |
| 17 | PhaseMoveTimer | Байтовый таймер вызовов обработчиков хода первой фазы |
| 18 | ReuseByte | FF заставляет FindReusableRecord очистить байт и пропустить запись в этом проходе |
| 25 | TargetCodeStep | Числовой шаг подвода фазовых кодов, не набор флагов |
| Прочие | Unknown0D и другие неустановленные поля | Игровой смысл ещё не доказан, известные значения инициализации указаны прямо |

Единицы и полный пространственный смысл трёх компонентов ещё не объявляются
установленными. Итератор использует старший байт Component0 равный 80
для проверки пропуска, а младший байт 80 при этом задаёт маркер конца.
Это специальные коды в полях компоненты, отдельный флаг занятости
в дополнительной памяти не создаётся.

## Разряды LinkFlags

Разряды 7..0 имеют схему `? ? ? ? ? ? L ?`, известный L занимает бит 1,
его маска 02. 60AE устанавливает L одновременно с созданием связи через
LinkedIndex. Полный разбор потребителей и всех писателей ещё не завершён.
При нуле известный L и все неизвестные разряды сброшены, но отсутствие
живого связанного объекта одним этим значением не доказывается.
Назначение других семи битов не выдумывается.

При создании ракеты известны также записи 90 по 06, нулей по 07..09,
08 по 0A, 1A по 0D, 01 по 11, выбранного 0A либо 32 по 13 и 02 по 25.
Неустановленные поля сохраняют Unknown, StateCode выделен по доказанному потребителю.
Все не затронутые инициализатором байты сохраняются, нулевое исходное
заполнение не считается доказательством их невостребованности.

## Связанные алгоритмы

[Адресные преобразователи](ActionRecordIndex.md) задают шаг 64.
[FindReusableRecord](ActionRecordSearch.md) ищет доступную запись,
очищая ReuseByte в проверяемых строках. [Итератор и фильтр](ActionRecordIterator.md)
используют те же первые два байта и полный ClassCode.
Начальное содержимое не доказывает всех инвариантов игрового исполнения.

Проверка сравнивает каждый из 1664 байтов физического источника,
вложенные смещения и все именованные экземпляры. Сборку выполняет
пользователь, статическая разметка не объявляется нативным запуском.

## Дополнительный потребитель ReuseByte

[CheckCloseRecordComponents](ActionCloseRecord.md) проверяет только бит 4 ReuseByte, ноль направляет в общий хвост инверсии, единица допускает проверку старших байтов компонент. Другие потребители продолжают использовать полный байт, в том числе код FF. Это не переименование всего поля в набор независимых флагов.

## StateCode

[DispatchObjectState](../Source/Action/DispatchObjectState.asm) читает байт
по смещению #0A, удваивает его с оборачиванием байта и выбирает слово
из ObjectStateHandlers. Это числовой код, а не независимые флаги.
Все разряды 7..0 принадлежат одному байту кода, при формировании индекса
старший разряд теряется. Нулевой код выбирает State00. Исходная таблица
имеет 22 опубликованных обработчика, проверки верхней границы на этом
входе нет. Допустимость остальных игровых значений этим не доказывается.
Смещение #0A, размер FActionRecord и все физические байты сохранены.

## ModelOffset

По смещению #06 хранится байтовое смещение таблицы 9E00, читаемое
[ReadObjectHeaderWord](../Source/Action/ReadObjectHeaderWord.asm).
Нулевое значение выбирает первую пару таблицы и само по себе не
означает отсутствие модели. Для обычных чётных значений номер пары
равен ModelOffset/2, но поле не переименовано в порядковый индекс.
Сам читатель не проверяет чётность, нечётное смещение и FF сохраняют
своё описанное физическое поведение. Разряды 7..0 образуют числовое
смещение, независимые флаги здесь не назначаются.

[PrepareRecordScale](../Source/Action/PrepareRecordScale.asm),
[FinishSpawnRecord](../Source/Action/FinishSpawnRecord.asm) и
[PrepareLargeEffect](../Source/Action/PrepareLargeEffect.asm) передают
поле одному читателю заголовка. Установленные писатели используют
разобранные таблицы шаблонов, пары моделей, выборку потока либо
константу #90 при создании ракеты. Конкретные игровые наименования
всех моделей этим именем не утверждаются.

## Фазовые индексы 07..09

OffsetPhase0, OffsetPhase1 и OffsetPhase2 задают три индекса исходной
256-байтовой синусоиды 9900. Единица поля соответствует одному индексу
страницы, арифметика оборачивается по модулю 256. Все разряды 7..0
образуют одно число, независимые флаги не назначаются. Нулевое значение
выбирает индекс ноль, на исходной странице его синус равен нулю.

[PrepareObjectOffsetTransform](../Source/Action/PrepareObjectOffsetTransform.asm)
передаёт первое и третье поля прямо, ко второму добавляет 128.
[BuildObjectOffsetCoefficients](../Source/Action/BuildObjectOffsetCoefficients.asm)
читает для каждого индекса пару значений с расстоянием 64 и вычисляет
три коэффициента. Имена пространственных осей не установлены и полям
не приписываются. [StepRecordTargetCodes](../Source/Action/StepRecordTargetCodes.asm)
подводит второе и третье поля к двум рассчитанным кодам по своим
различным правилам ограничения шага. [Физические шаблоны](ActionSpawnPhysicalRows.md)
содержат начальный OffsetPhase1. Разметка подтверждает использование
полей на разобранных путях, а не завершённость всех игровых классов.

## Восстанавливаемое состояние и числовые счётчики

SavedStateCode по 16 хранит код состояния, возвращаемый в StateCode
после хода либо ожидания. Его прямо читают
[AdvanceObjectOffsetFall](../Source/Action/AdvanceObjectOffsetFall.asm) и
[AdvanceObjectPhaseWait](../Source/Action/AdvanceObjectPhaseWait.asm).
[ConfigureClass9Link](../Source/Action/ConfigureClass9Link.asm) отдельно
распознаёт полный код 0D. Это один числовой код, а не независимые флаги,
нулевое значение при прямом восстановлении выбирает State00.
Полный игровой смысл всех кодов и всех классов этим не устанавливается.

PhaseMoveTimer по 17 уменьшается при каждом вызове двух обработчиков
хода. Смена состояния происходит при исходном таймере 1. Исходный ноль
не означает немедленное завершение, он оборачивается в FF. При переходе
из нарастания в спад записывается 1E, то есть 30 вызовов обработчика.
Единица здесь является вызовом соответствующего обработчика, перевод
в миллисекунды либо фиксированную частоту игровых кадров не утверждается.
Все восемь разрядов составляют числовой таймер.

TargetCodeStep по 25 задаёт предельный байтовый шаг
[StepRecordTargetCodes](../Source/Action/StepRecordTargetCodes.asm).
Два поля используют разные условия уменьшения шага и пропуска записи,
[точный алгоритм](ActionRecordCodeStep.md) сохраняет эти различия.
Нулевой шаг может приводить к записи прежнего значения, а не к пропуску
обработчика. Все разряды 7..0 относятся к числу. Создание ракеты пишет
02, подготовитель обычной записи выбирает 01 либо 02 по заголовку модели.
Адреса, физический размер записи и значения инициализации не изменены.
