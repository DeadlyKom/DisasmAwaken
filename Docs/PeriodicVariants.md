# Периодический вызывающий путь анимации вариантов

[DrawVariantPanel](../Source/Station/DrawVariantPanel.asm) записывает 78D6 в операнд MenuCommandState.PeriodicCall по 9A89. MainLoop имеет исходный CALL по 9A88, поле цели начинается с 9A89. Это прямое основание кода callback, адреса не выбраны по сходству байтов.

- [Station.RefreshVariantPanel](../Source/Station/RefreshVariantPanel.asm) по 78BD.
- [Station.UpdateVariantPanel](../Source/Station/UpdateVariantPanel.asm) по 78D6.

Нормальный путь вращает временную маску, проверяет последний обработчик списка, получает количество выбранных вариантов, очищает тело и вызывает [DrawVariantCluster](../Source/Map/DrawVariantCluster.asm) в банке 1. Отложенный путь зависит от наличия активного элемента. Подробные договоры обоих входов описаны в исходниках и ниже. Статическое основание callback не является нативным запуском.


[Обёртка наличия](../Source/Station/TryDrawVariantPanel.asm) проверяет точный указатель обработчика в списке. При отсутствии возвращает без рисования, при наличии последовательно исполняет [рисователь панели](../Source/Station/DrawVariantPanel.asm). Между файлами нет дополнительного CALL.

## Построение панели и подготовка вариантов

Рисователь читает свой индекс из операнда ItemIndex. SetBandFillMode временно настраивает шесть слов полосовой рамки по FillMode, DrawCaptionItem регистрирует и рисует рамку с заголовком, ResetBandMode восстанавливает обычные значения слов. Последующее CheckItemRect выбирает периодический callback, но не защищает уже выполненное рисование. Поэтому допустимость рамки остаётся входным условием. Например, ширина три допустима рисователю заголовка, но проверка минимального размера четыре заменяет периодическую цель на EmptyCallback.

Количество получается через [GetSelectedVariantCount](../Source/Station/GetSelectedVariantCount.asm). При нуле процедура возвращает сразу, прежние ресурсные операнды и Count KARTA не сбрасываются. При ненулевом количестве AF временно обменивается с альтернативным набором, выбирается банк KARTA, AF возвращается и [PrepareVariantResources](../Source/Map/PrepareVariantResources.asm) подготавливает ровно 1..6 указателей. Поиск сохранённых ключей может изменить IX. Входной IX не объявлен сохранённым. IY и альтернативные общие пары сохраняются при договоре вложенного HALT.

SelectRamBank объединяет входной байт со старшими пятью битами CurrentPage. Поэтому один и тот же вход A=11 выбирает физический банк 1 с итоговым байтом 11 при обычном показе банка 5 и 19 при показе теневого банка 7. Последующий A=10 возвращает соответственно 10 либо 18. Это сохранение бита показа экрана, произвольная старая конфигурация не восстанавливается.

## Запрос отложенной перерисовки

RefreshPending читается целиком. Ноль выбирает обычный периодический путь, ненулевой код передаёт управление в RefreshVariantPanel. Только эта ветвь проверяет ActiveItemState.Active. Пока активный элемент существует, запрос и тактовая маска не меняются. При отсутствии активного элемента запрос сбрасывается до дальнейших операций.

Обработчик панели переносится в конец списка по индексу, используя настоящий MoveItemToTail с фиксированным сдвигом 128 байтов. Вход предполагает, что обработчик уже существует. При отсутствии совпадения помощник использовал бы входной HL как новую обёртку, такой случай не принят за допустимый вход RefreshVariantPanel.

BeginScreenUpdate сохраняет старые 6912 байтов экрана в банке 7 и показывает этот снимок. Затем TryDrawVariantPanel исполняет действительный рисователь, а общий хвост EndScreenUpdate возобновляет указатель и показывает изменённый базовый экран. При ненулевом количестве последовательность записей 7FFD равна 17,18,19,18,10. При нуле она равна 17,18,10. Самая первая 17 открывает банк 7 для копирования с показом банка 5, 18 показывает готовый снимок с банком кода 0.

## Маска периодичности и последний обработчик

Начальная CadenceMask равна 80, схема разрядов 7..0 — 1 0 0 0 0 0 0 0. После RRCA старый бит 0 попадает в Carry, нулевой Carry даёт ранний RET. Начальная единица доходит до бита 0 за семь поворотов, восьмой разрешает рисунок и восстанавливает 80. Нулевой байт не разрешает ни одного рисунка, FF разрешает каждый. Это циклическая временная последовательность, отдельными флагами её разряды не являются.

Поворот выполняется до проверки последнего обработчика. Поэтому неподходящая верхняя запись списка не останавливает маску, только пропускает текущий рисунок. Проверяется точный адрес рисователя панели, а не индекс её записи. На раннем выходе по Carry=0 Z и PV ещё относятся к предшествующему OR нулевого RefreshPending, они равны единице даже при ненулевом повёрнутом A. Выводить смысл Z из текущего A здесь нельзя.

## Прямоугольник указателя и очистка

При принятом такте и совпавшем последнем обработчике количество сохраняется через PUSH AF. По ItemIndex считываются четыре физических поля X,Y,Width,Height. Пиксельная позиция указателя переводится в символьную тремя сдвигами каждого байта. Точный допуск равен X-1≤tileX<X+Width и Y-1≤tileY<Y+Height при обычной допустимой геометрии. Левая и верхняя соседние ячейки принимаются отдельными переходами при нулевой разности. Замена обычным прямоугольником от X,Y изменила бы поведение.

Внутри расширенной зоны выполняется SuspendPointer и ResumeRequired получает 1. Вне зоны он получает 0. Это полный числовой код, после рисунка проверяемый через OR A. Затем DE с символьным началом сохраняется на стек, FillWindowBody очищает внутреннее тело по ещё действующему TextWindow, DE восстанавливается, выбирается KARTA и сохранённый AF количества возвращается перед C677.

После DrawVariantCluster возвращается банк станции и при ненулевом ResumeRequired выполняется ResumePointer. Основной AF в конце равен 0100 при выполненном возобновлении либо 0044 при его отсутствии. Это сохранённое решение о возобновлении, не общий признак успешности игровой операции. HL, DE и BC остаются от последнего шага анимационного кластера. Нулевое количество не отменяет очистку, центральную метку C677 и потребление первой пары её потока.

FVariantUpdateFrame после PUSH DE по 792E содержит SavedOriginXY по SP+0, SavedCountAF по SP+2 и ReturnAddress по SP+4. Каждое поле занимает два байта. После заливки POP DE удаляет первое слово, перед вызовом C677 POP AF удаляет второе. Во время внутренней заливки SP заимствуется отдельным помощником, его IRQ-договор сохраняет силу. Нового постоянного буфера или стека не введено.

## Проверки

[CheckPeriodicVariants](../Tools/Disasm/Research/CheckPeriodicVariants.py) исполнил 512 сочетаний всех масок и двух последних обработчиков, 255 ненулевых кодов активного элемента, все 49152 позиции указателя и четыре отсутствующих указателя списка. Нормальный callback прошёл 256 полных банковых вызовов для всех восьми кодов количества, четырёх прямоугольников, четырёх позиций указателя и двух режимов заливки. Реальная заливка, C677 и указатель сравниваются с независимой композицией всего bitmap и атрибутов. Проверены курсоры, ресурсы, оба переключения банков и выходные регистры.

Отложенная ветвь прошла 96 полных перестроений с исходными MoveItemToTail, BeginScreenUpdate, DrawCaptionItem, подготовкой ресурсов и EndScreenUpdate. Проверены исходный снимок банка 7, порядок записей порта, ресурсы, сохранение результата перед завершающим показом, конечный указатель и SP. Это интеграционная проверка реального рисователя, отдельный независимый oracle всей рамки в данном тесте не заявлен. Пиксельный договор заголовка проверен в CaptionItem отдельно.

Во всех 96 отложенных случаях настоящий HALT пробуждён явной фикстурой, ISR не исполнялся. Владелец указателя в этой модели нулевой. Ненулевые владельцы, аппаратные IRQ, произвольная прежняя конфигурация paging, весь цикл главного меню, сборка и нативный запуск этим отчётом не подтверждены.
