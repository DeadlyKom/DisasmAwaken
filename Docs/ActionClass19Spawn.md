# Создание класса 19 и исходный производный код списка

[SpawnClass19AndUpdateList](../Source/Action/SpawnClass19AndUpdateList.asm)
занимает 6417..64DE перенесённого ACTION банка 5. Нижние два бита
ReuseByte родителя являются в этом контексте счётчиком попыток 0..3.
Ноль возвращает AF=0054 без изменения RAM. Иначе поле уменьшается
на один, остальные шесть битов сохраняются. Попытка расходуется
**до** поиска свободной записи и при отказе не восстанавливается.

Для прочитанного R вычисляются `q=R AND 31`, `x=q<27 ? q : q-5`,
`marked=x<5`. H получает полный R, L получает x и временный бит 7
при marked. Биты 4..6 того же R дают управляющий код 1..8, сохраняемый
через AF'. Его общее игровое назначение не выдумывается.
[FindReusableRecord](ActionRecordSearch.md) ищет место, при отказе
возвращаются AF=8042, IY маркера, HL сохранённой пары из R,
AF' управляющего кода, родительский счётчик уже уменьшен.

Найденный ребёнок получает:

| Поля | Значение |
| --- | --- |
| Components0..2 | каждая соответствующая компонента родителя плюс 200 по модулю 65536 |
| ModelOffset | 98, байтовое смещение таблицы моделей |
| StateCode | 04, обработчик ускоренных фаз |
| LinkedIndex, LinkFlags | FF, 0 |
| Unknown0D..0F | OffsetPhase0..2 родителя, отдельные фазы вычислителя |
| Unknown10 | min(max(родительский байт минус 30, 0), 69) |
| Unknown11 | управляющий код 1..8 |
| ClassCode | 13, десятичный 19 |
| Unknown13 | 14, десятичное 20 |
| ReuseByte | 10 при marked, иначе 0 |
| Unknown23 | нормализованный x от 0 до 26 |

Прочие поля не обнуляются. В частности, фазы 07..09 ребёнка не
инициализируются этим входом. [State04](ActionFastPhaseState.md)
изменяет их, но его [вычислитель](ActionLocalOffsets.md) читает именно
клонированные байты 0D..0F. Бит 4 ReuseByte позднее проверяет
[State0E](ActionLinkedProximity.md) до перезаписи всей пометки.

Важная особенность оригинала, после второго EXX **HL остаётся парой
из R, а не адресом IY ребёнка**. Именно этот HL передаётся
[RecordAddressToIndex](ActionRecordIndex.md). Пусть
`packed=(R<<8) | x | (marked ? 128 : 0)`, тогда код для списка
`E=(((packed-A100) AND FFFF) / 64) AND FF`, деление целое.
Код не обязан совпадать с индексом созданной записи. Он всегда чётный
и может равняться FE, например для прочитанного R=20, 60, A0 либо E0.
Это установленное поведение, подстановка IY ради исправления не сделана.

Список с A01C имеет отдельные значения FF и FE. FE завершает вызов
без добавления за маркером. FF заменяется кодом E. Обычный элемент
разыменовывается как индекс, при High выбранной Component0=80 он
заменяется E, иначе просмотр продолжается. Таким образом, производный
FE может реально заменить FF либо недоступную цель и стать более
ранним маркером следующего просмотра. Этот случай не исключён моделью.

После успешного создания HL указывает достигнутую ячейку списка,
DE=00:E, B=x, C равен прежнему ReuseByte родителя. Для конечного FE
AF=FE6A, для заменённого FF AF=FF2A, для заменённой недоступной цели
AF=8042. Поэтому Z сам по себе не означает, был ли код записан.
AF' содержит ограниченный Unknown10 и флаги CP значения до верхнего
ограничения с 70. Альтернативные пары зависят от последней проверки
списка, IX, I, IM, IFF и paging сохраняются, SP после RET увеличен
на два. Максимальная дополнительная рамка равна двум байтам.

R точно рассчитывается независимой композицией. Нулевой счётчик
даёт 5 M1. До чтения R при ненулевом счётчике проходит 14 M1,
нормализация 27..31 добавляет один M1, временный бит 7 добавляет два.
Далее учитываются фактическая длина поиска, ветви ограничения и каждый
просмотренный элемент списка. Бит 7 R сохраняется, точные T не измерялись.

[Независимая модель](../Tools/Disasm/Research/CheckActionClass19Spawn.py)
проверила 92160 сценариев, все пары ReuseByte и начального R, все
Unknown10 и все первые байты списка. Реальные поиск и оба преобразования
индекса исполняются. Сверены регистры, флаги, R, SP, восемь банков и
кратность всех записей. Получены 171 реальная запись производного FE
в список. Полное произведение входов, аппаратные IRQ, сборка и
нативный запуск не выполнялись.

[Исходный физический список](ActionCandidateList.md) содержит десять кодов FF и завершающий FE. Это начальная разметка, общий предел произвольного runtime-списка этим не устанавливается.
