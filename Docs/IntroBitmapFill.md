# Заполнение первых 128 строк INTRO

[FillBitmap](../Source/Intro/FillBitmap.asm) занимает исходные адреса #6A67..#6AC0. Входной C задаёт заполнитель, входной B не используется. HL начинается с #4000, собственный B задаёт 128 строк. В каждой строке 32 развёрнутые записи с INC L между ними, затем L восстанавливается из E. Это сохраняет байтовую колонку до отдельного перехода ULA.

INC H переходит к следующей пиксельной строке. После каждых восьми строк младший адрес получает #20. Если сложение переполнилось, старший адрес уже относится к следующей части экрана. Иначе H уменьшается на восемь. Так обходится ровно диапазон #4000..#4FFF, каждая из 128 строк содержит 32 разных байта. Последние 64 строки bitmap и атрибуты не изменяются.

На выходе HL=#5000, D сохранён, E=#E0, B=0, C сохранён. Последний ADD A,#20 получает #E0+#20, поэтому A=0 и F=#41. Это конечные Z/Carry расчёта адреса, а не отдельный код успешности. Альтернативные пары, IX/IY, I/IM/IFF сохраняются. RET снимает внешний адрес возврата, сама процедура CPU-стек не записывает. Стек и код должны быть вне заполняемой области.

## Полная стоимость выборок

Входные LD HL и LD B дают 2 M1. Каждая строка требует 70 M1 без редкой коррекции адреса. Шестнадцать границ восьми строк добавляют по четыре, четырнадцать из них требуют ещё три инструкции коррекции H. Последний RET добавляет один. Итого 2+128*70+16*4+14*3+1=9069 M1. В этой процедуре нет префиксов, каждая исполненная инструкция даёт одну выборку. R изменяется по модулю 128 с сохранением бита 7.

## Проверка и её границы

[CheckIntroBitmapFill](../Tools/Disasm/Research/CheckIntroBitmapFill.py) прошёл 512 вызовов, отдельные серии всех 256 заполнителей и всех 256 исходных F. Это не полное совместное произведение C/F. Проверены вся RAM, точные значения и кратность 4096 записей, регистры и внешнее снятие возврата. Начальные I/IM/R варьируются, IFF=0. Использованы SP=#7FFE/#8000/#8001/#BFFE, пары C/F распределены между этими стеками, полное произведение со SP не заявлено.

[Отчёт](../Tools/Disasm/Reports/IntroBitmapFillVerification.json) подтверждает 9069 M1 прямым подсчётом настоящих инструкций и конечный R. Используется плоское загруженное INTRO. Аппаратные IRQ/NMI, точные T, сборка и нативный запуск не выполнялись. Эти результаты не доказывают полный кадр вступления или безопасное перекрытие стека с экраном.
