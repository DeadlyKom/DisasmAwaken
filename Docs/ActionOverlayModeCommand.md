# Смена режима отображения целей

[CycleTargetOverlayMode](../Source/Action/CycleTargetOverlayMode.asm), исходные адреса 7480..74A2 переносимого ядра ACTION банка 5, является целью Index11 [таблицы клавиш](../Source/Action/Data/KeyHandlerPointers.asm). Команда меняет существующий операнд AA9A в [UpdateFrame](../Source/Action/UpdateFrame.asm), новая память не выделяется.

Сначала читается CommandDelay. Ненулевое значение даёт немедленный возврат без записей, A содержит задержку, F соответствует AND A. При нуле задержка получает 10, после чего проверяется полный код оборудования Guidance.Value по 9C25. Только FF означает отсутствие системы наведения и завершает обработку. Задержка уже установлена и при этом отказе. Сопоставление поля с авторским описанием отдельно разобрано в [раскладке оборудования](ActionEquipmentCodes.md).

Если оборудование имеется, рассчитывается `t=(Mode+1) AND FF`. При t<4 сохраняется t, иначе сохраняется 1. Поэтому обычный цикл 1→2→3→1 не является полным описанием всех байтовых входов. 00 переходит в 01, FE в 01, FF в 00. Нулевой результат не исправляется. Это полный числовой код, а не набор независимых флагов.

Потребитель в UpdateFrame сначала уменьшает копию Mode. Если исходный Mode=1, условный CALL пропускается. При Mode=2 вызванному [ToggleTargetOverlay](../Source/Controls/ToggleTargetOverlay.asm) передаётся A=1, он ограничивается короткими рамками. При Mode=3 передаётся A=2, выполняется полный проход. Для остальных режимов, кроме 1 и 2, передаваемый байт также разрешает полный проход. В частности, исходный 00 даёт FF после DEC. Инициализация по умолчанию и произвольная самомодификация режима являются отдельными путями.

После принятого изменения CursorA по ECA9 получает исходный звуковой поток EE02. На этом пути HL=EE02, DE и BC сохранены, A содержит новый Mode. F остаётся результатом сравнения увеличенного t с 4, а не сравнением окончательного Mode с 4. При отказе по отсутствию оборудования HL сохраняется, A=0, F=50. Альтернативные регистры, IX/IY, I, IM и IFF сохраняются. SP после RET равен входному SP+2. Команда не выполняет OUT и не пишет временные слова CPU-стека. На входе нужен банк 0 для правильной записи потока AY.

[Модель](../Tools/Disasm/Research/CheckActionOverlayModeCommand.py) проверила 1280 сценариев, все 256 задержек, все 256 полных кодов оборудования и все 256 режимов при трёх кодах оборудования. Сверены вся RAM и архитектурные регистры кроме R и тактов. [Отчёт](../Tools/Disasm/Reports/ActionOverlayModeCommandVerification.json) фиксирует оборачивание FF в 00 и задержку при отсутствующем оборудовании. IRQ, нативное изображение и звук не проверялись, ассемблер не запускался. Последующий рисователь имеет собственную ограниченную [проверку](ControlsTargetOverlay.md).

[Факты оформления и именования](../Tools/Disasm/Research/ActionOverlayModeCommandFacts.py) используются [общим издателем клавиатурных команд](../Tools/Disasm/Research/PublishActionTargetCommands.py). Исследовательский Python для обычной сборки не требуется.
