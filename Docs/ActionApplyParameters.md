# Применение набора параметров ACTION

[ApplyParameterSet](../Source/Action/ApplyParameterSet.asm), AC5D..ACAA,
читает последовательные поля 00..0E набора Parameters по 9BA4.
Его подготавливает [BuildParameterTables](ControlsParameterTables.md).
Перед входом должен быть выбран верхний банк 0, это делает вход AC44
в [ActivateParameterSet](ActionParameterActivation.md).

## Маршрутизация полей

| Поле | Адрес цели | Доказанный локальный смысл |
| --- | --- | --- |
| 00 | F79C | операнд LD C,n команды F79B, банк 0 |
| 01 | нет записи | чтение сохранено, значение заменяется следующим полем |
| 02 | F798 | операнд LD C,n команды F797, банк 0 |
| 03 | A968 | операнд ADD A,n команды A967 |
| 04 | 63B9 | PairedLineStep, операнд ADD A,n фазового допуска двух линий по 63B8 |
| 05 | A8B5 | операнд ADD A,n команды A8B4 |
| 06 | 7B6B и 6874 | операнды CP n по 7B6A и ADD A,n по 6873 |
| 07 | 6615 | Class0RLimit, изменяемый операнд CP аппаратного R в ConfigureClass0Link |
| 08 | E6E7 | RandomLowLimit, изменяемый операнд CP младшего байта Stream10 в FindFilteredRecordOr26 |
| 09 | E823 | LinkedRLimit, операнд CP R по E822, запись обратной связи при R не меньше порога |
| 0A | 65E5 | Class3RLimit, изменяемый операнд CP аппаратного R в ConfigureClass3Link |
| 0B | 79A4 | операнд CP n команды 79A3 |
| 0C | 7E07 | операнд OR n команды 7E06 |
| 0D | 7E09 | операнд LD H,n команды 7E08 |
| 0E | 7DE4 | операнд OR n команды 7DE3 |

Всего выполняются 15 записей. Прочитанное поле 01 нельзя считать
мусором или свободным байтом, оно занимает свой слот физического
набора и участвует в продвижении указателя. Поле 06 намеренно
используется дважды. Игровые имена полей и полное поведение
изменяемых процедур ещё не установлены, известные операнды
не являются доказательством смысла всех параметров игры.

Адреса ниже 8000 принадлежат фиксированному банку 5,
адреса 8000..BFFF фиксированному банку 2, верхние адреса
в этой процедуре относятся к предварительно выбранному банку 0.
Пять неизвестных целей не выдаются за доказанную самомодификацию.

## Регистры и побочные эффекты

На выходе HL=9BB2, A содержит поле 0E. DE, BC и весь F сохраняются.
Также сохраняются альтернативные регистры, IX, IY, I, IM и IFF.
SP после RET равен входному SP+2. Временных PUSH нет,
кроме пятнадцати целей RAM не записывается. R получает ровно 46 M1.

Входной AF не задаёт значения полей, но его F возвращается буквально.
Порт выбора банка здесь не записывается, условие банка принадлежит входному договору.

## Проверка

[Модель](../Tools/Disasm/Research/CheckActionApplyParameters.py)
прошла 3840 сценариев, все 256 значений каждого из 15 полей.
Остальные поля одновременно меняются, проверяются все 256 входных F.
Память содержит настоящий ACTION с исходным переносом ядра и выбранным
верхним банком 0. Сверены все регистры, F, R, SP, каждый байт RAM
и кратность каждой записи.

[Отчёт](../Tools/Disasm/Reports/ActionApplyParametersVerification.json)
относится к прямому применению полей, полный AC44 проверен отдельно. Он не доказывает игровые имена полей,
аппаратные IRQ, сборку или нативный запуск.

[Три изменяемых порога](ActionParameterThresholds.md) связаны с реальными операндами CP и проверены для всех значений порога и сравниваемого байта. Это локальная роль трёх полей, полная игровая роль всех параметров ещё не установлена.

Поле 09 установлено по [CheckAndToggleLinkedOverlay](ActionLinkedOverlay.md), адрес E823 является непосредственным операндом CP по E822. Писатель AC8E регистрируется в физическом банке 2, цель в верхнем банке 0. Порог влияет на запись бита 0 LinkFlags и обратного LinkedIndex до проверок знаков и переполнений.

Поле 04 связано с [RequestPairedAimLines](ActionPairedAimLines.md), сумма по 63B8 обновляет фазу и только при Carry допускает расход шкалы и две линии. Вся таблица 15 целевых записей теперь привязана к исходным инструкциям, полный игровой смысл остальных параметров от этого не считается установленным.
