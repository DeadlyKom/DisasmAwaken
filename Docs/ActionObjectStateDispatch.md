# Выбор обработчика состояния объекта

F843 обнуляет LinkFlags по IX+0C и удваивает байт состояния IX+0A
с оборачиванием до восьми бит. Слово по `EF50+смещение` становится
адресом обработчика. Физические указатели по EF50..EF7B образуют
22 экземпляра FObjectStateHandler. Сразу за таблицей по EF7C стоит
самостоятельный RET, авторская метка NTH. EF7D является входом
обработчика состояния 14. [Таблица](../Source/Action/Data/ObjectStateHandlers.asm) ·
[Происхождение RET](ActionObjectStateReturnOnly.md)

[Отдельная проверка охвата](../Tools/Disasm/Research/CheckObjectStateCoverage.py)
сверяет все 22 указателя с физическими диапазонами и точками входа реестра
функций. Все 22 цели оформлены отдельными процедурами. Реестр подтверждает
адреса и размещение. Полный охват алгоритмов и нативные вызовы всех
состояний проверяются отдельно. [Текущий реестр охвата](../Tools/Disasm/Reports/ObjectStateCoverage.json).

Состояния 13, 14 и 15 передают управление к общему F0F8 после локального
обновления записи. Проверены 200 704 сценария до начала F0F8.
[Фазовое ожидание](ActionObjectPhaseWait.md).
[Прямой ход](ActionObjectOffsetRise.md).
[Обратный ход](ActionObjectOffsetFall.md).

Диспетчер сохраняет IX и помещает F85E на CPU-стек, затем выполняет
JP (HL). При возврате обработчика по F85E восстанавливается IX,
вызывается PrepareRecordScale и продолжается обход записей по F735.
Модель проверяет выбор цели и рамку до первой инструкции обработчика.
[Диспетчер](../Source/Action/DispatchObjectState.asm).

Вход F7C6 назначает состояние 0A для класса 12h. Для классов ниже 10h
он сохраняет состояния 06 и 07, иначе записывает 05. Прочие классы
сохраняют исходное состояние. [Установка 0A](../Source/Action/SetClass18ObjectState.asm).

F7E6 записывает входной A по IX+13. Для классов ниже 10h отдельные
состояния допускают выбор 02 либо 05. Состояние 02 требует отсутствия
связи FF либо чтения R меньше 0A. В последующем выборе порог R равен
70h для класса 03, 75h для 00 и 50h в остальных допускаемых классах.
Ниже порога выбирается 02, иначе 05. Состояния 06 и 07 сохраняются.

В 205 056 сценариях проверены регистры включая R, записи полей и
четыре байта рамки. Для всех 256 байтов сохранён исходный индекс
`(2×состояние)&FF`, в том числе чтение за пределами 22 указателей.
Такие чтения не расширяют набор допустимых игровых состояний.
[Отчёт](../Tools/Disasm/Reports/ActionObjectStateDispatchVerification.json).

## Возврат после обработчика

На `ResumeUpdate` по `#F85E` верхнее слово стека восстанавливает IX.
Вызов [PrepareRecordScale](../Source/Action/PrepareRecordScale.asm)
читает заголовок модели, задаёт масштаб и переходит в
[UpdateRecordComponents](../Source/Action/UpdateRecordComponents.asm).
При штатном возврате выполняется переход к следующей записи по `#F735`.

Конец диспетчера совпадает с границей кода в архивном `SP.C` с учётом
переноса и изменения кадра IX. Текущий загрузчик записывает следующие
1946 нулевых байтов как часть ACTION. [Сравнение версий и модель загрузки](ActionArchivedFileEnd.md)

[Модель возврата](../Tools/Disasm/Research/CheckActionObjectStateReturn.py)
проверила 32768 комбинаций класса и чётного индекса модели. Сверены
принятые компоненты, частичные записи при отказе, маркер повторного
использования, восстановление смещений и SP. Запрос предупреждения
в этой модели отключён.

Ещё 768 сценариев начинались с косвенного вызова. Они проверили
все значения таймера для состояний `#13`, `#14` и `#15` на записи
с маркером `#8000`. Результаты этой серии ограничены тремя фазовыми
обработчиками. [Результаты](../Tools/Disasm/Reports/ActionObjectStateReturnVerification.json)
