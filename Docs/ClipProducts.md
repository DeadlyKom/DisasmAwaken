# Рабочие точки и произведения для пересечений

Фазы изменяемых операндов описаны в [MapRuntimeProfiles](MapRuntimeProfiles.md). Исходные произведения и их выполнение после настоящего D0C3 проверены раздельно.

Два физических экземпляра FProjectedPoint расположены в [ClipEndpoints](../Source/Map/Data/ClipEndpoints.asm), FirstPoint по DE2F и SecondPoint по DE34. Они имеют поля X, Y и ClipCodes. Четыре FClipProduct находятся в [ClipProducts](../Source/Map/Data/ClipProducts.asm). Каждый содержит LowWord, затем HighWord, то есть 32-битный результат с младшими байтами вперёд. Все исходные 26 байтов равны нулю и сохранены без нормализации. ClipCodes=0 в таком первоначальном экземпляре не означает рассчитанный внутренний код F0.

| Процедура | HL перед умножением | DE перед умножением | Место результата |
| --- | --- | --- | --- |
| [ComputeTopClipProduct](../Source/Map/ComputeTopClipProduct.asm) | Y1-MinY | X1-X2 | DE6B..DE6E |
| [ComputeBottomClipProduct](../Source/Map/ComputeBottomClipProduct.asm) | Y1-MaxY | X1-X2 | DE6F..DE72 |
| [ComputeLeftClipProduct](../Source/Map/ComputeLeftClipProduct.asm) | Y1-Y2 | X1-MinX | DE73..DE76 |
| [ComputeRightClipProduct](../Source/Map/ComputeRightClipProduct.asm) | Y1-Y2 | X1-MaxX | DE77..DE7A |

MinX, MinY, MaxX, MaxY — значения изменяемых операндов, исходно 0, 0, 255, 255. Установщик D0C3 записывает их младшие байты, старшие остаются нулевыми.

Все вычитания сначала оборачиваются до 16 бит. Полученные слова интерпретируются знаковым [MultiplySigned16](SignedMultiply.md). Порядок множителей нельзя бездумно переставлять. Исключение второго операнда DE=8000 при модуле HL не меньше 256 действует и здесь. Его модельные случаи не объявляются достижимой ошибкой игрового отсечения без анализа допустимых координат вызывающего кода.

Каждая процедура сохраняет DE результата в LowWord и HL в HighWord. После двух LD основные регистры и флаги остаются такими, как их вернул MultiplySigned16. Его входной BC после подготовки равен MinY для верхней границы, MaxY для нижней и Y2 для двух вертикальных границ. Это задаёт точный контекст условного сохранения B,C ядром умножения. Альтернативные регистры и IY сохраняются, IX меняется только по договору полного ядра.

Рабочие записи используют существующие ячейки таблицы кодов, не возникающие при допустимом индексе. DE2F соответствует невозможному второму коду F, строка 3 содержит одновременно правую и левую стороны, диапазон DE6B..DE6F имеет невозможные вторые коды, а строка 7 также невозможна. Это не выделение новых буферов. Остальные байты низкой и высокой таблиц сохранены физически. [Общий разбор косвенной группы](MapClipHandlers.md) ещё не завершён.

[Модель](../Tools/Disasm/Research/CheckClipProducts.py) проверяет 278528 вызовов с настоящим умножением. Для каждой процедуры перебраны все вторые операнды при первом 256 и добавлены 4096 случайных пар конечных точек. Проверены 32-битный результат, основные HL, DE, BC, AF и IX, сохранение IY, альтернативных регистров, других слотов произведений и стек. R и T эта координатная матрица независимо не сопоставляет. Четыре случая второго операнда 8000 воспроизведены с исходной особенностью. Сборка, IRQ и нативный запуск не выполнялись.

[Проверка настроенных произведений](../Tools/Disasm/Research/CheckConfiguredClipProducts.py) выполнила 303104 случая в 256 профилях настоящего D0C3. Каждая граница приняла все 256 значений, включая неупорядоченные пары минимумов и максимумов. В каждом профиле проверены случайные точки и граничные разности, в одном профиле — все 65536 слов второго множителя для каждой процедуры. В 1028 случаях воспроизведена особенность второго операнда 8000. Проверены точные регистры, флаги, стек, точки и чужие слоты произведений. Полный декартов набор четырёх границ не заявляется. Вызовы не подменялись, IRQ, сборка и нативный запуск не выполнялись.


## Изменение R внутри вычислителей произведений

Corrupt четырёх вычислителей явно включает R. Режим --refresh-witness [CheckClipIntersections.py](../Tools/Disasm/Research/CheckClipIntersections.py) дополнительно фиксирует вход и возврат этих помощников внутри уже выполняемых полных пересечений. В восьми наблюдениях, по два на помощника, R изменился и совпал с отдельным подсчётом M1 по достигнутым опкодам. Внешний CALL из Append... в собственную стоимость вычислителя не включён, его вложенный вызов MultiplySigned16 и собственный RET включены. [Отчёт с отдельными профилями помощников](../Tools/Disasm/Reports/ClipIntersectionRefreshWitnessVerification.json).

Для контрольных точек (0,0), (64,64) и исходных границ 0/0/255/255 получены следующие значения.

| Вычислитель | Собственные M1 |
|---|---:|
| ComputeTopClipProduct | 80 |
| ComputeBottomClipProduct | 94 |
| ComputeLeftClipProduct | 84 |
| ComputeRightClipProduct | 81 |

Помощники получают начальный R=01 либо 96 после внешнего CALL. Это наблюдения конкретных путей с исходными множителями и границами, постоянная стоимость для всех значений ими не задаётся. Все прежние профили пересечений в расширенном отчёте сохранились. Основная функция координатной проверки не менялась, дополнительные поля отчёта только разделяют уже выполненный путь на участки. Все сочетания координат и регистров, точные T и аппаратные шинные циклы не доказаны. [Полные и кэшированные входы пересечений](ClipIntersections.md#регистр-r-и-контрольные-пути).
