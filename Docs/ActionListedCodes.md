# Объединение кодов точек по списку

[CombineListedVertexCodes](../Source/Action/CombineListedVertexCodes.asm) занимает DDD1–DDEF банка 0. [Проверка исходных инструкций](../Tools/Disasm/Research/CheckActionListedCodes.py) отделяет полный OR списка от раннего нулевого кода.

HL указывает на заголовок. Список байтовых смещений начинается по HL+1, количество задано B. Нулевой B означает 256 элементов. Для каждого индекса читается байт по 8E00+((индекс+4) AND FF), смещение 4 является полем FRenderProjectedPoint.ClipCode. Оборачивание внутри страницы сохранено, кратность индекса пяти не проверяется.

Каждый ненулевой код включается через OR в C. При полном завершении A=C, Carry и Z сброшены, остальные флаги являются точными флагами OR. Если встречен нуль, возвращаются A=0/F=45, Carry и Z установлены. C сохраняет OR предыдущих ненулевых кодов. DE в обоих случаях указывает сразу за последним прочитанным индексом. Нулевой код не является обычным результатом [ClassifyProjectedVertices](./ActionVertexCodes.md), но отдельный путь его обработки присутствует в оригинале и проверен.

HL и B восстанавливаются, IXL получает исходное значение B. IXH, IY и весь альтернативный набор сохраняются. CPU-стек использует два дополнительных байта сохранённого HL, после RET SP увеличен на два. I, IM, IFF и paging сохраняются. При полном проходе из k элементов R увеличивается на 11+10×k. При раннем нуле после k ненулевых элементов на 19+10×k. Старший бит R сохраняется.

[Отчёт](../Tools/Disasm/Reports/ActionListedCodesVerification.json) содержит 99712 успешных сценариев. Проверены все 256 счётчиков и каждая допустимая позиция нуля, все 65536 пар байтов индекс/код, смешанные списки, точные регистры, флаги, R, вся физическая RAM и кратность двух стековых записей. Полный рисователь, IRQ, сборка и нативный запуск не проверялись.
