# Сквозной переход между станцией и полётом

[Модель](../Tools/Disasm/Research/CheckStationFlightCycle.py) выполняет два
профиля. Первый начинается с исходного STATIONF по 6300. Второй берёт
сохранённый адрес USR из AWAKEN.B, исполняет код по 5D41, читает вступление
и проходит исходный [загрузчик станции](../Source/Intro/LoadStation.asm) до 6300.
[Разбор перехода](IntroStationTransition.md)
Оба профиля достигают восьмого входа в цикл станции по 9A81 с SP=5FFF,
страницей 10 и выбранным кораблём 06. Затем модель вызывает штатный
вход BeginTransition по 7E5A, выбор элемента интерфейса задаётся этим вызовом.

Перед вылетом оба профиля исполняют исходный LANG. Событие 5 получает
индекс строки оборудования 23. Начальное состояние корабля 06 даёт
сообщение 6 и оставляет код FF и исходные 2 000 кредитов. Для успешной
покупки задаются корабль 00 и 10 000 кредитов. Код FE записывает сам
LANG, он же списывает цену. Выбор строки задаётся на границе вызова
интерпретатора, интерфейс торговли отдельно описан в
[модели оборудования](../Tools/Disasm/Research/CheckOriginalEquipmentTrade.py).

[Переход в ACTION](StationExit.md) сохраняет 512 байтов состояния станции
в 4000..41FF, вызывает файловый сервис с ключом ACTION с типом C и получает
управление по 4236. Исходный код копирует все 512 байтов в 9BBD..9DBC, после
чего исполняются перенос, загрузочные процедуры ACTION и
[64 полных полётных кадра](ActionFlightCycle.md).

В профиле со вступлением проверено окно 5DA0..5EDA. Перед полётом начало
окна содержит хвост переносимого загрузчика вступления. Инициализация ACTION
меняет в этом окне только три байта, по 5E20, 5E21 и 5E23. Содержимое
первых 315 байтов CONTROL после 64 кадров совпадает с диском и остаётся
в банке 1 по DADE..DC18. Трасса этих кадров не содержит выборок команд ни
в наблюдаемом окне общей RAM, ни в указанном диапазоне CONTROL банка 1.
[Сопоставление двух размещений](ControlsTemporaryModule.md)

После 64 кадров в этом же профиле сканер выбирает
[запрос гиперперехода](../Source/Action/RequestHyperJump.asm) по строке
`#FD`, маске `#10`. На входе команды модель задаёт ненулевой запас,
оборудование, стоимость и отличающийся ключ назначения. Команда списывает
14 единиц при стоимости 7. Исполняются очередь текста, задержка и
[перенесённый загрузчик](ActionHyperReload.md). После подстановки чтения ACTION
сверены 481 байт переноса и два полных кадра свежего полёта.
В проверенных участках гиперперехода и перезапуска снова нет входов в оба
диапазона CONTROL, а при инициализации повторяются те же три записи.

[Команда возврата](ActionStationReturnCommand.md) проверена в двух профилях.
В обоих случаях реальный сканер считывает замкнутый бит 3 порта FBFE и
через запись Index12, восемнадцатую при счёте с нуля, вызывает 7606.

- Исходный байт оснащения FF сохраняется. Команда возвращается в
  RestoreKeyScanFrame, сканирование завершается, следующий кадр начинается.
- Приобретённый код FE сохраняется до команды возврата. После 64 кадров
  команда списывает его до FF и запускает PrepareStationReload. Этот код
  сохраняет 512 байтов после перестановки двух младших полей счётчика.
  Копия LoadStationStateRelay вызывает файловый сервис с ключом STATIONF
  с типом C и продолжает по 421F. Сверены 481 байт, восстановленный из
  копии в 983B..9A1B, и 31 байт из свежего файла в 9A1C..9A3A. После
  перезапуска проверены восемь входов в цикл станции с SP=5FFF.

[Отчёт](../Tools/Disasm/Reports/StationFlightCycleVerification.json) привязан
к хешу исходного диска. Модель подставляет дисковые сервисы по каталогу и
содержимому этого образа. Она берёт сохранённый USR из BASIC, интерпретатор
в этой проверке не исполняется. Нажатие моделируется ответом порта. В циклах TraceFlight действуют
модельные прерывания. Проверка охватывает ограниченные участки между ними,
сборка и нативный запуск в этой серии не выполнялись.

## Сквозной прогон с ROM TR-DOS

Отдельный [сценарий](../Tools/Disasm/Research/CheckBootBankFileReads.py)
продолжает [запуск командой RUN](IntroStationTransition.md#сквозное-исполнение-команды-run) на том же снимке RAM.
После семи кадров станции он исполняет исходную покупку оборудования,
вылет, 64 полётных кадра, гиперпереход, ещё два кадра и возврат к входу
цикла станции `#9A59`. Вызовы TR-DOS проходят через ROM 5.04T, порты
контроллера получают данные оригинального TRD.

Проверены порядок файловых секторов в обоих направлениях, списание
14 единиц при гиперпереходе, возврат 481 байта контекста после перезапуска
ACTION и ещё 481 байта при загрузке станции. Последние 31 байт станционного
контекста берутся из свежего STATIONF. Клавиши, исходное состояние покупки
и допуск гиперперехода заданы моделью.
[Вылет](../Source/StationExit/LoadAction.asm) ·
[Перезапуск ACTION](../Source/Action/ReloadActionAfterHyperJump.asm) ·
[Возврат](../Source/Controls/LoadStationStateRelay.asm)

При вызовах `#0E` с `A=0` после целых секторов ACTION и STATIONF ROM
дополнительно читает первый сектор следующего каталожного файла, DATAS
или LANG. В трассе эти чтения идут в буфер `#5D25`. Ветвь ROM `#2FDE`
проверяет нулевой остаток уже после чтения и возвращается без `LDIR`.
Когда LANG затем загружается в свой банк, его первый сектор читается
снова по адресу `#C000`.
