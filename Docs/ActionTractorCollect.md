# Прицельный запрос, притягивание и сбор объекта

[RequestAimOrCollectTarget](../Source/Action/RequestAimOrCollectTarget.asm) занимает исходные 7317..741C переносимого ядра ACTION банка 5 и является целью Index06 [таблицы клавиш](../Source/Action/Data/KeyHandlerPointers.asm). Полный байт Mode хранится в операнде LD A,n по 7318, его меняет [команда силового луча](ActionTractorModeCommand.md).

## Выбор действия и цели

При Mode=0 выполняется хвостовой переход в [RequestPairedAimLines](../Source/Action/RequestPairedAimLines.asm), без собственной рамки CALL. Действуют отдельные [фазовый допуск и договор двух XOR-линий](ActionPairedAimLines.md). При ненулевом Mode читается Target0. Любой отрицательный байт, то есть 80..FF, немедленно возвращается без изменения памяти. Это проверка знака, не только сравнение с FF.

Ненулевой режим с кодом 00..7F вызывает [RecordIndexToAddress](ActionRecordIndex.md). Доступность записи далее определяется полным старшим байтом первой компоненты, значение 80 отвергается. Затем требуется StateCode=04. При любом отказе Target0 получает FF. Преобразователь не проверяет границ массива, допустимость физической записи и банка остаётся условием входа.

## Притягивание через SP

У принятой записи Unknown10 по смещению 10 сразу обнуляется. База записи сохраняется на обычном CPU-стеке, исходный SP после этого PUSH записывается в операнд RestoreStack. Затем SP временно устанавливается в базу объекта. Последовательные POP и PUSH читают и изменяют три 16-битовые компоненты прямо через этот стек данных.

Компонента со старшим байтом 00 или FF не меняется и учитывается как близкая. Это диапазон FF00..FFFF и 0000..00FF, то есть −256..255 в знаковой интерпретации. Прочая положительная компонента уменьшается на 50, прочая отрицательная увеличивается на 50 по модулю 65536. Единицы этих 50 из одного алгоритма не устанавливаются. Все три компоненты обрабатываются до решения о дальности.

После третьей компоненты обычный SP восстанавливается из изменённого операнда, база снимается в HL. Если близкими были не все три компоненты, следует RET с A, равным числу близких осей, F от CP этого числа с 3. HL указывает запись, E содержит число близких осей, D сохранён, BC равен последнему шагу 0000 либо FFCE. Target0 остаётся выбранным. Unknown10 и SavedSP уже изменены.

Весь участок требует отсутствия IRQ и повторного входа. Сам обработчик DI не выполняет и IFF не меняет, поэтому временный SP в объекте нельзя скрывать обычной формулировкой о стеке вызовов.

## Выбор пополнения и отказы

Когда все компоненты близки, Target0 получает FF **до** дальнейших проверок. Для ClassCode=#13 берутся Unknown23 как полный байтовый код вида и Unknown11 как полный байт пополнения. Для ClassCode=#10 выбирается вид 0F, для остальных классов 1B. В последних двух случаях количество равно `(R AND 07)+1`, R читается после исходной последовательности M1, это не вызов программного генератора.

Байт правила читается по 741D+вид без проверки границ. Поле 7..6 задаёт только условие изменения Current по 9BD2. При 00 кандидат равен `(Current+количество) AND FF` и сравнивается с Limit по 9BD3. Перенос суммы не проверяется. При ненулевом поле Current сохраняется. Если Limit меньше кандидата, процедура возвращается с уже снятым Target0, объект остаётся активным.

Далее выбирается **байт** по 9BD4+вид, без умножения вида на размер [пары груза](ActionOwnedCargoPhysicalData.md). Новый байт равен `(старый+количество) AND FF`. При результате 201..255 следует отказ, количество не записывается, Current не обновляется, Target0 уже снят. Перенос этого сложения также не проверяется. Например, FF+1 превращается в 00 и не отвергается как переполнение.

При успехе записываются новый байт и Current, первая компонента объекта получает младший байт 00 и старший 80, отмечая запись недоступной. При установленном бите 4 ReuseByte дополнительно устанавливается бит 2 PanelEvents.Flags по A78C. [Выброс мины](ActionEjectCommands.md) создаёт именно такую пометку, но этот потребитель не проверяет происхождения записи. Затем CursorA получает EE1B и в очередь ставится F36D, сообщение о подобранном объекте. Отказ очереди не отменяет сбор.

## Правила и перекрытие кода с данными

[TractorCargoRules](../Source/Action/Data/TractorCargoRules.asm) содержит 28 самостоятельных физических экземпляров FTractorCargoRule по 741D..7438. Схема Control `a1 a0 u5 u4 u3 u2 u1 u0`, маска поля учёта C0. Значение a1:a0=00 прибавляет количество к Current, 01, 10 и 11 исключают это прибавление. Различный игровой смысл трёх ненулевых кодов и назначение младших шести битов не установлены. Нулевой полный байт включает обычный учёт.

Для видов 28 и 29 обработчик реально читает 7439 и 743A, первые два байта следующего [ToggleTractorMode](../Source/Action/ToggleTractorMode.asm). Его исходная инструкция LD A,(A85F) содержит 3A,5F,A8. Поэтому правило 28 равно 3A и имеет нулевое поле C0, правило 29 равно 5F и имеет поле 40. Эти байты продолжают собираться как инструкция, второй физической копии данных не создаётся. [Проверка разметки](../Tools/Disasm/Research/ActionTractorCargoRules.py) сохраняет это перекрытие. Граница 28 физических записей не объявляется проверкой диапазона, более крупный код продолжает чтение следующих байтов кода.

## Проверка

[264679 сценариев](../Tools/Disasm/Reports/ActionTractorCollectVerification.json) [модели](../Tools/Disasm/Research/CheckActionTractorCollect.py) исполняют весь исходный обработчик, настоящий преобразователь индекса, прицельный дочерний код и очередь. Проверяются все слова по каждой из трёх осей, все 65536 пар старого байта груза и количества, все байты режима, цели, правила и вида, все классы с пятью граничными R и граничные состояния очереди. Четыре дополнительных сценария действительно рисуют обе прицельные линии. Более широкая проверка рисователя остаётся отдельной.

Наблюдался настоящий SP внутри записи объекта. Сверены архитектурные регистры кроме R и тактов, вся физическая RAM и кратность записей вне восемнадцати временных байтов обычного CPU-стека, порядок OUT. Для количества от R независимо учтены M1 префикса. Остаточные слова обычного стека и полный итоговый R родительского прохода не сверяются. [Числовой эталон](../Tools/Disasm/Research/ReferenceActionTractorCollect.py) использует ранее проверенный договор дочернего прицельного кода.

Полное произведение всех полей, достижимость произвольных проверенных кодов в нормальной игре, аппаратные IRQ, точные такты и нативная игра не доказаны. Ассемблер не запускался.
