# Исходные записи NEWS и ORDER и стоимость гиперперехода

Сразу после 49 байтов оборудования, по `9C41..9C87`, в ACTION лежат последовательности, совпадающие со строками `NEWS` и `ORDER` из встроенных заметок. Участок `NEWS` занимает семь байтов `01 00 00 00 00 00 00`. Состояние, два нулевых слова и отдельные нулевые байты оформлены в исходном порядке. Значение `01` зафиксировано как начальное состояние, его игровая ветвь пока неизвестна. [Запись NEWS](../Source/Action/Data/NewsState.asm), [авторские заметки](ActionEmbeddedNotes.md).

С `9C48` следуют четыре записи `ORDER` по 16 байтов. Каждая начинается с `FF` и содержит 15 нулевых байтов. В заметках после них описана доставка, указаны размеры данных назначения, двух времён, денег и веса. Порядок чтений и точные смещения этих полей исполняемым кодом пока не подтверждены, поэтому у физического тела записи сохранены имена по смещениям. Смысл `FF` как условия игрового перехода остаётся неизвестен. [Записи ORDER](../Source/Action/Data/DeliveryOrders.asm).

По `9C8A` расположен отдельный байт `Cost` с исходным значением `00`. Две инструкции `LD A, (9C8A)` по `7108` и `7127` читают его как базовую стоимость для Preferred и Fallback. Первый маршрут удваивает байт в слове, второй списывает его один раз. При выходе из станции он получает последний результат измерителя карты по `9908` через смещение `CD` общего блока. Байт попадает и в диапазон `9BBD..9D9D`, который сохраняется при перезагрузке после гиперперехода. Соседний `9C88` содержит перенесённый счётчик станции, назначение байта `9C89` ещё неизвестно. Область с `9C8B` входит в передаваемый станционный контекст, её поля разбираются отдельно. [Физическая стоимость](../Source/Action/Data/HyperJumpCost.asm), [RequestHyperJump](../Source/Action/RequestHyperJump.asm), [перенос состояния](MapDistanceAndRenderState.md), [хвост контекста](ActionContextTail.md), [перезагрузка](ActionHyperReload.md).

Скрипт сверяет строки исходных заметок, все 71 байт сопоставленных записей и два машинных операнда стоимости. Статическая проверка отдельно сверяет три размещения, исходные байты, размеры и смещения полей.
