# Повторное использование записи по IY

[MarkIYRecordForReuse](../Source/Action/MarkIYRecordForReuse.asm) занимает исходные тринадцать байтов F03D..F049 ACTION банка 0. Она выполняет тот же протокол, что [вариант по IX](../Source/Action/MarkRecordForReuse.asm), но адрес записи передаётся в IY.

Записи строго следуют порядку `Component0.High=80`, `Component0.Low=00`, `ReuseByte=FF`. Это код доступной записи 8000 с однократным пропуском. Первый [FindReusableRecord](../Source/Action/FindReusableRecord.asm), достигший этой записи, обнуляет FF и пропускает её. Следующий достигший поиск уже может принять запись. Число кадров или вызовов, остановившихся на более ранней записи, такой отсрочки не определяет.

Все данные регистров, включая HL, DE, BC, AF, альтернативные регистры, IX и IY, сохранены. R получает семь M1, бит 7 сохраняется. После RET SP равен входному SP+2. CPU-стек, порты, I, IM, IFF и paging не меняются. Три байта записи меняются в указанном порядке. Другой код не должен просматривать промежуточное слово 8080 при прежнем Low=80. Самостоятельного DI здесь нет.

[Модель](../Tools/Disasm/Research/CheckActionIYRecordReuse.py) использует общий числовой эталон [протокола](../Tools/Disasm/Research/CheckActionRecordReuse.py), исполняя настоящий F03D с индексным регистром IY. Проверены 7450 сценариев, все 256 F, 26 физических записей, три дополнительных адреса на границах и два настоящих поиска после пометки каждой физической записи. Сопоставлены все регистры включая R, восемь банков RAM и точный порядок трёх однобайтовых записей.

[Отчёт](../Tools/Disasm/Reports/ActionIYRecordReuseVerification.json) не доказывает назначение остальных значений ReuseByte, IRQ, точные T, сборку или нативный запуск. [Подробное объяснение кода доступности](./ActionRecordReuse.md) общее для двух вариантов.


MarkIYRecordForReuse дополнительно исполнена в последовательной модели заполненного пула вместе с настоящими CreateMissileForTarget и повторным использованием. Модель сохраняет исходное состояние между вызовами. [Режим с двумя настоящими пометчиками, отчёт и границы](ActionObjectRecords.md#повторение-с-настоящими-процедурами-освобождения).
