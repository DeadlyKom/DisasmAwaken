# Создание мусора форсажа

[CreateBoostDebrisRecord](../Source/Action/CreateBoostDebrisRecord.asm)
занимает исходные байты ACTION `#617D..#6200`, перенесённые в фиксированную
RAM банка 5. Подтверждён условный вызов из AdvanceBoost по 7539, его две фазы вращения определяют допуск.
Класс 14 связан с авторским T_TRASH, «МУСОР ДЛЯ ФОРСАЖА», и моделью TRASH по D8BA. Проверка происхождения приведена ниже.

Процедура вызывает [FindReusableRecord](../Source/Action/FindReusableRecord.asm).
Отказ завершает внешний вызов. Поиск сохраняет своё исходное поведение,
в том числе очистку ReuseByte пропускаемых слотов со значением FF.
При успехе один раз обновляется [случайный поток 8](ActionFoldedRandom.md).

Из младшего и старшего байтов нового слова получаются две компоненты.
Для знакового байта s используется `4*s + 1024` при s>=0,
либо `4*s - 1024` при s<0. Это создаёт отступ от нулевой области,
а не обычное умножение с последующим ограничением. Третья компонента
равна 30000 при нулевом байте `#6E75`, иначе равна -30000.
Этот байт является первым опкодом пары NegateFirst в [переключателе вида](ActionViewDirectionCommand.md), канонический передний вид задаёт 00, задний ED. Произвольный ненулевой байт по-прежнему выбирает -30000.

Затем исполняется настоящий
[TransformVectorTransposed](../Source/Action/TransformVectorTransposed.asm).
Все три возвращённых слова записываются в Components. При переполнении
процедура не отказывается от создания, частично сохранённые результаты
дочернего преобразования остаются действующими.

| Поле | Исходное значение |
|---|---|
| ModelOffset | C0 |
| OffsetPhase0, OffsetPhase1, OffsetPhase2 | 0C, 1D, 37 |
| StateCode | 04 |
| ClassCode | 14, десятичное 20 |
| EffectReserve | FA |
| ReuseByte, LinkFlags, OffsetScaleHigh | 00 |
| TargetCodeStep, OffsetScaleLow, Phase2OrTarget | 02 |

Остальные поля свободного слота не инициализируются и сохраняют прежние
байты. Связь с другой записью здесь не создаётся. Значения неизвестных
полей описаны как значения, их игровые роли не выдумываются.

При успехе AF=0044, HL, DE, BC содержат результаты преобразования.
Альтернативные пары HL', DE', BC' оставлены потоком 8, AF' оставлен
преобразованием. IX и paging сохраняются. Дополнительная глубина стека
составляет восемь байтов, включая рамки дочерних вызовов.

[Композиционная модель](../Tools/Disasm/Research/CheckActionClass20Spawn.py)
сопоставляет числовой эталон с исполнением оригинальных инструкций,
не подменяя поиск, поток или преобразование. Проверяются все регистры,
R, SP, восемь физических банков, значения и кратность записей.
Исчерпаны все 65536 слов начального состояния потока на выбранных
свёртках, предусмотрены разные места выделения, отказ и матрицы.
Полное произведение входных данных, аппаратные IRQ, сборка и нативный
запуск игры этой проверкой не подтверждаются.


Создатель дополнительно исполнен в 30 последовательных циклах заполнения исходного пула вместе с настоящим ReleaseBoostDebrisRecords. Генератор и состояние не сбрасываются между циклами, классы и свободные слоты не подставляются вручную. [Цикл, отчёт и границы](ActionObjectRecords.md#циклы-создания-и-массового-освобождения-класса-14).


## Авторское назначение и текущий вызывающий код

[CheckActionBoostDebrisIdentity.py](../Tools/Disasm/Research/CheckActionBoostDebrisIdentity.py) связывает четыре независимых свидетельства. Авторский awk1.trd:EQUS.a объявляет T_TRASH=#14 и прямо подписывает «МУСОР ДЛЯ ФОРСАЖА». OBJECTS2.a объявляет 24 байта модели TRASH, LABELS.a задаёт D8BA. Весь OBJECT3D длиной 10580 байтов совпадает с текущим, эти 24 байта отдельно сериализованы и сверены.

В текущем ACTION слово по 9EC0, элемент таблицы с байтовым смещением C0, равно D8BA. Создатель записывает ModelOffset=C0 инструкцией по 61DA и ClassCode=14 по 61DE. AdvanceBoost по 7539 выполняет CALL C,617D после двух вращений. Все три инструкции сверены с физическими файловыми смещениями, а не только текстовыми именами. [Отчёт](../Tools/Disasm/Reports/ActionBoostDebrisIdentityVerification.json), [полный поиск TRASH/T_TRASH в 160 источниках](../Tools/Disasm/Reports/ArchivedTrashNamesInspection.json).

Тем самым установлено назначение записи как мусора форсажа, а прежнее утверждение об отсутствии вызывающего входа устарело. Процедура получила имя CreateBoostDebrisRecord и файл [CreateBoostDebrisRecord.asm](../Source/Action/CreateBoostDebrisRecord.asm). Адрес 617D и физические инструкции сохранены, условие вызова и нативные границы не расширены до доказательства всех состояний либо внешнего вида в эмуляторе. Исследовательские имена Class20 сохраняют числовой контекст класса 14, десятичное 20.
