# State0B, периодический ребёнок класса 3

[SpawnPeriodicClass3Record](../Source/Action/SpawnPeriodicClass3Record.asm)
занимает F3F0..F49B ACTION банка 0. Операнд SpawnPhase по F3F1 обновляется
как `(старое+1) AND 0F`. Только ноль допускает создание. Фаза общая для
всех записей, поэтому период равен 16 вызовам этого входа, а не обязательно
16 игровым кадрам. Исходный байт равен 0A, первое разрешение после шести
вызовов. Все исходные старшие биты отбрасываются после INC.

На разрешённом вызове [FindReusableRecord](ActionRecordSearch.md) ищет
свободную запись. Отсутствие места завершает создание. Для найденного
слота проверяется старший байт Component0 связанной записи, индекс которой
берётся из Unknown0D родителя. Это обычный
[RecordIndexToAddress](ActionRecordIndex.md), FF не имеет особого смысла.
При старшем байте 80 родитель получает StateCode=09, ребёнок не заполняется.
Очистка ReuseByte найденного слота, уже выполненная поиском, сохраняется.

При доступной связи ребёнок получает Components0 и 2 родителя без изменений.
К Component1 прибавляется BC с B=1 либо 2 по младшему биту прочитанного R
и C=80. Арифметика оборачивается по модулю 65536. Слово по 9BC1 передаётся
[ClassifyCoordinateRegion](ActionRegionType.md), код 0..3 превращается
двумя RLCA и ADD 10 в ModelOffset 10, 14, 18 либо 1C.

Остальные записываемые поля ребёнка:

| Поле | Исходное значение |
| --- | --- |
| TargetIndex, физический 0F | 96, управляющий байт 150 |
| OffsetPhase0, 1, 2 | 40, 0, 0 |
| Unknown11 | 46, десятичное 70 |
| StateCode | 02 |
| SavedStateCode | 0C |
| LinkFlags | 0 |
| ClassCode | 3 |
| Unknown14 | 0 |
| LinkOverride | FF |
| LinkedIndex | Unknown0D родителя |
| Unknown13 | 64, десятичное 100 |
| Unknown10 | 1E, десятичное 30 |
| TargetCodeStep | 2 |

Прочие поля свободного слота не обнуляются автоматически. После заполнения
SavedStateCode родителя уменьшается на один. **В данном состоянии это
счётчик оставшихся созданий**, имя физического поля не делает его здесь
сохранённым состоянием. Только переход 1→0 переводит родителя в StateCode=09,
начальный ноль становится FF. Все пути, включая пропущенную фазу,
заканчиваются [ResetRecordUpdateBases](../Source/Action/ResetRecordUpdateBases.asm).
HL=0, Base0..2=0 на любом выходе, выполняется полный внешний RET.

После создания DE=0040, BC содержит смещение второй компоненты,
A равен результату декремента родительского счётчика, F от DEC с Carry=0.
При пропуске фазы DE, BC и IY сохраняются, A равен новой фазе, F от AND 0F.
При отказе поиска AF=8042, DE=0040, IY указывает маркер. При недоступной
связи AF=8042, IY указывает найденный, но не заполненный слот.
HL', DE', BC', AF', IX, I, IM, IFF и paging сохраняются. Максимальная
дополнительная рамка CPU-стека равна двум байтам, SP после RET увеличен на два.

R добавляет 10 M1 при пропуске фазы, 12 M1 плюс стоимость поиска при
отказе поиска, 34 M1 плюс поиск при недоступной связи. При создании
добавляет 108 M1 плюс стоимости поиска и классификации, ещё 2 M1 при
установке родительского состояния 09. Бит 7 R сохраняется.
Общий операнд SpawnPhase зарегистрирован в [самомодификации](ModifiedCode.md).

[Независимая композиционная модель](../Tools/Disasm/Research/CheckActionPeriodicClass3State.py)
проверила 135168 сценариев. Исчерпаны все пары фазы и родительского
счётчика, все 65536 слов координат классификатора, все R с четырьмя
профилями списка и четырьмя граничными индексами. Реальные дети
исполняются, сверены регистры, флаги, R, SP, восемь банков и все записи.
Полное произведение остальных входов, IRQ, сборка и нативный запуск
не выполнялись.
