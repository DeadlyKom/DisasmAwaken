# Краевые маски предпросмотра D3D

[Физические записи](../Source/D3D/Data/PreviewEdgeMasks.asm) занимают
C000..C1FF в банке 4, смещения 0000..01FF записи D3D. Всего 16 записей по
32 байта. Страница C0 выбирается для первой строки контура, C1 для второй,
далее страницы чередуются от начала контура независимо от экранного Y.

Внутри страницы позиция пикселя от 0 до 7 задаёт смещение 32×позиция.
Пары левого края занимают первые 16 байтов, правого края следующие 16.
Индекс заполнения от 0 до 7 прибавляется с удвоением.
[Подготовитель](../Source/D3D/FillPreviewPolygon.asm) задаёт первую страницу,
[строковый проход](../Source/D3D/StepPreviewPolygonRow.asm) чередует страницы
и читает левую пару, [вывод правого края](../Source/D3D/WritePreviewPolygonSpan.asm)
берёт правую.

Для индексов 0..4 левый AND равен `(FF << (8 - позиция)) AND FF`,
правый AND равен `FF >> позиция`. OR равен шаблону строки AND инверсия
соответствующего AND. Если края в разных байтах, для каждого применяется
`(старый AND mask) OR pattern`. В одном байте маски AND объединяются через
OR, значение из правой пары ограничивается инверсией общей маски.
Полные внутренние байты получают шаблон строки из D100 с учётом чередования.

Индексы 5..7 адресуют сохранённые 96 пар по той же формуле. Некоторые пары
содержат ненулевые значения, хотя внутренние шаблоны равны нулю.
В исходных инструкциях эти пары читаются буквально и могут менять пиксели
вне геометрического полуинтервала. Отдельное исходное назначение этих
значений и игровые пути выбора индексов 5..7 пока не установлены.
Формулы для 0..4 к этим байтам не применяются.

[Проверка](../Tools/Disasm/Research/CheckPreviewEdgeMaskPages.py) сравнила
160 пар с независимыми формулами и выполнила 2400 двухстрочных контуров.
Сверен весь bitmap для всех восьми индексов, обеих страниц, всех фаз
краёв и случаев с общей либо раздельными байтовыми колонками.
[Отчёт исполнения](../Tools/Disasm/Reports/PreviewEdgeMaskPagesVerification.json)
и [сверка размещения](../Tools/Disasm/Reports/PreviewEdgeMaskPagesClassification.json)
фиксируют границы проверки.

Начальные 512 байтов совпадают с двумя страницами ACTION и копией DATAS. Строковое ядро ACTION использует те же краевые пары, но при принудительном индексе 5..7 читает другие внутренние шаблоны. [Сверка ACTION и 3DPART](ActionPolygonExtraMaskPairs.md)
