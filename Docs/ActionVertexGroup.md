# Группа проектируемых вершин ACTION

[ProjectRenderVertexGroup](../Source/Action/ProjectRenderVertexGroup.asm) занимает D694–D79F банка 0. Он строит восемь комбинаций трёх подготовленных координат и передаёт выбранные точки в [ProjectRenderVertex](../Source/Action/ProjectRenderVertex.asm). [Модель группы](../Tools/Disasm/Research/ReferenceActionVertexGroup.py) проверяется [исполнением исходных инструкций](../Tools/Disasm/Research/CheckActionVertexGroup.py). Новая память не выделяется.

## Входы и комбинации

Три изменяемых слова PackedFirst/Second/Third содержат пары локальных осей. Младший байт пары является первой осью перспективы, старший второй. Три отдельных байта DepthFirst/Second/Third задают глубину. Их вычисляет [PrepareRenderVertexProducts](./ActionVertexProducts.md), последовательно продолжающий исполнение в этом генераторе.

Обозначим входные пары U, V, W. R вращает каждый байт пары через RLC независимо. N отдельно отрицает каждый байт. Сложения и вычитания ниже выполняются над целым 16-разрядным словом, перенос между байтами нельзя удалять.

| Комбинация | Пара |
| --- | --- |
| 0 | U+V+W |
| 1 | пара0−R(U) |
| 3 | пара1−R(V) |
| 2 | пара3+R(U) |
| 5 | N(пара2) |
| 4 | пара5+R(U) |
| 6 | пара4−R(V) |
| 7 | пара6−R(U) |

Для глубин повторяется та же последовательность, но вся арифметика восьмибитовая. Глубины 0, 1, 2, 3 хранятся в IXH, IYH, IXL, IYL. Остальные четыре записываются в операнды непосредственных загрузок. Полные пары всех восьми комбинаций также записываются в свои операнды.

## Код группы

IXL на входе содержит полный код. До любых битовых проверок выполняются две проверки числового значения.

- 01 выдаёт только комбинацию 0.
- 81 выдаёт комбинацию 0, затем её покомпонентное отрицание. Это не обычный выбор комбинаций 0 и 7.
- Остальные значения служат маской. Разряды 7..0 соответствуют комбинациям 7..0, нулевой разряд означает пропуск. Порядок посещения строго 0, 1, 3, 2, 6, 7, 5, 4.

Прямой вход с кодом 00 не пишет точек, но вычисляет все комбинации. Родительский обработчик может использовать нулевой байт как маркер до вызова этой процедуры, это отдельный уровень формата.

## Два назначения SP

Входной CPU SP сохраняется в операнде SavedSP. Затем SP получает 8E00 с изменяемым младшим байтом NextOffset. CALL внутри тела отсутствует. Проекция вызывается через JP с адресом продолжения в HL и записывает точку двумя PUSH в рабочую RAM.

Каждая выбранная точка увеличивает рабочий SP на пять, включая точки с отказом перспективы. Два слова занимают входной SP−4..SP−1, пятый байт остаётся нетронутым. После всех точек HL получает конечный рабочий SP, NextOffset получает только L, затем восстанавливается CPU SP и выполняется RET. Если рабочий адрес пересёк границу страницы, его старший байт для следующего вызова не сохраняется. Ограничителя ёмкости нет.

## Точный выход

HL содержит конечный рабочий адрес. DE для особых кодов содержит последнюю переданную пару, для обычных масок всегда пару 4. B сохраняет исходный код, C содержит RLC младшего байта входного U. A равен L. Финальное ADD HL,SP сохраняет S/Z/PV последнего пути и формирует H/N/C=0, X/Y от старшего байта рабочего адреса. Если обычная маска пропускает комбинацию 4, S/Z/PV равны 0/1/1 от последнего BIT, а не от предыдущей перспективы.

Альтернативный набор получает результат последней перспективы, а при нуле точек сохраняется целиком. IXH содержит глубину 0, для кода 81 её отрицание. IXL содержит глубину 2, IYH/IYL глубины 1/3. I, IM, IFF и paging сохраняются. R меняется, его точное приращение и время отдельно не доказаны.

## Проверка и границы

[Отчёт](../Tools/Disasm/Reports/ActionVertexGroupVerification.json) содержит 206592 успешных сценария. Проверены все коды с шестью масштабами и четырьмя базами, все значения каждого из трёх упакованных слов отдельными срезами, все байты глубин, все младшие рабочие смещения и смешанные входы. Исполняется настоящий дочерний код перспективы без подмены. Числовой эталон композиционный, использует ранее проверенную формулу перспективы.

Сверяются точные регистры и флаги кроме R, вся физическая RAM, кратность записей и сохранение пятого байта каждой точки. CPU-стек не записывается внутри тела, внешний RET проверяется отдельно. Все совместные сочетания входов не исчерпаны. Полный проход объекта, IRQ, сборка и нативный игровой запуск этим отчётом не подтверждаются.

[Физические Point00..Point27](ActionProjectedPointsData.md) оформлены существующей FRenderProjectedPoint с сохранением всех начальных дисковых байтов.
