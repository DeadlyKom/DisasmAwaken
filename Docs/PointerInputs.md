# Клавиатура, джойстик и шаги указателя

[PollJoystick](../Source/Station/PollJoystick.asm) по `#6638` и [PollKeys](../Source/Station/PollKeys.asm) по `#6641` используют общий [ApplyPointerInput](../Source/Station/ApplyPointerInput.asm). Interrupt сначала вызывает ClearInputFlags, затем джойстик, клавиатуру и мышь. Два первых источника накапливают шесть общих флагов, но каждый отдельно изменяет координаты.

## Текущая выборка и накопленные флаги

Схема текущего байта A, разряды `7..0`:

```text
7        6        5        4        3   2     1     0
0        0        Action1  Action2  Up  Down  Left  Right
```

Маски равны `#20`, `#10`, `#08`, `#04`, `#02`, `#01` соответственно. Ноль означает отсутствие всех действий текущего источника. Разряды независимы, сочетание нескольких битов допустимо. Для джойстика общий путь требует нулевых разрядов 6 и 7. Клавиатура создаёт только шесть младших битов.

Каждый бит переносится через Carry в байт 0 либо 1, затем объединяется через OR с соответствующим полем физической [FInputFlags](../Source/Station/Data/InputFlags.asm). Порядок полей Right, Left, Down, Up, Action2, Action1. Это шесть отдельных байтов. После ClearInputFlags они нулевые, каждый опрос сохраняет уже накопленные действия другого источника. Если в байтах были посторонние старшие биты, OR их не нормализует.

Движение выбирается из текущего A, а не из накопленного результата. Поэтому вправо от джойстика и влево от клавиатуры выполняют два последовательных шага, сохраняя оба флага. Противоречие внутри одной выборки выбирает пустой обработчик и отменяет движение обеих осей. Кнопки действия на движение не влияют.

После семи RRC и сброса битов 5,6 смещение указателя равно `2*(A AND 15)` при нулевых исходных битах 6,7. В общем байтовом случае оно равно `((A AND #4F)<<1) OR (A>>7)`. Поэтому верхние биты не являются произвольно игнорируемыми, при их наличии может читаться нечётный адрес или область за таблицей. Исходный код это не проверяет.

## Шестнадцать направлений

Физическая [таблица FPointerDirection](../Source/Station/Data/PointerDirections.asm) сохраняет все 16 исходных слов в порядке масок 0..15. Внутри каждой записи Handler содержит адрес выполняемого кода.

| Маска | Обработчик | Действие |
| --- | --- | --- |
| 0 | NoPointerMotion | без движения |
| 1 | [StepRight](../Source/Station/StepRight.asm) | вправо |
| 2 | [StepLeft](../Source/Station/StepLeft.asm) | влево |
| 3 | NoPointerMotion | обе горизонтальные стороны |
| 4 | [StepDown](../Source/Station/StepDown.asm) | вниз |
| 5 | [StepDownRight](../Source/Station/StepDownRight.asm) | вниз и вправо |
| 6 | [StepDownLeft](../Source/Station/StepDownLeft.asm) | вниз и влево |
| 7 | NoPointerMotion | противоречие по X |
| 8 | [StepUp](../Source/Station/StepUp.asm) | вверх |
| 9 | [StepUpRight](../Source/Station/StepUpRight.asm) | вверх и вправо |
| A | [StepUpLeft](../Source/Station/StepUpLeft.asm) | вверх и влево |
| B | NoPointerMotion | противоречие по X |
| C..F | NoPointerMotion | противоречие по Y |

Шаг берётся из изменяемого операнда Step, пределы из MaxX и MaxY. StartStation задаёт Step=2, MaxX=255, MaxY=191. Это отличается от положительного предела X=254 в опросе [мыши](MouseInput.md).

Уменьшение X или Y ограничивается нулём при займе. Увеличение X проверяет перенос и верхний предел. Увеличение Y сравнивает с пределом только байтовую сумму, перенос сложения не проверяется. Для штатного шага 2 и Y=0..191 переполнения байта нет. Для произвольного большого шага или исходного Y за пределами экрана нельзя заменять этот код общей формулой насыщения математической суммы.

## Цепочка возврата

ApplyPointerInput читает адрес Handler, кладёт адрес [CommitPointerInput](../Source/Station/CommitPointerInput.asm) по `#66D3` на CPU-стек и выполняет JP `(HL)`. BC содержит текущие X,Y, E шаг, D предел Y, A предел X. RET выбранного обработчика сначала ведёт к записи PointerXY=BC. Следующий RET возвращается исходному вызывающему коду. Собственного CALL к Handler нет.

На выходе общего пути BC содержит итоговые координаты, DE=`#BF02` при штатных операндах. HL и AF рабочие. Индексные и альтернативные регистры сохраняются. Пустой обработчик сохраняет прежние координаты, но CommitPointerInput всё равно записывает их в память.

## Настроенные клавиши

[Шесть FKeyBinding](../Source/Station/Data/PointerKeys.asm) по `#99B6` имеют физические поля RowMask и KeyMask. RowMask становится старшим байтом порта, младший равен `#FE`. Нажатие определяется точным условием `(IN AND KeyMask)==0`. При многобитовой маске нулевыми должны быть все проверяемые разряды. Нулевая маска всегда даёт нажатие.

Порядок записей Up, Down, Left, Right, Action2, Action1. Исходные пары равны `FB/01`, `FD/01`, `DF/02`, `DF/01`, `7F/01`, `7F/04`. Каждая запись вызывает отдельное чтение порта, совпадающие строки не объединяются. Полученные разряды устанавливаются в порядке 3,2,1,0,4,5.

PollJoystick сначала проверяет изменяемый JoyDisabled. При ненулевом байте только AF меняется от AND этого значения. При нуле исходный IN A,(`1F`) читает полный порт `#001F`, поскольку старший байт берётся из нулевого A.

## Проверка

[Модель](../Tools/Disasm/Research/CheckPointerInputs.py) исполняет исходный опрос, косвенный переход, все обработчики направлений и продолжение записи координат. [Отчёт](../Tools/Disasm/Reports/PointerInputsVerification.json) содержит 41215 вызовов. Проверены все 64 сочетания направлений и действий обоих источников на границах, накопление байтов со значениями 0,1,128,255, все исходные X=0..255 и Y=0..191 для 16 направлений, все ненулевые запреты джойстика и 4096 последовательных пар опроса.

Модель использует согласованные значения клавиатурных строк из исходных шести привязок. Проверяются порядок IN, физические флаги, итоговые координаты, регистры и стек. IRQ и реальные устройства ввода не исполняются. Изменение пользовательских привязок, другие значения шага и пределов не заявляются проверенными этой моделью, их алгоритмические ограничения описаны выше.
