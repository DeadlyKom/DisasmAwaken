# Загрузчик и рисователь BANK во внекаталожных секторах

В исходном TRD сохранились две области кода вне каталожных файлов.
Первые команды по смещению диска 8C200 согласуются с исполняемым адресом
6000. Фиксированное окно 6000..BFFF занимает 24576 исходных байтов
8C200..921FF. Начало по 92200 согласуется с банковой областью C000. В частности,
таблица по смещению 92569 лежит по C369 и содержит указатели 63AE, 635B,
637E на три селектора страниц фиксированного блока. Эти соответствия
проверены исполнением исходных инструкций. Сами области уже сохранены
в [компоненте свободных секторов](../Tools/Disasm/Disk/Unallocated/087300.bin)
и возвращаются в TRD по прежнему физическому смещению.

## Загрузка

Вход 6520 шесть раз выбирает страницу через 6350 и передаёт следующий
девятибайтовый ключ из 60D6 загрузчику 653C. Порядок ключей — BANK0,
BANK1, BANK2, BANK3, BANK4, BANK5, у всех расширение C.
Загрузчик копирует ключ в 5CDD, сохраняет адрес следующего ключа
и вызывает 3D13 с HL=C000, A=FF и C=0E.
Проверенная ветвь 63AE с нулевым исходным 6641 выдаёт в порт 7FFD
значения 50..55. В модели бит 6 выбирает расширенную группу,
поэтому файлы оказываются на страницах 8..13. Две другие ветви селектора
и аппаратные конфигурации этим опытом не проверялись.

При исполнении с входа 6000 исходный код сначала загружает choose1 и
choose2 в экранные страницы 5 и 7. Код 6500 заменяет их атрибуты на 07,
сохраняя растры. После второго выбора экрана BANK загружаются с выходами
58..5D, поскольку бит теневого экрана уже включён. Исполнение достигает
HALT по 6053 с SP=6000 и конфигурацией 18. Модель исполняет 64 полных
цикла с исходным обработчиком IM2 по 67A4, включая код по 885C,
и возвращается в 6054. Проверены чередование экранов, порядок индексов
кадров и сохранение SP. В отчёте записаны хеши растров обоих экранов.
Прерывания подаются на границах циклов, клавиатура остаётся отпущенной.
После этих циклов модель замыкает бит 0 порта BFFE. Исходный код
переходит в IM 1 и передаёт TR-DOS ключ `ENGINE  C` с HL=4000.
В каталоге этого TRD такого ключа нет, поэтому проверка останавливает
ветвь на входе 3D13. [Отдельный запуск блока по 4000](FighterAssets.md#код-во-внекаталожных-секторах)
использует байты из внекаталожных секторов и не подставляет их как
результат запроса ENGINE.

## Таблицы и вывод

Код C1D2 копирует 50 байтов по указателю из C1E7. У записи два
однобайтовых поля, индекс BANK и число кадров, затем два списка по
двенадцать little endian указателей. Число кадров задаёт используемую
длину обоих списков. Двенадцать записей распределены по две на BANK.
Первый список выбирает нечётную полосу пары, второй — чётную.
В отдельных последовательностях индексы возвращаются в обратном
порядке после крайнего кадра.

6062 увеличивает индекс кадра с оборачиванием и копирует 600 байтов
из первого списка в 67D7. По одному указателю каждого BANK эта
фиксированная длина приводит к чтению через FFFF, последние 51–99
байтов берутся из ROM. Полные копии проверены с этим оборачиванием.
659D читает заголовок этой копии, добавляет бит 7 к старшему байту
адреса экрана и рисует в экранную область страницы 7.
65B0 выбирает второй указатель и рисует из загруженного BANK
в экран по 4000. Обе ветви сходятся на 65C3. Этот цикл копирует
ровно шесть байтов на строку, а 63D2 переводит адрес на следующую
строку по раскладке ULA.

## Чтения за концом растровой полосы

Для кадра с индексом 6 первого маршрута каждого BANK фиксированные 600 байтов захватывают начало соседнего промежутка. Трасса отмечает чтения по #608E в соответствующих расширенных страницах 8..13. В остальных проверенных кадрах чтения этих хвостов отсутствуют. Ресурсы содержат исходные байты по прежним файловым смещениям, правая граница исключена.

|---|---|---:|
| [BANK0](../Source/Resources/33_BANK0/StripStagingTail.bin) | #1C92..#1CE3 | 81 |
| [BANK1](../Source/Resources/34_BANK1/StripStagingTail.bin) | #1CFE..#1D49 | 75 |
| [BANK2](../Source/Resources/35_BANK2/StripStagingTail.bin) | #1CB6..#1D07 | 81 |

| [BANK5](../Source/Resources/38_BANK5/StripStagingTail.bin) | #1D16..#1D61 | 75 |

В буфере #67D7 каждый хвост начинается после трёхбайтового заголовка и всех строк выбранной полосы. Во всех шести случаях подмена хвоста на побитово инвертированные байты перед настоящим #659D оставила экран страницы 7 побайтово прежним. Запуск 64 последовательных кадров загрузчика дополнительно показал два чтения хвоста BANK0. Назначение самих значений в хвостах и штатный вход в этот загрузчик из активной игры остаются открытыми. [Сценарий](../Tools/Disasm/Research/CheckBankStripArchiveConsumer.py)
и [отчёт](../Tools/Disasm/Reports/BankStripArchiveConsumerVerification.json)
сверяют 6 файловых запросов, все 12 таблиц, 101 пару отрисовок и

в эти 12 таблиц. Растровая формула, две экранные страницы и остальная
часть каждого экрана сверены независимо.

## Совпадения в промежутках

Пять участков совпадают с физическими байтами после 92200. Их суммарная
длина 3142 байта. В таблице конечное смещение каждого диапазона исключено.

| Файл | Смещение в файле | Смещение на диске | Байтов |
|---|---|---|---|
| BANK0 | 1C92..1DF8 | 93F0A | 358 |
| BANK1 | 1CFE..1E76 | 93F5B | 376 |
| BANK2 | 1CB6..1EDA | 93F13 | 548 |
| BANK4 | 1B4E..1FA2 | 93DAB | 1108 |
| BANK5 | 1D16..2006 | 93F73 | 752 |

Совпадения подтверждают физическое родство данных. Их происхождение
во времени не установлено. Начальные 417 байтов пяти совпадений читает фиксированный LDIR при копировании полосы. Чтение остальной части совпадений не установлено.
[24 полные копии маршрутов](BankArchiveRouteCopies.md) занимают 1200
из этих байтов. Их поля оформлены отдельно в четырёх файлах BANK.
Проверка изолирует загрузку и рисование архивного блока, подменяет
TR-DOS по каталогу и использует модель расширенного paging.
Активный игровой путь к этим секторам, нативное исполнение и сборка
остаются за границей проверки.
