# Загрузчик и рисователь BANK во внекаталожных секторах

Две области кода принадлежат [архивному START.C](ArchiveMenuHandoff.md).
Первые команды по смещению диска 8C200 согласуются с исполняемым адресом
6000. Фиксированное окно 6000..BFFF занимает 24576 исходных байтов
8C200..921FF. Начало по 92200 согласуется с банковой областью C000. В частности,
таблица по смещению 92569 лежит по C369 и содержит указатели 63AE, 635B,
637E на три селектора страниц фиксированного блока. Эти соответствия
проверены исполнением исходных инструкций. Сборочный модуль START
возвращает 129 секторов по `#8C200`. Статическая сверка охватывает
12077 инструкций, включая три [исполняемых слоя](BankArchiveTileLayers.md#исполняемые-слои)
и процедуры подготовки растров, и 1144 байта структур. Каталожная запись
сохраняет нулевой первый байт.
[Сборочный модуль](../Source/Files/47_START.inc)

## Загрузка

Вход 6520 шесть раз выбирает страницу через 6350 и передаёт следующий
девятибайтовый ключ из 60D6 загрузчику 653C. Порядок ключей — BANK0,
BANK1, BANK2, BANK3, BANK4, BANK5, у всех расширение C.
Загрузчик копирует ключ в 5CDD, сохраняет адрес следующего ключа
и вызывает 3D13 с HL=C000, A=FF и C=0E.
Проверенная ветвь 63AE с нулевым исходным 6641 выдаёт в порт 7FFD
значения 50..55. В модели бит 6 выбирает расширенную группу,
поэтому файлы оказываются на страницах 8..13. Записи портов обеих
других ветвей подтверждены отдельно для всех шести кодов, размещение
страниц на соответствующих аппаратных конфигурациях остаётся открытым.
[Архивное меню и выбор селектора](StartArchiveMenu.md)
· [Исходник загрузчика](../Source/ArchiveStart/LoadBanks.asm)
· [Ключи файлов](../Source/ArchiveStart/Data/BankKeys.asm)

В отдельном профиле по входу `#6520` эти же шесть загрузок выполнило
исходное ПЗУ TR-DOS 5.04T. Для каждого файла сверены 64 прямых чтения
в `#C000..#FFFF` и байты всей выбранной страницы. Затем ПЗУ читает ещё
один сектор в `#5D25` и возвращается при нулевом остатке длины. Для
`BANK0`–`BANK5` это соответственно сектор 7 дорожек 99, 103, 107, 111,
115 и 119. Расширенные страницы и контроллер в этом профиле моделируются.

При исполнении с входа 6000 исходный код сначала загружает choose1 и
choose2 в экранные страницы 5 и 7. Код 6500 заменяет их атрибуты на 07,
сохраняя растры. После второго выбора экрана BANK загружаются с выходами
58..5D, поскольку бит теневого экрана уже включён. Исполнение достигает
HALT по 6053 с SP=6000 и конфигурацией 18. Модель исполняет 64 полных
цикла с исходным обработчиком IM2 по 67A4, включая код по 885C,
и возвращается в 6054. Проверены чередование экранов, порядок индексов
кадров и сохранение SP. В отчёте записаны хеши растров обоих экранов.
Прерывания подаются на границах циклов, клавиатура остаётся отпущенной.
После этих циклов модель замыкает бит 0 порта BFFE. Исходный код
переходит в IM 1 и передаёт TR-DOS ключ `ENGINE  C` с HL=4000.
В исходном каталоге запись этого файла начинается с нуля. В прогоне с TR-DOS 5.04T
загрузки `choose1`, `choose2` и всех BANK, 64 кадра и реакции меню
дали те же результаты, что в прогоне с подстановкой файлов. На запросе
ENGINE ПЗУ прочитало первые три сектора дорожки 0 и вернуло управление
на `#4000` со статусом `#01` по `#5D0F`. Экранный диапазон `#4000..#5AFF`
сохранил прежние байты. Модель остановилась до первой выборки по `#4000`.
[Отдельный запуск блока по 4000](FighterAssets.md#код-во-внекаталожных-секторах)
начинается с байтов из внекаталожных секторов. [Сквозная модель](ArchiveMenuHandoff.md)
с восстановленной первой буквой `ENGINE` подтвердила загрузку этих байтов
по `#4000` из исходных секторов и продолжение исполнения.

### Временный стек START

Кадровый IRQ сохраняет прерванный `SP` в операнде `RestoreStack` и ставит
временный `SP` на #67A4. Девять начальных `PUSH` занимают #6792..#67A3.
Вложенные вызовы используют пространство ниже. Два прогона с ROM TR-DOS,
включая переход к ENGINE и смену селектора в одном из прогонов, показали
чтение и запись всех 26 байтов по #678A..#67A3. Их исходное содержимое
нулевое. Нижние 14 нулевых байтов #677C..#6789 сохранены отдельно, их
использование в других режимах не установлено.
[Область стека](../Source/ArchiveStart/Data/FrameStack.asm)
· [Трасса](../Tools/Disasm/Reports/ArchiveMenuHandoffVerification.json)

В этих же прогонах START не обращался к #63E1..#63FF, #6725..#675A и
#6C87..#6C89. По #6725 и #6740 лежат две одинаковые 27-байтовые записи.
Их первые 12 байтов совпадают с четырьмя парами портов и масок клавиш
`W`, `S`, `D`, `A` при чтении как четыре записи `dw порт, db маска`.
Назначение обеих копий и пятнадцати завершающих нулей не установлено.
[Исходный порядок областей](../Source/Files/47_START.inc)

## Таблицы и вывод

Код C1D2 копирует 50 байтов по указателю из C1E7. У записи два
однобайтовых поля, индекс BANK и число кадров, затем два списка по
двенадцать little endian указателей. Число кадров задаёт используемую
длину обоих списков. Двенадцать записей распределены по две на BANK.
Первый список выбирает нечётную полосу пары, второй — чётную.
В отдельных последовательностях индексы возвращаются в обратном
порядке после крайнего кадра.
[Двенадцать физических маршрутов](../Source/ArchiveStart/Data/RouteTable.asm)
· [Два рабочих экземпляра](../Source/ArchiveStart/Data/Routes.asm)

6062 увеличивает индекс кадра с оборачиванием и копирует 600 байтов
из первого списка в 67D7. По одному указателю каждого BANK эта
фиксированная длина приводит к чтению через FFFF, последние 51–99
байтов берутся из ROM. Полные копии проверены с этим оборачиванием.
659D читает заголовок этой копии, добавляет бит 7 к старшему байту
адреса экрана и рисует в экранную область страницы 7.
65B0 выбирает второй указатель и рисует из загруженного BANK
в экран по 4000. Обе ветви сходятся на 65C3. Этот цикл копирует
ровно шесть байтов на строку, а 63D2 переводит адрес на следующую
строку по раскладке ULA.

Правый вход `#609C` копирует 600 байтов в отдельный буфер `#6A2F`.
После выбора адреса правый рисователь `#660F` прибавляет 31 к младшему
байту указателя без переноса в старший. Каждый из шести байтов строки
проходит через таблицу обращения битов `#6400` и записывается справа
налево. Проверены все 256 значений таблицы, 101 пара прямых и буферных
отрисовок, 105 060 записанных байтов и оборачивание счётчиков всех 12
маршрутов. Ненулевой флаг готовности блокирует повторный перенос.

## Чтения за концом растровой полосы

Для кадра с индексом 6 первого маршрута каждого BANK фиксированные 600 байтов захватывают начало соседнего промежутка. Трасса отмечает чтения по `#608E` слева и `#60C8` справа в соответствующих расширенных страницах 8..13. В остальных проверенных кадрах чтения этих хвостов отсутствуют. Ресурсы содержат исходные байты по прежним файловым смещениям, правая граница исключена.

| Файл | Смещение | Длина |
|---|---|---:|
| [BANK0](../Source/Resources/33_BANK0/StripStagingTail.bin) | #1C92..#1CE3 | 81 |
| [BANK1](../Source/Resources/34_BANK1/StripStagingTail.bin) | #1CFE..#1D49 | 75 |
| [BANK2](../Source/Resources/35_BANK2/StripStagingTail.bin) | #1CB6..#1D07 | 81 |
| [BANK3](../Source/Resources/36_BANK3/StripStagingTail.bin) | #1B66..#1BD5 | 111 |
| [BANK4](../Source/Resources/37_BANK4/StripStagingTail.bin) | #1B4E..#1BB7 | 105 |
| [BANK5](../Source/Resources/38_BANK5/StripStagingTail.bin) | #1D16..#1D61 | 75 |

В буфере #67D7 каждый хвост начинается после трёхбайтового заголовка и всех строк выбранной полосы. Во всех шести случаях подмена хвоста на побитово инвертированные байты перед настоящим #659D оставила экран страницы 7 побайтово прежним. Запуск 64 последовательных кадров загрузчика дополнительно показал два чтения хвоста BANK0. Назначение самих значений в хвостах и штатный вход в этот загрузчик из активной игры остаются открытыми. [Сценарий](../Tools/Disasm/Research/CheckBankStripArchiveConsumer.py)
и [отчёт](../Tools/Disasm/Reports/BankStripArchiveConsumerVerification.json)

в эти 12 таблиц. Растровая формула, две экранные страницы и остальная
часть каждого экрана сверены независимо.

## Совпадения в промежутках

Пять участков совпадают с физическими байтами после 92200. Их суммарная
длина 3142 байта. В таблице конечное смещение каждого диапазона исключено.

| Файл | Смещение в файле | Смещение на диске | Байтов |
|---|---|---|---|
| BANK0 | 1C92..1DF8 | 93F0A | 358 |
| BANK1 | 1CFE..1E76 | 93F5B | 376 |
| BANK2 | 1CB6..1EDA | 93F13 | 548 |
| BANK4 | 1B4E..1FA2 | 93DAB | 1108 |
| BANK5 | 1D16..2006 | 93F73 | 752 |

Совпадения подтверждают физическое родство данных. Их происхождение
во времени не установлено. Начальные 417 байтов пяти совпадений читает фиксированный LDIR при копировании полосы. Чтение остальной части совпадений не установлено.

В самих внекаталожных секторах доказано чтение исходного третьего
растрового слоя рисователем #C004/#C026. Часть совпадений после хвостов
LDIR выделена как точные копии этого слоя. [Рисователь и границы копий](BankArchiveTileLayers.md)
[24 полные копии маршрутов](BankArchiveRouteCopies.md) занимают 1200
из этих байтов. Их поля оформлены отдельно в четырёх файлах BANK.
Вызовы ПЗУ проверены и с отдельного входа `#6520`, и с архивного старта
по `#6000`. В проверке 101 пары отрисовок используются исходные файлы
без вызова ПЗУ.
Активный игровой путь к этим секторам, нативное исполнение и сборка
остаются за границей проверки.
