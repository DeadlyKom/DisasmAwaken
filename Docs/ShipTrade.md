# Подтверждение модели и исходная торговля кораблями

[ConfirmShipModelTrade](../Source/Station/ConfirmShipModelTrade.asm), вход `#79C7`, читает строку `PanelHoverState.ShipsRow`. Значение `FF` даёт немедленный выход без выбора банка и без побочных записей. Остальные строки записываются в операнд `D3DPreviewState.RowOperand` банка 4. Поле `BaseOperand` сохраняется, поэтому индекс сценария равен байтовой сумме этих двух компонентов.

Событие вычисляется из полных байтов `ShipPanelState.OwnedMode` и `Selector`:

| OwnedMode | Selector | Событие |
|---|---|---|
| 0 | 0 | 1, покупка корабля |
| ненулевой | 0 | 2, продажа корабля |
| 0 | ненулевой | 3 |
| ненулевой | ненулевой | 4 |

После выбора банка 6 вызывается [RunMarketScript](../Source/Text/RunMarketScript.asm). Активный [физический сценарий](../Source/Text/Data/MarketScript.asm) имеет блоки событий 1 и 2. Блоков 3 и 4 в нём нет. При этих событиях выполняется общий начальный пересчёт загрузки `T`, затем интерпретатор пропускает несовпадающие блоки. Это свойство исходного образа, дополнять его отсутствующими сделками нельзя.

## Покупка, событие 1

Проверки идут в исходном порядке. Наличие текущего корабля, байт `#9849` не равен `FF`, ставит сообщение M02. Цена выбранного корабля больше кредитов даёт M01. Вместимость меньше пересчитанной загрузки даёт M03. Нарушение порога хотя бы одной активной строки оснащения даёт M07. В проверке `o.s` индекс строки снимается со стека, но проверяются все 30 строк.

При успехе `+K` выбирает корабль по сумме компонентов банка 4. Из кредитов вычитается цена, вместимость становится полем `K.t`, загрузка пересчитывается, M12 ставит сообщение о завершении. Цена — слово `#9803+5*индекс`, вместимость — байт `#9802+5*индекс`. Эти значения установлены для семи корабельных записей по их фактическим читателям и записи результата сделки.

## Продажа, событие 2

При отсутствии текущего корабля ставится M09. При нулевом байте `k.s`, физически `#9806+5*текущий_индекс`, выполняется строка `M04,=c+k.c,-K,#`. Она начисляет цену текущего корабля с насыщением до `FFFF` и очищает выбор в `FF`. Вместимость остаётся прежней. Команда `#` сама является переходом в `NextCommand`, завершение на CR обеспечено предшествующей M04. Игровое назначение поля `k.s` за пределами этого доказанного условия пока не установлено.

Обычный путь сначала проверяет сумму кредитов с **ценой выбранной строки K.c**, затем начисляет **цену текущего корабля k.c**. Эти индексы могут различаться. Превышение 65000 вызывает строчную m11 и не прекращает начисление. После `-K` вместимость обнуляется, загрузка пересчитывается и ставится M12. Арифметика сложения насыщается до `FFFF`.

Номера M в сценарии начинаются с единицы, физический индекс очереди сообщения на единицу меньше. M устанавливает завершение на следующем CR, m этого флага самостоятельно не устанавливает.

## Завершение интерфейса

При любом нормальном возврате LANG, включая отказ сделки, обработчик выполняет BeginScreenUpdate, [DrawItem00](../Source/Station/DrawItem00.asm), EndScreenUpdate. Затем удаляет список моделей и вызывает [DropShipDetailPanels](../Source/Station/DropShipDetailPanels.asm), последовательно удаляющий панели 30, 26, 27, 28, 29 по текущим изменяемым индексам. Каждый найденный ключ сдвигает ровно 128 байтов, включая физический хвост списка. Периодическая цель становится EmptyCallback, активность обнуляется. Отказ сделки не удерживает эти панели открытыми.

## Проверка и границы

[CheckOriginalShipTrade.py](../Tools/Disasm/Research/CheckOriginalShipTrade.py) исполняет неизменённые интерпретатор и сценарий, сравнивает независимые результаты кредитов, выбора, вместимости и очереди сообщений. Проверено 1400 случаев, все семь корабельных строк, события 1..4, денежные границы, отказы по загрузке и оснащению. [Отчёт](../Tools/Disasm/Reports/OriginalShipTradeVerification.json).

[CheckShipTradeAction.py](../Tools/Disasm/Research/CheckShipTradeAction.py) проверяет 168 полных действий с настоящим статусным рисунком, порядок вызовов и шесть удалений, 512 комбинаций для покрытия каждого байта двух переключателей и 256 ранних выходов FF с разными флагами. [Отчёт](../Tools/Disasm/Reports/ShipTradeActionVerification.json).

Независимое сравнение всего bitmap статуса, нативный запуск и сборка этими проверками не выполняются. Они не заменяют разбор остальных ветвей оснащения и прочих событий LANG.
