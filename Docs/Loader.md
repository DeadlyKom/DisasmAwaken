# Первый вход загрузчика

[ReadIntroSectors](../Source/Basic/ReadIntroSectors.asm) находится в
первой записи AWAKEN, исходный код занимает файловые байты `#0006..#001D`
и исполняется с `#5D41`. Его контракт установлен до передачи управления
TR-DOS, без предположений о сохраняемых регистрах конкретного ROM.

DI запрещает прерывания. SP заменяется исходным значением `#5FFF`,
IY получает `#5C3A`. Прежний стек вызывающего BASIC-кода больше не используется.
На новый стек помещается адрес `Intro.InitializeIntro.Entry = #6500`,
а DEC H уменьшает адрес чтения до `#6400`.

Перед JP в TR-DOS `#3D13` регистры имеют следующие значения:

| Значение | Состояние |
| --- | --- |
| HL | #6400, начало чтения вступления |
| DE | слово из LoaderState.NextIntroBlock по #5CF4 |
| BC | #2C05, 44 физических сектора и номер функции чтения |
| AF | входной A, F=#22 плюс входной Carry после DEC H |
| IY | #5C3A |
| SP | #5FFD, на вершине слово #6500 |

Сам загрузчик не меняет IX, альтернативные регистры, I и IM.
Дальнейшие эффекты ROM TR-DOS в этот контракт не включаются.
После чтения ожидается возврат дисковой системы на #6500. Отдельной
проверки ошибки в этих 24 байтах нет.

[CheckBasicLoader.py](../Tools/Disasm/Research/CheckBasicLoader.py)
подтвердил состояние интерфейса на 5120 сочетаниях, включая все входные F.
Проверка останавливается перед первой инструкцией TR-DOS, поэтому она
не подтверждает само дисковое чтение или запуск игры.
Результат — [BasicLoaderVerification.json](../Tools/Disasm/Reports/BasicLoaderVerification.json).

Отдельная модель с ROM TR-DOS 5.04T исполнила и дисковую часть.
Сверены 44 физических сектора, содержимое `#6400..#8FFF`, возврат
на `#6500` и восстановление SP до `#5FFF`.
[Сценарий и границы проверки](BasicProgram.md) ·
[Результат](../Tools/Disasm/Reports/BasicIntroDiskReadVerification.json)

[Исходная BASIC-программа](BasicProgram.md) содержит USR 23873 в печатном и скрытом числовом виде. Это доказывает предназначенный вход 5D41, прежняя привязка 5CD1 была ошибочной и исправлена без изменения байтов.


## Граница загрузчика перед TR-DOS

[ReadIntroSectors](../Source/Basic/ReadIntroSectors.asm) по #5D41 заканчивает локальный договор перед первой инструкцией #3D13. Его десять инструкций дают 12 M1, LD IY,nn и LD DE,(nn) содержат по два M1. Исходный CPU SP заменяется на #5FFF, PUSH HL записывает #6500 по #5FFD/#5FFE, затем DEC H готовит адрес чтения #6400. Прежний адрес возврата BASIC больше не используется. A сохраняется, F=#22 OR входной Carry, IFF=0, I и IM сохраняются. SP на границе равен #5FFD.

[Локальная модель](../Tools/Disasm/Research/CheckBasicLoader.py) в 5120 профилях проверяет все F, четыре исходных A и пять слов NextIntroBlock. Секторный источник непосредственно сопоставлен с оригинальным TRD и хешем образа. Сравниваются вся RAM, точный R и ровно две CPU-записи, #5FFD=00 и #5FFE=65. Альтернативные регистры и IX сохраняются. Эта модель не исполняет ROM TR-DOS и не читает секторы. Произвольные слова положения нужны для проверки передачи аргумента, они не объявлены допустимыми адресами реального чтения.

[Отдельная модель RUN исходного BASIC](../Tools/Disasm/Reports/AwakenBasicRunVerification.json) получает NextIntroBlock=#1202. [Отдельная модель дискового чтения](../Tools/Disasm/Reports/BasicIntroDiskReadVerification.json) выполняет настоящий ROM TR-DOS 5.04T с моделью дисковых портов. Оба отчёта указывают одинаковый хеш DOS ROM e21d37271d087eab5ef8f88d8f3a58c8c19da1fa857b9790eaa974b231db9e13. Подтверждение чтения и возврата к #6500 относится к этим отдельным проверкам, не к остановке локального загрузчика перед #3D13. Ошибка диска и нативный запуск данным уточнением не доказываются.

[Локальный отчёт](../Tools/Disasm/Reports/BasicLoaderVerification.json), [канонический договор](../Tools/Disasm/Research/BasicReadIntroFacts.py). Код, размер, расположение и точка USR исходного BASIC сохранены, сборка не выполнялась.
