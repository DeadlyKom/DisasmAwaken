# Обработка близкой записи, три разных входа

[DispatchCloseRecord](../Source/Action/DispatchCloseRecord.asm) по E506, [CheckCloseRecordComponents](../Source/Action/CheckCloseRecordComponents.asm) по E51F и [ReverseCloseRecordState](../Source/Action/ReverseCloseRecordState.asm) по E54A занимают 86 исходных байтов ACTION банка 0. Разделение сохраняет все исходные инструкции и адреса, дополнительный переход между файлами не добавляется.

## Корневой вход E506

Полный байт InhibitCode по E507 является непосредственным операндом LD A,n. Значение 00 допускает обработку, 01..FF немедленно возвращают A=код, F от AND A, не меняя RAM, IX, HL, DE и BC. Это проверка целого байта на ноль, биты 7..0 не объявляются независимыми флагами.

При допуске адрес записи из HL′ переносится в IX через PUSH и POP. Оба регистровых набора сохраняют принадлежность. ClassCode 11 соответствует создаваемой ракете, он игнорируется. Класс 14 также возвращается без изменения состояния, его полный игровой смысл не установлен. Оба выхода оставляют A=ClassCode и F=42.

Класс 12 переходит [TransferToStationLoader](ActionStationTransfer.md), выбирающему банк 1 и PC=DCE3 при незаблокированном 7FFD. На локальной границе HL и BC сохраняются, DE=0, AF=1142, IX адрес записи, SP остаётся входным. Это передача управления, а не возврат внешнему CALL. Код Controls и последующая дисковая загрузка в данной модели не исполняются.

Прочие классы переходят общему хвосту инверсии по E54A. Исходный JP по E51C не даёт прохода корневого входа к E51F. Дополнительный игровой вызывающий путь E51F пока не установлен, этот участок не выдаётся за обязательно выполняемую проверку корневого входа.

## Дополнительный вход E51F

Здесь IX уже должен указывать запись. Корневая проверка InhibitCode не выполняется, адрес из HL′ не переносится, классы 11 и 14 не игнорируются автоматически.

Сначала проверяется бит 4 ReuseByte, маска 10. Ноль направляет в общий хвост, единица допускает проверку трёх старших байтов компонент. Каждый старший байт при отрицательном знаке проходит CPL без INC. Поэтому допускаются диапазоны 00..03 и FC..FF. Это не вычисление полного модуля слова и не равнозначная замена на NEG. При отказе любой компоненты выполняется общий хвост, при допуске всех трёх передача идёт TransferToStationLoader. В последнем случае AF=1193, HL и BC сохраняются, DE=0, SP остаётся входным.

В этом дополнительном входе ClassCode не определяет сам допуск передачи. Поэтому модель отдельно проверяет все его классы, не подставляя условия корневого входа. После условного JP по E547 при недопуске последней компоненты возможен проход в следующий файл общего хвоста. Их include имеют обязательный порядок (0), (1).

Схема ReuseByte `7 6 5 4 3 2 1 0` здесь имеет только один установленный потребитель разряда 4. Другие биты этим входом не проверяются. Нулевое целое поле запрещает передачу через данную дополнительную проверку. Это не доказательство назначения всего поля как набора флагов: [FindReusableRecord](ActionRecordSearch.md) использует полный байт и его особый код FF.

## Общий хвост E54A

InhibitCode косвенно уменьшается DEC (HL) на один по модулю 256, исходный 00 становится FF. Писатель изменяемого кода зарегистрирован в [ModifiedCode](ModifiedCode.md). Затем реальный [ReverseScaledVector](ActionVectorReverse.md) меняет знак трёх компонент, обновляет SpeedWord и задаёт EnabledCode=1. После него повторно читается ClassCode.

Для класса не 12 возвращаются HL=новое SpeedWord, DE и BC сохраняются, A=ClassCode, F от CP с 12. Для класса 12 дополнительно обнуляется FirstValue и AF=0044. Это байт первой шкалы по #A794. Альтернативные регистры, IX, IY, I, IM и IFF сохраняются, SP увеличивается на два. Портовых операций этого хвоста нет. Он исполняет 51 M1 для класса не 12 и 54 M1 для класса 12.

## Границы и проверка

Корневой вход использует 3 M1 при запрете, 12 для класса 11, 14 для класса 14, 27 при передаче и 67 при инверсии. Максимальная дополнительная глубина стека равна четырём байтам для передачи, двум для ветвей с сохранением записи либо вызовом инверсии и нулю для раннего запрета. Временные PUSH и CALL переиспользуют одни ячейки, их глубины не суммируются как независимые рамки.

[CheckActionCloseRecord.py](../Tools/Disasm/Research/CheckActionCloseRecord.py) исполняет оригинальные инструкции всех трёх входов и настоящие дочерние инверсию и селектор страницы. [Отчёт](../Tools/Disasm/Reports/ActionCloseRecordVerification.json) содержит 93184 сценария. Проверены все классы и коды запрета, все ReuseByte и старшие байты компонент по отдельным сечениям, 512 совместных крайних комбинаций трёх старших байтов, самостоятельный общий хвост по всем сочетаниям класса и запрета и четыре исходные конфигурации банка 0.

Модель родителя использует отдельно проверенную формулу инверсии, полный независимый эталон всех детей не заявляется. Сравниваются регистры, оба набора, флаги, R, SP, восемь физических банков, каждая запись RAM и фактические OUT 7FFD. Продолжение DCE3, дисковая загрузка, прерывания, весь игровой кадр и нативный переход режима не выполнялись. Прямые сценарии E51F доказывают его локальный договор, но не игровой путь его вызова.
