# Генератор, 35 координат и XOR-точки

| Вход банка 1 | Процедура | Результат |
| --- | --- | --- |
| CA8D | [NextBufferRandom](../Source/Controls/NextBufferRandom.asm) | Новый Seed и его младший байт |
| CAB3 | [InitializeBufferPoints](../Source/Controls/InitializeBufferPoints.asm) | 35 записей Y,X |
| CAE3 | [XorBufferPoints](../Source/Controls/XorBufferPoints.asm) | 35 операций XOR над линейным растром |

Таблицы адресации строит [ActionBoot.BuildBitmapTables](../Source/ActionBoot/BuildBitmapTables.asm).
Растр 8000..8BFF затем переносит [CopyViewportToScreen](ControlsBufferCopy.md).
Все адреса Controls в этом документе относятся к загруженному CONTROL0
в банке 1. Одноимённые адреса других банков не отождествляются с ним.

## Исходное состояние генератора

Seed находится в двух байтах CA8F..CA90 внутри LD BC,nn. В оригинале
он равен нулю. NextBufferRandom использует альтернативные HL, DE и BC,
поэтому основные пары сохраняются. AF′, IX и IY также сохраняются.
Дополнительных записей на CPU-стеке нет, RET потребляет внешний возврат.

Для исходного состояния s вычисляются промежуточные слова по модулю 65536:

```
t = (7*s - 4) AND FFFF
u = (HIGH(t) - LOW(t)) AND FFFF
v = (t - u) AND FFFF
newSeed = (v - 1) AND FFFF
```

На выходе A=LOW(newSeed), HL′=newSeed, DE′=u, BC′=LOW(t).
Основной F соответствует SBC t-u, поскольку последующее DEC HL
флагов не меняет. Флаги не являются проверкой возвращаемого A.
Оба OR A перед SBC исключают влияние входного Carry.
I, IM и IFF сохраняются.

Переход проверен на оригинальных инструкциях для всех 65536 состояний.
По фактической таблице переходов для штатного Seed=0 обнаружены
59 шагов до цикла, затем цикл из 387 состояний. Первое повторившееся
состояние равно 8414 десятичное, 20DE шестнадцатеричное. Во всей
таблице 65282 различных следующих состояния. Генератор не является
перестановкой всех 65536 слов и не имеет полного 16-битового периода.
Изменение генератора ради качества распределения здесь недопустимо.

## Подготовка координат

InitializeBufferPoints выполняет ровно 70 настоящих вызовов генератора,
по два на каждую из 35 точек. Сначала получается X. Нуль заменяется
на 2, значения 254 и 255 уменьшаются на 2. Итого X находится в 1..253,
значения 2, 252 и 253 имеют дополнительные прообразы.

Затем X сохраняется через EX AF,AF′ и генерируется Y. Сначала берутся
семь младших битов. Нуль заменяется на 2, значения 95..127 уменьшаются
на 64 и попадают в 31..63. Итоговый диапазон Y равен 1..94. Это
неравномерное ограничение с дополнительными прообразами, не остаток
от деления на 94 и не повторная генерация при выходе за границу.

Сохраняются Y, затем X. Физические [ControlsBufferPoints](../Source/Controls/Data/BufferPoints.asm)
занимают C500..C545, 35 экземпляров FBufferPoint по два байта.
Поле Y имеет смещение 0, X смещение 1, последняя запись Point22
находится по C544. После заполнения HL=C546, BC и DE сохранены,
AF=4642. Альтернативные пары содержат результат последнего генератора.
A′ содержит последний Y. F′ сохраняет только Carry последнего
ограничения Y, остальные биты сброшены промежуточным INC L.

В исходном диске все 70 байтов нулевые, это полноценные начальные
значения записей. Соседние [страницы кэша корня C000..C2FF](../Source/Controls/Data/RootCache.asm), [квадраты C300..C4FF](../Source/Controls/Data/Squares.asm) и [шрифт C600..C86F](ControlsTextFont.md) оформлены отдельно.

Авторский `SPACE.a` выделяет `#100` байтов под `DOTB` сразу после
таблицы квадратов. В `STARHSUN.a` процедуры звёзд читают и меняют
координаты через `DOTB` и `DOTB+1`. В текущем CONTROL0 с архивным
совпадают все первые 1536 байтов, включая страницу `#C500..#C5FF`.
Доказанные 35 пар занимают первые 70 байтов страницы. Остальные 186
байтов по `#C546..#C5FF` сохраняют исходное заполнение резерва.
Отдельный игровой читатель этой части страницы пока не установлен.

[Авторский архив](https://opensourcezx.untergrund.net/a_games-awaken_src.html) ·

## Четыре страницы таблиц

BuildBitmapTables исполняется в загрузчике игрового модуля. Для всех
256 значений Y он сохраняет старший и младший байты 8000+32×Y.
Для всех 256 значений X сохраняются X DIV 8 и 80 с циклическим
сдвигом вправо на X AND 7.

| Страница | Содержимое |
| --- | --- |
| 9400..94FF | HIGH(8000+32×Y) |
| 9500..95FF | LOW(8000+32×Y) |
| 9600..96FF | X DIV 8 |
| 9700..97FF | 80 >> (X AND 7) |

Это генерируемые во время исполнения таблицы. В обычную сборку не
добавляется статический килобайт новых данных и не резервируется другая
RAM. Содержимое этих адресов в других состояниях игры может иметь
иной смысл, например таблицы экранных эффектов интро.

## Наложение точек

XorBufferPoints читает все 35 записей. Из первых двух страниц получает
адрес строки по Y. К младшему байту прибавляет значение третьей
страницы по X, старший байт при этом не увеличивается. При штатных
таблицах и Y=0..95 получается 8000+32×Y+floor(X/8).
Из четвёртой страницы берётся маска пикселя, которая накладывается XOR.

Потребитель не проверяет координаты и не пропускает нулевые записи.
При 35 нулевых записях один и тот же пиксель по 8000 переключается
35 раз, итог равен однократной инверсии. Две совпавшие точки могут
взаимно исчезнуть через XOR, совпадения не удаляются.

После последней точки BC=C546, HL=9700+X последней точки, DE её
адрес назначения, AF=4642. Альтернативные и индексные регистры,
I, IM и IFF сохраняются. Дополнительных PUSH и CALL нет.
Контракт использует доступный растр Y=0..95. Произвольные старшие Y
могут адресовать другие рабочие области и сами таблицы, это не
объявляется безопасным вариантом того же договора.

[Action.UpdateFrame](../Source/Action/UpdateFrame.asm) вызывает CAE3
после выбора страницы 11. Подготовка вызывается из
[Action.InitializeBankedBufferPoints](../Source/Action/InitializeBankedBufferPoints.asm) также после выбора
11 и затем возвращает страницу 10. Полные договоры этих вызывающих
игровых процедур не объявлены доказанными. Обновление координат внутри
UnknownCB00 остаётся отдельным неразобранным алгоритмом.

## Проверки

[ReferenceControlsBufferPoints](../Tools/Disasm/Research/ReferenceControlsBufferPoints.py)
задаёт математический переход Seed, байтовые ограничения и страницы
адресации независимо от Z80-инструкций.
[CheckControlsBufferPoints](../Tools/Disasm/Research/CheckControlsBufferPoints.py)
исполнил 66754 сценария:

- один настоящий построитель таблиц, все 1024 байта и конечные регистры;
- все 65536 исходных состояний генератора, точный основной F и рабочие альтернативные пары;
- 512 полных подготовок, каждая с 70 настоящими CALL, проверкой всех записей стека, Seed и координат;
- 705 полных проходов рисователя, включая все 24576 координат растра и два специальных сценария совпадающих точек.

Сравниваются вся RAM, все записи с повторениями, SP, сохраняемые регистры
и документированные результаты. Перемещения стека при CALL проверяются
как множество записей с кратностями, временной порядок этих стековых
байтов отдельной шинной моделью не доказывается.
[Отчёт](../Tools/Disasm/Reports/ControlsBufferPointsVerification.json).

Реальные IRQ, полный игровой цикл и нативный кадр этой моделью не
подтверждены. Python используется только для исследования и проверок,
обычная сборка использует ASM, STRUCT и штатный Lua-упаковщик.
Ассемблер Codex не запускал.
