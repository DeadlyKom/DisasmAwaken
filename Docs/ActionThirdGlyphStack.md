# Восстановление стека перед публикацией третьего знака

[RestoreThirdGlyphStack](../Source/Action/RestoreThirdGlyphStack.asm) — одна исходная LD SP,nn по 6CB1..6CB3 перенесённого ACTION. Слово SavedCpuSP по 6CB2 заполняется до входа в ComputePatchedVector. Вычислитель использует SP как числовой накопитель и переходит на этот адрес через IY.

Инструкция восстанавливает обычный CPU SP без разыменования прежнего арифметического значения. AF и все данные регистров сохранены, RAM не записывается. R получает один M1 с сохранением бита 7. I, IM, IFF и paging сохраняются при отсутствии вмешательства IRQ.

Это часть (0) последовательной пары include. Часть (1), [PublishThirdGlyphVector](../Source/Action/PublishThirdGlyphVector.asm), начинается с RET PE. Поэтому CPU-стек требуется восстановить и при отказе вычислителя по переполнению. Дополнительного машинного JP между файлами нет.

[Модель](../Tools/Disasm/Research/CheckActionThirdGlyphStack.py) проверила все 65536 слов SavedCpuSP, регистры включая R, все банки RAM и отсутствие записей. Она останавливается по 6CB4 до первого чтения стека. Допустимость каждого синтетического SP для последующего RET не заявляется, игровой вызывающий код обязан сохранить действительный стек с внешним возвратом.

[Отчёт](../Tools/Disasm/Reports/ActionThirdGlyphStackVerification.json) не подтверждает IRQ, точные T, сборку или нативный запуск. EQU именует существующий операнд, новая область памяти не выделяется.
