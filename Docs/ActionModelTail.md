# Дополнительные пакеты OBJECT3D

После последней цели исходной таблицы указателей по смещению 2469
остаются семь последовательных пакетов. Последний нулевой ограничитель
лежит по 2953, непосредственно перед секторным суффиксом. Всего 1259
байтов, 207 граней и 19 открытых линий.

| Начало | Конец без включения | Получаемых вершин | Авторское имя и исходник |
|---|---|---:|---|
| 2469 | 251F | 32 | `St16`, [ModelSt16](../Source/Action/Data/ModelSt16.asm) |
| 251F | 25C1 | 24 | `St_pirat`, [ModelStPirat](../Source/Action/Data/ModelStPirat.asm) |
| 25C1 | 266B | 32 | `Prison`, [ModelPrison](../Source/Action/Data/ModelPrison.asm) |
| 266B | 2707 | 28 | `St_u1`, [ModelStU1](../Source/Action/Data/ModelStU1.asm) |
| 2707 | 27AB | 26 | `St_scince`, [ModelStScince](../Source/Action/Data/ModelStScince.asm) |
| 27AB | 2859 | 28 | `St_u2`, [ModelStU2](../Source/Action/Data/ModelStU2.asm) |
| 2859 | 2954 | 37 | `Gip_pl`, [ModelGipPl](../Source/Action/Data/ModelGipPl.asm) |

Физические заголовки используют подтверждённые авторские имена
St16, StPirat, Prison, StU1, StScince, StU2 и GipPl в модуле
ActionModels. Имена приведены к принятому написанию без подчёркиваний,
сокращения StU1, StU2 и GipPl не расшифровываются предположительно.
Метки, имена файлов и ссылки из TailModelPointers согласованы.
Все адреса, группы, примитивы и исходный порядок четырнадцати
указателей сохранены. Соответствие новых меток исходным авторским
именам повторно проверяет `model_name_provenance` в
[реестре границ ресурсов](../Tools/Disasm/Reports/ResourceSemanticLimits.json).

Действует тот же [формат](ActionModelPackets.md), включая два независимых
нулевых ограничителя. Число вершин равно сумме числа установленных битов
масок групп. Каждый индекс кратен пяти и выбирает существующую вершину
своего пакета. Материалы граней лежат в пределах 0..4, длины линий
соответствуют исходному формату.

[Сценарий](../Tools/Disasm/Research/CheckActionModelTail.py) заново
разбирает каждый пакет, проверяет границы и собирает его представление
обратно в исходные байты для сравнения. [Отчёт](../Tools/Disasm/Reports/ActionModelTailVerification.json)
сохраняет границы, индексы и объём. Эти пакеты отсутствуют среди 128 слов
по 9E00 и не дублируют один из 95 основных потоков побайтно.

Сразу за этой таблицей, по 9F00..9F1B ACTION, лежат 14 физических
FObjectDataPointer. Каждое начало дополнительного пакета банка 4 записано
дважды подряд. Адрес модели 27AB идёт перед адресом 2707, исходный порядок
сохранён. Обычные читатели таблицы 9E используют оборачивание младшего
байта, поэтому они не доходят до дополнительных слов. Потребитель `#9F00`
остаётся неизвестным. Авторские имена подтверждены совпадением 142 слов
таблицы и всего `OBJECT3D.C`.
[Физические указатели](../Source/Action/Data/TailModelPointers.asm),
[сверка адресов](../Tools/Disasm/Reports/ActionTailModelPointersVerification.json).

В `3DTABS.a` селекторы определены через младший байт адреса `$.b`.

читателям они выберут пары из первой страницы, указанные справа.

## Выбор через шаблон ST16k

В авторском `OBJGENER.a` таблица `STATTB` содержит 16 указателей
на шаблоны генерации станций. Совпали порядок выбора, все 16 текущих
указателей `#7799..#77B8` и 160 байтов строк с ограничителями.
В двенадцатой позиции, индекс 11, исходник задаёт `ST16k` с
селектором `IST16`. В текущем ACTION это строка по `#784F`.
Из всех 16 шаблонов только у неё авторская пара и фактически
выбираемая пара различаются. Обе половины `IST16` находятся в
следующей странице и имеют тот же селектор `#00`, что `IPOL1`.

Исходный генератор карт включает точку с ключом `4B38 44FA 00`
в стартовый сектор. С этим ключом `BuildSeededIndices` выбирает
индекс 11. Модель исполняет `SpawnAlternate` и получает запись
класса `#12` с `ModelOffset=#00`. Затем `RenderSceneFrame`
работает с этой же записью. При ближней глубине чтение идёт
по `#9E02..#9E03` к пакету `Kd1` по `#C040`. При дальней
глубине чтение идёт по `#9E00..#9E01` к пакету `KN01pol1` по
`#C000`. В каждом случае сверены адрес чтения заголовка, полная
копия пакета и изменение линейного растра. Обе таблицы указателей
в модели сохраняют исходные слова.

Вход генерации, свободная запись и геометрия кадра подготовлены.
Модель доказывает связь выбранного шаблона с двумя реально
читаемыми пакетами. Потребитель модели по `#E469` остаётся
неизвестным.

### Планировщик после гиперперехода

Станционный сценарий купил «Гиперслед» и 7 единиц МРП при
подготовленных типе корабля и бюджете. Команда центрирования карты
выбрала `4B38 44FA 00` и записала дальность 3. Настоящий полётный
сканер принял команду прыжка, списались 6 единиц МРП. ПЗУ TR-DOS
5.04T с моделью контроллера прочитало 321 сектор данных для
перезапуска ACTION и его банков.

За 256 полных кадров без ввода планировщик 29 раз дошёл до
`#794B` и трижды до другой ветви выбора по `#7B78`. В первом
входе по `#794B`, на кадре 24, три знаковых слова равны
`1535, 255, −257`. Во всех 29 входах хотя бы один модуль достигал
112, поэтому ни разу не выбирался `ST16k`.

Из того же состояния повторены 64 кадра. С кадра 33 сканер
получал на порту `#BFFE` сброшенный бит 3 и на каждом кадре
вызывал [RequestBoost](../Source/Action/RequestBoost.asm).
Все 64 кадровых обновления совпали с вычитанием трёх знаковых
слов `#E5B3`, `#E5D2`, `#E5ED` из
[24-битного вектора](ActionSubtractWorkVector.md#последовательное-вычитание).
При исходной ориентации первые две компоненты остались
`392960, 65280`, третья изменилась с `−65281` до `−105848`.
Из шести входов по `#794B` ни один не прошёл проверку расстояния.

При повторе кадра 24 из снимка на входе `#794B` с исходными
данными совпали все восемь банков RAM и регистры на выходе.
При замене трёх проверяемых слов на `112, 0, 34` выбор шаблона
по-прежнему не выполняется. При `0, 0, 34` та же цепочка
доходит до `#7859`, выбирает `ST16k` и записывает класс `#12`
и селектор `#00` в свободную исходную запись `#A100`.
Слова указателей обеих страниц сохраняются. Штатный путь
сближения проверен отдельным повтором из состояния после прыжка.
На кадрах 1..26 сканер читает сброшенный бит 1 порта `#BFFE`,
на кадрах 21..26 одновременно сброшен бит 1 порта `#FDFE`.
Они вызывают RequestXPositive и RequestYNegative. После затухания
управления с кадра 59 удерживается форсаж, бит 3 порта `#BFFE`.
На кадре 168 проверяемые слова равны `108, −23, −60`.
Выполняется `#7859`, строка `#784F` создаёт запись `#A100`
с классом `#12` и селектором `#00`. На всех 168 выходах кадра
сохранены SP=`#BFFC` и страница `#10`. Координаты и исполняемый
код в этом повторе не подставляются, прерывания исполняются.
Это результат модели Z80 с ПЗУ и контроллером TR-DOS,
нативная проверка данного маршрута в Unreal не выполнена.

После отпускания форсажа на кадрах 169..176 одновременно нажимаются
RequestXPositive и RequestYPositive, для второго сканер читает
сброшенный бит 2 порта `#FEFE`. На кадре 177 при чтении заголовка
SP равен `#A11A`, полю ViewPosition.X созданной записи. Только
эта запись добавляется в очередь. Узел `#8F00` сохраняет её
преобразованные координаты и дальний селектор `#00`.
Читатель заголовка и копировщик выбирают слово `#9E00..#9E01`
и адрес `#C000` в банке 4. Все 64 байта пакета `KN01pol1`
совпадают с копией в `#9F1C..#9F5B`.

Код вершин `#F8` допускает модель к RenderClippedRecords,
где линейный растр `#8000..#8BFF` остаётся прежним. Этот кадр
подтверждает выбор и чтение ресурса для созданной записи.
[Гиперпереход, кадры и обращения к модели](../Tools/Disasm/Reports/ActionStationTemplateFlightVerification.json)

[Копировщик](ActionObjectStreamStorage.md) также проверен для каждого из
14 слов с подстановкой этого слова в существующую страницу 9E.
Последний пакет занимает 251 байт назначения и заканчивается перед
`#A017`. Сама страница 9F этим способом не читается, её штатный
потребитель остаётся неизвестным.

В [кадровой модели](../Tools/Disasm/Research/CheckActionNonemptyRenderFrame.py)
при той же подстановке указателя все семь пакетов проходят подготовку
проекции и вывод граней. В каждом случае изменяется линейный растр.
На последнем пакете зафиксированы запись ограничителя по `#A016` и его
чтение при обходе граней. В оригинальном файле указатели и пакеты
остаются на своих местах.

## Байтовый индекс авторского ST16k

[Сопоставление блоков станции](ActionSpawnPhysicalRows.md#авторские-блоки-станции-и-слово-80ff) подтвердило IST16=#00 в ST16k. В текущем читателе страницы #9E он выбирает KN01pol1, а соседний индекс #02 выбирает Kd1. Два указателя St16 остаются по #9F00 и #9F02, модель лежит в банке 4 по #E469. Авторское имя не доказывает потребителя этих указателей в исследуемой версии. Байты сохранены.
