# Проверка списка перед переносом элемента

[MoveItemToTailIfListed](../Source/Station/MoveItemToTailIfListed.asm), BE27..BE37, получает кандидата новой обёртки в HL и индекс записи FInterfaceItem в DE. Он сохраняет оба аргумента, получает адрес поля DrawHandler выбранной записи и читает его полный двухбайтовый указатель.

[TestDrawPointer](../Source/Station/TestDrawPointer.asm) проверяет этот указатель в текущем списке. При отсутствии обёртка возвращает исходные HL,DE,BC без записи списка. A=1 и Z=0. Carry определяется последним сравнением указателя, при пустом списке он равен нулю, поскольку GetItemField перед этим вернул F1A0.

При присутствии указателя исходные аргументы уже восстановлены двумя POP. Последовательное исполнение переходит в [MoveItemToTail](../Source/Station/MoveItemToTail.asm) без нового CALL. Порядок этих INCLUDE обязателен. Оба пути используют исходный адрес возврата вызывающего кода.

Два поиска имеют разные ключи. Первый сравнивает полный DrawHandler из записи, второй читает индекс из Handler+1 каждой обёртки списка. При согласованных записях это одна и та же обёртка. При несогласованности исходный код допускает следующее.

- DrawHandler отсутствует, но другая обёртка имеет тот же индекс — список не меняется, второй поиск не выполняется.
- DrawHandler присутствует, но искомого индекса нет — MoveItemToTail добавляет исходного кандидата HL.
- DrawHandler присутствует, а индекс найден у другой обёртки — переносится найденная по индексу обёртка.

Эти случаи не исправлены дополнительной проверкой согласованности. Название обёртки обозначает условие запуска переноса, оно не гарантирует тождество двух поисков при повреждённых данных. Первый байт временно отключённого обработчика может быть RET, оба помощника всё равно читают указатель и операнд индекса, сам обработчик не вызывается.

FListedItemMoveFrame после двух PUSH содержит SavedHL по SP+0, SavedDE по SP+2 и ReturnAddress по SP+4. Все поля двухбайтовые. Перед RET NZ либо последовательным входом переноса первые два слова уже сняты. Постоянной памяти для кадра не выделено.

Физический перенос и его ограничение описаны в [MoveDrawItem](MoveDrawItem.md). При найденном индексе исходный LDIR всегда копирует 128 байтов, включая данные за ограничителем короткого списка. Для большого количества последующих записей это не эквивалентно обычному логическому удалению. Обёртка BE27 не изменяет этот алгоритм.

[CheckItemMoveGuard.py](../Tools/Disasm/Research/CheckItemMoveGuard.py) проверил 770 вызовов с настоящими обоими поисками и переносом. Включены 220 отсутствующих указателей, 210 добавлений при присутствующем указателе без индекса, 130 случаев выбора другой обёртки и 100 случаев за границей фиксированного сдвига. Сравнивались все 4096 байтов хвостового буфера, исходная запись, AF, сохранённые регистры и SP. Проверены активные и временно отключённые обёртки. Сборка, аппаратные IRQ и нативный запуск не выполнялись.
