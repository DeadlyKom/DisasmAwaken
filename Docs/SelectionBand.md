# XOR-подсветка строки, банк 1

[XorSelectionBand](../Source/Map/XorSelectionBand.asm) по `#C908` исполняется в банке 1, содержащем MAP. Станционные обработчики подсветки вызывают этот вход после выбора банка 1. Одинаковый числовой адрес в другом банковом окне не обозначает эту процедуру.

HL задаёт начало bitmap, B число полных байтов 0..31, E рисунок пропуска краёв. Обрабатываются ровно восемь пиксельных строк. Перед началом вычисляется `4*(31-B)` и записывается в операнд JR WidthSkip по `#C91D` банка 1. Это выбирает один из 32 входов развёрнутого ядра, включая отсутствие полных байтов.

## Маски и чередование

Для каждой строки первый RRC E проверяет левый край. При переносе 1 край пропускается, иначе применяется XOR #1F и L увеличивается. Затем инвертируются B полных байтов через CPL. Следующий RRC E проверяет правый край, при 0 применяется XOR #F8 без последующего увеличения L.

Схема исходного E, разряды `7..0`:

```text
R3 L3 R2 L2 R1 L1 R0 L0
```

Значение 1 пропускает соответствующий край, ноль применяет маску. Пары 0..3 обслуживают четыре строки и повторяются для строк 4..7. Поэтому E=#00 даёт оба края, #55 только правый, #AA только левый, #FF ни одного. Произвольные байты задают чередование по строкам. После 16 вращений E возвращает исходное значение, D не меняется.

Полная инверсия выполняется для каждой строки даже при пропуске обоих краёв. Нулевое B отключает только полные байты, частичные края сохраняются. Для обычной горизонтальной полосы сумма X, B и числа применённых краёв не должна превышать 32. Само ядро не отсекает превышение.

Каждый INC L изменяет только младший байт, перенос в H отсутствует. Поэтому для произвольного длинного сочетания столбца и ширины адрес физически оборачивается в пределах 256-байтовой страницы. Модель включает такие случаи отдельно от корректной геометрической полосы.

## Переход строки и выход

После записи L возвращается к сохранённому началу, H увеличивается. Ненулевая фаза H AND 7 означает следующую строку того же знакоместа. При нулевой фазе L увеличивается на 32, при отсутствии переноса H дополнительно уменьшается на 8. Это стандартная раскладка bitmap Spectrum.

Для входного Y=0..184 возвращается HL начала Y+8 с тем же X. При Y=184 это уже адрес атрибутов, но запись туда не выполняется. B=0,C младший адрес начала восьмой обработанной строки. DE, индексные и альтернативные регистры сохраняются, SP восстанавливается. A остаётся от последнего адресного перехода, F=#42 OR его Carry. При заданных координатах Carry=1 только для Y=56,120,184. Итоговый Z не является признаком изменения пикселей, он всегда установлен последним DEC B.

Процедура не переключает банк сама и не запрещает прерывания. Общий операнд WidthSkip делает её нереентерабельной при вложенном вызове с другой шириной. Для обычного IRQ требуется сохранение регистров, страницы и этого операнда.

## Проверка

[CheckSelectionBand](../Tools/Disasm/Research/CheckSelectionBand.py) прошёл [183040 случаев](../Tools/Disasm/Reports/SelectionBandVerification.json). Проверены все 256 рисунков краёв, все B=0..31, каждый Y=0..184 и X=0..31 с граничными комбинациями и четырьмя основными режимами. Независимая побайтовая модель учитывает инверсию и оборачивание младшего адреса. Сравнивается весь экранный буфер, конечные HL,DE,BC, полный AF, сохраняемые регистры и изменяемый JR.

В этой проверке образ MAP загружен в окно модели напрямую. Физическое переключение банков, IRQ и нативное отображение не исполняются. Станционные обёртки проверяются отдельно, результат ядра не подменяет доказательство их выбора строки и смены страницы.
