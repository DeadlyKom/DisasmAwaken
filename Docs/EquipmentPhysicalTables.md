# Физические таблицы оснащения станции

В записи STATIONF (slot 4) между последней строкой рынка и первой парой
клавиатурной таблицы лежат 280 байтов по файловым смещениям 3592..36A9.
При загрузке с 6000 им соответствуют 9592..96A9. Физический шаг всех шести
таблиц равен двум байтам.

| Адреса | Записей | Поля |
|---|---:|---|
| 9592..95D3 | 33 | [Цена](../Source/Station/Data/EquipmentPrices.asm), слово |
| 95D4..95EF | 14 | [Цена второго набора](../Source/Station/Data/SecondEquipmentPrices.asm), слово |
| 95F0..9631 | 33 | [Порог и вес](../Source/Station/Data/EquipmentWeights.asm), два байта |
| 9632..964D | 14 | [Порог и вес второго набора](../Source/Station/Data/SecondWeightFactors.asm), два байта |
| 964E..968F | 33 | [Левая и правая границы](../Source/Station/Data/EquipmentNeighborBounds.asm), два байта |
| 9690..96A9 | 13 | [Границы второго набора](../Source/Station/Data/SecondNeighborBounds.asm), два байта |

[PrintEquipmentRows](../Source/Station/PrintEquipmentRows.asm) читает слово цены
и сравнивает KeySize с первым байтом пары 95F0. При KeySize не меньше порога
второй байт печатается в колонке «Вес», иначе выводится дефис. [Стековые
запросы LANG](MarketAccess.md) используют те же цену и вес. У печатателя
исходный TopRow шестнадцатибитный, у стековых запросов используется младший
байт. Обе адресные формулы могут выйти за физическую границу.

В [хвосте количеств](../Source/Station/Data/PrimaryQuantityTail.asm) по
98AC..98AF находятся три дополнительные строки FF, 00, FF и маркер 80.
Индексы 30..32 используют последние три физические цены и пары порога с
весом. Индекс 33 завершает цикл до чтения цены. Проверка исполнила эти
четыре начальных индекса на исходном тексте и таблицах, сравнила
прочитанные адреса, выходные флаги и bitmap.
[Отчёт](../Tools/Disasm/Reports/EquipmentRowsVerification.json).

[Прямая проверка](EntryThreshold.md) читает первый байт пары в обоих наборах.
[Взвешенная сумма](WeightedLoad.md) берёт второй байт, 30 множителей начиная
с 95F1 и 14 начиная с 9633. Эти пределы циклов не изменяют физическое число
записей. У [проверки 14 строк](ThresholdSets.md) по 9632 идёт последовательный
поток активности с шагом один, а по 98F6 поток порогов с шагом два. Поэтому
проверка читает оба поля первых семи пар 9632. У прямой проверки порядок
ролей иной. [Печататель второго набора](SecondaryEquipmentRows.md) использует
слова Property070 для колонки цены, а байты Property071 для веса.

[Типы кораблей](../Source/Station/Data/EquipmentShipTypeSets.asm) занимают
33 записи с 9400, [типы скимеров](../Source/Station/Data/EquipmentSkimmerTypeSets.asm)
ещё 14 записей с 9484. В каждой строке четыре байта.
Выбранный тип сравнивается со всеми четырьмя. В печатателе значение
типа с bit7=1 отключает проверку маркера, при снятом bit7 отсутствие
совпадения разрешает вывод FB.

[Поиск соседей](ActiveNeighbors.md) интерпретирует левый байт как отрицание
расстояния по модулю 256, правый как прямое расстояние. В исходных данных
каждая непустая группа задаёт один и тот же замкнутый интервал для всех её
элементов. Например, первые две пары 00 01 и FF 00 разрешают каждой строке
найти другую. Индекс 13 второй таблицы вычисляет адрес 96AA и читает два
нуля из уже существующего [клавиатурного якоря](../Source/Station/Data/KeyboardCodes.asm).
Эта пара физически сохранена в клавиатурной таблице. Исходные обработчики
не ограничивают допустимый индекс, наличие игровой команды с этим индексом
само по себе из адресной формулы не следует.

[Проверка](../Tools/Disasm/Research/CheckEquipmentPhysicalTables.py)
исполнила шесть входов LANG на неизменённых байтах таблиц STATIONF,
по 256 индексов на вход. Сверены адреса, регистры, результат чтения, границы
групп и выход за физический диапазон. Область доказательства и 1536 случаев
зафиксированы в [отчёте](../Tools/Disasm/Reports/EquipmentPhysicalTablesVerification.json).
