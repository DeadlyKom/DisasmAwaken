# Курсор, количество и порядок второго списка

[RefreshSecondaryPointOrder](../Source/Map/RefreshSecondaryPointOrder.asm) сначала нормализует существующий курсор по 6309. Читая первые байты с шагом назад 5, он пропускает FF и все байты 7F..FE, пока не встретит 00..7E. Только после завершения поиска найденный адрес ограничивается снизу началом второго списка 993D. Верхнего ограничения нет. Для корректного возврата необходим достижимый подходящий байт, сама проверка нижней границы не защищает память обратного прохода.

Затем второй список читается вперёд. FF пропускается, 00..7E увеличивает количество, 7F..FE завершает подсчёт. Различие 7F связано с INC A перед JP M. [Общий поиск](StoredMapPoints.md) проверяет исходный знак и считает 7F допустимым. [Выбор ресурса](VariantResources.md) заканчивается при любом отрицательном исходном байте, включая FF. Это три разных исходных договора, их не следует объединять в один алгоритм с одинаковыми условиями.

Служебный байт Layout по 9970 обновляется формулой (Layout AND F0) OR N. При фактической ёмкости десять N лежит в 0..10, схема разрядов имеет вид `7..6 — Unknown, 5..4 — код режима, 3..0 — количество`. Код 00 означает Clear, 01 Set, 10 и 11 Xor, назначение битов 7..6 ещё не установлено. Нулевая младшая тетрада означает отсутствие подсчитанных записей. Исходное физическое значение 22 не исправляется на 20 или 00, даже несмотря на исходные пустые записи.

При N>0 по 9971 записываются N плотных смещений 0,5,10,...,5*(N-1). Эти байты не являются фактическими позициями непустых записей при наличии дыр. Например, одна запись в третьем слоте даёт единственное смещение 0, а не 10. Остальные байты массива не очищаются. При N=0 вся прежняя таблица смещений сохраняется.

На ненулевом результате HL у конца записанной части массива, DE=5, BC=00FB, A=5*N, F от последнего ADD A,5. C=FB остаётся от исходного обратного шага FFFB, отдельной загрузки C=5 в коде нет. На нулевом результате HL у записи сразу после ограничителя, AF=0054 от AND A. Альтернативные и индексные пары сохраняются.

[Модель](../Tools/Disasm/Research/CheckSecondaryPointOrder.py) исполняет 10240 вариантов. Проверены все первые байты во всех десяти позициях, несколько положений курсора, все служебные байты и количества 0..10. Для обратного поиска явно подготовлен доступный положительный байт до списка, это ограничение фикстуры не выдаётся за встроенную защиту алгоритма. Проверены адрес курсора, вся таблица смещений, регистры, флаги и стек. Сборка и нативный запуск не выполнялись.

Исходные одиннадцать байтов состояния оформлены экземпляром FStoredMapOrder в [StoredMapOrder](../Source/Station/Data/StoredMapOrder.asm). Сохранены Layout=22 и десять нулевых смещений, начальное несовпадение с пустым списком не исправлялось.

Потребитель Layout и индексов разобран в [MapPointChain](MapPointChain.md). Младшая тетрада задаёт N, биты 5..4 режим Clear/Set/Xor, биты 7..6 остаются Unknown. По N индексам рисуются N−1 соседних отрезков без автоматического замыкания. Обновление порядка сохраняет режим и неизвестные биты.
