# Файлы и секторные размеры в загрузчике станции

При переносе загрузчика из STATIONF по 4000 шесть ключей попадают по 402A..405F. Каждый содержит восемь байтов имени с исходными пробелами и байт типа C. Сохраняются регистр букв в `stscr`, порядок ключей и физические смещения файла. [Записи](../Source/StationBoot/Data/FileKeys.asm), [потребитель](../Source/StationBoot/StartStation.asm).

| Ключ | Назначение при загрузке |
| --- | --- |
| KARTA | Банк 1, C000 |
| MUZ1 | Банк 3, DB00, затем инициализация музыки |
| stscr | Поиск каталожной записи и выбор одного упакованного фона в банке 3 |
| HELP | Банк 7, DB00 |
| D3D | Банк 4, C000 |
| LANG | Банк 6, C000 |

Младшие четыре бита результата `LD A, R` выбирают одну из шестнадцати записей по 4060. Сумма размеров предыдущих фонов задаёт секторное смещение, к нему прибавляется начальное положение файла stscr из каталога. Размер выбранной записи передаётся в B, C получает 05, HL указывает C000. Сумма всех исходных размеров составляет 239 секторов, логическая длина файла в каталоге соответствует только первому потоку. [Размеры](../Source/StationBoot/Data/BackdropSizes.asm), [раскладка фонов](Rendering.md).

В 256 профилях проверены все входные байты R, включая изменение R при выборке самой команды. Каждый фон выбран шестнадцать раз. Исходные команды сформировали правильные трек, сектор и число секторов, после подстановки дискового чтения настоящий распаковщик вернул исходный экран. [Проверка](../Tools/Disasm/Research/CheckStationBackdropSelection.py), [отчёт](../Tools/Disasm/Reports/StationBackdropSelectionVerification.json).
