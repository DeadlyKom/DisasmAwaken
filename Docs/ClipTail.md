# Общие помощники отсечения карты

Фазы изменяемых операндов описаны в [MapRuntimeProfiles](MapRuntimeProfiles.md). Прежние модели исходного профиля не заменяют проверку после D0C3 и переключения условий хвостов DFC3.

Исходные DAB0..DB62 разделены по независимым входам без изменения 179 байтов и 85 инструкций. Это завершает разбор общего хвоста, но [табличные обработчики](MapClipHandlers.md) ещё содержат неразобранный порядок действий и выходов. Четыре [произведения](ClipProducts.md) и четыре [пересечения](ClipIntersections.md) документированы отдельно.

## Добавление углов

| Вход | Пара X,Y |
| --- | --- |
| [AppendTopLeftCorner](../Source/Map/AppendTopLeftCorner.asm), DAB0 | 0,0 |
| [AppendTopRightCorner](../Source/Map/AppendTopRightCorner.asm), DABB | 255,0 |
| [AppendBottomLeftCorner](../Source/Map/AppendBottomLeftCorner.asm), DAC6 | 0,255 |
| [AppendBottomRightCorner](../Source/Map/AppendBottomRightCorner.asm), DAD1 | 255,255 |

Байт MapClipState.CornerBlock по DE3A проверяется целиком. Ноль разрешает запись, любое ненулевое значение даёт ранний выход. Это числовой предикат, отдельные биты не выделены. Ветка запрета возвращает A=CornerBlock и флаги AND A, включая H=1 и Carry=0. HL, DE, BC сохранены. Разрешённая ветка подготавливает DE и переходит в общий писатель без добавочного CALL. Сам байт CornerBlock здесь не меняется. Полный набор его внешних писателей пока не установлен, известный вход D48B записывает 1.

## Вычитания произведений

| Вход | Разность |
| --- | --- |
| [SubtractTopLeftProducts](../Source/Map/SubtractTopLeftProducts.asm), DADC | TopProduct−LeftProduct |
| [SubtractTopRightProducts](../Source/Map/SubtractTopRightProducts.asm), DAF0 | TopProduct−RightProduct |
| [SubtractBottomLeftProducts](../Source/Map/SubtractBottomLeftProducts.asm), DB04 | BottomProduct−LeftProduct |
| [SubtractBottomRightProducts](../Source/Map/SubtractBottomRightProducts.asm), DB18 | BottomProduct−RightProduct |

Сначала вычитаются младшие слова с Carry=0, затем старшие с полученным заёмом. HL возвращает только старшее слово результата, BC старшее слово правого операнда, A и DE сохранены. F содержит флаги последнего SBC. Поэтому Z означает нулевое старшее слово с учётом заёма и не проверяет нулевую 32-битную разность. S — старший бит оборачиваемой разности, Carry — полный беззнаковый заём. При знаковом переполнении один S не доказывает математический порядок операндов.

[SubtractClipPointX](../Source/Map/SubtractClipPointX.asm) по DB2C и [SubtractClipPointY](../Source/Map/SubtractClipPointY.asm) по DB37 возвращают HL=координата второй точки минус координата первой modulo 65536. DE содержит первую координату. A и BC сохранены, F получен из SBC при очищенном входном Carry. Исходные точки не меняются.

## Общая запись двух байтов

[AppendSecondClipPoint](../Source/Map/AppendSecondClipPoint.asm) по DB42 читает только младшие X,Y второй точки. Публичный вход FromDE по DB4A принимает готовые E=X, D=Y. Писатель записывает E по F900|OutputSize, затем D по F900|((OutputSize+1)&255), сохраняет новый OutputSize=(старый+2)&255. Ни ёмкость, ни коды отсечения здесь не проверяются. При нечётном размере FF первый байт попадёт в F9FF, второй в F900, следующая точка начинается с F901.

После записи HL=F900|новый размер, A=новый размер, DE содержит записанную пару, BC сохранён. F соответствует последнему INC L, Carry проходит неизменным от входа. Углы приходят сюда после AND A, поэтому возвращают Carry=0. Альтернативные регистры, IX и IY не меняются у всех помощников этой страницы. Обычный возврат снимает только собственное слово адреса.

## Специальное снятие кадра

[UnwindClipFrame](../Source/Map/UnwindClipFrame.asm) по DB59 требует иной кадр, описанный FClipUnwindFrame. Его нельзя проверять обычным CALL с единственным адресом на вершине стека.

| Смещение от входного SP | Поле | Потребление |
| --- | --- | --- |
| 0 | FirstWord | POP AF, старший байт становится A |
| 2 | SecondWord | POP BC, затем старший байт переносится в C и уменьшается |
| 4 | ThirdWord | POP HL, база возвращаемого значения |
| 6 | ReturnAddress | настоящий адрес последнего RET |

Результат BC=(high(SecondWord)−1)&255, HL=(ThirdWord+BC)&65535, A=high(FirstWord), SP=входной SP+8. Carry установлен, H=N=0, S/Z/PV остаются от DEC счётчика, биты 5 и 3 берутся из A инструкцией SCF. DE сохранён. Эти имена полей нейтральны, они описывают фактическое потребление слов. Их смысл у всех вызывающих табличных обработчиков ещё не установлен.

## Проверка

[CheckClipTail.py](../Tools/Disasm/Research/CheckClipTail.py) исполняет исходные инструкции в модели Z80. [Отчёт](../Tools/Disasm/Reports/ClipTailVerification.json) содержит 1 023 672 случая, в том числе все вторые координаты для семи первых граничных слов, заёмы и переполнения произведений, все байты запрета углов, курсор FF и 65 536 специальных кадров. Проверяются регистры, флаги, SP и выходная страница с защитными байтами. Это проверка самостоятельных помощников, без запуска всей таблицы, прерываний, сборки и нативного эмулятора.

Настроенные углы проверены [отдельной моделью](../Tools/Disasm/Research/CheckConfiguredClipCorners.py), 523264 случая после настоящего D0C3, 256 профилей со всеми значениями каждой границы. При CornerBlock=0 перебраны все курсоры, при запрете все ненулевые блокирующие байты. Проверены точные координаты Min/Max, регистры, флаги, вся страница вывода и соседние байты. Перечисленные выше пары 0/255 описывают исходные LD DE, после установщика они заменяются парами Min/Max из его параметров. Полный декартов перебор четырёх границ не заявляется, сборка, IRQ и нативный запуск не выполнялись.
