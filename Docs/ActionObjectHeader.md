# Чтение слова по указателю OBJECT3D

[ReadObjectHeaderWord](../Source/Action/ReadObjectHeaderWord.asm) находится в общей RAM по AACC..AAE1. Входной A задаёт **байтовое смещение** таблицы страницы 9E00. Код не умножает его на два и не проверяет чётность. Младший байт указателя читается по 9E00+A, старший по 9E00+((A+1) AND FF). INC L оборачивает FF в 00 внутри страницы 9E, это существенная особенность нечётного конечного индекса.

Затем SelectMemoryPage получает полную конфигурацию 14, выбирающую банк 4. По считанному адресу читается слово little-endian. INC HL увеличивает полный адрес, поэтому второй байт слова может перейти через границу окна RAM или из FFFF в 0000. В конце выбирается полная конфигурация 10, банк 0. Исходная конфигурация не восстанавливается.

## Данные и потребитель

Загрузчик [InitializeFlight](../Source/ActionBoot/InitializeFlight.asm) выбирает банк 4 и ключ OBJECT3D по исходному адресу 42FD. Фактический файл — [24_OBJECT3D.C.bin](../Tools/Disasm/Extracted/Active/24_OBJECT3D.C.bin), его длина 10580 байтов. Страница указателей 9E00 находится в общей RAM ACTION. Все 128 исходных чётных смещений дают адреса внутри загруженного OBJECT3D. Полный допустимый диапазон игровых индексов остаётся открытым.

В [RenderSceneFrame](../Source/Action/RenderSceneFrame.asm) вход вызывается с кодом из 9B8E. В исходных записях L содержит BoundMantissa, H содержит ScaleExponent. [PrepareProjectionScale](../Source/Action/PrepareProjectionScale.asm) использует H для изменения трёх относительных переходов и масштабирует L. Полученное слово проверяет близость записи и участвует в [расчёте проецируемой границы](ActionProjectedBounds.md). Физические единицы этой границы пока неизвестны.

## Контракт и проверка

HL содержит считанное слово, DE и BC сохраняются, A=10. F соответствует INC входного A, Carry сохраняется от входа. Поэтому Z означает именно A=FF на входе, а не нулевой результат HL. Альтернативные регистры, IX, IY, I, IM и IFF сохраняются. SP увеличивается на два после внешнего RET, два настоящих вызова SelectMemoryPage требуют максимум четыре дополнительных байта CPU-стека. R получает 27 M1. Таблица и данные объекта не изменяются.

[CheckActionObjectHeader.py](../Tools/Disasm/Research/CheckActionObjectHeader.py) исполняет обе настоящие обёртки выбора страницы. [Отчёт](../Tools/Disasm/Reports/ActionObjectHeaderVerification.json) содержит 81920 сценариев. С исходной страницей указателей проверены все 256 индексов, обе исходные величины Carry и 32 незаблокированные конфигурации 7FFD. Дополнительно все 65536 слов адреса подставлены в таблицу **в модели**, чтобы проверить переносы окна, ROM и чтение временного стека. Это не утверждение о содержимом оригинальной таблицы для всех этих адресов.

Проверяются восемь физических банков, все записи RAM и их кратность, оба OUT 7FFD, регистры, флаги, R и SP. В банк 4 помещены оригинальные байты OBJECT3D, неизвестный хвост заполнен A4. Чтения вне загруженного файла и чтения ROM при искусственных индексах характеризуют модель, они не доказывают реальные игровые данные или допустимость таких индексов. Прерывания, нативный запуск и сборка Codex не выполнялись.

[Физическая таблица 9E00](ActionObjectPointers.md) оформлена 128 экземплярами FObjectDataPointer. Потребитель [CopyObjectData](ActionObjectCopy.md) отдельно проверен для полного конечного потока, эти доказательства не заменяют проверку игрового выбора индекса. Константы страницы указателей, полного paging банка 4 и возврата к ACTION используются совместно.
