# Сброс базовых операндов обновления

[ResetRecordUpdateBases](../Source/Action/ResetRecordUpdateBases.asm) занимает исходные тринадцать байтов F572..F57E ACTION банка 0. Ноль из непосредственного операнда LD HL,0000 записывается в Base0 по E5B0, Base1 по E5CF и Base2 по E5EA. Это реальные операнды LoadBase0..2 в [UpdateRecordComponents](../Source/Action/UpdateRecordComponents.asm).

После сброса формула следующего обновления становится Component-Active. Active0..2, Original0..2 и WarningLatch этим фрагментом не меняются. Входной HL не используется. После RET HL=0000, остальные данные регистров сохранены, R получает пять M1, SP равен входному SP+2. I, IM, IFF и paging сохранены при отсутствии вмешательства IRQ. CPU-стек и порты не записываются, меняются только шесть байтов базовых слов.

[Модель](../Tools/Disasm/Research/CheckActionRecordBaseReset.py) проверила 65536 входных AF и все прежние слова каждого Base, используя три перестановки полного домена. Сопоставлены регистры включая R, все банки RAM и кратность записей. Порядок байтовых обращений модели не доказывает порядок аппаратных шинных циклов LD (nn),HL.

[Отчёт](../Tools/Disasm/Reports/ActionRecordBaseResetVerification.json) ограничен исходным нулевым операндом F573. Его писатель не установлен, изменение этого слова не объявляется невозможным. Полное произведение прежних баз, IRQ, точные T, сборка и нативный запуск не проверялись. Дополнительная память не выделялась.
