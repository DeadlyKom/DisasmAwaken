# Граничный отбор перед подготовкой проекции

[ClipProjectionBounds](../Source/Action/ClipProjectionBounds.asm) занимает E213..E298 ACTION банка 0. Фрагмент использует три слова результата [ComputePatchedVector](ActionPatchedVector.md), входное слово DE, исходный C и показатель h, ранее настроенный [PrepareProjectionScale](ActionScaleHeader.md). Последовательный договор заканчивается перед E299, E40F либо E0E2. RET и записи памяти отсутствуют.

## Таблица нормированных квадратов

[ProjectionSquares.asm](../Source/Action/Data/ProjectionSquares.asm) содержит 256 физических FSymmetricSquareValue размером один байт. Каждый экземпляр Index00..IndexFF имеет поле Value. По исходному байтовому индексу i значение точно равно `floor(min(i,255-i)^2/127)`. Все 256 исходных байтов по 9800..98FF сверены с этой формулой. Таблица симметрична относительно середины между 127 и 128, это не квадрат signed8 с простой нормировкой на 128.

Для параметра C вычисляется его арифметическая половина `s = signed8(C) >> 1`. Индексы вокруг центра k равны `(k-s) mod 256` и `(k-s+C) mod 256`. Разность отсчётов оборачивается в байт, затем умножается на `2^(h-1)` через подготовленный JR и оставшиеся ADD HL,HL. Для X k=36, для Y k=33. Физические смещения и значения таблицы сохранены, дополнительная RAM не выделяется. Другая дисковая копия тех же данных в DATAS не изменяется этим выделением.

## Проверки слов

Сначала вычисляется слово `Z + входной DE` по модулю 65536. Если его старший бит установлен, управление передаётся E0E2. Иначе исходный C сохраняется в IXL и выполняются две проверки каждой оси. Обозначим asr16 арифметический сдвиг слова с сохранением знака, а wrap16 — сохранение младших 16 бит.

Для X промежуточное слово равно `asr16(wrap16(asr16(Z,1)+X),1)`. К нему прибавляется табличный допуск X, слово оборачивается и проверяется его старший бит. Если он сброшен, из результата вычитается исходный X, вновь с оборачиванием и проверкой старшего бита. Любой установленный знаковый бит передаёт управление E0E2.

Для Y применяется та же последовательность, но начальная глубина сдвигается на два: `asr16(wrap16(asr16(Z,2)+Y),1)`. Эта разница между осями существенна. Переполнение отдельно не проверяется, замена выражений неограниченной знаковой арифметикой изменила бы оригинал.

После обеих осей проверяется SkipDetail по 6F59. Значение 00 допускает последовательное продолжение в [PrepareProjectedBounds](ActionProjectedBounds.md) по E299, любой байт 01..FF передаёт управление E40F. Это проверка полного байта на ноль, разряды 7..0 не объявляются независимыми флагами. Полный игровой смысл всех писателей SkipDetail ещё не установлен.

## Регистры и продолжения

При первом отказе HL содержит слово Z+DE, DE и BC сохраняются, A остаётся входным, F соответствует ADC с нулевым входным переносом. После X BC равно X, DE содержит табличный допуск X, A — байтовую разность квадратов X. После Y эти регистры относятся к Y. HL и F соответствуют последней достигнутой сумме ADC либо разности SBC. После последней проверки A=SkipDetail, F соответствует AND A, при допуске это AF=0054.

IXL получает исходный C только после допуска глубины, старший байт IX сохраняется. HL′, DE′, BC′, AF′, IY, SP, I, IM и IFF сохраняются. R зависит от достигнутой границы и числа удвоений, все пути проверены моделью. Записей CPU-стека и портовых операций нет. Предыдущие 66 байтов E1D1..E212 разобраны отдельно как [CheckCloseRecordBounds](ActionCloseBounds.md), включая настоящий условный вызов [DispatchCloseRecord](ActionCloseRecord.md). Доказательства соседних блоков не подменяют весь цикл.

## Проверка

[CheckActionProjectionClip.py](../Tools/Disasm/Research/CheckActionProjectionClip.py) использует независимые формулы табличных допусков, знаковых сдвигов и флагов 16-битовых сравнений. [Отчёт](../Tools/Disasm/Reports/ActionProjectionClipVerification.json) содержит 267008 сценариев и все семь путей. По отдельным сечениям проверены все слова X, Y, Z и исходного DE, все байты C и допустимые показатели 1..6, все значения SkipDetail и граничные оборачивания.

Сравниваются регистры, флаги, R, неизменный SP и вся RAM, отсутствие записей проверяется отдельно. Полный декартов перебор совместных входов, продолжения, весь игровой кадр, прерывания, нативный запуск и сборка Codex не выполняются. Совпадение математической формулы таблицы не доказывает её неизменность во всех фазах игры, локальный договор требует исходных значений по 9800.
