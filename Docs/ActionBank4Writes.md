# Банковые записи кадра в OBJECT3D

В [UpdateFrame](../Source/Action/UpdateFrame.asm) блок A981..AA89 выбирает полную конфигурацию 14, выполняет восемьдесят байтовых записей и выбирает конфигурацию 10. Код этого блока находится в фиксированном банке 2. Верхнее окно во время чтений и записей относится к банку 4, где загрузчик разместил [OBJECT3D](../Tools/Disasm/Extracted/Active/24_OBJECT3D.C.bin), запись диска 24.

Три источника D408, D6CC и D873 читаются из банка 4, каждый байт проходит XOR 60. Первый результат записывается в один адрес, второй в 46 адресов, третий в 33. Маска 60 имеет разряды 7..0 `0 1 1 0 0 0 0 0`, она переключает биты 6 и 5, сохраняя остальные. Значение исходного нуля превращается в 60, это не признак отсутствия данных. [Разметка всех 95 потоков](ActionModelPackets.md) установила, что все восемьдесят целей являются заголовками граней, тип и число вершин сохраняются, а исходные источники переключают числовой материал 2↔4. Все остальные поля и runtime-писатели этим не доказываются.

Три чтения и 80 записей используют имена физических полей
`ActionModels.Rxxxx_nn.Header`. Эти имена привязаны к структурам слота
24. В блоке один восьмиугольник, 46 четырёхугольников и 33 треугольника.
Каждая группа получает полный байт своего опорного заголовка после
XOR с MaterialToggle. Статическая сверка разрешает каждое имя до
исходного операнда и проверяет адрес поля внутри физической записи.

Среди адресов есть C9A2, C9C4, CA24, CA2F и CA96. В ACTION банка 0 по тем же числам находятся инструкции построителя коэффициентов. Это другие физические байты. Их ошибочные старые связи в ModifiedCode удалены, все фактические записи сохранены с банком и дисковым смещением в [ActionBank4DataWrites.json](../Tools/Disasm/Reports/ActionBank4DataWrites.json). Аналогично уточнены остальные совпадения адресов этого доказанного блока. Числовое совпадение с кодом 3DPART также не определяет цель банковой записи.

[CheckActionBank4Writes.py](../Tools/Disasm/Research/CheckActionBank4Writes.py) исполняет настоящий блок и SelectMemoryPage с восемью физическими банками. [Отчёт](../Tools/Disasm/Reports/ActionBank4WritesVerification.json) содержит 3076 сценариев, оригинальный OBJECT3D и все байты каждого источника отдельными сечениями в четырёх незаблокированных конфигурациях банка 0.

Проверяются регистры, оба альтернативных набора, флаги, R, SP, вся RAM, каждая запись и оба OUT 7FFD. Все восемьдесят записей попадают в банк 4, банк 0 сохраняется целиком. Две рамки селектора проверяются с точными остаточными байтами, максимум дополнительного стека четыре байта. Предшествующий вызов AY и следующий вызов панели не исполняются. Доказательство не распространяется на весь UpdateFrame, заблокированное paging, IRQ или нативную игру.
