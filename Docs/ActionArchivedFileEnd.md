# Конец кода ACTION и загрузка хвоста банка 0

В авторском `awk5.trd` запись 68 `SP.C` загружается по `#6000`.
Её логическая длина `#984B` заканчивается сразу после `JP #F71E`
по `#F848`. В последнем секторе остаётся 181 нулевой байт
за логической длиной, `#F84B..#F8FF` в пересчёте на адреса загрузки.

У [диспетчера текущего ACTION](../Source/Action/DispatchObjectState.asm)
до загрузки базы таблицы совпадают 137 байтов архивного диспетчера
после поправки `+#17` в 11 локальных адресах и замены отдельной цели
класса 18 с `#F07E` на `#F075`. В хвосте база таблицы меняется
с `#EF61` на `#EF50`. В текущей версии перед вызовом сохраняется IX,
а адрес продолжения `#F85E` восстанавливает его перед вызовом `#E55C`.
Последняя команда в обоих вариантах возвращает управление к обходу
следующей записи. В текущем ACTION это `JP #F735` по `#F863`.
[Договор диспетчера](ActionObjectStateDispatch.md)

Текущий файл имеет логическую длину `#A000`. Все 1946 байтов
от `#F866` до `#FFFF` лежат внутри этой длины и равны нулю.
В [сквозной модели](../Tools/Disasm/Research/CheckBootBankFileReads.py)
они заменили заполнители `#A5` при вылете и `#5A` при гиперпереходе
в физическом банке 0 уже к входу `#6000`. В обоих случаях исполнен
исходный TR-DOS с моделированием контроллера. До запуска станции
таким же способом подтверждена запись 2852 байтов `#F4DC..#FFFF`
вместо `#5A`. При возврате из полёта этот диапазон уже нулевой к
входу `#6300`, включая часть прежнего кода ACTION.
[Результат загрузок](../Tools/Disasm/Reports/BootBankFileReadsVerification.json)

В 231 сценарии исходного рисователя проверены все обращения к
`#F866..#FFFF` физического банка 0. В 229 сценариях готовились рёбра
граней. Из всего диапазона рисователь использовал только слово
`#FFDE..#FFDF`. Два `PUSH HL` по `#D273` и `#D3AE` дали 6332 записи,
а десять мест чтения дали 6332 чтения. Каждое чтение происходило
после первой записи соответствующего байта. Эти сценарии исполняют
исходные геометрические процедуры с подготовленными объектами и без IRQ.
[Временное слово](../Source/Action/Data/PolygonScratch.asm)
· [Трасса рисователя](../Tools/Disasm/Reports/ActionNonemptyRenderFrameVerification.json)

После исходного гиперперехода проверены 497 полных кадров с IRQ,
включая полёт по клавишам до создания записи ST16k и чтения её модели.
Три повторных входа в планировщик проверяют границу допуска отдельно.
Во всей этой трассе к хвосту банка 0 обращались только те же команды
заливки. Первым действием была запись обоих байтов `#FFDE..#FFDF`.
Суммарно зафиксированы 2420 записей и 2420 чтений слова.
[Трасса полёта и обращения к хвосту](../Tools/Disasm/Reports/ActionStationTemplateFlightVerification.json)

При шумовом переходе ROM читает и записывает байты хвоста через IY.
Отдельно оформлен 41 исходный байт, включая флаг выбора регистра
буквы по `#FDAB`. Для установленных индексных обращений максимальный
адрес `#FF7E`, последний 32-байтовый диапазон в них не входит.
Отдельная сверка всех ветвей IM 1 в двух исходных ROM исключает
этот диапазон и для остальных обращений обработчика при
проверенной рамке шумового HALT.
[Граница адресов при шумовом переходе](ActionNoiseExit.md#граница-адресов-обработчика-im-1)

В дистрибутивном `AWAK_SDC.SCL` все 28 файлов совпадают с записями
3..30 исходного TRD по полным физическим секторам, включая хвосты
AWAKEN, ACTION, STATIONF и [FINALF](FinalCycle.md). В заголовках
совпадают тип, адрес, логическая длина и число секторов. Различаются
три имени.

| Слот TRD | Имя в SCL | Имя в TRD |
| --- | --- | --- |
| 3 | `_awaken_` | ` AWAKEN ` |
| 25 | `PANELN` | `PANEL` |
| 28 | `PANEL` | `PANELFF` |

Проверка также сверяет контрольную сумму SCL. Дисковый ключ `PANEL`
из текущего загрузчика выбирает панель, называвшуюся `PANELN` в SCL.
Вариант `PANELFF` остаётся отдельным файлом.
[Архивная проверка](../Tools/Disasm/Research/CheckActionArchivedFileEnd.py) ·
[Результат](../Tools/Disasm/Reports/ActionArchivedFileEndVerification.json)

Установлены граница последней процедуры, физические байты и их запись
загрузчиком. Отдельные адреса внутри хвоста используются заливкой и
обработчиком прерывания ROM. Назначение соседних диапазонов остаётся
в [реестре неизвестных](UnclassifiedRanges.md).
