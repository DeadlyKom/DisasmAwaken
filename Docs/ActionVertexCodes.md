# Коды положения экранных точек

[ClassifyProjectedVertices](../Source/Action/ClassifyProjectedVertices.asm) занимает DEF3–DFB5 ACTION банка 0. Он заполняет пятый байт записей, созданных [проходом вершин](./ActionObjectVertices.md), и возвращает OR их кодов. [Проверка](../Tools/Disasm/Research/CheckActionVertexCodes.py) исполняет реальные инструкции, включая [общий хвост отказа](../Source/Action/AbortProjectedVertexScan.asm).

## Записи и границы

FRenderProjectedPoint занимает пять байтов. Second по смещению 0 проверяется на диапазон 0..255, First по смещению 2 на диапазон 0..95. ClipCode по смещению 4 получает код, сама перспектива этот байт не меняет. Начало записей 8E00, NextOffset должен равняться 4+5×n, договор покрывает n от 1 до 50. Исходные объекты дают не более 40 точек.

Старший байт Second=80 является полным числовым маркером отказа, проверяется до знака. При нём обход немедленно заканчивается с A=0/F=44. Уже записанные коды предыдущих точек сохраняются, последующие не записываются. Остальные отрицательные Second получают только отрицательную сторону. Для First отрицательная и старшая стороны также взаимоисключающие.

## Схема ClipCode

| Разряд | Значение 1 |
| --- | --- |
| 7 | First не находится на отрицательной стороне |
| 6 | First не находится на стороне >=96 |
| 5 | Second не находится на отрицательной стороне |
| 4 | Second не находится на стороне >=256 |
| 3 | First<0 |
| 2 | First>=96 |
| 1 | Second<0 |
| 0 | Second>=256 |

Младшая тетрада S содержит стороны, полный байт равен ((S XOR 15)<<4) OR S. Это парные признаки, восемь независимых флагов здесь отсутствуют. У внутренней точки S=0, ClipCode=F0. Полный нулевой байт не является обычным результатом классификации и может сохраняться у ещё не достигнутой записи. Девять допустимых кодов F0, E1, D2, B4, 78, A5, 69, 96, 5A.

Общий результат A равен OR всех ClipCode. Единица младшего разряда означает, что хотя бы одна точка снаружи соответствующей границы. Ноль соответствующего старшего разряда означает, что все обработанные точки снаружи этой границы. Результат F0 означает, что все точки внутри. FF сам по себе не доказывает видимость фигуры. Если есть маркер 80xx, вместо этого возвращается нуль.

## Регистры и обход

HL сохраняется через два байта CPU-стека, DE, IX/IY и альтернативные HL/DE/BC сохраняются. B=5×n. C содержит стороны последней точки при завершении либо нуль у точки с маркером. При полном проходе AF содержит общий OR с его логическими флагами, альтернативный A равен 5×n, альтернативный F равен CP B при равных операндах. При маркере AF=0044, альтернативный AF содержит OR предыдущих точек. SP после RET увеличен на два. I, IM, IFF и paging сохраняются, R меняется, портов нет.

Все перемещения выполняются через INC L без переноса в H. Вход с нулевым или несогласованным количеством не входит в доказанный договор, проверка ограничения самим кодом отсутствует.

## Проверка

[Отчёт](../Tools/Disasm/Reports/ActionVertexCodesVerification.json) содержит 525288 сценариев. Все 65536 слов Second проверены с пятью вариантами First, все 65536 слов First с тремя вариантами Second. Списки длиной 1..50 проверены с разными сторонами и поздними маркерами. Общий хвост отказа выполнен 2228 раз.

Сверяются точные регистры и флаги кроме R, вся физическая RAM и кратность записей. Совместная область всех списков не исчерпана. Точное обновление R и время, пустой/некорректный список, IRQ, сборка и нативный игровой вывод этим отчётом не подтверждаются.

[Физические Point00..Point27](ActionProjectedPointsData.md) оформлены существующей FRenderProjectedPoint с сохранением всех начальных дисковых байтов.
