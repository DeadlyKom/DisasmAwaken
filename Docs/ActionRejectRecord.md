# Отказ обновления записи

[RejectRecordUpdate](../Source/Action/RejectRecordUpdate.asm) занимает исходные семь байтов E658..E65E ACTION банка 0. Это часть (0) жёстко упорядоченной пары, после CALL без дополнительного машинного перехода начинается часть (1), [ReleaseStationPartsOrRestoreOffsets](../Source/Action/ReleaseStationPartsOrRestoreOffsets.asm).

Входной SP может указывать на компоненты FActionRecord, поэтому первая инструкция восстанавливает его из существующего операнда ActionOffsetState.SavedCpuSP по E605. Только затем вызывается [MarkRecordForReuse](../Source/Action/MarkRecordForReuse.asm). Эта последовательность не записывает адрес возврата CALL поверх компонент. Действительный CPU SP должен содержать внешний возврат и допускать два временных байта под ним.

Пометка записывает по IX Component0=8000 и ReuseByte=FF, не меняя ClassCode. Общий хвост для класса 12 обнуляет два байта состояния и помечает остальные активные записи класса 12. Сама IX-запись уже помечена и пропускается итератором. Для других классов выполняется [RestoreHalvedOffsets](../Source/Action/RestoreHalvedOffsets.asm), восстанавливающий исходные слова только для класса 14.

Результаты регистров определяет общий хвост. Альтернативные регистры и IX сохранены. После внешнего RET SP равен SavedCpuSP+2. Входной временный SP не восстанавливается. Этот вход добавляет десять M1 к стоимости хвоста, всего 25 для класса 14 и 18 для остальных кодов вне 12. CALL пометки записывает E65F в два байта под восстановленным CPU SP. Проход класса 12 повторно использует эти же байты.

[Модель](../Tools/Disasm/Research/CheckActionRejectRecord.py) использует [общий числовой эталон](../Tools/Disasm/Research/CheckActionClassReuse.py), но начинает с настоящего E658. В 2129 сценариях IX расположен внутри массива физических записей A100..A77F, входной SP указывает на одну из трёх пар компонент. Исполнены реальные пометка IX, хвост очистки, итератор, пометка IY и восстановитель. Сопоставлены все регистры включая R, восемь банков RAM и кратность записей.

[Отчёт](../Tools/Disasm/Reports/ActionRejectRecordVerification.json) отделяет это доказательство от сборки, аппаратных IRQ, точных T, аппаратного порядка шинных циклов стека и нативного запуска. Полное пространство списков не перебиралось.
