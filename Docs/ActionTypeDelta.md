# Табличная поправка состояния

[ApplyIndexedDelta](../Source/Action/ApplyIndexedDelta.asm), банк 5, перенесённые
6380..63B5, выполняет ограниченное знаковое сложение с дополнительной обработкой
бита 5. Вход B задаёт индекс из 16 записей
[TypeDeltas](../Source/Action/Data/TypeDeltas.asm). Записи FIndexedDelta физически
занимают 634B..635A, смещения 0588..0597 записи 17 ACTION.

| Индексы | Исходная поправка signed8 |
|---|---|
| 00 | -6 |
| 01 | 10 |
| 02 | 15 |
| 03 | 18 |
| 04 | 9 |
| 05..07 | -6 |
| 08 | 6 |
| 09..0F | 0 |

Если B не меньше 16, процедура возвращается без изменения состояния.
Иначе она читает поправку и байт режима 9B83. Ненулевой режим добавляет
10 к неотрицательной поправке, отрицательные поправки не меняются.
Табличные нули при включённом режиме становятся 10, пропуском они не являются.

Затем старый байт 9BCD интерпретируется как signed8 и к нему прибавляется
поправка. Сумма ограничивается диапазоном 0..127. Если старый байт,
теперь интерпретированный как unsigned8, был меньше 32, у результата
дополнительно устанавливается бит 5. Например, старый 0 и поправка -6
дают 32, старый FF и та же поправка дают 0. Старый 7F с поправкой 18
даёт 7F. Это числовые свойства оригинала, игровой смысл 9BCD, 9B83
и бита 5 пока не доказан.

Исходная обработка переполнения сохранена буквально. После переполненного
ADD выполняется SUB C, восстанавливающий старый байт и его знак, затем
LD A,7F. Условный JP P проверяет флаги SUB. Поэтому положительное
переполнение остаётся 7F, отрицательное обнуляется. Замены инструкций
высокоуровневой формулой в собираемом исходнике нет.

## Входы и договор

Это отдельный вход CALL 6380 из пути 706C, где B прочитан из записи по DE+7.
Тот же код является продолжением
[Unknown635B](../Source/Action/Unknown635B.asm) после его условного RET Z.
Остальной алгоритм Unknown635B остаётся неизвестным. Его самомодификация
635C и запись ECA9 в данном выделении не переименовываются.
Порядок двух include жёсткий, между ними не добавлена команда перехода.

Недопустимый индекс сохраняет HL, DE и BC, A получает B, F соответствует
CP B,16. При допустимом индексе HL=634B+индекс, DE сохраняется,
B получает прежний байт 9BCD, C и A новый байт. F соответствует сравнению
прежнего unsigned8 со значением 32, а не сравнению результата с нулём.
Альтернативные регистры, IX, IY, I, IM и IFF сохраняются.
SP увеличивается на два после RET. CPU-стек не записывается.
При допустимом индексе выполняется ровно одна запись 9BCD, в том числе
при совпадении старого и нового значения. Иных записей и OUT нет.

Для недопустимого индекса R получает 3 M1. Для допустимого стоимость равна
23 M1, плюс 0 при нулевом режиме, 3 при ненулевом режиме и отрицательной
поправке, 5 при ненулевом режиме и неотрицательной поправке. Дополнительно
прибавляются 2 M1 при знаковом переполнении, 1 M1 при обнулении отрицательного
результата и 2 M1 при установке бита 5. Бит 7 R сохраняется,
младшие семь переполняются по модулю 128.

## Проверка

[Независимая модель](../Tools/Disasm/Research/CheckActionTypeDelta.py) прошла
90112 сценариев. Проверены все 16 допустимых индексов со всеми 256
исходными байтами для нулевого и ненулевого режима, все 256 байтов режима
на пяти границах состояния и все 240 недопустимых индексов по 256 сценариев.
Это не полный перебор совместного пространства. Начальные AF варьируются,
полный перебор всех AF не заявляется.

Эталон использует signed8, clamp и условное OR 32 независимо от потока
инструкций CPU. Проверены все регистры, F, R, SP, каждый байт RAM и ровно
одна запись состояния либо отсутствие записей. IRQ, сборка и нативный
запуск не выполнялись. Соответствие индексов игровым типам остаётся неизвестным.
