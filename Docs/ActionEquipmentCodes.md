# Раскладка оборудования из встроенных заметок

В исходном ACTION последовательность по `#9C10..#9C40` полностью
совпадает с 49 числовыми литералами встроенного описания оборудования.
[Проверка соответствия](../Tools/Disasm/Research/InspectActionEquipmentNotes.py)
читает только числовые литералы из оригинального текста и сверяет их
с физическими байтами TRD. Совпадают все значения и оба маркера 80,
а не только отдельные FF и FE.

Первые четыре байта уже оформлены как
[выбираемая пара](../Source/Action/Data/PreferredByteState.asm) и
[остаток ракет](../Source/Action/Data/MissileStock.asm).
В описании это два топлива «Космонефть» и «Рубин», затем ракеты РЛН-1
и РЛН-2. Доказанный приоритет выбора этих пар сохраняется, единицы
топлива или пределы количества этой связью не вводятся.

Остальные 45 байтов оформлены реальными экземплярами FEquipmentCode
в [корабельном блоке](../Source/Action/Data/ShipEquipment.asm) и
[блоке скиммера](../Source/Action/Data/SkimmerEquipment.asm).
Поле Value является полным байтом, отдельные независимые флаги
ему не назначаются. Имена взяты из совпавшего авторского описания.
Для ряда элементов игровые потребители ещё не установлены.

| Адрес | Поле | Установленный потребитель |
|---|---|---|
| 9C14 | MineMx1 | EjectMine уменьшает полный ненулевой счётчик, включая FF |
| 9C1A | AntiMissilePs1 | CheckRecordEffectThreshold выбирает порог 1E при значении не FF |
| 9C1B | AntiMissilePs2 | Следующая проверка выбирает порог 3C при значении не FF |
| 9C1C | ShieldFortress | UpdateFrame выбирает стоимость события 3 |
| 9C1D | ShieldDefense1 | Следующая проверка выбирает стоимость 2 |
| 9C1E | ShieldDefense2 | Следующая проверка выбирает стоимость 1 |
| 9C24 | TractorBeam | ToggleTractorMode допускается при полном коде не FF |
| 9C25 | Guidance | CycleTargetOverlayMode допускается при полном коде не FF |
| 9C27 | ReturnSystem | RequestStationReturn проверяет полный код не FF и списывает его перед переходом |
| 9C28 | FreeFlight | ToggleFreeFlightMode допускается при полном коде не FF и ограничителе 0088 |
| 9C29 | RefuelSystem | UpdateBodyMotion пропускает ветвь пополнения при FF |
| 9C2A | FuelAdditive | PrepareHyperJumpRelay выполняет 64 внешних цикла разогрева при наличии, 128 при FF |
| 9C2B | TargetIdentity | DrawRadar берёт форму по ClassCode, при FF использует форму 1 |

Для этих читателей проверяется полный байт через INC A.
FF отключает соответствующую возможность, любое другое значение
проходит проверку. FE из авторского начального состояния является
частным случаем такого допуска, равенство только FE в код не добавлялось.
Порядок приоритетов сохранён. Полный эффект и последующее изменение
состояния определяются исходными процедурами, а не названием системы.

`HyperDiablo` по `#9C30` проверяется при [старом сбросе полёта](ControlsResetFlightContext.md).
На станции по тому же смещению находится строка «Анекдот». Полётный
сброс выбирает шаблон векторов по признаку наличия, а его штатный вход
из активной игры пока не установлен.

Имена остальных элементов описывают их положение в авторской раскладке,
они не доказывают реализацию лазеров, посадки на планету, скиммера
или всех перечисленных систем в штатном игровом процессе этой версии.
Реальные потребители и незавершённые возможности перечисляются отдельно
от распознанного формата начальных данных.

[Реестр происхождения имён](../Tools/Disasm/Reports/ActionEquipmentNotesMapping.json)
содержит каждый литерал, комментарий автора и физический адрес.
[Публикация](../Tools/Disasm/Research/ClassifyActionEquipmentData.py)
сверяет поля, символы, размещение и инструкции. Соседние 267 байтов
за маркером скиммера остаются неразмеченными. Сборка и нативный запуск
этим результатом не подтверждаются.

Команды [силового луча](ActionTractorModeCommand.md) и [режима отображения целей](ActionOverlayModeCommand.md) проверены на всех полных кодах соответствующего оборудования. Эти проверки подтверждают допуск команд, полный игровой алгоритм каждого оборудования этим не устанавливается.

[Команда свободного полёта](ActionFreeFlightCommand.md) также проверяет полный код FreeFlight.Value, FF даёт отказ после установки задержки. Это допуск команды и проверенная запись опкода, весь последующий игровой полёт этим не подтверждается.

[Система возврата](ActionStationReturnCommand.md) списывается перед сохранением состояния, а [запас мин](ActionEjectCommands.md) расходуется до попытки размещения. Проверки различают отсутствие оборудования FF и нулевой запас, для мин FF является ненулевым числом и уменьшается.
