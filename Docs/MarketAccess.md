# Стековые запросы полей и маркера рынка

Исследуется исходная запись LANG (slot 5). Адреса ниже относятся к её окну
#C000. Регистр DE возвращает результат выражения языка. На вершине CPU-стека
лежит слово индекса, под ним адрес возврата. Это договор хвостового диспетчера,
а не обычного CALL: ParseFieldSuffix помещает индекс через PUSH HL перед
передачей управления DispatchToken, заканчивающемуся JP (HL).

| Исходник | Вход | Операция |
|---|---|---|
| [ReadStridedWord](../Source/Text/ReadStridedWord.asm) | #C4D7 | слово по #9592 + 2 * индекс |
| [ReadStridedByte](../Source/Text/ReadStridedByte.asm) | #C4E3 | байт по #95F1 + 2 * индекс |
| [GetMarketPrice](../Source/Text/GetMarketPrice.asm) | #C5C7 | байт Price по #9556 + 2 * индекс |
| [IsMarketMarkClear](../Source/Text/IsMarketMarkClear.asm) | #C5CD | 1, если bit7 по #9555 + 2 * индекс снят, иначе 0 |

Два отдельных входа ReadAtBase (#C4DA и #C4E6) принимают базу в DE,
пропуская её штатную загрузку. Старший байт индекса всегда отбрасывается.
Чтение слова возвращает младший байт в E и старший в D, HL указывает на
старший байт. Чтение байта возвращает нулевой D и HL на прочитанном байте.
Адресная арифметика выполняется по модулю 65536. Итоговый SP увеличен на
четыре байта, два для индекса и два для возврата. BC, альтернативный набор,
IX, IY, I и IFF сохраняются, память не меняется.

## Флаги

У трёх чтений A сохранён. S, Z и P/V сохранены из входного F. H и C получены
от ADD HL,DE для 2 * индекс + база, X/Y взяты из старшего байта суммы, N снят.
Последующие LD, INC HL и RET флаги не изменяют.

У запроса маркера A равен E. При снятом bit7 F=0 после INC A из нуля.
При установленном bit7 F=#90 OR (прочитанный байт AND #28). Нулевой флаг
снят в обоих случаях, поэтому Z не кодирует возвращаемую истину.

## Физические данные и ограничения

Price и StockAndMark принадлежат [FMarketRow](../Includes/Structs/Include.inc),
физические записи описаны в [MarketRows](../Source/Station/Data/MarketRows.asm).
Для рынка предусмотрены индексы 0..29. Исходный код не проверяет эту границу,
по индексам 30..255 читает последующую память. Тест таких индексов проверяет
именно отсутствие ограничения, а не подтверждает их допустимость в игре.
Смысл таблиц #9592 и #95F1 и игровое название старшего маркера остаются
неустановленными. [Генератор рынка](MarketGeneration.md) заменяет либо
сохраняет bit7 в зависимости от операнда MarkMode.

## Проверка

[CheckMarketAccess.py](../Tools/Disasm/Research/CheckMarketAccess.py) исполняет
оригинальные байты трёх штатных входов чтения и двух общих хвостов, каждый
для 256 индексов и 256 входных F (всего 327680 случаев). Ещё 65536 случаев
проверяют все индексы и значения StockAndMark для запроса маркера.
Проверяются возвращаемые регистры, флаги, положение SP и сохранность BC,
альтернативных регистров и IX/IY. Отдельные базы хвостов проверяют перенос
между страницами, штатные базы сами по себе такого переноса не дают.
Старший байт стекового индекса преднамеренно ненулевой в части случаев.

[Отчёт](../Tools/Disasm/Reports/MarketAccessVerification.json) подтверждает
модель исходных обработчиков. Прерывания не исполнялись, сборка и нативный
запуск этой проверкой не выполняются. Общий разбор языка изложен в
[ScriptLanguage](ScriptLanguage.md).

Дополнительные входы [Property070](../Source/Text/Property070.asm) и [Property071](../Source/Text/Property071.asm) выбирают базы #95D4 для слова и #9633 для байта. Их полные регистровые договоры совпадают с соответствующими общими хвостами. В CheckMarketAccess для каждого добавлены 65536 случаев, все байты индекса и входного F. Игровая роль полей пока не доказана.
