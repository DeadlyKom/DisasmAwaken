# Физические суффиксы выделенных секторов

[Проверка происхождения](../Tools/Disasm/Research/InspectAllocatedSectorSuffixes.py), [первичный реестр](../Tools/Disasm/Reports/AllocatedSectorSuffixInspection.json), [текущие диапазоны](../Tools/Disasm/Research/AllocatedSectorSuffixResources.py).

16 диапазонов, 2558 байтов, находятся после объявленной длины соответствующих небейсиковых файлов и внутри выделенных им секторов. Это положительно установленная физическая роль. Содержимое всех байтов, включая повторяющийся текст и нули, сохраняется буквально. Термины «неиспользуемый», «мусор», «свободная память» к ним не применяются. Чтение TR-DOS полными секторами, прямое секторное чтение и последующие обращения игры этой классификацией не исключаются.

BASIC-файл AWAKEN исключён. За его объявленной длиной находятся подтверждённые машинные модули вступления, поэтому общий вывод о роли всех байтов после поля Length был бы ошибкой. Длина каталога и доказанный исполняемый состав не смешиваются.

В первом секторе AWAKEN отдельно проверены 132 байта после копируемой
части. В штатной команде RUN они вытесняются из буфера к входу USR.
[Границы первого сектора](BasicProgram.md)

У OBJECT3D и FINALF прежний неизвестный диапазон пересекал логическую границу. Неизвестная часть внутри длины остаётся отдельной и не классифицируется по роли последующего суффикса. Все физические смещения и порядок включений сохранены.

## Повторы внутри файлов

Восемь суффиксов целиком повторяют более ранние участки тех же файлов.
Все 1061 байт совпадают побайтово. Правая граница каждого диапазона
в таблице исключена.

| Файл | Суффикс | Совпадающий участок | Смещение копии |
| --- | --- | --- | --- |
| LANG | `#0F18..#1000` | `#0D18..#0E00` | `#0200` |
| D3D | `#3E6A..#3F00` | `#3C6A..#3D00` | `#0200` |
| HELP | `#1721..#1800` | `#1521..#1600` | `#0200` |
| VOXAL | `#0EC8..#0F00` | `#0CC8..#0D00` | `#0200` |
| CONTROL0 | `#1ADE..#1B00` | `#18DE..#1900` | `#0200` |
| CONTROL | `#194A..#1A00` | `#174A..#1800` | `#0200` |
| OBJECT3D | `#2954..#2A00` | `#2754..#2800` | `#0200` |
| scene1po | `#48F4..#4900` | `#47F4..#4800` | `#0100` |

Копия LANG содержит продолжение условий покупки и начало продажи
оснащения. В ней нет `#5F`, поэтому поиск заголовка из `ActivateResourceRecord`
не может найти разделитель внутри этих 232 байтов. Исходный поиск
не ограничен концом суффикса. Способ, которым копии появились на диске,
и другие обращения к их байтам остаются открытыми.
[Торговый сценарий](../Source/Text/Data/MarketScript.asm) ·
[Поиск заголовка](../Source/Text/ActivateResourceRecord.asm)

Пять вызовов `StartStation` с `A=#03` и `C=#0E` проверены по два раза
с ROM 5.04T. Модель входит после выбора соответствующего банка и исполняет
оригинальную загрузку через модель контроллера. Вместе с логическими данными
в RAM попадают суффиксы MUZ1, HELP, D3D и LANG. В частности, 3864 логических
байта LANG и 232 байта его суффикса занимают `#C000..#CFFF`, байт по `#D000`
сохраняется. Отдельный тест индексатора HELP подтвердил чтение из хвоста
при подготовленном селекторе 8 и отсутствие указателей в хвост при
штатных индексах 0..7. [Индексатор HELP](HelpLineIndex.md) ·
[Загрузчик](../Source/StationBoot/StartStation.asm) ·
[Сценарий](../Tools/Disasm/Research/CheckBootBankFileReads.py) ·
[Результат](../Tools/Disasm/Reports/BootBankFileReadsVerification.json)

Шесть банковых вызовов ACTION проверены тем же способом. В банке 1
CONTROL0 сначала занимает `#C000..#DAFF`, включая свой 34-байтовый
суффикс. Сразу после него CONTROL начинает загрузку по `#DADE`.
Два последовательных исходных вызова подтверждают замену этих 34 байтов
началом CONTROL и сохранение всех предшествующих байтов CONTROL0.
[Загрузчик полёта](../Source/ActionBoot/InitializeFlight.asm)

VerifySources проверяет каждый текущий ресурс по извлечённым физическим секторам, его SourceMap, начало после объявленной длины и полный набор байтов. Публикация предварительно сверяет оригинальный TRD, длины и SHA256. Сборка и нативный запуск не выполнялись. Эта физическая классификация не является полным смысловым разбором возможных игровых потребителей.
