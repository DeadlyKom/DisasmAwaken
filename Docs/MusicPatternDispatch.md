# Маршрутизация исходных музыкальных команд

Начальные декодеры находятся в [DecodePatternA](../Source/Music/DecodePatternA.asm), [DecodePatternB](../Source/Music/DecodePatternB.asm) и [DecodePatternC](../Source/Music/DecodePatternC.asm). Здесь описана отдельная проверка маршрутизации до обработчика. Полные алгоритмы, внутренние входы, эффекты и контракты приведены в [MusicPattern](MusicPattern.md).

DE указывает на командный байт. Вход устанавливает BC=1020, читает байт и увеличивает полный DE. Цепочка сложений с Carry выбирает диапазон, а A на входе выбранного обработчика содержит исходный код минус нижнюю границу диапазона. Входной F не влияет на выбор, все проверяемые флаги создаются сложениями.

| Коды | A и C | B |
| --- | --- | --- |
| F0..FF | Совместная команда сэмпла и орнамента | То же |
| D0..EF | Выбор сэмпла либо завершение строки | То же |
| C0..CF | Громкость либо выключение ноты | То же |
| B0..BF | Огибающая либо счётчик строки | То же |
| 50..AF | Нота | То же |
| 40..4F | Орнамент | То же |
| 20..3F | Попадает в объединённую ветвь 10..3F | Отдельная команда базового шума |
| 10..1F | Совместная команда огибающей и сэмпла | То же |
| 00..0F | Чтение слова адреса и помещение его в стек | То же |

Различие 20..3F подтверждено собственными исходными байтами каждого канала. Оно не исправляется по описанию другого проигрывателя или по предполагаемому стандарту формата.

## Отложенные адреса

Для младших кодов декодер не вызывает обработчик немедленно. Он читает слово, помещает его в стек через PUSH HL и продолжает читать команды строки. Последующий RET снимает последний такой адрес. Сами обработчики в проверке маршрутизации не исполняются, корректность произвольного набора этих кодов не предполагается.

Адрес слова считается с оборачиванием младшего байта внутри заданной страницы:

`WordAddress = Page * 256 + ((E0 + 2 * Code + AnchorLow) & FF)`.

Для A Page=DD и AnchorLow=DE, для B Page=DD и AnchorLow=FE, для C Page=DE и AnchorLow=1E. Это не сплошные таблицы шестнадцати настоящих указателей. Области перемежаются с исполняемым кодом. Фактически считанные слова для семи выделенных кодов:

| Код | A | B | C |
| --- | --- | --- | --- |
| 01 | E60C | E65D | E6AE |
| 02 | E623 | E674 | E6C9 |
| 03 | E647 | E698 | E6EE |
| 04 | E652 | E6A3 | E6F4 |
| 05 | DDCA | DDEA | DE0A |
| 08 | DB8C | DB8C | DB8C |
| 09 | E6FA | E6FA | E6FA |

DB8C является разобранным [ReadEnvelopeSlide](../Source/Music/ReadEnvelopeSlide.asm), E6AE — [SetToneSlideC](../Source/Music/SetToneSlideC.asm), DDCA и DE0A — чтение длительностей A и C. Назначения остальных входов требуют собственного разбора.

Для кодов 00, 06, 07 и 0A..0F адресное вычисление тоже выполняется, но получаемые слова захватывают соседние инструкции и другие данные. Например, код 00 даёт цели 000D для A, C9DE для B, E136 для C. Применимость таких слов как обработчиков не доказана, модель не передаёт им управление. Отдельный вызывающий путь A распознаёт нулевой маркер конца паттерна до обычного декодера.

В C помещение адреса в стек дополнительно копирует текущую ноту E2B9 в операнд E6EC. A и B этой записи на данном пути не делают. Указатели сэмплов и орнаментов в последующих обработчиках требуют исходной страницы H=DB, поэтому эта локальная проверка не объявляет допустимой произвольную перестановку команд после отложенного адреса.

## Проверка

[CheckMusicPatternDispatch.py](../Tools/Disasm/Research/CheckMusicPatternDispatch.py) проверяет все 256 команд при всех 256 входных F в каждом из трёх декодеров, всего 196608 случаев. Сверяются граница выбранной ветви, A, F, BC=1020, продвижение DE, сохранность остальных регистров и стека. Для младших кодов проверяются физическое слово на стеке и дополнительная запись C. [Отчёт](../Tools/Disasm/Reports/MusicPatternDispatchVerification.json).

Проверка останавливается перед телами обработчиков либо после помещения отложенного адреса. Она не доказывает полный разбор строки, правильность эффектов, синтез, IRQ или нативное аудио.
