# Рисователь ребра и проверка bitmap

[RasterizePreviewEdge.asm](../Source/D3D/RasterizePreviewEdge.asm), банк 4, #DE1C..#DF45, оформлен с физическими параметрами и восемью писателями изменяемых opcode. Независимая пиксельная и регистровая модель проверена для экранного профиля и трёх согласованных режимов.

## Физические входы

| Адрес | Содержимое |
| --- | --- |
| #C24B..#C24C | Начало, младший байт колонка, старший строка |
| #C24D..#C24E | Конец в том же формате |
| #C26F | Байт пиксельной операции |
| #C270 | Байт условного перехода на границе экранного байта |
| #DE34 | Младший адрес начала таблицы масок |
| #C900..#CBFF | Две страницы строк и страница колонок из BuildSpriteLineTable |
| #CDB0..#CDB7 | Маски одного пикселя #80,#40,...,#01 |
| #CDB8..#CDBF | Инверсии этих масок |

Старший байт координатного слова используется как индекс таблиц строк, младший как индекс колонки и пиксельного бита. Это физическое соглашение рисователя. Его нельзя смешивать с названиями логических осей матрицы.

Три подтверждённые пары режимов готовятся проходами граней:

| Режим | #C26F | #C270 | #DE34 | Результат |
| --- | --- | --- | --- | --- |
| XOR | #A9, XOR C | #38, JR C | #B0 | Переключение пикселя |
| OR | #B1, OR C | #38, JR C | #B0 | Установка пикселя |
| AND | #A1, AND C | #30, JR NC | #B8 | Сброс пикселя |

Это байты инструкций, не независимые биты флагового байта. Для AND нужны одновременно инверсная маска и противоположное условие перехода. Замена только пиксельного opcode не даёт правильного режима.

## Нормализация и точки

Полное совпадение входных координат проверяется вычитанием слов, такой отрезок не рисуется. При разных строках начало выбирается по меньшему байту строки. При одинаковых строках исходный порядок концов сохраняется.

Пусть dy — разность строк после этой перестановки, dx модуль разности колонок, s направление колонки +1 либо −1. M=max(dx,dy), N=min(dx,dy), e0=floor(M/2). Число шагов малой оси после t шагов равно:

u(t)=floor((t*N+M−1−e0)/M).

При dx>=dy рисуются точки (r0+u(t), c0+s*t), иначе (r0+t, c0+s*u(t)). Индексы t равны 0..M−1. Начальная точка входит, конечная исключена. Поэтому горизонтальный отрезок при перестановке одинаковых строк может исключить другой крайний пиксель.

Эта формула независима от последовательности JR, EX AF и DJNZ исходника. Она используется в [пиксельной модели](../Tools/Disasm/Research/PreviewEdgeRasterOracle.py).

## Четыре ветви и самомодификация

Исходник выбирает пологую либо крутую ветвь и направление колонки. Каждая ветвь записывает ровно два байта инструкций:

| Ветвь | Пиксельная операция | Условие перехода границы байта |
| --- | --- | --- |
| Влево, пологая | #DE66 | #DE69 |
| Влево, крутая | #DEA5 | #DEBF |
| Вправо, пологая | #DEE2 | #DEE5 |
| Вправо, крутая | #DF21 | #DF3B |

Исходная пиксельная инструкция равна NOP. До нормального исполнения её подготавливает сама выбранная ветвь. Наблюдение отдельных кадров не покрывает все эти opcode, дополнительная модель принудительно проверяет все четыре направления и три режима.

В пологих ветвях несколько пикселей одного байта сначала накапливаются в A. При смене байта или строки он записывается, затем читается следующий байт. Возможны записи неизменившегося соседнего байта, их нельзя объявлять лишними и удалять.

В крутых ветвях текущий байт записывается на каждом шаге строки. Маска меняется при переносе накопителя ошибки по малой оси. Переход строки выполняется в формате ULA с отдельными обработками границ восьми строк и частей экрана.

## Таблицы и начало окна

[BuildSpriteLineTable](SpriteLineTable.md) действительно вызывается в проверке, его вызов не подменяется. Для относительного r берётся расширенный ULA-адрес строки y0+r, для относительного c байтовая колонка равна floor(x0/8)+floor(c/8).

Маска зависит только от c AND 7. Поэтому не выровненное x0 округляется к началу байтовой колонки, остаток x0 AND 7 дополнительно в маску не включается. Проверены начала (0,0), (19,25), (57,40), (96,88), во втором случае фактическая колонка начала равна 24.

Текущий доказанный профиль требует, чтобы все точки и исключённый конец попадали в bitmap 256 на 192 после добавления начала окна. Сам рисователь отсечение не делает. Произвольные внеэкранные таблицы или неподготовленные пары opcode этой проверкой не объявляются безопасными.

## Выходные регистры

Для разных концов HL содержит экранный адрес исключённого конца, D=M, E=N, B=0. C содержит маску пикселя конца либо её инверсию для AND. IX/IY и альтернативные HL/DE/BC сохраняются, CPU-SP после RET равен входному+2.

В пологой ветви A на выходе равен текущему байту bitmap по HL. Его F принадлежит последнему повороту маски, смене байтовой колонки либо продвижению строки, в зависимости от последнего переноса ошибки.

В крутой ветви A/F относятся к вычислению последнего перехода строки. Они не возвращают пиксельное значение. Альтернативный A' во всех четырёх ветвях равен e0, F' относится к последнему вычитанию ошибки, её восстановлению либо повороту маски и смене колонки.

Точные формулы этих случаев находятся в функциях registers, row_context, column_context независимой модели. Проверка сравнивает сами A/F и A'/F', а не только эти описания.

Для совпавших концов HL=0, DE равен входному слову конца, BC, A, IX/IY и альтернативный набор сохраняются, F=#42. Bitmap и opcode не записываются. Вызывающий код не должен считать этот ранний выход сохранением HL.

## Результат проверки и остаток

[CheckPreviewEdgeRaster.py](../Tools/Disasm/Research/CheckPreviewEdgeRaster.py) прошёл 30464 случая. Сравнивается весь bitmap 6144 байта с независимым множеством точек и пиксельными операциями. Проверены все пары длин осей 0..63 в обоих направлениях, каждая начальная экранная строка, четыре исходных рисунка bitmap, случайные концы, смещённые начала и все три режима.

Сверены конечные HL/DE/BC, точные основные и альтернативные AF, сохраняемые регистры, CPU-возврат, два изменяемых opcode и допустимые адреса экранных записей. [Отчёт](../Tools/Disasm/Reports/PreviewEdgeRasterVerification.json) явно ограничен экранным профилем.

Четыре байта концов, пара режима и обе таблицы масок оформлены физически, ASM использует их имена, восемь писателей opcode зарегистрированы. Полные проходы граней, полигональная заливка, отсечение, весь кадр, IRQ, сборка и нативная игра остаются открытыми.

Физические параметры оформлены как [PreviewEdgeEndpoints](../Source/D3D/Data/PreviewEdgeEndpoints.asm), [PreviewEdgeMode](../Source/D3D/Data/PreviewEdgeMode.asm) и [PreviewPixelMasks](../Source/D3D/Data/PreviewPixelMasks.asm). Два экземпляра реальных структур сохраняют четыре и два исходных байта, массивы масок ещё шестнадцать. Начальная пара режима #0000 сохранена из образа, она не заменяется рабочим режимом до фактической подготовки вызывающим кодом.
