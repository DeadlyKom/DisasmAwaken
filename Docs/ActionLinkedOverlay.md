# Проверка и вывод связанных векторов

[CheckAndToggleLinkedOverlay](../Source/Action/CheckAndToggleLinkedOverlay.asm) занимает E804..E862 ACTION банка 0. Он использует три физические слова 1A/1C/1E текущей записи и выбранный контекст [LoadLinkedRecordVectors](../Source/Action/LoadLinkedRecordVectors.asm). Глобальные игровые единицы этих полей пока не установлены, поэтому имена Unknown сохранены.

## Ранние отказы и обратная связь

Полный Unknown1B=80 возвращает Carry=1 до каких-либо обменов. Иначе BC/HL/DE загружаются словами 1A/1C/1E, EXX переносит их в альтернативный набор. Отказ чтения выбранного контекста возвращает Carry=1, этот EXX не отменяется. Для обычной связи RecordPointer должен быть подготовлен вызывающим. Особая связь 1A использует свой фиксированный контекст.

При успешном чтении R сравнивается с изменяемым операндом LinkRLimit по E823. Если R не меньше порога, бит 0 LinkFlags выбранной записи устанавливается, её LinkedIndex получает результат преобразования текущего IX в индекс. Это обратная ссылка на текущую запись. Записи выполняются до последующих проверок и при их отказе не откатываются. Поле 09 набора параметров пишет именно этот порог, иных назначений из этого не следует.

## Знаки и переполнения

После очередного EXX `AND D` проверяет совместный старший бит двух глубин. Если обе отрицательны, функция сразу возвращает Carry=0. Один отрицательный конец эту проверку проходит. Затем последовательно проверяются три разности signed16:

1. Output0 минус BC.
2. Output2 минус DE.
3. HL минус Output1.

Каждый SBC вычисляется без входного переноса. HL и DE восстанавливаются, SCF устанавливает Carry, не уничтожая P/V. Условный RET PE использует именно signed overflow SBC. При первом переполнении оставшиеся разности не вычисляются.

## Вывод и результат

После всех допусков [ToggleTargetOverlay](../Source/Action/ToggleTargetOverlay.asm) исполняет обе проекции, классификацию, отсечение и XOR-сегмент. IX сохраняется вокруг вызова. Завершающий AND A очищает Carry независимо от результата экранного вывода. Поэтому Carry=0 может означать совместно отрицательные глубины, ранний экранный отказ либо фактическое рисование. Carry сам по себе не доказывает изменение пикселя.

I, IM, IFF, paging и IX сохраняются. Остальные рабочие и альтернативные пары определяются достигнутой ветвью. Внешний RET увеличивает SP на два. Все исходные стековые записи и операнды дочерних процедур входят в модель.

## Доказательство

[Числовая модель](../Tools/Disasm/Research/ReferenceActionLinkedOverlay.py) сохраняет реальные побочные эффекты детей. [Проверка](../Tools/Disasm/Research/CheckActionLinkedOverlay.py) исполняет настоящий E804 до внешнего RET. Набор из 462848 сценариев включает все 256×256 пар R/порог, все значения каждого из шести слов на срезах и смешанные случаи с особой связью, отказом и ссылкой на себя. Сравниваются точные регистры, восемь банков RAM и кратность записей. На путях без растеризатора R также проверен точно. [Результат](../Tools/Disasm/Reports/ActionLinkedOverlayVerification.json).

Полное произведение входов не исчерпано. R и точные T растеризатора, аппаратные IRQ, сборка и нативная игра не проверялись.
