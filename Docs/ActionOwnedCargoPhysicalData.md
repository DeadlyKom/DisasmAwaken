# Физические пары груза ACTION

[OwnedCargoRows](../Source/Action/Data/OwnedCargoRows.asm) содержит тридцать физических экземпляров существующей структуры FOwnedCargoRow. Диапазон 9BD4..9C0F занимает 60 байтов, каждая запись содержит QuantityAndMark и Price. Байты не объединяются в слово и не переупорядочиваются.

Все 60 исходных байтов точно совпадают с тридцатью парами литералов TWRI в [авторских заметках ACTION](ActionEmbeddedNotes.md), где явно написано «КОЛ/ЦЕНА ЗА КОТОРУЮ КУПИЛ». [Проверка](../Tools/Disasm/Research/ActionOwnedCargoPhysicalData.py) извлекает только эти числовые литералы и подписи, не выполняя содержащий их текст. [Реестр](../Tools/Disasm/Reports/ActionCargoNotesMapping.json) сохраняет исходное авторское имя каждого товара, значения полей и контрольную сумму. Начальные количества дают сумму 25, это наблюдение над оригиналом, не объявление рабочего состояния игры после загрузки.

Структура уже используется [станционными парами груза](../Source/Station/Data/OwnedCargoRows.asm). Относительное смещение равно 23 как для 9852 относительно сохраняемой базы 983B, так и для 9BD4 относительно базы 9BBD. [HandleItem08](../Source/Station/HandleItem08.asm) переносит 512 байтов станции в 4000..41FF, а [LoadAction.AfterLoad](../Source/StationExit/LoadAction.asm) после успешного возврата TR-DOS переносит их в 9BBD..9DBC. Это условный путь передачи состояния из исходного кода, не доказательство нативной загрузки текущего среза.

## Различные читатели полей

Станционный читатель разделяет QuantityAndMark на биты 6..0 количества и бит 7 специальной пометки вывода, общий игровой смысл этой пометки остаётся неизвестным. Схема байта `m q6 q5 q4 q3 q2 q1 q0`, маска количества 7F, маска пометки 80. Нулевое значение задаёт нулевое количество без пометки. Price является полным числовым байтом цены, не набором флагов.

Клавиатурная ветвь выброса по 7594 ищет первый ненулевой **байт**, начиная с 9BD4, всего 30 байтов. Она не делает шаг по двум полям и не просматривает все 60 байтов. Поэтому область поиска охватывает только Row00..Row14, включая их Price. Нечётное смещение с ненулевой ценой также может быть выбрано. Найденный байт обнуляется целиком и передаётся в Unknown11 создаваемого объекта, его смещение относительно 9BD4 передаётся как вид. Семь младших битов количества здесь не выделяются. Этот исходный алгоритм не заменён корректирующим обходом тридцати записей.

[10664 сценария команд выброса](../Tools/Disasm/Reports/ActionEjectCommandsVerification.json) включают все тридцать возможных байтовых позиций, то есть оба поля первых пятнадцати записей. Они проверяют реальный подготовленный вход [SpawnPrepared](ActionPreparedClass19Spawn.md), поиск места и очередь. Ветка 7594 не уменьшает Current общего счётчика тоннажа по 9BD2. Ненулевой выбранный байт обнуляется до попытки размещения, отказ размещения его не восстанавливает. Сообщение о выбросе ставится независимо от результата создания объекта.

Имена товаров в реестре происходят из совпавших исходных литералов. Конкретное соответствие каждого индекса объекта игровой товарной строке и оставшиеся потребители поля Price исследуются отдельно. Ассемблер и нативная игра не запускались. Исследовательский Python для обычной сборки не требуется.
