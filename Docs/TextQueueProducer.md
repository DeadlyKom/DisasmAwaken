# Производитель очереди чисел и строк Controls

Очередь расположена в банке 1 вместе с CONTROL0 и CONTROL.
[QueueNumber](../Source/Controls/QueueNumber.asm) по EC56 формирует
числовую запись из A, после чего без CALL продолжает исполнение в
[QueueTextItem](../Source/Controls/QueueTextItem.asm) по EC59.
Порядок включения этих двух исходников жёсткий, дополнительный JP
для обозначения продолжения не добавлен.

## Физическая запись

[TextQueue.asm](../Source/Controls/Data/TextQueue.asm) содержит 16
физических FTextQueueItem Slot00..Slot0F по EC80..EC9F и отдельный
двухбайтовый End по ECA0..ECA1. Размер элемента равен двум байтам:

| Поле | Смещение | Содержание |
| --- | ---: | --- |
| HighKind | 0 | 00 конец кольца, 01 свободно, 02 байтовое число, 03..FF старший байт адреса строки |
| LowValue | 1 | число при HighKind=02, младший байт адреса при HighKind>=03 |

HighKind является числовым кодом либо старшим байтом адреса, независимых
флаговых битов здесь нет. Указатель хранится старшим байтом первым.
Оформление одним DW изменило бы физический порядок и поведение, поэтому
в структуре объявлены два DB. Исходные свободные записи содержат 01, 01,
End содержит 00, 00. LowValue свободной записи не читается производителем
и обычным путём потребителя, но его исходная единица сохранена.

Тип 02 означает число, а не код символа. [Потребитель](../Source/Controls/UnknownECA2.asm)
передаёт LowValue в [десятичный обработчик](../Source/Controls/UnknownECF3.asm).
Тот выводит минимум две цифры с начальным нулём, например 00, 07, 42,
а для 100..255 три цифры. Эта связь проверена на всех 256 байтах с
исполнением настоящего рисователя глифов. Полные договоры потребителя
и растрового ядра пока остаются неразобранными, их Unknown сохранён.

## Аргументы и поиск

QueueTextItem принимает запись в DE. D записывается в HighKind, E в
LowValue. Проверки D на допустимость нет. Поэтому D=00 создаст ещё
один маркер, D=01 оставит запись свободной. При корректном использовании
D=02 задаёт число, D>=03 является старшим байтом доступного адреса строки.
QueueNumber устанавливает E равным входному A, D равным 02 и использует
тот же алгоритм.

WriteCursor по EC5D является двухбайтовым операндом LD HL, nn по EC5C,
отдельная память для него не выделяется. Исходный курсор равен EC80.
Его также задаёт [начальная настройка](../Source/Controls/UnknownEC0E.asm),
которая записывает EC80. Производитель сохраняет после удачной записи
адрес следующего элемента, в том числе ECA0 после Slot0F. Следовательно,
для обычных вызовов курсор принадлежит 17 адресам Slot00..Slot0F и End.

Перед поиском B получает 16. В каждом проходе читается HighKind:

1. Значение 01 немедленно выбирает запись для сохранения.
2. Значение 00 переносит HL на Slot00, затем DJNZ расходует попытку.
3. Остальные значения пропускают два байта, затем DJNZ расходует попытку.

После 16 чтений без найденного 01 функция возвращается. Очередь и
WriteCursor при таком отказе не меняются. Результат поиска не возвращается
через Z, Carry или другой регистр, входной AF восстанавливается целиком.
Это молчаливый отказ, а не обязательное подтверждение приёма записи.

При успехе последовательно записываются D и E. Затем адрес после записи
сохраняется в WriteCursor, младший байт перед старшим. Исходные инструкции
и этот порядок записи сохранены. Проверка не включает ISR, способный
вмешаться между записью двух полей, поэтому атомарность при произвольном
прерывании не заявляется.

## Граничное поведение

Сам маркер End занимает одну из шестнадцати проверок. Если WriteCursor
указывает End, следующие пятнадцать проверок охватывают только
Slot00..Slot0E. При единственном свободном Slot0F происходит отказ,
хотя очередь не заполнена. WriteCursor при этом остаётся End, поэтому
повторный вызов с тем же состоянием снова откажет.

Эта особенность воспроизведена на исходных байтах и сохранена. Лимит
не увеличен до 17, обход маркера не сделан бесплатным, никаких новых
буферов или мест хранения курсора не введено.

## Регистры и физическая рамка стека

QueueTextItem сохраняет HL, DE, BC, AF. QueueNumber сохраняет HL, BC, AF,
а DE на выходе равно 0200 OR входной A. В обоих случаях сохраняются
HL′, DE′, BC′, AF′, IX, IY, I, IM и IFF. R изменяется при исполнении.
Процедуры не выполняют OUT, не переключают банк и не выполняют DI.
Нужный банк выбирает вызывающий код Action.

QueueTextItem делает PUSH HL, PUSH BC, PUSH AF. FTextQueueInsertFrame
описывает фактические восемь байтов от входного SP−6:

| Поле | Смещение | Физическое содержание |
| --- | ---: | --- |
| SavedAF | 0 | F, затем A |
| SavedBC | 2 | C, затем B |
| SavedHL | 4 | L, затем H |
| CallerReturn | 6 | внешний адрес возврата little endian |

Затем POP AF, POP BC, POP HL и RET восстанавливают регистры. Итоговый
SP равен входному SP+2, шесть байтов сохранений остаются в RAM стека.
На неудачном пути нет записей очереди, но эти шесть байтов стека всё
равно записываются. Статического экземпляра этой рамки нет.

## Проверки

[ReferenceControlsTextQueue.py](../Tools/Disasm/Research/ReferenceControlsTextQueue.py)
задаёт независимый ограниченный поиск. [CheckControlsTextQueue.py](../Tools/Disasm/Research/CheckControlsTextQueue.py)
прошёл 132807 вызовов производителя, включая все 65536 масок свободных
записей, все сырые слова DE, все AF числового входа, каждый начальный
курсор и каждое единственное свободное место при шести занятых кодах.

Сравниваются вся память, каждая фактическая запись с повторениями,
точные основные и сохраняемые регистры, восемь байтов рамки, SP и
порядок четырёх записей успешного добавления. Найдены 128765 физических
записей и 4042 молчаливых отказа в этом наборе. Отдельный сценарий
проверяет пропущенный Slot0F после маркера.

Ещё 256 проходов через исходный десятичный обработчик и рисователь
подтверждают последовательности цифр без подмены вызовов. Независимый
bitmap, полный потребитель, прокрутка, аппаратные IRQ и нативная игра
этой проверкой не доказаны. [Отчёт](../Tools/Disasm/Reports/ControlsTextQueueVerification.json).

[VerifySources](../Tools/Disasm/VerifySources.py) дополнительно проверяет
34 исходных байта, все физические поля и размеры обеих структур.
Обычная сборка использует готовые ASM и STRUCT, Python для неё не требуется.
Ассемблер в этом этапе не запускался.
