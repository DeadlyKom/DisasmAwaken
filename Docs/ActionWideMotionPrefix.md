# Смещение списка широких векторов

## Вход 6780 и рабочий вектор

Первый вход [фрагмента 6780](../Source/Action/UpdateBodyMotion.asm) обновляет
слово в операнде `#6781`. Пусть исходное слово равно `w`.
Первая запись всегда равна `w >> 1`. При чётном `w` управление
переходит прямо на `#688A`. При нечётном `w` команда `RR H`
выполняет вторую запись, сохраняя младший байт первой и устанавливая
старший в `#80 OR (w >> 10)`. Затем режим 1 выбирает вход `#6742`,
режим 2 выбирает `#6765`, остальные режимы идут на `#679B`.
[Модель](../Tools/Disasm/Research/CheckActionBodyVectorSchedule.py)
прошла все 65536 исходных слов при четырёх представительных режимах.
[Результаты](../Tools/Disasm/Reports/ActionBodyVectorScheduleVerification.json)

Вход `#679B` последовательно вычитает из трёх 24-битных компонент
по `#9B6F`, `#9B72` и `#9B75` знаковые 16-битные шаги по
`#E5B3`, `#E5D2` и `#E5ED`. У каждой компоненты сначала пишется
младшее слово. При переполнении старший байт текущей компоненты и
последующие компоненты сохраняются, управление переходит на `#6727`.
Без переполнения управление доходит до вызова `#67F5`.
[Модель](../Tools/Disasm/Research/CheckActionSubtractTransformVector.py)
сверила регистры, включая R, и точную последовательность записей
в 671232 сценариях до одной из этих границ.
[Результаты](../Tools/Disasm/Reports/ActionSubtractTransformVectorVerification.json)

## Обновление панели после оценки вектора

`#67F5` получает максимум свёрнутых старших байтов через
[MaxFoldedVectorHigh](../Source/Action/MaxFoldedVectorHigh.asm).
При нулевом максимуме средние байты знаковых компонент обращаются
по знаку и сравниваются как беззнаковые. Из максимального среднего
байта вычисляется значение четвёртой шкалы по формуле
`min(46, ((−max) mod 256) >> 1)`. Запрос четвёртой шкалы получает 1.

Байт `#9C29 = #FF` вызывает немедленный возврат. Иначе фаза в
`#683C` поворачивается вправо. Её прежний младший бит 1 разрешает
пополнение. Младший байт счётчика `#9BD2` увеличивается по модулю 256.
Кандидат сравнивается со старшим байтом `#9BD3`. Если кандидат не
выше лимита, он сохраняется и на единицу увеличивается поле, выбранное
[SelectPreferredByte](../Source/Action/SelectPreferredByte.asm).
На обоих исходах сравнения запрашивается обновление второй шкалы.

При ненулевом максимуме прежнее ненулевое значение четвёртой шкалы
переносится в запрос, а само значение обнуляется. При максимуме от
28 операнд `SpawnLowLimit` получает `min(255, max − 27 + bias)`,
где SpawnBiasBase читается из `#6874`. Одно поле 06 ApplyParameterSet первоначально записывает одинаковый байт в SpawnLowLimit и SpawnBiasBase. При максимуме ниже 28 пересчёт не производится. Вход TransitionBodyMode дополнительно устанавливает SpawnLowLimit=FF, не меняя SpawnBiasBase. При максимуме от 64 и режиме,
отличном от 2, выполняется переход к `#6727`.
[Модель](../Tools/Disasm/Research/CheckActionBodyVectorPanel.py) сверила
точки выхода, SP и кратность записей в 72192 сценариях, включая все
пары счётчика и лимита.
[Результаты](../Tools/Disasm/Reports/ActionBodyVectorPanelVerification.json)

## Хвост 688A

Общий хвост [фрагмента 6780](../Source/Action/UpdateBodyMotion.asm) начинается
по `#688A`. Изменяемый операнд `SeedIndex` задаёт количество записей.
При нуле хвост сразу возвращается.

При ненулевом количестве из трёх знаковых слов `#E5B3`, `#E5D2` и
`#E5ED` вычисляются шаги. Два арифметических сдвига дают округление
вниз при делении на четыре. Нулевой результат заменяется единицей.
Полученные слова помещаются в операнды по `#68D5`, `#68FD` и `#6925`.
У каждой записи [широкого вектора](ActionWideVectors.md) три шага
вычитаются со знаковым расширением до 32 бит и переносом из младшего
слова. Указатель `IY` сдвигается на 12 байтов после каждой записи.

Затем вызывается [FindFirstNearWideVector](../Source/Action/FindFirstNearWideVector.asm).
Если он вернул `L = 0`, из `H` вычисляется
`min(46, ((−H) mod 256) >> 1)`. Результат записывается по `#6693`, а
`#668E` получает единицу. Иначе прежнее ненулевое значение `#6693`
переносится в `#668E`, а `#6693` обнуляется. На этом пути флаги на
возврате задаёт сравнение байта `#9BC5` с `E` поиска.

В 3584 сценариях проверены SP, остаток кадра вызова, адрес в `IY`
и всё 64-килобайтное окно памяти. На ненулевых списках исполнение
доведено до возврата после настоящего поиска, включая 768 случаев
с `L = 0` и 2304 с `L ≠ 0`. Проверены количества от 0 до 6,
соответствующие физическим записям. Исходный счётчик не ограничен
числом этих записей. Большие списки в этой модели не использовались.
