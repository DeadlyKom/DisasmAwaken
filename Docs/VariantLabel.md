# Подпись варианта ключа

[PrintVariantLabel](../Source/Map/PrintVariantLabel.asm) получает первое слово ключа в HL, второе в DE и порядковый байт варианта в A. [PrintSelectedVariantLabel](../Source/Map/PrintSelectedVariantLabel.asm) загружает эти два слова из MapSelection и последовательно входит в тот же алгоритм. Вызывающий DrawItem19 использует как выбранный Variant, так и перечисление порядковых байтов. Игровая роль всех вариантов и списка Variant ещё требует отдельного разбора.

Оба слова копируются в уже существующий рабочий [FSignatureKey](WorldSignature.md) по 631C. C сохраняет входной вариант, B получает вариант+1 по модулю 256. XOR четырёх исходных байтов, ограниченный маской 07, выбирает две формы подписи. При результате 0 или 1 печатается единственный дефис. В этом случае рабочий ключ остаётся исходным, HL и DE сохраняются, B и C содержат подготовленные счётчик и вариант.

Для классов 2..7 настоящий StepSignatureKey вызывается вариант+1 раз. DJNZ с первоначальным B=0 выполняет 256 шагов, поэтому вход FF обрабатывается без специальной ветви. По XOR-свёртке последнего шага S строится буква с кодом 80+(S AND 0F), затем дефис и десятичный номер. Номер равен ((S SHR 4)+1+вариант) modulo 256. Старший перенос намеренно теряется исходным ADD A,C. Это не трёхзначный номер без ограничения диапазона и не строка HEX.

Буква остаётся исходным кодом CP866 80..8F. Последняя печать номера передана хвостовому PrintWord с A=0. Промежуточные отказы глифов не проверяются, поэтому вызывающий должен учитывать состояние окна и итоговый статус по договору печати. HL и DE после числовой формы являются результатами последнего шага ключа. Альтернативные и индексные регистры сохраняются.

[Модель](../Tools/Disasm/Research/CheckVariantLabel.py) исполняет 4096 проходов двух входов. Проверены все 256 вариантов для всех восьми классов XOR, точные состояния рабочего ключа, число настоящих шагов, коды настоящих глифов и цифр, регистры и стек. Выделены 1024 случая единственного дефиса. Сборка, IRQ и нативный запуск не выполнялись.
