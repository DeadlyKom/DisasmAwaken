# Выбор LF-записи справочного текста

[Help.SelectText](../Source/Help/SelectText.asm) по DB57..DB5A записи 8 выполняется в банке 7. Он записывает A в непосредственный операнд LD A индексатора по DB01 и возвращается. Это самомодификация одного байта, отдельная область RAM не выделяется. Те же CPU-адреса в музыкальном либо другом банке не определяют эту процедуру.

Следующий [IndexTextLines](../Source/Help/IndexTextLines.asm) читает подготовленное значение, берёт HL=E3E2 и вызывает [SkipLfRecords](../Source/Station/SkipLfRecords.asm). SelectText сам не ищет запись, не заполняет таблицу строк и не рисует текст. Он сохраняет буквально любое A, существование соответствующей LF-записи должен обеспечить вызывающий код. [Контракт индексирования](HelpLineIndex.md) проверен отдельно, включая ограничение N<1024 и требование продвижения по тексту.

Все основные, альтернативные и индексные регистры, флаги, I, IM и IFF сохраняются, SP после RET равен входному+2. Единственная запись имеет адрес DB01 и значение входного A. Opcode 3E самого LD A и остальные байты остаются прежними.

[CheckHelpTextSelector](../Tools/Disasm/Research/CheckHelpTextSelector.py) исполняет оригинальные четыре байта 32 01 DB C9. [Отчёт](../Tools/Disasm/Reports/HelpTextSelectorVerification.json) подтверждает все 65536 пар A,F, точный набор записей, контекст и CPU-возврат. Индексатор после изменения операнда в этой модели не исполняется. Прерывания, сборка и нативный запуск не выполнялись.
