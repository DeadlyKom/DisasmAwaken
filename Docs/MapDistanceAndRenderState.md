# Поля переноса состояния и рабочие значения отрисовки

## Станция и полёт

`MeasureCoordinateDistance` всегда пишет байт результата по `9908`. Для совпадения это ноль, для измеренного расстояния возможны значения 1..85, для переполнения — FF. Это результат последнего вызова. Среди вызывающих есть панель информации о системе и генератор предложения миссии. [Измеритель](CoordinateDistance.md), [поле](../Source/Station/Data/MeasuredDistance.asm).

`HandleItem08` сохраняет 512 байтов станции с `983B` по `4000`. После загрузки ACTION `LoadAction.AfterLoad` восстанавливает их с `9BBD`. Смещение `CD` внутри обеих копий переносит станционный `9908` на полётный `9C8A`. Обработчик гиперперехода считывает его целиком, включая FF. Маршрут Preferred удваивает его в слове, Fallback использует исходный байт. При обратном переходе подготавливаются 512 байтов, из которых реле возвращает 481. Смещение `CD` входит в этот перенос. [Переход в ACTION](StationExit.md), [поле стоимости](../Source/Action/Data/HyperJumpCost.asm), [переход в станцию](ControlsStateStationRelay.md).

Смещение `CB` связывает `9906` станции и `9C88` полёта. При подготовке перехода станция увеличивает байт на 30 по модулю 256, если код «Система Ус-01» по `98AA` отличается от FF. Обе исходные копии содержат 100. Полётный потребитель счётчика пока не установлен. В SAVE те же смещения содержат два поля, нулевая копия SAVE5 сохранена побайтно. [Подготовка перехода](../Source/Station/HandleItem08.asm), [станционный счётчик](../Source/Station/Data/TransitionCounter.asm), [копия ACTION](../Source/Action/Data/TransitionCounter.asm), [SAVE](SavedStateLayout.md).

Соседние станционные байты `#9907` и `#9909` переносятся вместе с
ними в `#9C89` и `#9C8B`. В архивном дисковом контексте эти позиции
соответствуют второму байту SPEED и старшему байту DALNO. Текущая
проверка допуска гиперперехода использует байт `#9C8A`. В обеих ветвях
соседние байты не читаются вплоть до входа сообщения или раннего
возврата. [Сравнение с архивом](ActionArchivedBodyContext.md#пара-speed-и-слово-dalno)

В старом `KARTA.C` измеритель возвращал результат в A без записи в RAM.
Awakenv02 перед возвратом записывает только `#9908`. В сравнительных
прогонах `#9907` и `#9909` сохранили разные контрольные значения на
всех проверенных путях, включая нулевую дальность и переполнение.
[Сравнение измерителей](CoordinateDistance.md#запись-результата-в-текущей-версии)

В сквозной модели с ROM TR-DOS покупка строки 28 за 2000 кредитов
устанавливает FE через исходный LANG. Проверен и отказ M07 для типа 6.
При исходном коде FF значение 100 переносится без прибавления. При FE
контрольное значение F3 становится 11 по модулю 256. Счётчик сохраняется
при перезагрузке ACTION и возврате на станцию. Чтений и записей по 9C88
в первых 64 кадрах обоих профилей нет. [Сквозная проверка](../Tools/Disasm/Reports/BootBankFileReadsVerification.json)

На станции байт по `#9906` читает обратный поиск при нормализации
курсора пустого маршрута. С исходными пустыми списками он влияет
на число чтений до ограничения курсора, итоговый курсор и порядок
маршрута остаются одинаковыми. [Точные адреса и 256 значений](SecondaryPointOrder.md)

Станционная запись описания 28 по `#DD41` называет «Систему Ус-01»
ускорителем двигателей. В старой авторской раскладке у той же позиции
подпись «МАРШРУТИЗАТОР». Это две физически сохранившиеся подписи, эффект
ускорения из них не следует. [Описания станции](StationPanelTextResources.md) ·
[Сопоставление позиций](ActionEquipmentCodes.md)

[Проверка](../Tools/Disasm/Research/CheckStationHyperJumpCostTransfer.py) исполняет измеритель, настоящий переход станции и восстановление блока в 360 сценариях. Дисковый вызов заменён постусловием успешной загрузки. Для 0, 85 и FF также исполняется настоящий загрузчик ACTION с моделью TR-DOS и один полный полётный кадр без нажатий. Другие случаи используют точные байты ядра после переноса. Команда проверяется с подготовленными запасами и допуском. Охвачены 175 допусков до сообщения, 4 совпадения ключей после списания и 181 отказ по запасу. [Отчёт](../Tools/Disasm/Reports/StationHyperJumpCostTransferVerification.json).

## Рабочие поля рендера

`RenderSceneFrame` сохраняет слова X, Y и глубины по `9B8F..9B94` перед проверкой модуля соответствующего старшего байта. Следующее слово записывается только после допуска предыдущего. Эти слова содержат исходные компоненты до преобразования, отдельные операнды преобразования получают только допущенные слова. Все потребители снимка не установлены. [Физический снимок](../Source/Action/Data/RenderInputSnapshot.asm), [писатель](../Source/Action/RenderSceneFrame.asm).

Малый рисователь CONTROL0 хранит полный байтовый режим по `CEF9` банка 1. Вход `ProjectAndDrawBody` обнуляет его, `BuildBodyProjection` и `DrawSmallBody` читают. Последний принимает значения 0..3. [Физический режим](../Source/Controls/Data/BodyDrawMode.asm), [малый рисователь](ControlsSmallBodies.md).
