# Начальное содержимое буфера OBJECT3D

[CopyObjectData](../Source/Action/CopyObjectData.asm) копирует поток
из банка 4 в существующее назначение `#9F1C`. Максимальный размер копии
по всем 128 исходным чётным указателям равен 238 байтам, последний
занятый байт в этом профиле расположен по A009. Это установленное
назначение копирования, новый буфер не выделяется.

Исходные дисковые байты `#9F1C..#A009` сохранены отдельным ресурсом
в [физическом составе ACTION](../Source/Files/17_ACTION.inc).
Они не заменены потоком одной выбранной модели или нулевым заполнением.

Отдельная серия проверяет нечётные индексы без изменения таблицы
`#9E00`. Из 128 полученных адресов 20 находятся внутри логического
файла OBJECT3D и задают конечные потоки по правилам копировщика.
Индекс `#57` даёт адрес `#C0D7` и копию длиной 250 байтов, до `#A015`
включительно. Двенадцать байтов `#A00A..#A015` входят в
[расширенный хвост назначения](../Source/Action/Resources/InitialObjectStreamExtendedTail.bin).
Нечётные индексы и корректность получаемой из них геометрии в игре
этой проверкой не установлены.

Для [14 дополнительных указателей](ActionModelTail.md) выполнена
та же проверка с подстановкой одного слова в `#9E00`. Самый длинный
из этих потоков содержит 251 байт и записывает также `#A016`.
[Кадровая модель](../Tools/Disasm/Research/CheckActionNonemptyRenderFrame.py)
провела через оригинальную отрисовку все семь дополнительных моделей.
На пакете `#E859` инструкция по `#AB13` записывает по `#A016`
нулевой ограничитель, а код по `#DD23` читает его при обходе граней.
Этот байт включён в расширенный хвост. Последние пять байтов
`#A017..#A01B` входят в объявленный автором 256-байтовый резерв
`OBJBUF` и сохранены отдельным ресурсом. Архивный DATAS хранит
весь этот блок, список CARGS и записи CARSB на одну страницу выше.
От начала таблицы указателей до конца текущего DATAS совпадают
2605 байтов с таким сдвигом.
[Хвост OBJBUF](../Source/Action/Resources/ObjectStreamBufferTail.bin) ·
[Авторское размещение](../Tools/Disasm/Reports/ActionArchivedLayoutVerification.json)

Штатный путь выбора дополнительных указателей не установлен.

[Проверка порядка обращений](../Tools/Disasm/Research/CheckActionObjectStreamStorage.py)
исполнила исходный CopyObjectData для всех 128 чётных указателей
с четырьмя вариантами прежнего содержимого: оригинал, 00, FF и A5.
Во всех 512 сценариях каждый байт текущей копии записан до первого
его чтения, результат равен соответствующему физическому потоку.
Реальный селектор выдаёт 14 и 10 в порт 7FFD.
В 34 дополнительных сценариях сверены порядок всех записей,
неизменность источника и остатка до `#A01C`, оба переключения
страниц и внешний возврат.

После штатной инициализации ACTION проверены все 128 нечётных
индексов в одном снимке RAM. Код копирования исполняется на
неизменённой таблице с принудительно заданным входным L.
В 52 случаях копирование достигает CandidateList, в 32 проверка
останавливает его после первой записи в `#A100`. Например,
индекс `#8D` копирует 262 байта из `#61CE` и меняет шесть
байтов CandidateList. Индекс `#25` читает четыре нулевых байта
`#A0C8..#A0CB` как два байта заголовка и два ограничителя.
Эти условные обращения не устанавливают роль промежутков
при обычном рисовании.

Во всех 25 начальных записях, 16 физических шаблонах и 72
выборах девяти классов ModelOffset чётный. Разбор индексных записей
по смещению `#06` в зарегистрированном полётном коде дал следующие источники.

| Запись в поле | Источник значения |
| --- | --- |
| `#6106`, `#61DA`, `#6472` | Константы `#90`, `#C0`, `#98` соответственно |
| `#78EC` | Поле одного из 16 физических шаблонов |
| `#79DF` | `((случайный байт AND #1C) OR #40) + поправка`, поправка равна `#00` или `#20` |
| `#7BF6` | Выбор модели для девяти исходных классов |
| `#E8D1` | `#88` или `#8C` |
| `#F44B` | `#10 + 4 × область`, область принимает значения от 0 до 3 |

Ещё один подтверждённый писатель, `#EAA5`, записывает `#B8` через DE
после копирования первых шести байтов дочерней записи. Две другие
индексные записи с тем же смещением относятся к полям
`FActionWideVector.Component1.Byte2` (`#6918`) и `FVisualEffect.Mode` (`#EC57`).
Из 55 различных значений этих писателей и начальных записей максимальную
копию по неизменённой таблице даёт `#F0`, 238 байтов до `#A009` включительно.

При входе в 65-й кадр модели без клавиш с подменой TR-DOS зарегистрирована
одна запись поля, `#78EC` положил `#F4` по `#A106`. Потребитель `#AACC`
прочитал заголовок модели `#F4` 57 раз. Вызовов копировщика `#AAE2` и записей
в таблицу `#9E00` в этом сценарии не было. Произвольные косвенные писатели
и достижимость нечётных значений в других фазах остаются открытыми.
[Результаты проверки](../Tools/Disasm/Reports/ActionObjectStreamStorageVerification.json)

Принудительный класс `#09` на входе выбора модели планировщика
показывает один условный источник нечётных значений: исходная таблица
даёт `#6440`, где среди прочитанного есть `#A1`, `#DD` и `#11`.
Модель подставляет `#09` непосредственно на входе `#7BDB`.
В 65536 проверках штатного выбора с `#7B78` допустимыми оказались
только классы `#00`, `#01`, `#02`, `#04..#08`. В зарегистрированном
коде ACTION в `#7BDB` ведут два перехода из этого селектора,
`#7BD1` и `#7BD7`.
[Таблица планировщика](ActionSpawnPhysicalRows.md) ·
[Проверка классов](../Tools/Disasm/Reports/ActionSpawnClassSelectionVerification.json)

Это не доказательство произвольной ёмкости назначения. CopyObjectData
длины не ограничивает, синтетический длинный поток может продолжить
запись за A009. Короткая копия не очищает оставшийся хвост.
Также эта проверка не доказывает порядок чтений любой другой фазы игры
до первого вызова копировщика и не исполняет дальнейший рисователь.

Потребитель скопированных вершин описан в
[TransformObjectVertices](ActionObjectVertices.md), формат пакетов в
[физических потоках OBJECT3D](ActionModelPackets.md).
[Публикация ресурса](../Tools/Disasm/Research/ClassifyActionObjectStreamStorage.py)
проверяет непересекающееся покрытие, соседние неизвестные диапазоны
и совпадение всех исходных байтов. Сборка и нативный запуск не выполнялись.
