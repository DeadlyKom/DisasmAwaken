# Декодирование музыкальных паттернов

Разбор относится к байтам MUZ1.C из исследуемого образа. Название PT3 описывает
используемый формат, поведение этой версии установлено по её инструкциям.
Команды не преобразованы в другой формат, исходные адреса и байты сохранены.

Физические блоки разделены по реальным входам и общим хвостам:

| Блок | Диапазон | Назначение |
| --- | --- | --- |
| [AdvancePatternBC](../Source/Music/AdvancePatternBC.asm) | E37C..E3DB | выбор очереди B/C и подготовительных маркеров |
| [PatternCommandsA](../Source/Music/PatternCommandsA.asm) | E3DC..E438 | внутренние обработчики и хвосты A |
| [DecodePatternA](../Source/Music/DecodePatternA.asm) | E439..E488 | чтение и распределение команд A |
| [PatternCommandsB](../Source/Music/PatternCommandsB.asm) | E489..E4E5 | внутренние обработчики и хвосты B |
| [DecodePatternB](../Source/Music/DecodePatternB.asm) | E4E6..E53C | чтение и распределение команд B |
| [PatternCommandsC](../Source/Music/PatternCommandsC.asm) | E53D..E582 | внутренние обработчики и хвосты C |
| [DecodePatternC](../Source/Music/DecodePatternC.asm) | E583..E60B | чтение, сброс новой ноты и распределение команд C |

## Поток команд и вход декодера

DE указывает следующую команду. Декодер читает байт и увеличивает DE.
Некоторые команды немедленно читают дополнительные байты, после них DE
продолжает указывать следующую команду. Нота 50..AF, выключение C0 и конец
строки D0 завершают чтение команд. Параметры отложенных эффектов находятся
после этого терминатора и читаются уже при исполнении RET-цепочки.

Entry каждого декодера устанавливает BC=1020. ReadCommand сохраняет это BC,
поэтому переход на Entry нужен после загрузки указателя через BC. H задаёт
текущую страницу таблицы, штатные кадровые вызывающие блоки устанавливают DB.
Сама процедура не восстанавливает H перед каждым поиском.

Диапазоны выбираются последовательными ADD с проверкой Carry, дополнительно
Z отделяет нулевую подкоманду. [MusicPatternDispatch](MusicPatternDispatch.md)
содержит отдельную проверку всех 256 кодов и всех входных F.

| Команда | Последующие данные | Действие |
| --- | --- | --- |
| F0..FF | сырой байт индекса сэмпла | выбрать орнамент по младшим четырём битам, снять огибающую, выбрать сэмпл |
| D1..EF | нет | выбрать сэмпл по индексу команда−D0 |
| D0 | затем параметры отложенных эффектов | закончить строку через RET |
| C1..CF | нет | записать смещение громкости (команда−C0)×16 |
| C0 | затем параметры отложенных эффектов | выключить ноту и закончить строку |
| B2..BF | старший байт периода, младший байт периода | задать форму команда−B1 и период общей огибающей, маску канала 10 |
| B1 | байт длительности | заменить перезагрузку счётчика строки выбранного канала |
| B0 | нет | снять маску огибающей выбранного канала |
| 50..AF | затем параметры отложенных эффектов | задать индекс ноты команда−50 и закончить строку |
| 40..4F | нет | выбрать орнамент по индексу команда−40 |
| 10 | сырой байт индекса сэмпла | снять маску огибающей и выбрать сэмпл |
| 11..3F у A/C, 11..1F у B | старший байт периода, младший байт периода, сырой байт индекса сэмпла | задать форму команда−10, период, маску 10 и сэмпл |
| 20..3F только у B | нет | записать базовый шум команда−20 по DF67 |
| 00..0F | параметры читаются после терминатора | прочитать адрес обработчика и поместить его в стек |

Сырой индекс сэмпла в совместной команде уже удвоен в потоке. Декодер
добавляет A0 к самому байту, дополнительного умножения нет. Нечётные значения
тоже читаются буквально. В отдельной команде D1..EF индекс сначала удваивается.

## Физические параметры и различия каналов

| Поле | A | B | C |
| --- | --- | --- | --- |
| ожидающая либо текущая нота | DE4D | DEDB | E2B9 |
| код NOP/CPL разрешения | DE48 | DED6 | непосредственный Disabled E1EE |
| смещение громкости | DE5D | DEEB | E22B |
| указатель сэмпла | DE52 | DEE0 | E1F5 |
| указатель орнамента | DE68 | DEF6 | E276 |
| маска огибающей | DE6E | DEFC | E235 |
| длительность строки | DFC9 | E39F | E3D0 |

У A/B новые параметры ещё ожидают переноса в синтез. Нота и выключение
устанавливают H′=D′, смена орнамента и маски огибающей устанавливает B′=D′.
Скольжение через отложенный обработчик устанавливает E′=D′. Кадровый
вызывающий блок заранее подготавливает D′=06, а остальные маркеры 18,
тем самым выбирает, какие изменяемые JR станут LD B,n на следующем тике.
[MusicChannelStaging](MusicChannelStaging.md) описывает физическое применение.

У C параметры действуют сразу. Нота обнуляет курсоры сэмпла E1F9 и орнамента
E27A, накопители шума E23C, огибающей E253 и тона E26A, счётчики скольжения
E29D и чередования E2D5, Disabled E1EE. Поправка уровня E20F становится 10.
SlideOffset E296 сама нота не обнуляет, это делает вызывающий распределитель
только при возвращённом B=1. Portamento возвращает B=0 и сохраняет смещение.
Выключение C0 обнуляет только счётчик чередования и задаёт Disabled=FF.

B0 и B2..BF у C сохраняют позицию орнамента. Отдельная смена орнамента
40..4F, F0..FF и совместный выбор огибающей и сэмпла 10..3F обнуляют её.
Эта разница сохранена. Форма огибающей находится по DF48, старший байт
периода по DF51, младший по DF50. Это порядок чтения из паттерна, в памяти
слово периода остаётся little endian. Общая огибающая не принадлежит
отдельному каналу, поздняя команда другого канала может заменить её состояние.

## Поиск указателей и изменение H

Для орнамента вычисляется младший адрес (E0+2×индекс)&FF. Для сэмпла
вычисляется (A0+удвоенный_индекс)&FF. Старший адрес берётся из текущего H.
Первый байт указателя читается в C, затем INC L увеличивает только L,
второй байт читается в B. Переноса в H нет даже при переходе L из FF в 00.
HL остаётся адресом второго прочитанного байта, а не самим указателем.

После отложенной команды HL содержит адрес её обработчика, обычно E6xx.
ReadCommand не восстанавливает H. Поэтому последующий поиск сэмпла либо
орнамента может читать слова из страницы E6, а не DB. Модель сохраняет
это поведение и проверяет смешанные последовательности на исходных байтах
этой страницы. Восстановление DB ради удобства исказило бы программу.

## Стек отложенных эффектов

Каждая команда 00..0F читает слово через фактическую адресацию таблицы,
загружает его в HL и делает PUSH HL. Для C дополнительно сохраняется
текущая нота E2B9 в PreviousNoteC по E6EC. Терминальная команда выполняет
RET, который сначала запускает самый поздний помещённый обработчик.
Его RET запускает предыдущий и далее внешний адрес возврата. Каждый
обработчик получает DE после параметров уже исполненных обработчиков.

Например, 03 04 D0 x y вызывает установку позиции орнамента с x, затем
установку позиции сэмпла с y. Две одинаковые команды 03 03 D0 x y записывают
позицию сэмпла сначала x, затем y. Последнее значение остаётся рабочим.

Поддерживаемые обработчики имеют коды 1, 2, 3, 4, 5, 8 и 9. Их точные
контракты, реальные записи указателей и физический FMusicDeferredPairFrame
описаны в [MusicEffects](MusicEffects.md). Слово выбирается по младшему адресу
(E0+2×код+якорь)&FF. Для A страница DD, якорь DE, для B DD и FE,
для C DE и 1E. Между указателями лежат инструкции, непрерывной таблицы
из шестнадцати корректных обработчиков здесь нет.

Коды 0, 6, 7 и 10..15 алгоритмически тоже читают слово и помещают его в стек.
Их слова зафиксированы отдельным отчётом маршрутизации, но последующее
исполнение этих целей не исследовано как допустимый музыкальный эффект.
Договор полных строк ограничен семью подтверждёнными кодами. Зарезервированные
коды не переименованы в выдуманные обработчики и не заменены безопасным RET.

## Выходные регистры декодеров

Без эффектов DE указывает байт сразу после терминатора. С эффектами он
дополнительно продвинут на сумму длин их параметров. AF′, IX, IY, I, IM
и IFF сохраняются. Внешний RET снимает только исходный адрес возврата,
поэтому итоговый SP равен входному SP+2 независимо от числа корректных эффектов.

| Терминатор без эффектов | AF A/B | AF C | BC | HL |
| --- | --- | --- | --- | --- |
| нота 50..AF | 0044 | 1044 | 0120 | у A/B прежний адрес поиска, у C ноль |
| выключение C0 | 2F41 | FFBB | 1020 | последний адрес поиска либо входное значение |
| конец строки D0 | 0041 | 0041 | 1020 | последний адрес поиска либо входное значение |

Эффекты могут заменить эти выходы. В частности, portamento задаёт B=0,
HL адресом изменяемой ноты, F=44. Установщики позиций, длительностей,
темпа и огибающей имеют собственные выходные A и HL, описанные по каждому
обработчику. При нескольких эффектах конечный результат задаёт самый
ранний записанный в потоке эффект, поскольку исполняется последним.

У A/B сохраняются AF′, C′, D′ и L′, меняются только H′, B′ и E′ по
перечисленным маркерам. У C все альтернативные пары сохраняются.
Все непосредственные и косвенные записи проверены отдельно от этих пар.

## Внутренние входы групп обработчиков

Это входы по JR из собственного декодера, универсального CALL-контракта
для произвольного A и F у группы нет. DE уже указывает данные после команды,
BC=1020, H содержит текущую страницу указателей. Условные входы получают
флаги непосредственно от последнего ADD выбора диапазона.

| Назначение | A | B | C | Аргумент и продолжение |
| --- | --- | --- | --- | --- |
| новая нота | E3DC Entry | E489 Entry | E5E6 SetNote | A=код−50, завершение строки через RET |
| громкость либо C0 | E3E4 SetVolume | E491 SetVolume | E53D Entry | A=код−C0, Z установлен только для C0 |
| B0/B1/B2..BF | E3F8 EnvelopeOrDelay | E4A5 EnvelopeOrDelay | E5B2 EnvelopeOrDelay | A=код−B0, ноль снимает маску, после DEC ноль выбирает B1 |
| форма и период | E404 ReadEnvelope | E4B1 ReadEnvelope | E550 ReadEnvelope | A уже равен форме, DE указывает старший байт периода |
| сохранить маску | E413 StoreEnvelope | E4C0 StoreEnvelope | E55F StoreEnvelope | A=00 либо 10, продолжение ReadCommand |
| F0..FF | E41B OrnamentSample | E4C8 OrnamentSample | E564 OrnamentSample | A=код−F0, после орнамента читается сырой индекс сэмпла |
| маска и сырой сэмпл | E427 EnvelopeSample | E4D4 EnvelopeSample | E570 EnvelopeSample | A=00 либо 10, у C дополнительно сброс курсора орнамента |
| указатель сэмпла | E42F StoreSample | E4DC StoreSample | E579 StoreSample | A уже удвоен, после записи переход в Entry декодера |

ReleaseNote и StoreEnable являются общими внутренними хвостами выключения
и новой ноты A/B. У C ReleaseNote физически находится в группе команд,
SetNote в конце декодера. Между StoreSample и следующим Entry нет машинного
JP, в исходниках стоит только комментарий продолжения, порядок include жёсткий.

## Счётчик A, переход позиции и временный SP

[AdvancePatternA](../Source/Music/AdvancePatternA.asm) находится по DF7F..DFE2,
не имеет собственного RET и продолжает исполнение в RenderChannelA. Сначала
уменьшается RowCounterA по DE1E. Из входного E в основные B и H копируются
подготовительные маркеры, L равен 1E, затем EXX переключает пары. При
ненулевом результате DEC разбор строки пропускается, но выбор кода сброса
скольжения и перенос маркеров всё равно выполняются.

Если счётчик истёк, читается байт по изменяемому PatternA из DF89. Ненулевой
байт передаётся декодеру. Ноль проверяется до входа в DecodePatternA и
означает переход позиции. В самом декодере код 00 обрабатывается иначе,
как чтение зарезервированного слова эффекта, эти контексты нельзя смешивать.

При переходе позиции базовый шум DF67 обнуляется, исходный SP сохраняется
в операнд SavedStack по DFBD. PositionCursor по DF98 указывает следующий
байт списка. Если этот байт FF, вместо его адреса выбирается LoopPosition
из DF9F. Выбранный байт читается как позиция, новый PositionCursor получает
адрес после него. Повторной проверки FF по адресу петли нет.

PatternTable из DFA7 задаёт базу таблицы. Адрес тройки вычисляется буквально
как (PatternTable+2×байт_позиции)&FFFF. Здесь нет умножения на шесть. Если
формат списка содержит индексы троек, их масштаб уже закодирован в самом
байте позиции. Именно два ADD HL,DE определяют поведение этой версии,
включая значения позиции, не кратные трём.

SP получает этот адрес. Три POP читают три последовательных little endian
слова. К каждому прибавляется ModuleBase из DFAE с шестнадцатибитным
оборачиванием. Первое слово становится DE потока A, второе сохраняется
как PatternB по E393, третье как PatternC по E3C4. Затем SP восстанавливается
из SavedStack. Пока он указывает таблицу, аппаратные IRQ недопустимы,
обычная обработка прерывания могла бы записать возврат прямо в данные.

Перед DecodePatternA старший байт HL устанавливается DB. Младший байт
при переходе позиции остаётся младшим байтом абсолютного указателя C,
при прежнем потоке берётся из рабочего HL после EXX. Первый поиск указателя
в декодере сам заменяет L, поэтому этот остаток не нормализуется.
CALL помещает на обычный восстановленный стек DFC4. После всей RET-цепочки
эффектов новый DE сохраняется в PatternA, RowCounterA получает RowDelayA
из DFC9, A получает ту же перезагрузку.

Далее рабочий B всегда уменьшается через DJNZ. При его прежнем значении 1
ResetOpcodeA по DE2E получает 22, иначе 01. Без декодера рабочий B взят
из входного B′ и также влияет на этот выбор. EXX возвращает подготовительный
комплект, из которого B записывается в OrnamentBlockA DE61, H в NoteBlockA
DE31, E в SlideBlockA DE72. В конце A равен этому E. F сохраняется от
DEC RowCounterA на пути без разбора, иначе от декодера и его эффектов.
Альтернативные пары содержат рабочий результат с уменьшенным B. AF′,
IX, IY, I, IM и IFF сохранены, SP равен входному значению, внешнего RET нет.

[CheckMusicAdvanceA.py](../Tools/Disasm/Research/CheckMusicAdvanceA.py)
прошёл 5712 сценариев. Проверены все байты счётчика и позиции, FF-петля,
все значения рабочего B на ветви без декодера, шесть баз модуля, переполнение
относительных указателей и эффекты после перехода позиции.
[Отчёт](../Tools/Disasm/Reports/MusicAdvanceAVerification.json) фиксирует
сравнение всей памяти, фактических записей, основных и альтернативных пар,
сохранение и восстановление SP. Проверка исходной композиции дополнительно
сопоставила все 1793 исполнения этого блока, 29 смен позиций и одну петлю.
Остальные тики проходят к синтезу через прямой JP и этот блок не исполняют.

## Распределение фаз B/C

Входное значение Phase по E37D уменьшается и сохраняется всегда. Прежнее
значение 1 выбирает C, прежнее 2 выбирает B. При остальных значениях
исполняется ещё один DEC только в A, затем RET. Сохранённая Phase равна
(старая−1)&FF, A равен (старая−2)&FF. HL, DE, BC и альтернативные пары
в этой ветви сохранены, F соответствует второму DEC с входным Carry.
Нулевая Phase переходит в FF, автоматического исправления нет.

Фаза C записывает 01 в вход тика DE1F, назначая применение строки A
на следующем тике. Счётчик DC0F уменьшается, нулевой исходный счётчик
становится FF. При ненулевом результате возвращаются A=1, HL=DC0F,
остальные пары сохраняются, F соответствует DEC счётчика с входным Carry.

При истечении C вызывается DecodePatternC с DE из E3C4 и HL=DB0F.
Новый DE сохраняется обратно, счётчик получает RowDelayC из E3D0, A
получает ту же длительность. Затем DEC B проверяет результат декодера.
Если прежний B равнялся 1, B=0, HL=0, SlideOffset E296 обнулён. Иначе
HL и SlideOffset сохраняют результат декодирования, B уменьшается по модулю
256. F соответствует этому DEC с Carry результата декодера. AF′ и все
альтернативные пары сохраняются, в том числе при самом вызове декодера C.

Фаза B уменьшает DC0E, затем подготавливает HL=180E, DE=0618 и B=18
при прежнем основном C, после чего выполняет EXX. Эти значения оказываются
в альтернативном комплекте, а рабочие HL, DE и BC берутся из входных
альтернативных пар. Если счётчик истёк, DE заменяется PatternB из E393,
H становится DB при сохранённом рабочем L, исполняется DecodePatternB.
Новый DE сохраняется, DC0E перезагружается RowDelayB из E39F.

Рабочий B уменьшается через DJNZ в обоих случаях, включая ветвь без
декодера. Если B до DJNZ равнялся 1, ResetOpcodeB по DEBC получает 22,
иначе 01. Поэтому нельзя заменять этот выбор константой, опираясь только
на отсутствие новой ноты. После EXX основные пары получают подготовленные
и уточнённые декодером маркеры. B записывается в OrnamentBlockB DEEF,
H в NoteBlockB DEBF, E в SlideBlockB DF00. A в конце равен этому E,
F сохраняется от декодера либо DEC DC0E, так как DJNZ и пересылки его
не меняют. Альтернативные пары содержат рабочий результат декодера с уже
уменьшенным B. AF′ не меняется.

CALL B помещает на стек E39A, CALL C помещает E3CB. Декодеры и их эффекты
возвращают SP в прежнее положение, финальный RET распределителя снимает
внешний адрес. Прерывания, R и реальное аппаратное время этими формулами
не моделируются. Фаза выбирает следующую подготовку, текущий звук уже
выведен предыдущим [OutputAyFrame](MusicAyOutput.md).

## Проверки и границы результата

[ReferenceMusicPattern.py](../Tools/Disasm/Research/ReferenceMusicPattern.py)
задаёт семантику команд, а не исполняет Z80. [CheckMusicPatternRows.py](../Tools/Disasm/Research/CheckMusicPatternRows.py)
сравнивает с ней исходные инструкции декодеров, без подмены обработчиков.
[Отчёт полных строк](../Tools/Disasm/Reports/MusicPatternRowsVerification.json)
содержит 46992 сценария, по 15664 для A, B и C. Проверены обычные команды,
все байты первых параметров поддерживаемых эффектов с тремя терминаторами,
все пары семи эффектов и 4096 смешанных последовательностей на канал.
Сравниваются вся память, все фактические записи с повторениями, основные
и альтернативные пары, SP и сохраняемые специальные регистры.

[ReferenceMusicPhases.py](../Tools/Disasm/Research/ReferenceMusicPhases.py)
использует ту же числовую семантику декодеров внутри независимой модели фаз.
[CheckMusicPatternPhases.py](../Tools/Disasm/Research/CheckMusicPatternPhases.py)
прошёл 13216 случаев, все байты фазы и счётчиков, оба Carry, все значения
рабочего B на ветви без декодера, команды и эффекты внутри реальных CALL.
[Отчёт фаз](../Tools/Disasm/Reports/MusicPatternPhasesVerification.json)
фиксирует также физические адреса возврата и записи маркеров следующего кадра.

Проверка исходной композиции на 5377 кадрах сравнивает независимо
[ядро синтеза](MusicSynthesis.md), все 2304 вызова декодеров, из них 496 A,
1314 B и 494 C, и все 5377 проходов распределителя фаз B/C. Для декодеров
сравниваются память и регистры, для фаз также все записи памяти.
Эта композиционная проверка не заменяет проверку алгоритмов всех игровых вызовов. Выполнение
зарезервированных эффектов, произвольные бесконечные или повреждённые строки,
аппаратные IRQ и нативный звук не подтверждены. Сборка не выполнялась.
