# Коды границ рабочих точек карты

Фазы изменяемых операндов описаны в [MapRuntimeProfiles](MapRuntimeProfiles.md). Исходный профиль и классификатор после настоящего D0C3 проверены отдельно. Переключение условий хвостов DFC3 относится к другому семейству процедур.

[BuildMapPointOutcodes](../Source/Map/BuildMapPointOutcodes.asm) читает количество из младшей тетрады байта по входному альтернативному HL. Рабочие записи начинаются по F800 банка KARTA. FProjectedPoint содержит X, DW по смещению 0, Y, DW по смещению 2, и ClipCodes, DB по смещению 4. Это существующий runtime-массив за концом исходного файла KARTA, отдельного дискового заполнителя для него не добавлено.

Координаты знаковые 16-битные. Исключённые верхние пороги StopX и StopY хранятся в изменяемых операндах D44D и D468. Исходно оба равны FF, внутренняя область равна 0..254. D0C3 записывает (MaxX+1) AND FF и (MaxY+1) AND FF. Нижняя граница по обеим осям остаётся нулевой, переданные установщику MinX/MinY её не меняют. При Max=255 соответствующий Stop равен нулю, внутренней области на этой оси нет. При отрицательном старшем байте устанавливается левая либо верхняя сторона. При ненулевом положительном старшем байте устанавливается правая либо нижняя сторона. При нулевом старшем байте младший байт сравнивается с соответствующим Stop, равенство уже означает выход.

| Разряд | Смысл |
| --- | --- |
| 0 | X>=StopX, справа |
| 1 | X<0, слева |
| 2 | Y>=StopY, снизу |
| 3 | Y<0, сверху |
| 4 | Дополнение разряда 0 |
| 5 | Дополнение разряда 1 |
| 6 | Дополнение разряда 2 |
| 7 | Дополнение разряда 3 |

Если младший код C, то ClipCodes=C OR ((C XOR 0F) SHL 4). Это четыре признака и их дополнения, а не восемь независимых флагов. Нулевой младший код означает точку внутри, весь байт при этом равен F0. Полный ClipCodes=00 алгоритмом не формируется. Нейтральное объявление структуры DB 00 не следует трактовать как уже рассчитанный внутренний код.

Все ClipCodes объединяются операцией OR. В результате установленный младший разряд означает выход хотя бы одной точки на соответствующую сторону. Сброшенный старший разряд означает выход всех обработанных точек на эту сторону. Это объясняет последующую проверку общего отбрасывания в D1AC, но не заменяет полный разбор его отсечения.

На выходе HL=F800+((5*N+1) AND FF), DE сохранён, B=5*N, C младший код последней точки. Основной AF содержит общий OR и его логические флаги. Альтернативные HL, DE, BC сохраняются, альтернативный AF содержит последнее равное сравнение конца. IX и IY сохраняются.

При N=0 код не возвращается немедленно. Шаги по L равны пяти по модулю 256, поэтому выполняются 256 циклов, записывающих каждый байт страницы. Часть следующих координат читается уже после их изменения предыдущими циклами. Это проверено отдельным последовательным оракулом. Известный прямой вызов из D1AC отсекает количества 0 и 1 заранее, поэтому самостоятельный тест нулевого входа не объявляется доказанным игровым сценарием.

[Модель](../Tools/Disasm/Research/CheckMapPointOutcodes.py) проверяет 131328 наборов, все 65536 слов каждой координаты и все 256 байтов заголовка. Проверены полный рабочий массив, соседние байты страницы, точные регистры, флаги и стек. Модель не выполняет полное рисование, сборку, IRQ или нативный запуск.

Для этого формата переиспользован существующий FProjectedPoint из общих структур проекта, совпадают X, Y и ClipCodes по смещениям 0,2,4 и размер 5. Исходное объявление не изменено. Общий формат записи не означает тождество игровых алгоритмов карты и 3DPART.

[Проверка настроенного классификатора](../Tools/Disasm/Research/CheckConfiguredMapOutcodes.py) выполняет D0C3 и D430 без подмены вызовов. Пройдены 331776 случаев, все 256 байтовых порогов каждой оси, каждый младший байт координаты при каждом пороге, все заголовки в каждом профиле и все 65536 слов обеих координат в одном профиле StopX=240, StopY=15. Пары порогов взяты как StopY=255-StopX, полный декартов набор пар не заявляется. Проверены полная страница, её соседние байты, регистры и флаги, включая 4096 нулевых количеств. Ненулевые минимумы намеренно менялись, их упорядоченность не требовалась классификатором. Это модель исполнения исходного кода, без IRQ, сборки и нативного запуска.
