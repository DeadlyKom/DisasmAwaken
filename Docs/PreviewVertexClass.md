# Классификация спроецированных вершин

[ClassifyPreviewVertices.asm](../Source/D3D/ClassifyPreviewVertices.asm), банк 4, #DF46..#DFA5, читает готовые записи страницы C6 после [обхода модели](PreviewModelGroups.md). В каждую пройденную запись добавляется пятый байт кода сторон. Проекция сама этот байт не заполняет.

## Физическая запись и стороны

| Смещение | Поле | Назначение |
| --- | --- | --- |
| 0..1 | Вторая координата | Слово результата с центром HalfY |
| 2..3 | Первая координата | Слово результата с центром HalfX |
| 4 | Код сторон | Классификатор заполняет после чтения обоих слов |

Старт #C601 указывает на старший байт второй координаты. Его точное значение #80 означает маркер отказа проекции и немедленно прекращает весь проход с A=0,F=#44. Это относится ко всем словам #8000..#80FF второй координаты. Такой же старший байт первой координаты обрабатывается обычным отрицательным значением.

Для каждой оси проверяется отрицательный знак, положительный ненулевой старший байт либо младший байт при нулевом старшем. Отрицательное слово выходит за нижний ноль. Любое положительное слово с ненулевым старшим байтом не меньше байтового верхнего предела. При нулевом старшем сравнивается младший с исключённым пределом.

Предел первой оси расположен по #DF7F и называется AfterMaxX, второй по #DF64 и называется AfterMaxY. [ConfigurePreviewClip](PreviewClipBounds.md) заполняет их значениями верхний предел+1 с байтовым оборачиванием. Ненулевые нижние границы из остальных операндов окна здесь не читаются.

## Биты

Младший код C содержит четыре независимых признака:

| Бит | Маска | Условие |
| --- | --- | --- |
| 3 | #08 | Первая координата меньше нуля |
| 2 | #04 | Первая координата не меньше AfterMaxX |
| 1 | #02 | Вторая координата меньше нуля |
| 0 | #01 | Вторая координата не меньше AfterMaxY |

Нулевой младший код означает вершину внутри обоих диапазонов. Два противоположных бита одной оси одновременно не устанавливаются. Поэтому фактически получаются девять кодов, а не все шестнадцать комбинаций младшей тетрады.

Пятый байт равен ((C XOR #0F) SHL 4) OR C. Схема разрядов 7..0: [не XBelow, не XAbove, не YBelow, не YAbove, XBelow, XAbove, YBelow, YAbove]. Старшая тетрада зависит от младшей и не является отдельным набором независимых флагов.

Внутренняя вершина получает #F0. Все полученные байты объединяются через OR в AF'. Итоговая младшая тетрада показывает OR выходов отдельных вершин, старшая равна инверсии AND младших кодов.

Вызывающий проход по #EF3F сначала проверяет нулевой результат, затем CPL и AND #F0 выявляют общую внешнюю сторону всех вершин. При отсутствии общей стороны младшая тетрада различает все внутренние вершины и необходимость дальнейшей обработки пересечений. Сам классификатор граней не рисует.

## Счётчик и исходное поведение пустого входа

B=(NextOffset−4) AND #FF. Для штатных n=1..50 NextOffset=4+5*n и обрабатываются ровно n записей. После пятого байта смещение следующей записи сравнивается с B, затем L ещё раз указывает на старший байт второй координаты.

Сложения адресов сделаны через INC/DEC L. При переходе через #FF страница C6 сохраняется. Число шагов до совпадения для произвольного B равно (205*B) mod 256, нулевой результат означает 256. Все чтения учитывают уже перезаписанные байты той же страницы.

В частности, NextOffset=4 не означает пустой пропуск. Если раньше не встретится маркер, выполняются 256 итераций с оборачиванием и записью во все позиции страницы. Это исходная особенность, защитный выход не добавляется. В проверенных физических моделях списки непустые.

## Регистры и частичные записи

HL сохраняется через PUSH/POP, DE, альтернативные HL/DE/BC и IX/IY также сохраняются. B содержит вычисленный байтовый конец, C последний младший код либо ноль после маркера.

При полном проходе основной AF содержит накопленный OR и его точные логические флаги. AF' содержит A'=B и F'=#42 OR (B AND #28), недокументированные биты CP берутся из сравниваемого B. При раннем маркере основной AF=#0044, альтернативный AF сохраняет уже накопленный OR, до первой вершины он равен #0044. Входной AF' не сохраняется.

После маркера код текущей и последующих записей не меняется, предыдущие коды остаются записанными. CPU-стек использует два байта под входным SP для сохранения HL, адрес возврата не записывается. Итоговый SP равен входному+2. I, IFF и IM не меняются.

## Проверка

[CheckPreviewVertexClass.py](../Tools/Disasm/Research/CheckPreviewVertexClass.py) сравнивает исходные инструкции с независимой [моделью координат и изменяемого буфера](../Tools/Disasm/Research/PreviewVertexClassOracle.py). Пройдены 199008 случаев: все 65536 слов каждой оси, все байтовые пороги и координаты, маркер в каждой проверяемой позиции, случайные буферы и все 256 счётчиков.

Проверены весь буфер, точные частичные записи, все изменяемые и сохраняемые регистры, AF' и CPU-стек. [Отчёт](../Tools/Disasm/Reports/PreviewVertexClassVerification.json) не подтверждает дальнейшую обработку граней, аппаратные IRQ, сборку или нативную игру.

Буфер [PreviewProjectedVertices.asm](../Source/D3D/Data/PreviewProjectedVertices.asm) сохраняет исходные 256 байтов страницы C6. Он содержит 51 физический FPreviewProjectedVertex с полями SecondAxis, FirstAxis, Outcode и отдельный TailByte по #C6FF. Начальные коды сохраняются из образа, значение #F0 не подставляется вместо исходных байтов. Декларация физической ёмкости не заменяет ограничения штатного прохода, подтверждённые модели имеют не больше 32 вершин.
