# Четыре входа выбора свойств ключа

[ReadCurrentKeyParams](../Source/Text/ReadCurrentKeyParams.asm) и [ReadOtherKeyParams](../Source/Text/ReadOtherKeyParams.asm) выбирают код 0 либо 1 по умолчанию и группу трёх полей. Таблица за якорем CA25 содержит s по CA28, c по CA2B и u по CA2E. Это [GetKeyMajor](../Source/Text/GetKeyMajor.asm), [GetKeyMinor](../Source/Text/GetKeyMinor.asm) и [GetKeySize](../Source/Text/GetKeySize.asm), а не читатели пятибайтовых записей.

[ReadCurrentKeyCodes](../Source/Text/ReadCurrentKeyCodes.asm) и [ReadOtherKeyCodes](../Source/Text/ReadOtherKeyCodes.asm) выбирают те же коды по умолчанию и группу двух полей за якорем CA2E. p по CA31 вызывает [GetKeyFingerprint](../Source/Text/GetKeyFingerprint.asm), g по CA34 [GetKeyRegion](../Source/Text/GetKeyRegion.asm). Формулы характеристик описаны в [WorldSignature](WorldSignature.md), выбор ключа в [KeyChoice](KeyChoice.md).

Без явного числа C получает 0 либо 1. Явное число через ParseFieldSuffix даёт (число-1) AND FFFF. Суффиксный обработчик снимает слово в BC и уменьшает C, второй ключ выбирается, если младший байт до уменьшения был 1. Следовательно, явное число 2 выбирает второй ключ, 1 текущий, 0 также текущий с изменением C до FE после исходного FFFF. Старший байт слова выбора сохраняется в B.

Без точки выполняется локальный RET, возвращающий DE якорь таблицы CA25 либо CA2E, HL индекс выбора, B исходный контекст и C код по умолчанию. Числовое поле при этом не вычислялось. A и F остаются от первого непрочитанного символа и последнего CP парсера. Это исходный путь, он не подменён выдачей признака.

С точкой результат и основные флаги определяются соответствующим обработчиком GetKey. У Size дополнительно EX DE,HL меняет смысл выходного HL. Альтернативный B задаётся числом 3 либо 2, его C и альтернативные HL/DE сохраняются. Альтернативный AF меняется банковым запросом поля. IX у первого непрочитанного символа, IY, I и IFF сохраняются, SP обычного возврата увеличен на два. Неизвестный суффикс передаёт управление SkipLine без обычного результата.

[CheckKeyFieldSelectors.py](../Tools/Disasm/Research/CheckKeyFieldSelectors.py) исполняет все четыре входа, разбор, поиск, пять настоящих обработчиков и переключения банков в 10920 случаях. Проверены все байтовые коды выбора, явные ноль и большие числа, текущий и второй ключи, варианты 0, 1, 255, все допустимые символы и путь без точки. Сверены DE, HL, BC, AF, IX, SP, альтернативные пары и записи страниц. Отчёт [KeyFieldSelectorsVerification](../Tools/Disasm/Reports/KeyFieldSelectorsVerification.json). Сборка, IRQ и нативный игровой запуск не выполнялись.

 
Во всех четырёх входах собственный префикс меняет регистры, затем выполняет JP ParseFieldSuffix, дополнительного кадра CALL он не создаёт. Парсер всегда записывает DefaultTarget по #C804..#C805 адресом локального NoSuffix. Без числа и точки это единственные записи RAM всей цепочки. При явном числе временные рамки сохраняют контекст и возврат десятичного читателя. На пути свойства слово выбора снимается GetKey-обработчиком и повторно используется его CALL DescribeKeyChoice.

Расширенная модель на тех же 10920 случаях сравнивает все нестековые записи с независимым расчётом. Ожидаются DefaultTarget, при запросе поля дополнительно выбор банка 1, инициализация четырёх байтов WorkKey и Variant+1 преобразований, выбор банков 0 и 6. Любая иная запись вне временного стека вызывает ошибку модели. При входном SP=#7FFE все остальные зарегистрированные записи находятся в #7FF0..#7FFD, исходное слово возврата по #7FFE..#7FFF сохраняется. Наблюдатель проверен отдельной настоящей записью CPU.

R изменяется, полное его значение в этой модели не проверено. Выборки ключей и Variant конечны, все адреса стека и все сочетания ключей не охвачены. Ошибочные суффиксы дополнительно проверены ниже. Порядок шинных циклов по журналу симулятора не устанавливается. При неизвестном суффиксе действует ранее разобранный нештатный выход FindToken через SkipLine со сбросом SP, договор обычного результата к нему не применяется.


## Ошибка выбора поля и отбрасывание стекового операнда

Дополнительные 5070 случаев исполняют все недопустимые байты суффикса для каждой из четырёх таблиц при пяти вариантах числового префикса, без числа, 0, 2, 65535 и 99999. Для таблиц s/c/u недопустимы 253 байта, для p/g 254. Весь диапазон 00..FF классифицируется буквально, NUL и CR в позиции суффикса также поступают в FindToken, поскольку ParseFieldSuffix уже потребил байт.

При исходном SP=#7FFE промах поиска достигает SkipLine со SP=#7FFA. Два нижних слова содержат временный возврат поиска и индекс выбора. Ни GetKey, ни DescribeKeyChoice не вызываются, банковых переключений и записей WorkKey нет. Нестековые записи до ошибки ограничены двумя байтами DefaultTarget. SkipLine заменяет SP значением SavedSP=#7FFE, пропускает оставшийся X до CR, затем NextCommand.ReadCommand видит NUL и возвращается по исходному адресу с SP=#8000. Этот путь не выдаёт обычное значение поля.

Проверены настоящие инструкции всех названных процедур. После входа SkipLine дополнительных записей CPU не зарегистрировано. Выборка не доказывает все размещения текста и стека, восстановление после произвольного повреждения сценария, прерывания или полный игровой запуск.


Четыре внешние обёртки со словной записью выражения дополнительно проверены полным исполнением, 10920 обычных случаев и 5070 ошибок суффикса. Сброс стека обходит запись результата, HL' и прежнее слово выражения сохраняются. Область прямого входа затенённой y и отдельный отчёт приведены в [ExpressionPushes](ExpressionPushes.md#полные-композиции-параметров-ключа).
