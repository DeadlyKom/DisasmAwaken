# Извлечение Awakenv02.trd

## Исходный носитель

Источник: `Tools/Disasm/Disk/original.trd`.
Размер: 655360 байт. Сектор: 256 байт. В одной логической дорожке 16 секторов.
Нумерация сектора в записи каталога начинается с нуля.

SHA-256:

```text
55a11de202a5334547e39a6db42c945242a2a53559dc1cf601522219e3463f32
```

Служебные байты `#08E0..#08FF` сохранены в манифесте как исходная строка hex.
Их значения не использовались как основание для исключения записей каталога.
Просмотрены все 128 записей, а не только число действующих файлов из
служебного сектора. Непустых записей обнаружено 44.

## Правила извлечения

Для каждой записи сохранены четыре файла:

| Суффикс | Значение |
| --- | --- |
| `.bin` | Байты по длине из полей `#0B..#0C` записи |
| `.sectors.bin` | Все сектора по числу из поля `#0D` |
| `.header.bin` | Все 16 байт исходной записи каталога |
| `.tail.bin` | Байты между логической длиной и концом выделенных секторов |

Смещение в образе вычислено по исходным полям записи:

```text
offset = (first_track * 16 + first_sector) * 256
allocated_length = sector_count * 256
```

Первые четыре килобайта сохранены в `Tools/Disasm/Disk/System.bin`.
Остальные области, не принадлежащие ни одной непустой записи каталога,
сохранены в `Tools/Disasm/Disk/Unallocated`. Их имена содержат физическое
смещение начала области в исходном образе.

Имена извлечённых файлов включают номер исходной записи, поэтому одинаковые
имена TR-DOS не приводят к перезаписи данных. Пробелы и неподходящие символы
заменены только в имени артефакта. Исходные восемь байт имени сохранены в
`raw_name_hex` манифеста и в `.header.bin`.

У удалённых записей первый байт имени уже заменён в самом образе на `#01`.
Исходный первый символ не восстановлен и не придуман. В имени извлечённого
артефакта вместо него поставлено подчёркивание.

Поле `parameter` манифеста содержит исходное слово `#09..#0A` без назначения
ему универсального смысла адреса загрузки. Интерпретация зависит от типа
файла и фактического пути загрузки. Нестандартные расширения сохранены.

## Важные области за логической длиной

| Запись | Имя в каталоге | Логическая длина | Выделено секторов | Полный размер | Хвост |
| --- | --- | ---: | ---: | ---: | ---: |
| 0, удалена | Первый символ утрачен, остаток `XTime15.B` | 327 | 237 | 60672 | 60345 |
| 3 | ` AWAKEN.B` | 119 | 45 | 11520 | 11401 |
| 9 | `stscr.C` | 3230 | 239 | 61184 | 57954 |

Термин «хвост» обозначает положение относительно каталожной длины,
а не отсутствие полезных данных.

В записи 3, со смещения `#0006` внутри первого сектора, обнаружены инструкции:

```text
DI
LD SP,#5FFF
LD IY,#5C3A
LD HL,#6500
PUSH HL
DEC H
LD DE,(#5CF4)
LD B,#2C
LD C,#05
JP #3D13
```

Последовательность устанавливает стек, кладёт на него адрес `#6500`,
выбирает буфер `#6400` и передаёт управление интерфейсу TR-DOS для чтения
44 секторов. Физическое начало этого чтения зависит от значения `#5CF4`.
Соответствие загруженных байтов конкретным адресам памяти пока не доказано.
Этот фрагмент является результатом статического чтения байтов, а не
готовой процедурой исходного проекта и не доказательством запуска игры.

Не следует линейно интерпретировать все хвосты как инструкции Z80.
В них могут находиться код, таблицы, графика и другие данные. Разделение
потребует трассировки реального загрузчика и его переключений банков.

## Проверка извлечения

`Tools/Disasm/Disk/Manifest.json` содержит:

- 44 записи, из них 41 действующая и 3 удалённые.
- Исходные параметры, физические смещения и контрольные суммы файлов.
- 46 физических компонентов, покрывающих все 655360 байт образа.
- Результат независимого от сохранённой копии образа размещения компонентов
  в пустом буфере по исходным физическим смещениям.

Проверены отсутствие пересечений компонентов, полное покрытие образа,
побайтовое совпадение и совпадение SHA-256. Результат сохранён в поле
`verification`, где `byte_identical` имеет значение `true`.

Это проверка извлечения. Она не подтверждает сборку из ASM, корректность
дизассемблирования, работоспособность проекта в SjASMPlus или запуск игры.
На этапе извлечения SjASMPlus и другие сборочные инструменты не запускались.
Последующая проверенная сборка описана отдельно в `Docs/Build.md`.

Скрипт использует стандартную библиотеку Python. При повторном извлечении
отказывается перезаписывать существующий файл, если его содержимое отличается.
