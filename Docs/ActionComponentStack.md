# Восстановление стека рабочих компонент

[RestoreComponentStack](../Source/Action/RestoreComponentStack.asm) — исходная LD SP,nn по 6C40..6C42 перенесённого ACTION. SavedCpuSP по 6C41 заполняется перед векторным вычислением. Вычислитель использует SP как числовой накопитель и возвращается сюда через IY.

Это часть (0) последовательной пары. Следующая часть (1), [EncodeSignedComponents](../Source/Action/EncodeSignedComponents.asm), начинается с RET PE. Поэтому действительный стек с внешним возвратом восстанавливается и при переполнении. RAM и данные регистров не меняются, SP получает сохранённое слово, R получает один M1 с сохранением бита 7. I, IM, IFF и paging сохраняются при отсутствии вмешательства IRQ.

[Проверка](../Tools/Disasm/Research/CheckActionComponentStack.py) прошла все 65536 значений сохранённого SP до первого чтения стека. Сопоставлены все регистры включая R, все банки RAM и отсутствие записей. Значения синтетического SP не являются новым размещением игрового стека и не объявляются допустимыми для последующего RET.

[Отчёт](../Tools/Disasm/Reports/ActionComponentStackVerification.json) не доказывает IRQ, точные T, сборку или нативный запуск. Физический операнд сохранён, дополнительная память не выделяется.
