# Публикация вектора третьего экранного знака

[PublishThirdGlyphVector](../Source/Action/PublishThirdGlyphVector.asm), исходные 6CB4..6CD5 перенесённого ACTION, связывает результаты [ComputePatchedVector](../Source/Action/ComputePatchedVector.asm) с физическим входом Third в [GlyphIndicatorState](../Source/Action/Data/GlyphIndicatorState.asm).

Входной P/V=1 немедленно завершает фрагмент, сохраняя старые X, Y и SignSource. На штатном пути это переполнение предыдущего арифметического вычислителя. CPU SP должен быть восстановлен до этого RET.

При входном P/V=0 выполняются присваивания в строгом порядке:

1. Third.X по 9B85 получает младший байт знаковой четверти Output0 по D9B6.
2. Third.Y по 9B84 получает младший байт знаковой четверти Output1 по D7C4.
3. Third.SignSource по 9B86 получает старший байт Output2 по D7A2.

SRA H и RRA выполняются дважды. Отрицательные слова делятся с округлением вниз, затем сохраняется только младший байт. Например FFFF даёт FF. Насыщения здесь нет. Настоящий [UpdateGlyphIndicators](../Source/Controls/UpdateGlyphIndicators.asm) позже ограничивает экранные координаты и выбирает заполненную либо полую форму по знаку SignSource. Входной вектор относится к компасу на станцию, его единицы расстояния ещё не установлены.

При публикации H равен арифметической четверти исходного старшего байта Output1, L сохраняет его исходный младший байт. A равен HIGH(Output2), но F остаётся от последнего RRA. S/Z/P отражают сдвинутый H, биты 5/3 — Third.Y, Carry — исходный бит 1 LOW(Output1), H/N сброшены. Поэтому выходной P/V успешного пути не является сохранённым статусом переполнения векторного вычислителя.

DE, BC, альтернативные и индексные регистры сохранены. При раннем выходе HL и AF тоже сохранены. I, IM, IFF и paging не меняются при отсутствии вмешательства IRQ. SP после RET равен входному SP+2, CPU-стек только читается. R получает один M1 для раннего выхода и 22 M1 для публикации с сохранением бита 7.

[Модель](../Tools/Disasm/Research/CheckActionThirdGlyphPublish.py) проверила 65792 сценария. Все 16-битные слова каждого делимого поля покрыты двумя перестановками домена, отдельно проверены все входные F. Сопоставлены регистры включая R, восемь банков RAM и порядок трёх однобайтовых записей. Полное произведение трёх входных слов не перебиралось.

[Отчёт](../Tools/Disasm/Reports/ActionThirdGlyphPublishVerification.json) не доказывает аппаратные IRQ, точные T, сборку или нативный запуск. Размещение и физические структуры сохранены, дополнительные поля или буферы не вводились.

Архивное назначение Third и источника #9B78 подтверждено как компас на станцию, [STATCOMPOS, физический вектор и полная сверка 71 байта](ActionThirdGlyphVector.md#компас-на-станцию-и-архивный-statcompos). Единицы расстояния остаются открытыми.
