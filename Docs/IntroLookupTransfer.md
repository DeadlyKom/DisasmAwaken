# Табличные фазы и перенос текстурных слов

[RenderLookupTexture](../Source/Intro/RenderLookupTexture.asm), вход `6B9C`,
подготавливает две сгенерированные цепочки и передаёт управление
[PresentLookupTexture](../Source/Intro/PresentLookupTexture.asm).
Контракт этого фрагмента заканчивается **перед** восстановлением CPU SP
в продолжении, весь кадровый путь с IRQ этим не считается проверенным.

Таблицы `9400..97FF` выбираются четырьмя младшими фазовыми индексами
из операндов `6BA2`, `6BA6`, `6BA9`, `6BAC`.
256 копий [PhaseSum](../Source/IntroTemplates/PhaseSum.asm) по `9900`
складывают по одному байту каждой таблицы modulo 256. Сумма выбирает
элемент `9800..98FF`, результат записывается в `9300..93FF`.
Все индексы увеличиваются только младшими байтами.

EX DE,HL переставляет две исходные таблицы на соседних копиях.
Коммутативная сумма сохраняется. Последняя, четвёртая, выборка каждого
прохода всё равно берётся из таблицы 94. Её Carry участвует в выходном F.
Последующий INC L первой фазы определяет остальные флаги.

В последней копии сумматора INC E заменён RET. Следующий EXX не исполняется.
Поэтому итоговый DE=93FF, активен набор таблицы 94, а альтернативные
HL', DE', BC' содержат таблицы 96, 97, 95 с прежними фазами.
Все четыре фазовых индекса после 256 шагов вернулись к исходным значениям.

Затем HL получает адрес строки из изменяемого операнда PointerRow по `6BB2`.
CPU SP сохраняется в `IntroLookupState.SavedSP` по `6BBD`, а рабочий SP
становится указателем на 608 байтов данных.
Цепочка `A800..ACC2` читает 304 слова и записывает по восемь слов
в начала 38 страниц `C0..E5`, всего 608 байтов.
Остальные 240 байтов каждой страницы не меняются.

Последний JP входит по `6BBC`. В этот момент SP равен PointerRow+608,
HL содержит последнее перенесённое слово. Продолжение первым LD SP,nn
восстановит CPU SP. Ни CALL, ни RET внутри переноса через временный SP нет.

[Проверка](../Tools/Disasm/Research/CheckIntroLookupTransfer.py) получает обе
настоящие цепочки исполнением
[InitializeLookupEffect](../Source/Intro/InitializeLookupEffect.asm) до таблиц фаз.
Отдельная числовая модель вычисляет суммы, конечные регистры, все физические
записи, сохранённый SP и кадр вызова сумматора.

768 сценариев покрывают все младшие значения каждой фазы в сочетаниях
и три CPU-стека. [Отчёт](../Tools/Disasm/Reports/IntroLookupTransferVerification.json)
подтверждает регистры кроме R, все восемь банков RAM и кратность записей.
Все 256⁴ сочетаний фаз не исчерпаны. Продолжение с IRQ, время и нативный
показ кадра не проверялись.
