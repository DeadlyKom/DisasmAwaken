# Три проверки исходных компонент с цепочкой Carry

[CheckCloseRecordBounds](../Source/Action/CheckCloseRecordBounds.asm) занимает E1D1..E212 ACTION банка 0. На входе HL содержит масштабированную границу из [PrepareProjectionScale](ActionScaleHeader.md), HL′ адрес записи для возможного [DispatchCloseRecord](ActionCloseRecord.md). BC сохраняется в рамке, а DE восстанавливается из исходной границы только на обычном пути. Это последовательный фрагмент без собственного RET, локальные выходы — E213 и DCE3 банка 1.

## Сравнения

В рамке сначала сохраняются BC и полное слово границы. Первая проверка использует unsigned-половину этой границы, полученную SRL H и RR L. Последний RR оставляет младший бит исходной границы в Carry. Проверяется Input0, для отрицательного слова выполняется ADC, для неотрицательного SBC. Поэтому арифметика имеет вид `left + negative_word + Carry` либо `left - positive_word - Carry`, с оборачиванием слова.

Если знаковый бит первого результата установлен, вызов обработчика пропускается. Иначе из рамки восстанавливается полная граница и проверяется Input2. POP и PUSH не сбрасывают Carry, BIT проверки знака также его сохраняет. После допуска Input2 тем же способом проверяется Input1. Его условный CALL P выполняется только при сброшенном Sign. Порядок компонент 0, 2, 1 сохраняется.

Каждый раз Carry берётся из предыдущей арифметики. Независимые сравнения `граница >= abs(component)` не эквивалентны этому коду. Например, при границе 1 половина равна 0 с Carry=1. Для Input0=0 первый SBC даёт FFFF и отказ. Для Input0=FFFF первый ADC с тем же Carry даёт 0000 и допускает следующий шаг. Знаковое переполнение отдельно не проверяется, изменение алгоритма ради симметрии или исправления границ не выполняется.

## Диспетчер и стек

Если условный вызов не выполнен, HL и F относятся к последней достигнутой арифметике, A остаётся входным. При вызове результат HL, AF и IX определяется DispatchCloseRecord. Вернувшийся путь затем извлекает исходную границу в DE и входной BC, SP становится равным входному, следующий PC=E213 в [ClipProjectionBounds](ActionProjectionClip.md).

При передаче класса 12 через диспетчер и [TransferToStationLoader](ActionStationTransfer.md) управление уходит на DCE3 банка 1. SP равен входному SP−6. Сохранённые BC, граница и адрес E211 остаются в рамке. DE=0, BC входной, AF=1142, IX содержит входной HL′. Позднейшая процедура смены режима не считается обычным возвратом этого вызова.

| Путь | Максимальная дополнительная глубина CPU-стека |
| --- | --- |
| отказ одной из трёх проверок | 4 байта |
| запрет диспетчера ненулевым InhibitCode | 6 байтов |
| вернувшаяся обработка записи | 8 байтов |
| передача следующему режиму | 10 байтов |

Временные рамки дочерних процедур переиспользуют одни ячейки, их размеры не складываются как независимые сохранения. HL′, DE′, BC′, AF′, IY, I, IM и IFF сохраняются в локальной границе. Векторные слова, SpeedWord и код запрета меняются только через доказанный дочерний путь. FirstValue через корневой вызов здесь не записывается: класс 12 передаёт режим вместо общего хвоста дополнительного входа.

## Проверка

[CheckActionCloseBounds.py](../Tools/Disasm/Research/CheckActionCloseBounds.py) исполняет исходные сравнения и настоящий диспетчер с его дочерними инверсией и селектором страницы. [Отчёт](../Tools/Disasm/Reports/ActionCloseBoundsVerification.json) содержит 267365 сценариев, все слова границы и трёх компонент по отдельным сечениям, все классы и коды запрета, четыре исходные конфигурации банка 0 и совместные крайние слова с нечётными границами.

Сравниваются регистры, оба набора, флаги, R, SP, восемь физических банков, каждая запись RAM и фактические OUT 7FFD. Эталон родителя использует отдельно доказанные числовые переходы диспетчера, полный независимый эталон всех детей и полный декартов перебор входов не заявляются. Продолжения E213 и DCE3 не исполняются. Весь окружающий цикл, дисковая загрузка, прерывания и нативный игровой процесс остаются отдельными границами проверки.
