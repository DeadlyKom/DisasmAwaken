# Косвенные чтения за таблицей количеств скимера

В STATIONF таблица из 14 кодов количества занимает `#98F6..#9903`.
Четыре байта после неё переносятся между станцией, полётом и сохранениями.
Исходные инструкции LANG могут читать эти байты через вычисляемые адреса.
Ниже указаны входы и состояния, при которых это подтверждено.
[Смещения переноса](ActionContextTail.md)

Три [поиска сохранённых точек карты](StoredMapPoints.md) дополнительно
проверены в 55296 сценариях с наблюдением всех шести байтов 9904..9909.
Они их не читали и не меняли. Литерал IX=9905 по C40F обозначает
позицию перед первой записью, до обращения к данным прибавляется пять.
Отсутствие чтения в этих поисках не отменяет подтверждённых ниже
косвенных чтений другими процедурами и не закрывает назначение пары 50 FF.

## Чтение вторым печатателем

Вход `#73DE` строит окно из исходного элемента 0. В модели после
рамки и заголовков доступны ширина 252 и высота 245. От этой точки
выполнены 98 прогонов `RenderRows` по `#73FB`, все начальные индексы
0..13 для блока STATIONF и шести исходных SAVE. В каждом прогоне
исходный текст `#F066` сохранён, 512 байтов состояния загружены целиком,
начальный индекс передан в HL. Прерывание исполнялось при подготовке
рамки, во время повторов тела прерывания отсутствовали.

В 21 попытке каждой отрисовки команда `#729D` последовательно читает
коды от `#98F6+HL` до двадцатого байта после него. Все четыре
соседних адреса входят в этот диапазон при каждом начальном индексе.
Для STATIONF и SAVE0..SAVE4 байты `#50, #FF, #00, #00` дают
количества 80, 0, 0, 0, для SAVE5 все четыре количества равны нулю.
Печататель оставляет 512 байтов состояния прежними. Штатное назначение
callback второго списка и независимое назначение самих байтов
остаются открытыми.

## Прямое чтение количества и предела

[ReadSecondQuantity](../Source/Text/ReadSecondQuantity.asm) принимает явное
десятичное число, вычитает единицу и читает по адресу `#98F6+индекс`.
Чтение по `#C1DC` использует исходный байт либо его побитовую инверсию
при установленном бите 7. [ReadSkimmerEquipmentLimit](../Source/Text/ReadSkimmerEquipmentLimit.asm)
получает индекс со стека, складывает его младший байт с той же базой и
проверяет бит 7 инструкцией по `#C580`. Для обоих путей проверено выполнение
оригинальных инструкций на четырёх неизменённых байтах STATIONF.

| Адрес | Байт | Явное число | Индекс со стека | Количество | Предел |
| --- | --- | ---: | ---: | ---: | ---: |
| `#9904` | `#50` | 15 | 14 | 80 | 127 |
| `#9905` | `#FF` | 16 | 15 | 0 | 1 |
| `#9907` | `#00` | 18 | 17 | 0 | 127 |
| `#9909` | `#00` | 20 | 19 | 0 | 127 |

[HasSecondActiveNeighbor](../Source/Text/HasSecondActiveNeighbor.asm)
проверен для всех 256 младших байтов индекса при исходных границах.
Индексы 0..13 обходятся без чтений перечисленных адресов. Из остальных
11 индексов обращаются к ним. Например, индекс 15 читает левый байт
`#9904` по `#C534`, индекс 14 читает правый `#9905` по `#C549`.

## Проверка порогов

[CheckThresholdSet14](../Source/Text/CheckThresholdSet14.asm) читает
байты порогов по `#98F6+2×строка`. Активность приходит последовательно из
`#9632`. Для исходного STATIONF первая строка активна, порог `#FF`.
Во всех 256 вариантах ключа с полученными признаками 1..16 сравнение
отклоняет первую строку и возвращает `HL=#98F6`, `B=14`, `A=0`.
При подстановке нулей в первые семь порогов сравнение по `#C50A`
доходит до `#9904`, читает исходный `#50` и возвращает отказ на строке 7.

## Взвешенная загрузка

[ComputeWeightedLoad](../Source/Text/ComputeWeightedLoad.asm) читает
дополнительное слагаемое по `#C8FD` из `#9829+((ROL8(код,2)+код) AND #FF)`.
При исходном индексе скимера `#FF` это чтение пропускается. Перебор всех
256 байтов дал следующие обращения к рассматриваемым четырём адресам.

| Код скимера | Адрес | Слагаемое |
| --- | --- | ---: |
| `#2C`, `#5F`, `#92`, `#C5` | `#9905` | 255 |
| `#F8` | `#9904` | 80 |
| `#F9` | `#9909` | 0 |

Прямые чтения проверены с явными индексами за таблицей. Поиск соседей и
дополнительное слагаемое проверены принудительным перебором, порог после
семи строк — с изменёнными входными данными. Штатное игровое обращение
к этим байтам и исходное назначение полей остаются открытыми. Разметка
образа сохраняет все четыре байта на прежних местах.

## Исходный торговый сценарий

Подтверждение второй категории модели передаёт LANG события 3 или 4,
обработчик второго списка оснащения передаёт 7 или 8. В активном
торговом тексте отсутствуют все четыре условных блока. В 44 прогонах
с настоящим интерпретатором эти события выполняли только общий начальный
пересчёт загрузки и сохраняли прежний выбор. Вход записи индекса
скимера и сумматор индекса из D3D не вызывались.
[События моделей](ShipTrade.md) · [Индекс D3D](Bank4Index.md)
· [Второй список оснащения](../Tools/Disasm/Reports/SecondaryEquipmentRowsVerification.json)

При четырёх индексах физического ценового списка скимеров и значении
`#FF` пересчёт не обращался к четырём соседним байтам. Если перед входом
в сценарий подставить один из шести кодов из таблицы выше, та же
команда `T` читает соответствующий соседний байт по #C8FD. Это
подтверждает зависимость от ранее записанного значения `SkimmerIndex`.
Происхождение этих кодов в штатном игровом состоянии не установлено.
[Трасса сценариев](../Tools/Disasm/Reports/SecondaryContextAliasesVerification.json)

## Явное присваивание и сохранение

В LANG команды `=i15:35`, `=i16:35`, `=i18:35` и `=i20:35`
выбирают соответственно `#9904`, `#9905`, `#9907` и `#9909`.
Писатель захватывает адрес после чтения по `#C1DC`. Перед записью
`Store` снова читает байт по `#C6DC` и инвертирует младший байт
результата, если бит 7 текущего значения установлен. Инструкция по
`#C6E2` записывает ровно один байт. Например, из исходных `#50` и
`#FF` при правом операнде 35 получаются `#23` и `#DC`.
[Писатель](../Source/Text/PushSecondQuantityWriter.asm)
· [Договор Store](IndexedWriters.md)

Модель выполнила 168 одиночных присваиваний на исходных блоках шести SAVE.
В каждом случае проверены два чтения цели, одна запись и все 512 байтов
состояния. Затем четыре присваивания были выполнены подряд для каждой
копии. Обычный писатель SAVE сохранил результат, а загрузчик прочитал
его обратно через ROM TR-DOS 5.04T и модель контроллера. Сравнены оба
сектора каждого файла и все остальные байты диска в памяти.

Строки присваивания подставлялись только в RAM модели, остальной
интерпретатор выполнялся на исходных байтах. Для SAVE5 напрямую
подставлен номер позиции 5. Доказан путь записи и сохранения при
явном индексе. Штатный источник таких присваиваний и исходное назначение
четырёх байтов остаются открытыми.
[Проверка](../Tools/Disasm/Research/CheckSecondaryContextWrites.py)
· [Результат](../Tools/Disasm/Reports/SecondaryContextWritesVerification.json)
