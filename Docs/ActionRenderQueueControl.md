# Чтение runtime-очереди

[ReadRenderQueue](../Source/Action/ReadRenderQueue.asm) содержит два входа, начало E4A6 и LoadNode по E4B1. [SelectRenderQueueNode](../Source/Action/SelectRenderQueueNode.asm) по E4FF проверяет полный байт смещения на конечное значение 01. Все адреса относятся к ACTION банка 0.

Основной вход восстанавливает SP из изменяемого операнда SavedEntrySP по E4A7. Этот операнд ранее заполняет пролог UnknownE020 до использования стека как указателя на записи. Затем A получает Head, H получает 8F, L и F сохраняются, управление передаётся селектору. При Head=01 селектор выполняет RET по восстановленному стеку. При другом байте он заменяет L на A и переходит в LoadNode. Сам селектор не проверяет допустимость страницы или смещения.

## Вход LoadNode

На входе HL указывает на [FActionRenderNode](ActionRenderQueueInsert.md). PUSH HL сохраняет указатель на обычном CPU-стеке, адрес этого слова записывается в SavedNodeSP по E4D6. Три INC L пропускают Next и два неизвестных байта 01/02, затем SP становится указателем на HeaderWord0. Допустимые смещения 00, 0E, ..., EE гарантируют отсутствие пересечения границы страницы при этом байтовом расчёте.

Два POP HL восстанавливают HeaderWord0 по 9B8D и PhasePair по 9B12. DEC SP возвращается к старшему байту PhasePair. Последующий POP AF берёт из него F, а из следующего байта Phase2 значение A для 9B14. Затем POP HL, POP DE и POP BC читают Output0, Output1, Output2 и сохраняют их в исходные переменные. Это точная обратная раскладка записи InsertRenderQueue, включая перекрытие F, без исправления исходного формата.

После загрузки SP восстанавливается из SavedNodeSP, указатель узла остаётся на вершине. CALL исполняет настоящий [UpdateAyEffects](ActionAyEffects.md), после возврата управление продолжается по [RenderQueuedObject](ActionQueuedObject.md). Максимум дополнительного CPU-стека в пределах самого LoadNode равен четырём байтам, два для сохранённого указателя и два для CALL. В точке E4DB SP равен входному SP минус 2. RenderQueuedObject сохраняет договор этой рамки до своего POP HL.

Итоговые AF, BC и HL задаются потребителем AY, DE остаётся равным загруженному Output1. AF содержит уровень `max(4, ChannelCLevel >> 1)` и флаги сравнения половины уровня с 4. BC=BFFD. H относится к продвинутому курсору B либо равен нулю при отключённом B, L содержит 00 или 20 по порогу прочитанного R. Значение R включает инструкции загрузки и CALL, поэтому сдвиг точки вызова менял бы шум. Альтернативные пары, IX, IY, I, IM, IFF и paging сохраняются.

## Проверки и ограничения

[CheckActionRenderQueueControl.py](../Tools/Disasm/Research/CheckActionRenderQueueControl.py) проверяет 131072 сценария. Все 65536 слов SavedEntrySP проверяются до передачи селектору, без чтения произвольного адреса как нативного стека. Отдельно проверяются все 65536 сочетаний A/F селектора, 256 возвратов по A=01 и 65280 переходов к LoadNode.

[CheckActionRenderQueueLoad.py](../Tools/Disasm/Research/CheckActionRenderQueueLoad.py) проверяет ещё 8704 композиционных сценария загрузки. Используются все восемнадцать физических смещений узлов, все байты R и уровня C, активность и завершение обоих потоков по исходным адресам EE02/EE1B. Эталон родительской загрузки соединён с ранее независимо проверенным договором AY, все дочерние инструкции исполняются без подмен. Это не второе независимое доказательство всего AY-потребителя.

Проверяются регистры обоих наборов, флаги, R, SP, вся физическая RAM, кратность записей, портовые события и чтения смесителя. [Отчёт управления](../Tools/Disasm/Reports/ActionRenderQueueControlVerification.json) и [отчёт загрузки](../Tools/Disasm/Reports/ActionRenderQueueLoadVerification.json) разделяют границы проверки. Код вывода после E4DB, весь обход очереди, нативное звучание, IRQ и сборка этими моделями не подтверждаются.
