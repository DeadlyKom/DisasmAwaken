# Запись пересечений ACTION

[AppendTopClipIntersection](../Source/Action/AppendTopClipIntersection.asm), вход C4F6, числитель TopProduct, фиксированная координата 0.

[AppendBottomClipIntersection](../Source/Action/AppendBottomClipIntersection.asm), вход C540, числитель BottomProduct, фиксированная координата 95.

[AppendLeftClipIntersection](../Source/Action/AppendLeftClipIntersection.asm), вход C58B, числитель LeftProduct, фиксированная координата 0.

[AppendRightClipIntersection](../Source/Action/AppendRightClipIntersection.asm), вход C5E7, числитель RightProduct, фиксированная координата 255.

Каждый вход читает свой FClipProduct и делит его настоящим [DivideSigned32To16](ActionSignedDivision.md). Для верхнего и нижнего пересечения делитель равен wrap16(SecondPoint.First−FirstPoint.First), полученное частное прибавляется к FirstPoint.Second. Для левого и правого делитель равен wrap16(SecondPoint.Second−FirstPoint.Second), частное прибавляется к FirstPoint.First. Нужны ненулевой signed16 делитель d и U<abs(d)×65536, где U=N для N>=0, иначе U=−N−1.

## Исходная проверка координат

Для верхней и нижней границы отрицательное полученное слово Second даёт 0. Неотрицательное слово с ненулевым старшим байтом даёт 255. При нулевом старшем байте сохраняется младший.

Для левой и правой границы отрицательное полное слово First даёт 0. Иначе проверяется только бит 7 младшего байта. Установленный бит даёт 95, сброшенный сохраняет младший байт. Значения 96..127 не ограничиваются. Ненулевой положительный старший байт сам по себе не запрещает младший байт 00..7F. Это фактическое правило исходных инструкций, его замена обычным clamp(0,95) изменила бы игру.

## Запись и регистры

В страницу 90 пишется пара Second, First с исходного OutputSize. Для верхней и нижней границы фиксирован First во втором байте, для левой и правой фиксирован Second в первом байте. INC L оборачивается внутри страницы, перенос в H не выполняется. Размер увеличивается на два по модулю 256. После возврата HL=9000 OR новый размер, A равен новому размеру, F является результатом последнего INC L с Carry=0. SP после RET увеличен на два, дополнительный CPU-стек занимает два байта CALL делителя.

BC равен выходу делителя. Для верхней и нижней границы D сохраняет старший байт исходного FirstPoint.Second. На отрицательном пути DE сохраняет всю базу, на остальных E получает записанный Second. Для левой и правой границы на прямом пути D получает записанный First, E сохраняет младший байт исходной FirstPoint.First. На обоих предельных путях DE сохраняет всю базу. Альтернативные HL/DE/BC, IXH и IY сохраняются. A' содержит младший байт результата делителя, F' берётся из договора делителя для подготовленных входов. IXL равен числу отрицательных аргументов N и d минус один по модулю 256. Предварительный EX AF,AF' переносит исходный основной Carry в альтернативный входной Carry делителя. I, IM, IFF и paging сохраняются, R меняется.

## Проверка

[Модель](../Tools/Disasm/Research/CheckActionClipIntersections.py) исполняет настоящую процедуру деления без подмены. [Отчёт](../Tools/Disasm/Reports/ActionClipIntersectionsVerification.json) содержит 279552 сценария, по 69888 на вход. Для каждого проверены все промежуточные слова 0000..FFFF, все выходные смещения, смешанные допустимые числители и знаменатели. Сверяются точные регистры и флаги кроме R, вся физическая RAM и кратность записей. Все совместные входы, R и время, IRQ, сборка и нативный игровой вывод не доказаны.


## Точный R писателей пересечений

Для каждого полного писателя стоимость равна K собственных M1
плюс полная стоимость DivideSigned32To16. CALL и конечный RET писателя
включены в K. Пусть translated равно обёрнутой сумме частного и базы.
Для Top K=29 при нулевом старшем байте, 30 при отрицательном слове,
31 при положительном ненулевом старшем байте. Для Bottom соответствующие
значения 29/29/31. Для Left отрицательное слово даёт K=29, для Right
K=28. На остальных вертикальных путях K=31 при установленном бите 7
младшего байта и 32 при сброшенном бите. Это сохраняет исходное правило,
положительный ненулевой старший байт вертикального результата отдельно
не насыщается до 95.

Для делителя N/D обозначают признаки отрицательного числителя/знаменателя,
U=(abs(числитель)-N)//abs(знаменатель). Стоимость равна
130+12*N+10*D-2*(N XOR D)-popcount(U) M1 в его согласованном домене.
Все числа стоимости десятичные. В
[помощнике счёта](../Tools/Disasm/Research/ReferenceActionClipRefresh.py)
ветви выбираются числовыми условиями, время CPU не используется как эталон.

[Новая проверка](../Tools/Disasm/Research/CheckActionClipIntersectionsRefresh.py)
и [отчёт](../Tools/Disasm/Reports/ActionClipIntersectionsRefreshVerification.json)
прошли 279552 сценария, по 69888 каждого писателя. Для каждого входа
перебраны все промежуточные слова, все выходные смещения и дополнительные
знаковые профили. Реально исполняется делитель, совпали регистры и флаги
с R, полное число M1, восемь банков RAM и кратность присваиваний.

Подтверждённый счёт подключён к Clipping.intersection, четыре заголовка
и владеющий реестр обновлены. Полный R диспетчера отсечения этим ещё
не доказан, его другие действия требуют отдельного счёта. Прежние
ограничения R относятся к старому отчёту. Все совместные входы, точные T,
аппаратные IRQ, сборка и нативная игра остаются непроверенными.
Исполняемые инструкции и адреса сохранены.
