# Выбор ключа для характеристики

[DescribeKeyChoice](../Source/Text/DescribeKeyChoice.asm), LANG #C924..#C934, начинает с DEC C. Входной C=1 выбирает пятибайтовый ключ по #9844..#9848, все остальные значения выбирают текущий ключ по #983F..#9843. Изменённый C сохраняется, входной ноль превращается в FF. Проверок иных кодов выбора нет.

Второй ключ загружается как FirstWord в HL, SecondWord в DE, Variant в A. Это подтверждает физический формат, но не доказывает его игровую роль. Далее используется [DescribeKeyForLang](../Source/Station/DescribeKeyForLang.asm). Текущий ключ получает [DescribeCurrentKeyForLang](../Source/Station/DescribeCurrentKeyForLang.asm). Обе обёртки описаны в [SignatureReturn](SignatureReturn.md), формула характеристики в [WorldSignature](WorldSignature.md).

HL, DE и основной AF содержат результат выбранной характеристики. B сохраняется, C уменьшен на один по модулю 256. Альтернативные HL, DE, BC и индексные регистры, I и IFF сохраняются, альтернативный AF содержит результат финального выбора страницы. Рабочий ключ изменяется. Последовательность банков 1, 0, 6 возвращает LANG в окно C000, стек должен оставаться вне этого окна. Прежние старшие биты порта сохраняются, ROM 1 устанавливается.

[CheckKeyChoice.py](../Tools/Disasm/Research/CheckKeyChoice.py) исполняет исходный LANG в физическом банке 6, оба фиксированных перехода, настоящее ядро MAP и переключения страниц. Первоначально проверено 1536 случаев выбора, затем модель расширена до 9216 случаев с пятью стековыми обработчиками. Охвачены все 256 значений C, два состояния экранного бита и варианты ключа 0, 1, 255. Сверены результат, сохранность регистров, изменение C, SP, порт и тень. Отчёт [KeyChoiceVerification](../Tools/Disasm/Reports/KeyChoiceVerification.json). Прерывания, сборка и нативный запуск не выполнялись.


Пять физических обработчиков возвращают отдельное поле в DE с нулевым D. [GetKeyMajor](../Source/Text/GetKeyMajor.asm) возвращает H, [GetKeyMinor](../Source/Text/GetKeyMinor.asm) E, [GetKeySize](../Source/Text/GetKeySize.asm) L, [GetKeyFingerprint](../Source/Text/GetKeyFingerprint.asm) A, [GetKeyRegion](../Source/Text/GetKeyRegion.asm) D исходной характеристики. Каждый снимает слово выбора через POP BC, затем вызывает DescribeKeyChoice. Старший байт слова сохраняется в B, младший уменьшается на один. SP после RET увеличен на четыре, слово выбора и возврат потреблены.

GetKeySize использует EX DE,HL, поэтому его итоговый HL равен исходной паре D:E характеристики, остальные четыре сохраняют H:L характеристики в HL. Основной AF во всех пяти обработчиках остаётся результатом характеристики, флаги не описывают выделенное поле DE. Например, нулевой код области сам по себе не означает Z=1. Проверка расширенной модели исполняет все пять исходных обработчиков с реальными банковыми вызовами, проверяет эти различия, результат и стек.
