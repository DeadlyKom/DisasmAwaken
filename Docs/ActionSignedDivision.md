# Делитель ACTION C88C

Диапазон C88C–C940 банка 0 оформлен отдельным [DivideSigned32To16.asm](../Source/Action/DivideSigned32To16.asm). Следующий вход C941 относится к [отдельному диспетчеру отсечения](ActionClipDispatch.md), его договор не смешивается с делителем. [Проверка](../Tools/Disasm/Research/CheckActionSignedDivision.py) исполняет фактические байты ACTION и отдельно сверяет каждую инструкцию делителя с вариантом карты после пересчёта внутренних адресов.

## Представление входа

HL содержит старшее слово числителя N, A следующий байт, альтернативный A младший байт. DE задаёт ненулевой signed16 делитель d. Входной флаг Sign обязан соответствовать знаку d, начальный переход проверяет именно F, а не старший бит D. Carry основного и альтернативного F допускают оба значения и участвуют в точных выходных флагах.

Для N>=0 величина U=N, для отрицательного N величина U=−N−1. Требуется U<abs(d)×65536. Деление на нуль и переполнение частного находятся вне численного договора.

## Алгоритм и частное

В IXL считается число отрицательных входов. Отрицательный делитель превращается в обычный модуль дополнительным кодом. Отрицательный числитель целиком дополняется побитово без прибавления единицы. Затем выполняются шестнадцать развёрнутых восстанавливающих шагов, сначала восемь битов A, затем восемь альтернативного A.

Остаток удваивается с очередным битом числителя, пробуется вычитание модуля делителя. При заёме вычитание отменяется. Carry=1 после восстановления кодирует нулевой разряд истинного частного, поэтому накопитель содержит дополненное частное.

Пусть q=floor(U/abs(d)). При одинаковых знаках возвращается HL=q, при разных знаках HL=q XOR FFFF. Это сохраняет исходную однокомплементную обработку. Она не совпадает с обычным усечением signed32/signed16 во всех случаях. Остаток не возвращается, HL заменяется собранными байтами ответа.

## Регистры

DE содержит модуль d. BC сохраняется при двух неотрицательных входах, получает исходное старшее слово N при отрицательном N, иначе исходный d при отрицательном d. A содержит старший байт HL, альтернативный A младший. Основной F сохраняет S/Z/PV от восьмой попытки старшего байта с последующими изменениями от восстановления знака. Точные формулы обоих F находятся в функции expected исследовательского CheckSignedDivision.py и отдельно проверяются на ACTION.

Альтернативные HL, DE и BC сохраняются. IXH сохраняется, IXL равен числу отрицательных входов минус один по модулю 256. IY, I, IM, IFF и paging сохраняются. SP после RET увеличен на два. Код не записывает RAM и не использует порты. R изменяется по формуле ниже, точные такты T отдельно не доказаны.

## Проверка и текущий статус

[Отчёт проверки](../Tools/Disasm/Reports/ActionSignedDivisionVerification.json) содержит результаты исполнения ACTION для всех младших слов положительного и побитово дополненного отрицательного числителя против десяти делителей, а также широкие допустимые числители. Сверяются точные регистры и флаги включая R, полное число M1, отсутствие любых записей RAM и правильный CPU-возврат.

Вход C941 оформлен отдельным [ClipSingleEdge](../Source/Action/ClipSingleEdge.asm). Проверка делителя не подменяет [собственные проверки диспетчера](ActionClipDispatch.md), его рамок и табличных случаев. Все совместные входы делителя, IRQ, T, сборка и нативный запуск не проверены.


## Полное число M1

Пусть negN равен единице для отрицательного N и нулю иначе, negD
аналогичен для исходного делителя d. q=floor(U/abs(d)) означает
неотрицательное частное до окончательного побитового дополнения.
Тогда число M1 от Entry до внешнего RET равно

`130 + 12*negN + 10*negD - 2*(negN XOR negD) - popcount(q)`.

popcount считает единицы в шестнадцатибитном q, не в окончательном HL
при разных знаках. Каждая единица соответствует успешному вычитанию,
которое не требует восстановления остатка. Добавочные 12 и 10 M1
относятся к обработке отрицательных числителя и делителя, поправка
двух M1 различает два завершающих пути дополнения частного.
При q в 0..FFFF и допустимом входном Sign получаются 114..152 M1.
Младшие семь битов R увеличиваются с оборачиванием, бит 7 сохраняется.
Это число чтений M1, не число тактов T.

Используется существующая числовая формула refresh_cost делителя карты,
её код не дублируется. В 1331200 сценариях на настоящих байтах ACTION
сверены начальные/конечные R и сумма приращений R каждой инструкции,
что не теряет кратные 128. Все 256 начальных R встречаются, наблюдались
все значения M1 114..152. Проверка каждой из 117 инструкций с явной
релокацией остаётся отдельным условием, совпадение имени процедуры
не используется как доказательство эквивалентности.

[Копия 3DPART](ThreeDOverlayMirror.md#делитель-и-m1) имеет те же
уточнённые входы и формулу. Её отдельная нативная загрузка не добавлялась.
