# Фон и станционный интерфейс

В `stscr.C` физически находятся 16 упакованных блоков. Число секторов взято
из исходной таблицы загрузчика:

```text
13, 11, 11, 12, 8, 14, 19, 15, 15, 13, 19, 12, 16, 20, 21, 20
```

Сумма равна 239. Заголовки содержат HR, распакованную длину `#1B00`
и упакованную длину. Логическая длина каталога описывает только первый блок.

После распаковки хранятся 768 знакомест по восемь байт пикселей, затем 768
атрибутов. Последовательные строки одного знакоместа подтверждены кодом
`#9D58..#9D75`, восемь чтений через BC и записи с увеличением D.

```text
source_pixel = (cell_row * 32 + column) * 8 + row
source_attribute = 6144 + cell_row * 32 + column
```

Поэтому обычный просмотр этого блока как SCR переставляет пиксели.
Изображения `Images/Screens/09_XX.png` сформированы после преобразования.
Панели `25_00..28_00` и экраны `31`, `32` имеют обычную экранную адресацию.

`Station.RestoreBackground` выбирает банк 3 и обходит карту `#8600..#88FF`.
Одна ветвь восстанавливает восемь пиксельных строк и атрибут фона, другая
сохраняет занятое интерфейсом знакоместо с вычисленным атрибутом. Не все
значения карты уже названы, ненулевой байт не объявлен простым булевым флагом.

В `#F0FD` лежат 46 записей FInterfaceItem по 16 байт, затем байт `#80`.
Список рисования `#F3DE` завершается словом `#0101`. Загрузчик встраивает
индекс записи в обработчик, поэтому порядок записей является частью контракта.

Событие берёт указатель из поля `+6`, прибавляет три и выполняет косвенный
переход. Поле `+12` задаёт вход для списка рисования. `#CBA9` восстанавливает
координаты и размеры из `+8..+11` в `+0..+3`.

Кадр `Tools/Disasm/Research/ModelScreens/station_bank5.png` получен из
оригинальных инструкций в модели с заменённым интерфейсом TR-DOS. Он
показывает формирование интерфейса, но не подтверждает полный старт с диска.
