# Вступление и переход к загрузке станции

[InitializeIntro](../Source/Intro/InitializeIntro.asm) переносит 256
байтов из `#65B7` в `#5D3B`, устанавливает SP в `#5FFF`
и выводит исходный экран. Затем переносит распаковщик с потоком
из `#8931` в `#6E31`, очищает рабочие банки и строит таблицы
и текстуры. После подготовки прокрутки запускает 300 шагов через
`RunTimedEffect`, передавая адрес `DrawFinalTextureFrame`.
Нажатие Space завершает этот участок досрочно. При досрочном
переходе SP указывает на временную рамку по `#5FF9`, при
исчерпании счётчика он равен `#5FFF`. Оба пути ведут в
перенесённый блок `#5D3B`.

После очистки экрана InitializeIntro сохраняет SP в
[исходное слово](../Source/Intro/Data/StackSnapshot.asm) по 65B4.
Все четыре профиля наблюдали значение 5FFF. На диске сохранён
исходный нуль. Завершающий LoadStation задаёт SP непосредственно.

## Снимок стека в выборке текстуры

В секторном хвосте AWAKEN четыре байта по `#02B3..#02B6` равны нулю.
TR-DOS записывает их в `#65B3..#65B6` при загрузке вступления. Затем
команда по `#6531` меняет два средних байта, и диапазон содержит
`00 FF 5F 00`. [Первый соседний байт](../Source/Intro/Data/StackSampleBefore.asm) ·
[Второй соседний байт](../Source/Intro/Data/StackSampleAfter.asm)

`LDIR` по `#6D9F` захватывает эти четыре байта при копировании части
страницы `#65` и пишет их по `#DC73..#DC76` банка 1. Они находятся
за пределом первых 38 строк, переносимых в банк 4. Команда по `#6A1B`
заполняет копию значением `#FF` до первого чтения. Сверены все четыре
профиля вступления, включая выход по клавише и все 300 кадров.
После чтения STATIONF в двух сквозных профилях прежний диапазон
содержит `98 CD 33 C3`. Изначальное назначение соседних нулей
остается открытым.
[Трасса выборки](../Tools/Disasm/Reports/IntroStationTransitionVerification.json) ·
[Трасса чтений ROM](../Tools/Disasm/Reports/BootBankFileReadsVerification.json)

## Переносимый загрузчик

Перенесённый [LoadStation](../Source/Intro/LoadStation.asm)
распаковывает исходный экран, копирует его в банк 7 и затем
сбрасывает SP в `#5FFF`. Перед обращением к TR-DOS устанавливает
`I=#3F`, `IM 1`, `IY=#5C3A`, страницу `#18` и запрещает
прерывания. Ключ `STATIONFC` копируется в `#5CDD`. Сначала
вызывается функция `#0A` для поиска, затем `#08` для чтения
заголовка. Из заголовка берутся сектор и дорожка для функции
`#05`. Ей передаётся `B=#C0`, `HL=#6000`, `DE=(#5CEB)`.
На вершину стека заранее помещается `#6300`. Переход в TR-DOS
выполняется через JP, поэтому дополнительный возврат отсутствует.
Сам блок не проверяет результат поиска или чтения заголовка.

[Модель перехода](../Tools/Disasm/Research/CheckIntroStationTransition.py)
выполнила полное вступление на исходных байтах и ПЗУ для
0, 1, 2 и 300 кадров последнего эффекта. Сверены перенос кода,
оба пути к загрузчику, независимая распаковка и копирование
всех 6 912 байтов экрана, состояние регистров и запросы TR-DOS.
Поиск и чтение заголовка подменены данными оригинального
каталога. Модель останавливается на входе секторного чтения,
поэтому его аппаратное поведение отдельно не подтверждено.

В [сквозной модели запуска](StationFlightCycle.md) обработчик TR-DOS
подставляет первые 160 секторов запроса с начала STATIONF. Они заполняют
`#6000..#FFFF` исходным файлом. Адрес оставшихся 32 секторов
оборачивается на `#0000..#1FFF`, поэтому в модели этот участок ПЗУ
сохраняется. Проверено продолжение по `#6300` с исходным содержимым RAM.
Секторный сервис TR-DOS и обмен с контроллером в этой проверке подменены.

Адрес назначения LDIR и конечный переход InitializeIntro используют одно имя IntroStationRuntime.Entry из [адресных привязок](../Includes/Variables/Include.inc). Это существующий вход по 5D3B после копирования LoadStation, новая память не выделяется. Фабрика [IntroStationRuntimeNames](../Tools/Disasm/Research/IntroStationRuntimeNames.py) сохраняет имя при подготовке отдельного кандидата экспорта.

## Чтение станции после каталога

Отдельная модель исполняет исходный хвост `LoadStation` с `#5D87`,
после получения каталожной записи. ROM TR-DOS 5.04T через модель
контроллера читает 192 сектора начиная с дорожки 20, физического сектора 15.
Первые 160 дают точное содержимое `STATIONF.C` по `#6000..#FFFF`.
Следующие 32 сектора физически принадлежат LANG и началу D3D. Адрес
приёмника оборачивается до `#0000`, ПЗУ сохраняется. Возврат происходит
с `PC=#6300`, `SP=#5FFF`, выбранная страница остаётся `#18`.
Поиск каталожной записи в этом профиле пропущен.
[Результат](../Tools/Disasm/Reports/BootBankFileReadsVerification.json)

## Сквозное исполнение команды RUN

В двух дополнительных профилях ROM начинает с [команды RUN](BasicProgram.md#чтение-первого-сектора-командой-run),
читает первый сектор AWAKEN и передаёт управление с BASIC на `#5D41`.
Затем исполняются чтение вступления, выход из эффекта по клавише и переносимый загрузчик.
Поиск STATIONF по `#0A`, получение записи по `#08` и чтение по `#05`
исполняются в исходном ROM. После возврата на `#6300` тот же снимок
проходит станционную загрузку банков и фона до `MainLoop` по `#9A59`.
На входе в цикл `SP=#5FFF`, страница `#10`, режим прерываний IM 2.
В обоих профилях пройдены семь кадров до повторного входа по `#9A81`.
Сверены последовательности всех 44 секторов вступления, 192 секторов
станции и пяти банковых файлов. Модель начинает с токенизированной
команды в редакторе, клавиатуру и контроллер моделирует.
[Сценарий](../Tools/Disasm/Research/CheckBootBankFileReads.py) ·
[Результат](../Tools/Disasm/Reports/BootBankFileReadsVerification.json)


## Наследуемая длина поиска TR-DOS

LoadStation копирует девятибайтовый FTrDosFileKey STATIONFC в TrDosState.Descriptor, но не записывает TrDosState.SearchKeyLength по #5D06. Поэтому длина сравнения имени с типом является входным состоянием переносимого блока.

[Дополнительная сквозная проверка](../Tools/Disasm/Research/CheckIntroStationSearchLength.py) начинает с прежней фикстуры редактора и исполняет RUN выбранным TR-DOS 5.04T, затем BASIC, загрузку вступления, само вступление, распаковщик, поиск STATIONF, чтение заголовка и 192 сектора станции. Поиск и дисковые функции не подменяются, модель контроллера и переключения ROM сохранена.

В исходном ROM по #0332 находится LD A,9, по #0334 — LD (#5D06),A. Начальное нулевое значение фикстуры перезаписывается этой командой обработчика RUN. После этого до входа свежей станции по #6300 других записей #5D06 не зарегистрировано. Значение 9 отдельно проверено на входе USR #5D41, перед вступлением #6500, перед переносимым загрузчиком #5D3B, перед #0A, после #08 и после секторного чтения.

Таким образом на подтверждённом пути LoadStation наследует длину девять от RUN, имя и тип действительно участвуют в поиске. Результат поиска равен слоту 4, заголовок совпадает со всеми 16 исходными байтами каталога, в RAM #6000..#FFFF получены точные 160 секторов STATIONF, SP после передачи равен #5FFF. Исходные две команды подготовки дескриптора оформлены через TrDosState.Descriptor и FTrDosFileKey без изменения байтов.

Проверка начинается с подготовленных системных переменных редактора, она не является холодным запуском TR-DOS и не доказывает все версии DOS, состояния диска или аппаратное исполнение. [Отчёт](../Tools/Disasm/Reports/IntroStationSearchLengthVerification.json), [канонический договор](../Tools/Disasm/Research/IntroLoadStationFacts.py), [исходник](../Source/Intro/LoadStation.asm). [Общий смысл длины #5D06](ActionBootFileKeys.md#длина-сравнения-имени-и-типа) установлен отдельно по циклу сравнения ROM.

Профиль наблюдения 5D06 выходит по клавише при первом опросе последнего эффекта, это число отдельно проверено и записано в отчёт. Длительное ожидание последнего эффекта ранее проверялось другой моделью и не приравнивается к новому мониторингу длины поиска.


## Фактическая цепочка IY и IRQ

[Сквозная модель вступления](../Tools/Disasm/Research/CheckIntroStationTransition.py) теперь фиксирует первый вход в каждый инициализатор и контекст каждого принятого ROM-прерывания. Внутри цепочки значения регистров не подготавливаются заново. Исходные 179 байтов #6500..#65B2 сопоставлены с TRD, ROM 48K проверен по хешу, входные IM=1 и IFF=0 заданы явно.

| Граница | Фактический IY | SP первого входа |
| --- | --- | --- |
| InitializeLookupEffect, #6C9C | #5C29 | #5FFD |
| BuildMirroredTexture, #6DB6 | #5C0F | #5FFD |
| InitializeColumnEffect, #6AC1 | #5C0F | #5FFD |
| InitializeScrolledTexture, #66FB | #5C0F | #5FFD |
| RunTimedEffect, #6A4B | #5C0F | #5FFD |
| DrawFinalTextureFrame, #661E, при N>0 | #5C0F | #5FF9 |
| DrawScrolledTexture, #66A3, при N>0 | #5C0F | #5FF9 |

Во всех четырёх профилях обработчик ROM принимает IRQ при IY=#5C29 и #5C0F. Поэтому стандартные договоры WaitInterrupt и PresentAttributes с IY=#5C3A не являются полным описанием этой фактической цепочки. Самостоятельные профили этих процедур остаются верными в своих условиях. Новая запись показывает конкретные другие контексты и не исправляет исходную работу с IYL.

Для N=0,1,2,300 исполненных кадров финального эффекта принято соответственно 45,48,51,945 IRQ, FRAMES при исходном нуле имеет те же значения. Переноса младшего слова FRAMES в этих четырёх сквозных случаях нет. Результат подготовленных отдельных проб #00FFFF нельзя объявлять событием этого прогона. На входе #5D3B IY=#5C0F и IM=1, IFF равен единице для N=0/300 и нулю для N=1/2. SP равен #5FF9 для досрочного выхода и #5FFF после всех 300 шагов.

Сценарий Space моделируется точным ответом #BE на опрос RunTimedEffect, а сканер ROM во время IRQ получает отпущенные клавиши и исходные KSTATE=#FF. Это намеренно разделённый ввод модели, он не доказывает физическое нажатие и обработку клавиши в нативном эмуляторе. Таблицы и финальные текстурные выборки в этой модели образованы действительными процедурами вступления, в отличие от изолированной модели DrawScrolledTexture с подготовленными таблицами. Эта сквозная проверка не доказывает полный смысл всех исходных слов таблиц и всех возможных игровых путей.

[Отчёт](../Tools/Disasm/Reports/IntroStationTransitionVerification.json) содержит контексты входов и распределение IRQ по адресу и IY для каждого N. Последующие поиск и чтение заголовка TR-DOS в этой модели подменяются, остановка происходит перед секторным чтением. Эти подмены не относятся к уже исполненному вступлению, но ограничивают доказательство дальнейшей загрузки. [Канонический договор](../Tools/Disasm/Research/IntroInitializationFacts.py), [исходник](../Source/Intro/InitializeIntro.asm), [отдельный перенос с IY=#5C0F](IntroGeneratedEffects.md#iy-столбцового-вывода-и-перенос-frames).


На границе загрузчика дополнительно проверены IX=0 и сохранение AF' с входным контрольным значением #A55A во всех четырёх профилях. Поэтому AF' исключён из Corrupt InitializeIntro. Другие выходные регистры не объявлены сохраняемыми по одному наблюдению их значения.


## Построитель исходной текстуры и IY

Дополнительные снимки [непрерывной модели](../Tools/Disasm/Research/CheckIntroStationTransition.py) фиксируют вход BuildIntroTexture по #6D8D и следующий CALL BuildAlternatingTexture по #6638. Первый получает HL=#6080 и IY=#5C3A, а следующая процедура получает HL=#9300, DE=#D300, BC=0, AF=#1449, IX=#6400 и IY=#5CFF. На обеих границах IFF=0, вторая имеет конфигурацию 7FFD=#14. Все четыре сквозных прогона подтвердили эти значения без подготовки регистров на внутренних границах.

[BuildIntroTexture](../Source/Intro/BuildIntroTexture.asm) не принимает исходный IYL как числовой аргумент. Он всегда начинает с IYL=#C0 и меняет второй байт FD-инструкции построителя на #2C, превращая LD IYL,A в INC IYL. Все 63 чтения параметров сохраняются, но вторые байты записей определяет счётчик. После 63 увеличений IYL=#FF. В исходном состоянии результат прохода заполнения пропусков даёт A=206 и копируются 206 фрагментов по 128 байтов. Только первые 38 строк подготовленного буфера сохраняются в банк 4 фиксированным LDIR размером #1300, лишние строки разобраны отдельно по источникам и перезаписи до чтения.

Следующий [BuildAlternatingTexture](../Source/Intro/BuildAlternatingTexture.asm) задаёт режим #6F, оставляя LD IYL,A. Он читает 63 байта с #6663 по #66A1 включительно. Последний фактически прочитанный параметр по #66A1 равен #29, поэтому перед InitializeLookupEffect получается IY=#5C29. Соседний байт #66A2 также равен #29, но это не делает его 64-м прочитанным параметром текущего построителя. Таким образом, переход #5C3A→#5CFF→#5C29 предшествует поздней замене IYL на #0F строителем атрибутов.

[Канонический договор](../Tools/Disasm/Research/IntroBuildTextureFacts.py) учитывает фиксированное начальное IYL, реальные банки записей, R, конфигурацию порта и отличие исходного профиля от произвольных параметров. AF=#1449 указан именно для четырёх исходных прогонов. [Отчёт сквозного исполнения](../Tools/Disasm/Reports/IntroStationTransitionVerification.json) сохраняет ограничения ввода, ROM и дальнейших DOS-подмен. Точное время, R всего построителя, все совместные параметры и нативное исполнение этой проверкой не установлены.


## Счётчик и два выхода RunTimedEffect

[RunTimedEffect](../Source/Intro/RunTimedEffect.asm) записывает HL в операнд StepCall. Перед каждой проверкой порта он сохраняет BC и AF, затем читает #7FFE и сравнивает полный байт с #BE. При другом ответе AF и BC восстанавливаются. Обработчик получает сохранённый контекст AF, а не флаги сравнения порта. Отдельный PUSH BC защищает счётчик от изменения вызванным обработчиком, после возврата POP BC восстанавливает его, DEC BC и OR двух байтов проверяют завершение.

При исходном n>0 выполняются n шагов с BC=n,n−1,...,1. При исходном нуле первый шаг получает BC=0, следующий #FFFF, и до нуля требуется 65536 шагов. Это следствие шестнадцатибитного счётчика исходного кода, а не результат выполненного прогона с нулевым BC. Обработчик обязан возвращаться и не повреждать сохранённый счётчик или самомодифицируемый операнд контроллера.

Обычный путь после последнего шага исполняет EI и последовательно переходит в FillBitmap с C=0. Очищаются первые 128 строк bitmap #4000..#4FFF. При сохраняющем рабочий контекст ISR итоговые HL=#5000, B=C=0, A=0, F=#41, E=#E0, D остаётся от последнего обработчика, SP увеличен на два. FillBitmap не создаёт дополнительного адреса возврата, порядок двух include уже отмечен номерами 0 и 1 в Source/Files/03_AWAKEN.inc.

При точном ответе #BE исходные PUSH AF и PUSH BC остаются на стеке, SP уменьшается на четыре относительно входа RunTimedEffect. Устанавливаются A=#BE, F=#6A от CP #BE, BC=#7FFE, затем EnterStation передаёт управление в #5D3B. Обычный возврат и очистка bitmap не выполняются. Финальный загрузчик задаёт свой SP самостоятельно. Это разные протоколы выхода, их нельзя свести к единому обещанию восстановления стека.

[Непрерывная модель](../Tools/Disasm/Research/CheckIntroStationTransition.py) сохраняет каждый счётчик и SP на входе настоящего DrawFinalTextureFrame. Для N=0,1,2,300 шагов получены именно первые N значений 300,299,...,1, на каждом вызове SP=#5FF9. Ранний вход загрузчика имеет AF=#BE6A, BC=#7FFE и SP=#5FF9, полный путь имеет AF=#0041, BC=0 и SP=#5FFF. IRQ и сами обработчики исполняются в исходной цепочке, значение IY на внутренних границах не подготавливается.

[Отчёт](../Tools/Disasm/Reports/IntroStationTransitionVerification.json) проверяет именно BC=300, заданный сценарий порта и четыре момента выхода. Произвольные обработчики, полный диапазон BC, все времена IRQ, точный общий R и нативное нажатие не доказаны этим набором. [Канонический договор](../Tools/Disasm/Research/IntroTimedEffectFacts.py) сохраняет эти границы. Код, расположение и структура исходного BASIC не менялись, сборка не выполнялась.
