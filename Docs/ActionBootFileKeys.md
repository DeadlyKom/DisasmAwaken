# Файловые ключи загрузчика полёта

[FileKeys](../Source/ActionBoot/Data/FileKeys.asm) содержит шесть физических
экземпляров FTrDosFileKey. Они занимают исходные файловые смещения
0113..0148 ACTION, после переноса загрузчика их адреса 42D0..4305.
Это адреса загрузочного контекста, к обычному отображению ACTION по
6000 они не приравниваются.

| Ключ | Адрес | Использование в InitializeFlight |
|---|---|---|
| Voxal | 42D0 | Чтение VOXAL в уже выбранный банк 3, начало EC00 |
| Voxal0 | 42D9 | Чтение VOXAL0 в банк 3 по C000 |
| Control | 42E2 | Поиск CONTROL и чтение в банк 1 по DADE |
| Control0 | 42EB | Поиск CONTROL0, сохранение положения файла и чтение в банк 1 по C000 |
| Panel | 42F4 | Чтение PANEL в банк 6 по C000 и распаковка |
| Object3D | 42FD | Чтение OBJECT3D в банк 4 по C000 |

Каждый ключ содержит восемь символов имени, включая исходные пробелы,
и байт C равный 43. Нулевого терминатора нет. Потребитель
[InitializeFlight](../Source/ActionBoot/InitializeFlight.asm) либо копирует
все девять байтов в 5CDD, либо передаёт их
[GetFileLocation](../Source/ActionBoot/GetFileLocation.asm), который делает
такое же копирование перед поиском и чтением заголовка TR-DOS.
Адрес назначения задаёт загрузчик и выбранный им банк, структура ключа
адрес загрузки не содержит.

Разметка повторно использует существующую структуру. Имена полей, размеры,
значения, пробелы в литералах и порядок запросов сохранены. Проверка
[VerifySources](../Tools/Disasm/VerifySources.py) сравнивает все 54 байта
с оригиналом и адреса шести экземпляров с реестром символов.
Исследовательский [сценарий публикации](../Tools/Disasm/Research/PublishActionBootFileKeys.py)
сохраняет отдельный кандидат и основание до замены файлов.

Модель [входа в полёт](ActionFlightCycle.md) рассматривает настоящие Z80
вызовы загрузчика с подставленными успешными дисковыми ответами. Разметка
ключей не расширяет это подтверждение до настоящего TR-DOS, ошибок диска
или нативной игры. Ассемблер при этой работе не запускался.


## Координаты каталога и физический номер сектора

[GetFileLocation](../Source/ActionBoot/GetFileLocation.asm) копирует девять байтов имени в #5CDD, вызывает поиск TR-DOS #0A, затем передаёт полученный индекс через A в функцию #08. Заголовок каталога занимает #5CDD..#5CEC. По #5CEA лежит число секторов, по #5CEB нулевой номер первого сектора, по #5CEC логическая дорожка. После LD HL,(#5CEB) инструкция INC L даёт физический номер 1…16 без изменения H. Значение 16 допустимо, его не следует преобразовывать в сектор 0 следующей дорожки.

[Новая проверка](../Tools/Disasm/Research/CheckActionBootFileLocation.py) исполняет исходные 27 байтов GetFileLocation и настоящий TR-DOS 5.04T при всех шести неизменённых ключах, с начальным цилиндром 0 либо 9. Во всех 12 случаях все 16 байтов прочитанной записи совпадают с каталогом оригинального TRD. Возвращаются число секторов и ожидаемый HL, входной адрес возврата снимается обычным RET. Для CONTROL0 это HL=#4B05 и A=#1B, для CONTROL — HL=#4C10 и A=#1A.

Стенд повторно использует подготовку системных переменных из CheckBootBankFileReads, включая #5D06=9 и #5D0C=#FF. Контроллер диска и переключение ROM моделируются, команды поиска и чтения записи не подменяются. Без подготовленного системного состояния этот изолированный вход не подтверждён. Данные самих файлов не читаются этой серией. Ошибки диска, отсутствие имени, произвольные каталоги, вмешательство IRQ и нативный запуск не проверены. [Результат](../Tools/Disasm/Reports/ActionBootFileLocationVerification.json).


## Обычная загрузка и возврат TR-DOS

Режим `--load` [проверки ключей](../Tools/Disasm/Research/CheckActionBootFileLocation.py) продолжает каждый из 12 успешных поисков через исходные LoadFileToBank либо LoadFileAtAddress. Для VOXAL и CONTROL использованы штатные назначения #EC00 и #DADE, для остальных файлов — #C000. Перед входом LoadFileToBank HL задан #1357, чтобы независимо проверить его замену. ПЗУ и модель контроллера те же, файловая функция #0E не подменяется.

При A=3 функция #0E заново читает каталог и ищет имя даже после предшествующего GetFileLocation. Во всех профилях наблюдались три чтения каталога, затем ровно все выделенные сектора нужного файла. Загрузка сверена с полными физическими байтами TRD, защитные байты перед назначением и после последнего сектора сохранились. В том числе переносятся 56 байтов хвоста VOXAL, 182 CONTROL, 34 CONTROL0, 73 PANEL и 172 OBJECT3D. VOXAL0 не имеет хвоста после логической длины.

[LoadFileToBank](../Source/ActionBoot/LoadFileToBank.asm) устанавливает HL=#C000 только перед передачей исполнения. При возврате из проверенного TR-DOS 5.04T все 12 профилей дают HL=#FF54, DE=#0100, BC=индекс записи каталога и AF=#FF98. Это ограниченный результат для указанного системного состояния и ROM, не общий договор всех TR-DOS. Оба входа возвращаются по исходному слову стека, SP увеличивается на два. Отдельного CALL между LoadFileToBank и [LoadFileAtAddress](../Source/ActionBoot/LoadFileAtAddress.asm) нет.

[Отчёт загрузки](../Tools/Disasm/Reports/ActionBootFileLoadVerification.json) отделён от прежнего отчёта поиска. Активный банк в этом изолированном стенде представлен плоским верхним окном, аппаратный банковый цикл, ошибки диска и нативная игра не проверены. Обычные сборочные инструменты не запускались.


## Длина сравнения имени и типа

Оба загрузчика, [InitializeFlight](../Source/ActionBoot/InitializeFlight.asm) и [StartStation](../Source/StationBoot/StartStation.asm), записывают 9 по #5D06. Для проверенного TR-DOS 5.04T это числовая длина поиска SearchKeyLength. По #1CD0 ПЗУ читает байт в A, затем копирует его в B. Цикл #2713 берёт байт запроса через DE, сравнивает с каталогом через HL, немедленно выходит при несовпадении и иначе продвигает оба указателя до DJNZ. Значение не интерпретируется этим кодом как набор независимых флагов.

Значение 9 включает все восемь символов имени и байт типа. Значение 8 не проверяет тип. Это отдельно от копирования ключа в системный буфер: GetFileLocation всегда копирует девять байтов, но длину сравнения сам не устанавливает. Она должна быть задана вызывающей средой. В исходниках повторно использован размер FTrDosFileKey, существующий адрес #5D06 назван TrDosState.SearchKeyLength. TrDosState.Descriptor по #5CDD обозначает уже существующий буфер, новая память не выделяется.

[Проверка выбранного ПЗУ](../Tools/Disasm/Research/CheckTrDosSearchKeyLength.py) выполняет 512 сравнений, все начальные B с равными строками и несовпадением последнего байта. При B=0 цикл сравнивает 256 байтов вследствие DJNZ, это не проверка допустимости такой длины в полном каталожном поиске. Ни RAM, ни байты CPU-стека самим сравнением не записываются.

Ещё восемь полных вызовов функции #0A проверяют оригинальный CONTROL0.C с двух начальных цилиндров. В запросе отдельно задан тип C либо X. При длине 8 оба запроса возвращают индекс 22, при длине 9 возвращается 22 для C и FF для X. То же значение записано в системный результат #5D0F. Каталог оригинального TRD не изменялся. [Отчёт](../Tools/Disasm/Reports/TrDosSearchKeyLengthVerification.json).

Контроллер и переключение ROM моделируются. Произвольные длины полного поиска, другие версии TR-DOS, IRQ и нативная игра не доказаны. Сборка не запускалась.
