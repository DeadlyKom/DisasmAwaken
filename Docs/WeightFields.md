# Кодированные количества оснащения и вторичный индекс

[SumSecondaryIndex](../Source/Text/SumSecondaryIndex.asm) суммирует
SecondaryEquipmentState.Row по 73D8 и младший байт TopRow по 737D.
Результат восьмибитный, A=C, B=0. HL и DE сохраняются, F от ADD,
перенос не расширяет индекс. Эти два операнда использует
[второй список оснащения](SecondaryEquipmentRows.md).

[ReadEquipmentQuantity](../Source/Text/ReadEquipmentQuantity.asm) использует GetEquipIndex и базу EquipmentQuantityCodes по 988E. [ReadSecondQuantity](../Source/Text/ReadSecondQuantity.asm) использует SumSecondaryIndex и базу SecondaryEquipmentData.Quantities по 98F6. Оба передают управление ParseFieldSuffix с двумя допустимыми свойствами s и n. Без точки полный индекс HL прибавляется к базе, читается байт, при установленном бите 7 выполняется CPL. Те же байты читают печататели списков и расчёт нагрузки. [Первый набор](PlayerSavedFields.md), [второй набор](StationTransportTradeTables.md).

Декодированное количество равно исходному байту при значениях 00..7F, иначе байту XOR FF. DE содержит результат с нулевым D. F при снятом бите 7 относится к OR A, при инверсии CPL сохраняет S/Z/PV от исходного OR, устанавливает H/N и берёт X/Y из нового A. Поэтому исходный FF даёт DE=0 с Z=0, исходный 00 даёт DE=0 с Z=1. У печатателя первичного списка исходный 80 завершает обход, прямой читатель декодирует его в 7F.

Без цифр индекс берётся из исходной суммы, с цифрами равен (число-1) AND FFFF. Прямое чтение не обрезает слово до байта. На выходе HL указывает на прочитанный байт, BC по-прежнему содержит исходный байтовый индекс. Общий ReadAtBase первого входа принимает произвольную DE базу и полный HL индекс. Альтернативный B установлен в 2, остальные альтернативные пары и AF' сохраняются на прямом пути, IX продвинут за число, IY, I и IFF сохранены, SP увеличен на два.

Суффикс s первого набора вызывает [CheckThresholdSet30](../Source/Text/CheckThresholdSet30.asm), второго [CheckThresholdSet14](../Source/Text/CheckThresholdSet14.asm), договоры в [ThresholdSets](ThresholdSets.md). Суффикс n вызывает [HasActiveNeighbor](../Source/Text/HasActiveNeighbor.asm) либо [HasSecondActiveNeighbor](../Source/Text/HasSecondActiveNeighbor.asm), договоры в [ActiveNeighbors](ActiveNeighbors.md). Стековый индекс снимается соответствующим обработчиком. При неизвестном суффиксе FindToken передаёт управление SkipLine без обычного результата.

[CheckWeightFields.py](../Tools/Disasm/Research/CheckWeightFields.py) проверил все 65536 пар компонентов вторичного индекса и 3584 прямых чтения количеств, все 256 кодированных байтов, явный ноль, большие числа и переполнение слова. Сверены результат, полный F прямого пути, HL/BC, IX, SP и альтернативные регистры. Отчёт [WeightFieldsVerification](../Tools/Disasm/Reports/WeightFieldsVerification.json). Суффиксные сканеры проверены собственными моделями, но полный составной путь с суффиксом в этой модели не исполнялся. Сборка, IRQ и нативный игровой запуск не выполнялись.

## Общая проверка трёх сумматоров индекса

CheckWeightFields дополнен GetEquipIndex и GetCargoIndex наряду с SumSecondaryIndex. Текущий отчёт содержит 196608 сумм, по 65536 пар каждого входа, и прежние 3584 прямых чтения полей. Все три сумматора выполняют семь M1, не пишут RAM или CPU-стек, возвращают только байтовую сумму с B=0. FF и перенос не получают специальных правил выбора. Сопоставление исходных двенадцати байтов подтверждает различие только адресов источников. [Общий договор и ссылки на исходники](ScriptLanguage.md#три-байтовых-сумматора-индекса). Сборка и нативный запуск не выполнялись.

## RAM и M1 прямых полей количества

ReadEquipmentQuantity и ReadSecondQuantity без суффикса пишут только два постоянных байта FieldSuffixState.DefaultTarget и временный CPU-стек. Без явного числа CALL сумматора индекса использует два байта ниже входного SP. С числом ParseFieldSuffix сохраняет BC и DE, вызывает ReadDecimal5, использует до восьми байтов ниже входного SP. Исходный возврат не меняется, POP не очищает временную RAM.

Внутренний ReadAtBase не пишет RAM и CPU-стек, выполняет семь M1 при исходном bit7=0 либо восемь при bit7=1. Если S равно 1 для установленного bit7, полный первый вход без числа выполняет 32+S M1, второй 33+S. При явном числе и разделителе ! первый выполняет 44+P+S, второй 45+P+S, где P равно 14, 39, 68, 103 или 134 для длины числа от одной до пяти. Старший бит R сохраняется.

CheckWeightFields подтвердил точные R и последовательности всех записей CPU в 3584 прямых чтениях, прежние 196608 сумм индексов также прошли. Суффиксные s/n этим не исполняются, их дополнительные эффекты и банки определяются отдельными договорами. Полное произведение индексов, кодов, флагов и R не проверяется. Сборка, прерывания и нативный запуск не выполнялись.


Прямые пути двух внешних обёрток со словной записью выражения дополнительно проверены полным исполнением в 3584 случаях. Их CPU-кадры, точный R и отдельный отчёт описаны в [ExpressionPushes](ExpressionPushes.md#прямые-композиции-двух-читателей-количества). Суффиксы s и n в эту составную выборку не входят.


## Полные суффиксы s и n

[CheckQuantitySuffixes.py](../Tools/Disasm/Research/CheckQuantitySuffixes.py) исполняет настоящие ReadEquipmentQuantity и ReadSecondQuantity, разбор индекса и два обработчика каждого входа. Прямой режим и --expression-wrappers проходят по 5200 случаев, по 2600 на s и n в каждом режиме. Охвачены все младшие индексы, отсутствие числа, явный ноль и большие числа. Сверены основные регистры, полные F, выбранные альтернативные регистры, IX, SP, вся нестековая последовательность записей и исходный возврат.

Суффикс s снимает слово индекса, но сам индекс не использует в проверке. Через настоящее банковое ядро вычисляется признак L текущего ключа, затем сравнивается весь набор из 30 либо 14 записей. Для второго набора сохранён исходный обратный порядок баз, пороги по 98F6 с шагом два, признаки активности по 9632 с шагом один. Проверены отключение кодами 00 и FF, равенство порогу, отказ на первой и последней активной записи. Результат 0 либо 1, B содержит остаток внешнего цикла, C сохраняет исходный индекс списка 36 выбранного профиля.

На s вне стека меняются DefaultTarget, WorkKey, CurrentPage и Limit по C509. Все Variant+1 шагов рабочего ключа сравниваются с независимым step_key. Аппаратный порт проходит банки 1, 0 и 6. У n банковых эффектов и записи Limit нет, вне стека меняется только DefaultTarget. Пара границ выбирается по оборачиваемому байту 2*младший_индекс, а адрес выбранного значения по полному младшему индексу. Проверены оба нулевых кода 00/FF, отсутствие соседей, левый и правый свидетель и нулевые пределы. Ожидаемый результат рассчитывает отдельный сканер соседей, BC и F не сводятся к выходу прямого количественного читателя.

[Прямой отчёт](../Tools/Disasm/Reports/QuantitySuffixesVerification.json) отделён от [составного](../Tools/Disasm/Reports/QuantitySuffixExpressionWrappersVerification.json). Во внешней обёртке результат дополнительно записывается по B800..B801, HL'=B802, DE' равно результату. Пара собственного CALL по 7FFC..7FFD повторно используется PUSH DE. Исходный возврат сохраняется. Все прочие стековые записи ограничены 7FF0..7FFD напрямую и 7FEE..7FFD в составном режиме.

Физические хеши и наблюдатель CPU проверены. Полный R, все слова ключей, границы, значения соседей, размещения стека и ошибочные суффиксы не перебирались. Игровая семантика зависимостей соседних строк и единицы порогов этим не установлены. Сборка, IRQ и нативный запуск не выполнялись.
