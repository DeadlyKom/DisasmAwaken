# Сброс полётного контекста по DD87

В CONTROL банка 1 по `DD87..DE09` находится подготовитель полётного состояния. Остаточный загрузчик по согласованной старой базе передаёт сюда управление после чтения секторов и распаковки. Его штатная загрузка в игре пока неизвестна. Сам подготовитель проверен с исходными байтами в банке 1 и настоящим продолжением по `DE0A`. [Код](../Source/Controls/ResetFlightContext.asm), [старый загрузчик](ControlsTemporaryModule.md), [активация параметров](ControlsParameterActivation.md).

`HyperDiablo.Value` по `9C30` проверяется на FF через `INC A`. Для FF старшие два байта третьей компоненты получают `0200`, иначе `1100`. Старшие два байта первой и второй компонент обнуляются, младшие байты трёх компонент сохраняются. Затем в список по `9B27` копируются 72 байта, по шесть существующих `FActionWideVector`. FF выбирает исходник `DF91`, любой другой код — `DFD9`. [Шаблон для FF](../Source/Controls/Data/VectorsNoDiablo.asm), [шаблон для прочих кодов](../Source/Controls/Data/VectorsWithDiablo.asm), [назначение списка](ActionWideVectors.md).

Обход объектов начинается с `A100` и идёт с шагом `40`. У каждой записи до `80 80` первые два байта становятся `00 80`, а `ReuseByte` — FF. Обход эффектов начинается с `A795` с шагом `12`. Он обнуляет `State` до первой записи с установленным знаком, сам маркер остаётся целым. При отсутствии маркеров пределы не проверяются.

Два слова и один байт по `9BC6..9BCA` копируются в `9BC1..9BC5`. После переноса четыре байта двух слов сворачиваются XOR, результат ограничивается маской 07. Ноль заменяется на C9. Запись по `7B60` изменяет **опкод** `LD A, 00`, байт по `7B61` остаётся прежним. При исходном потоке планировщик достигает этого места только после допуска по фазе. Первая инструкция с каждым возможным опкодом и дальнейший переход при нулевом 7B61 проверены отдельно. [Цель изменения](../Source/Action/ScheduleSpawn.asm), [разбор опкодов](ActionSpawnSchedule.md).

Выполнение продолжается по `DE0A` без дополнительного JP. Подготовка таблиц и активация меняют банк на 0 и используют внешний адрес возврата. Модель покрыла все 256 кодов оборудования для восьми значений свёртки, сверила регистры префикса кроме R и T, все банки, порядок записей и настоящий хвост до внешнего возврата. Прерывания и нативный запуск не выполнялись. [Модель](../Tools/Disasm/Research/CheckControlsResetFlightContext.py), [отчёт](../Tools/Disasm/Reports/ControlsResetFlightContextVerification.json).
