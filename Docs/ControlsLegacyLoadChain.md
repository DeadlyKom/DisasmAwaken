# Старый загрузчик упакованного блока

Четыре фрагмента занимают исходные смещения `007F..013A` CONTROL. Рабочие адреса `5E1F..5EDA` согласуются с пятью абсолютными ссылками исходных инструкций. Эти адреса используются для описания старой копии. Физическая запись в TRD сохраняется на месте. Загрузка этой копии текущей игрой пока не установлена. [Доказательства адресов](ControlsTemporaryModule.md).

| Вход | Договор |
| --- | --- |
| [5E1F](../Source/Controls/LoadLegacyPackedBlock.asm) | Читает блок в текущий банк по C000, вызывает распаковку на месте, восстанавливает CPU-стек, выбирает банк 1 и вызывает сброс полётного контекста |
| [5E4D](../Source/Controls/ReadLegacySectors.asm) | Читает сектора с повторами, ведёт логический трек и сектор, шаг головки выдаёт при переходе на новый чётный трек |
| [5ED2](../Source/Controls/WriteLegacyDiskPort.asm) | Загружает IX адресом ROM-команды вывода в порт и последовательно продолжает по 5ED6 |
| [5ED6](../Source/Controls/CallLegacyDosRom.asm) | Кладёт адрес ROM-процедуры на стек и переходит на 3D2F, откуда RET выбирает этот адрес |

После распаковки старый вход берёт сохранённый порт 7FFD со стека. Операнд `RestoreStack` задаёт рамку со старым IX и внешним адресом возврата. Сохранение SP из начала файла пишет именно этот операнд. В проверенной рамке после сброса контекста остаётся банк 0. Старый вход записывает DB в регистр 7 AY, восстанавливает IX, запрещает IRQ и снимает внешний возврат. [Писатель операнда](../Source/Controls/RunTemporaryModule.asm), [сброс контекста](ControlsResetFlightContext.md).

Четыре условных профиля используют действительные координаты и длину исходного PANEL. Эти значения подставлены в нулевые операнды старого входа для модели. Выполнены оригинальные команды чтения, TR-DOS ROM, распаковщика и сброса. Сверены 6912 байтов результата, оба варианта оборудования, повтор первого сектора, восстановленные IX и SP, два переключения банка и обе записи AY. [Сценарий](../Tools/Disasm/Research/CheckControlsLegacyLoadChain.py), [отчёт](../Tools/Disasm/Reports/ControlsLegacyLoadChainVerification.json).

Изолированная проверка 5E4D охватывает 16 профилей четырёх ROM. Порты и переключение ROM моделируются. [Проверка дискового цикла](../Tools/Disasm/Reports/ControlsLegacySectorReadVerification.json).

[InitializeFlight](../Source/ActionBoot/InitializeFlight.asm) получает координаты CONTROL0 через GetFileLocation. Записи по 4267 и 426A помещают в RAM байты `05 4B` по 5E20 и `1B` по 5E23. Это сектор 5, логический трек 75 и 27 секторов из исходного каталога. Адреса совпадают с операндами старой копии, но в двух профилях байты самих команд остаются от начального состояния RAM. С пустой RAM получается `00 05 4B 00 1B`, с исходной копией завершения вступления — `28 05 4B 29 1B`. Код старой копии по-прежнему виден в банке 1 начиная с DB5D. Ни один из двух профилей не исполняет старый вход. [Проверка адресов записи](../Tools/Disasm/Reports/ActionLegacyBootOperandsVerification.json).

CONTROL0 в оригинале загружается по C000 как исходные данные и код, его первые байты `FF EF E9 E4 DF DC` не образуют заголовок HR. По C600 того же банка находится исходный шрифт. Эти наблюдения объясняют расхождение между действующим загрузчиком и требованием упакованного потока старого входа. Фактический перенос старой копии и вызов с совместимым ресурсом в игре остаются неизвестны.
