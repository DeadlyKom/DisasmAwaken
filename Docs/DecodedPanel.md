# Панель расшифровки и допуск финального перехода

[DrawDecodedMessagePanel](../Source/Station/DrawDecodedMessagePanel.asm) — обработчик рисования записи 24. Сначала вызывается DrawCaptionItem, затем Style устанавливается в 1 для переноса длинного предупреждения. На обычном пути выполняется хвостовой [PrintDecodedMessage](../Source/Station/PrintDecodedMessage.asm).

Панель проверяет FirstWord текущего ключа на 4B37, затем SecondWord на 4E25. Формула [имени системы](SystemName.md) для этих двух слов даёт исходную строку Дзета-43/78-Д, то есть ту самую систему, которая указана в сообщении 0. При несовпадении любого слова печатается сообщение по MessageIndex.

Только после совпадения обоих слов проверяется полный байт `#98A0`,
код количества позиции «X артефакт». Это строка 18 при нумерации с нуля,
`#988E + 18`. Рисователь оснащения использует тот же индекс для имени
по `#EF82`, количества, цены, веса и таблицы типов. Исходный код `#FF`
означает нулевое количество в инверсном представлении. Покупка даёт
`#FE`, продажа одной единицы возвращает `#FF`. Панель принимает ровно
`#FE`. Код `#01` при прямом представлении также означает одну единицу,
но условие панели его отклоняет.

[Общий рисователь](../Source/Station/PrintEquipmentRows.asm)

Цена позиции 25000, порог размера системы 15, вес 2. Исходная таблица
типов содержит `05 06 04 FF`, событие покупки исключает указанные типы.
В проверенных контекстах ключ Дзета-43/78-Д с вариантами 0 и 5 даёт
размер 16 и 15 соответственно. В обоих случаях при корабле типа 0,
подготовленных кредитах и исходном коде `#FF` событие покупки LANG
достигает `#C6E2` в банке 6. Общий писатель по этому адресу сохраняет
`#FE` именно по `#98A0`. Продажа отдельным прогоном записывает `#FF`
через тот же вход и возвращает уплаченную сумму.

Финальный путь делает DI, копирует ровно 512 байтов от 6E11 в 4000 и прыгает в 4000. [Финальный загрузчик](FinalExit.md) занимает первые 92 байта копии, имя файла следующие девять. Оставшиеся соседние байты исходного большого переноса сохраняются. CPU-стек и последующий переход в TR-DOS описаны отдельно, возврат из финальной ветви в эту панель не предусмотрен.

При обычном возврате HL и AF относятся к PrintDecodedMessage, DE равен 4B37 при первом несовпавшем слове и 4E25 во всех остальных обычных путях. BC, альтернативные общие пары и IX,IY сохраняются по договору рамки и текста, AF' остаётся рабочим от рамки. Стиль остаётся 1. Панель сохраняет MessageIndex, оба слова ключа и ArtifactCode.

Изолированная проверка охватывает 131328 условий, отдельно все первые и вторые слова и все 256 кодов `#98A0`. В 32 полных вызовах выполняется исходная рамка, 24 возвращают сообщение и 8 доходят через перенесённый загрузчик до TR-DOS. Сравнены все 512 байтов копии. Каждый вызов имеет явно пробуждённый HALT заголовка. [Проверка панели](../Tools/Disasm/Research/CheckDecodedPanel.py) · [Отчёт](../Tools/Disasm/Reports/DecodedPanelVerification.json) · [Пиксельная проверка сообщения](DecodedMessage.md)

Сквозной прогон использует результат исходной покупки без подстановки
`#FE`, выполняет оригинальную рамку и её IM2, переносит загрузчик,
читает FINALF через ПЗУ и выводит оба финальных растра. Покупка
запускается из подготовленного состояния станции с заданным ключом,
кредитами и выбранной строкой. Путь накопления денег и прибытие в
систему в этом прогоне не моделируются.
