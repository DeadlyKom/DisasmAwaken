# Построение таблицы приближённого логарифма

[BuildLogarithmTable](../Source/ActionBoot/BuildLogarithmTable.asm) занимает исходные адреса загрузчика 438F..43CE. Фактические значения приближают логарифм, точные байты задаются целочисленной суммой. Младшие байты хранятся в странице 9100, старшие в 9200.

Для аргумента 0 задаётся специальное T[0]=F000. Для n от 1 до 255 точная формула имеет вид:

```
q(i) = floor(0xB8AA * 65536 / (0x8000*i + 0x3AE9))
T(n) = floor(sum(q(i), i=1..n-1) / 256)
```

Пустая сумма даёт T[1]=0. Сначала сохраняется очередное значение накопителя, затем вычисляется следующее слагаемое. Сумма поддерживается в 24 разрядах как A:DE. В таблицу попадают старшие 16 бит, младший E остаётся в накопителе и влияет на последующие значения. После последнего слагаемого сумма равна 07FFED, этот окончательный результат в таблицу уже не записывается.

## Деление и регистры

Делитель C:DE собирается из аргумента n и константы 74E9. SRL C делит индекс на два, RR D переносит нечётность в старший разряд D, а E=E9 остаётся прежним. Получается ровно `0x8000*n + 0x3AE9`. Исходный остаток A:HL равен 00B8AA. Шестнадцать шагов удваивают остаток, пробуют вычесть делитель и восстанавливают его при займе. Инвертированный заём поступает в следующий бит частного через RL L и RL H в другом наборе регистров. Это даёт q(n), а не приближение частного.

Перед делением старший байт суммы сохраняется в A′, указатель и младшее слово суммы — четырьмя байтами CPU-стека. После деления POP DE и EX AF возвращают сумму, к ней прибавляется частное, затем восстанавливается указатель. Обмены наборами не предполагаются парными на одной итерации, точные итоговые значения обоих наборов проверены отдельно.

На выходе HL=9100, DE=FFED, BC=007F, AF=0750, HL′=DB3E, DE′=BAE9, BC′=007F, AF′=0D00. IX, IY, I, IM и IFF сохраняются. SP увеличивается на два после RET, дополнительных байтов CPU-стека требуется четыре. Страницы содержат ровно 512 записанных байтов, иных постоянных данных процедура не меняет. R получает 69347 M1 с обычным сохранением его старшего бита, это число не выдаётся за такты процессора. Портовых операций нет.

## Назначение и точность

Для n=1..255 значение приближает `256*log2(n)`. На этом конечном множестве разность фактической таблицы и вещественной формулы лежит от −4 до примерно +0,153148. Проверка вещественным log2 нужна только для математической характеристики, оригинальные байты определяются целочисленной суммой. Отдельный индекс 0 в эту оценку не входит. Поведение потребителя AE73 при нуле аргумента, нормализации и переполнении требует отдельного разбора, из имени таблицы оно не следует.

[CheckActionLogarithmTable.py](../Tools/Disasm/Research/CheckActionLogarithmTable.py) исполняет исходные инструкции в изолированной модели загрузчика. [Отчёт](../Tools/Disasm/Reports/ActionLogarithmTableVerification.json) подтверждает 256 полных построений с разными начальными флагами, регистровыми наборами и R. Сравниваются все 512 байтов, вся остальная RAM, кратность каждой записи, оба регистровых набора, флаги, SP и R. Прерывания, нативная загрузка и сборка Codex не выполнялись. Таблица 9300 и полный алгоритм проекции этим результатом не подтверждаются.
