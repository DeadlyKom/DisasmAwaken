# Смена кадров и положение бойцов ENGINE

В `#41F8` сравниваются запрошенное и загруженное действия. При смене
запроса выставляется `FramePending`, а задержка прежней группы остаётся
как была. При одинаковом действии задержка уменьшается по модулю байта.
Когда остаток равен нулю, индекс увеличивается. Если новый индекс уже
вне группы, бит 6 флагов выбирает возврат к `RepeatStep`. При сброшенном
бите запрашивается `NextAction`, а индекс сбрасывается в 0.
[Отсчёт задержки](../Source/ArchiveEngine/AdvanceFighterStep.asm)

Между отсчётом и применением кадров основной цикл вызывает `#40D2`.
Там исполняется одна команда `RET`. Затем `#4236` выбирает страницу 0
с двумя таблицами BAR и обрабатывает обе записи. Если действие
прежнее, `#427B` продолжает подготовку только при установленном
`FramePending`. При смене действия он читает из таблицы BAR относительное
слово, прибавляет базу конкретной копии BAR и переносит четырёхбайтовый
заголовок в рабочую запись. Индекс первой записи выбирается так.

| Смена запроса | Индекс |
| --- | --- |
| Из 1 в 2 или из 2 в 1 | `9 − старый индекс` по модулю байта, значение 9 и выше заменяется на 8 |
| На `#1C..#21` | Прежний индекс |
| Остальные | 0 |

Загрузка действия `#23` переключает бит 0 стороны. Независимо от кода
действия ненулевой `TurnPending` при смене группы сбрасывается и тоже
переключает бит 0. Если оба условия выполнены, два переключения оставляют
сторону прежней. [Подключение действия](../Source/ArchiveEngine/ApplyFighterAction.asm)
· [Пересчёт индекса](../Source/ArchiveEngine/MirrorFrameIndex.asm)

## Применение шага

Адрес шага вычисляется как `Steps + 14 × StepIndex`. Читаются задержка,
MoveX, MoveY, две поправки положения кадра, индекс BD, адрес пары маски
и рисунка, ширина и высота. Прямая сторона прибавляет горизонтальные
смещения, зеркальная вычитает. Вертикальные величины прибавляются
в обоих случаях. В записи сохраняются младшие байты координат. Адрес
рисования равен `#7700 + 92 × ((DrawY + SpriteYBias) AND #FF) + DrawX`.
[Применение шага](../Source/ArchiveEngine/ApplyFighterStep.asm)
· [Горизонтальные проверки](FighterAssets.md#горизонтальные-границы-сцены)

Ветки у левого и правого края читают X противоположного бойца. Обе
возвращаются к общей точке чтения MoveY через `JP`, сохраняя положенный
на стек адрес следующего поля шага. Они могут изменить X и младший байт
начала окна. [Левая ветка](../Source/ArchiveEngine/ClampAtLeft.asm)
· [Правая ветка](../Source/ArchiveEngine/ClampAtRight.asm)

## Сближение и разворот

Вход `#415D` вычисляет максимальное вертикальное смещение по нижним
строкам двух кадров. Кандидат появляется при байтовой сумме `DrawY + Height`
от 166. Из неё вычитается 166, результат ограничивается `MaxVertical`.
Если итоговый максимум нулевой, вертикальное смещение обнуляется и
проверяются базовые координаты бойцов. При равных Y и расстоянии X меньше
пяти каждый боец с ненулевым младшим байтом MoveX сдвигается от соседа.
При равных X первый направляется вправо, второй влево.

При разных Y сравнение передаёт управление проверкам стороны. Для
каждого бойца ненулевая сторона требует разворота, если его X меньше
X соседа. Нулевая сторона требует его, если X не меньше. При запросах
0, 1, 2, 4, 9 и 11 код сразу ставит 34. При 34 или 35 оставляет запрос.
Остальные действия получают `TurnPending`.
[Согласование положения](../Source/ArchiveEngine/ReconcileCombatView.asm)
· [Разведение](../Source/ArchiveEngine/CompareFighterPositions.asm)
· [Запрос разворота](../Source/ArchiveEngine/RequestFighterTurn.asm)

Проверка сравнила полные рабочие записи в 12 288 сценариях отсчёта,
9912 сменах группы и 2048 вызовах пересчёта индекса. Дополнительно
проверены 408 применений физических шагов, 29 376 случаев горизонтальной
границы, 1008 сравнений стороны, 28 случаев раздвижения и 49 кандидатов
вертикального смещения. [Модель](../Tools/Disasm/Research/CheckFighterArchiveConsumer.py)

## Отдельный переход по 40A9

Восемь байтов по `#40A9` выбирают страницу 0 и передают управление по
`#5C26`. Поиск во всех 655360 байтах нашёл 14 вхождений слова `#40A9`.
Ни перед одним из них нет кода абсолютного `JP` или `CALL`. Единственное
вхождение слова `#5C26` находится в самом переходе по `#40AE`.
[Исходник](../Source/ArchiveEngine/TransferTo5C26.asm)

Адрес `#5C26` лежит в конце системной таблицы потоков BASIC `STRMS`
по `#5C10..#5C35`. После подготовки переменных BASIC ни в одном из
четырёх сквозных прогонов до 32-го кадра ENGINE не было записей в
`#5C26..#5C35` и исполнение по `#40A9` не наблюдалось. Принудительный
вход из каждого такого состояния выбрал страницу 0 с прежними SP и IFF,
после чего выполнил 16 `NOP` из нулевых байтов таблицы. Модель остановлена
перед выборкой по `#5C36`, где начинается системное слово `CHARS`.
Косвенный вход и иной контекст назначения остаются открытыми.
[Руководство Sinclair, глава 25](https://worldofspectrum.net/ZXBasicManual/zxmanchap25.html)
