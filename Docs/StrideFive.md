# Стековое чтение с шагом пять

[ReadStrideFiveWord](../Source/Text/ReadStrideFiveWord.asm) читает слово по #9803+5*индекс, [ReadStrideFiveByte](../Source/Text/ReadStrideFiveByte.asm) байт по #9802+5*индекс. У обоих есть отдельный ReadAtBase, принимающий базу в DE. [ReadShipSaleField](../Source/Text/ReadShipSaleField.asm) выбирает #9806 для байта, по которому сценарий допускает особую продажу корабля. [ReadSkimmerPriceField](../Source/Text/ReadSkimmerPriceField.asm) выбирает #9826 для слова c второго набора. [ReadSkimmerLoadAddend](../Source/Text/ReadSkimmerLoadAddend.asm) выбирает #9829 для байта v, который также прибавляется при расчёте нагрузки. [Физические записи и подтверждённые потребители](StationTransportTradeTables.md).

На вершине CPU-стека находится слово индекса поверх адреса возврата. POP HL снимает индекс, LD H,0 отбрасывает старший байт. PUSH HL временно сохраняет индекс, два ADD HL,HL дают 4*индекс, POP BC восстанавливает индекс в BC, ADD HL,BC получает 5*индекс. Последний ADD HL,DE прибавляет базу. Входной BC теряется и заменяется байтовым индексом с нулевым B.

Байтовый вход возвращает HL как адрес прочитанного поля, E как значение, D=0. Словный вход читает младший и старший байты последовательно, поэтому HL на возврате указывает на старший байт, DE содержит слово. A сохраняется. F соответствует последнему ADD HL,DE, S/Z/PV сохранены от входа, H/C вычислены по сложению базы и пятибайтового смещения, X/Y из старшего байта итогового адреса, N=0. Альтернативные и индексные регистры, I и IFF сохранены, SP увеличен на четыре, индекс и возврат потреблены. Записи в таблицы нет.

Логические границы массива не проверяются. В станционной загрузке отдельно подтверждены семь записей кораблей и четыре записи второго набора. Чтения с большими индексами адресуются по той же формуле и могут попадать в соседние данные. Все игровые писатели полей ещё требуют подтверждения.

[CheckStrideFive.py](../Tools/Disasm/Research/CheckStrideFive.py) исполняет исходные инструкции пяти входов и двух общих хвостов. Каждый проверен во всех 256 индексах и всех 256 входных флагах, суммарно 458752 случая. Проверяются вычисленный адрес, значение, полные флаги, BC, SP, отбрасывание старшего байта индекса, сохранность альтернативных и индексных регистров. Отчёт [StrideFiveVerification](../Tools/Disasm/Reports/StrideFiveVerification.json). Прерывания, сборка и нативный запуск не выполнялись.


## Собственные записи и точный счётчик R

Расширенная проверка всех прежних 458752 случаев подтверждает физические секторы STATION и LANG по оригинальному TRD, проверяет наблюдатель самостоятельной записью CPU и сравнивает всю последовательность записей RAM. Единственный PUSH HL повторно использует уже снятое слово индекса. По исходному SP записывается младший байт индекса, по SP+1 ноль. Прежний старший байт индекса отбрасывается физически, даже когда итоговое значение совпадает с нулём. Слово возврата по SP+2..SP+3 сохраняется. Других собственных записей нет, таблицы только читаются.

Все инструкции хвостов не имеют префиксов, M1 равно числу исполненных инструкций. ReadAtBase словного читателя даёт 12 M1, байтового 11 M1. Полные входы ReadStrideFiveWord и ReadStrideFiveByte добавляют по одному LD базы, соответственно 13 и 12 M1. Обёртки ReadShipSaleField, ReadSkimmerPriceField и ReadSkimmerLoadAddend добавляют LD и JP к общему хвосту, соответственно 13, 14 и 13 M1.

В модели начальный R меняется вместе с индексом и флагами, сохранность бита 7 и прибавление по модулю 128 проверены. Также проверены I, IFF и IM. Это конечная выборка входных сочетаний, все базы и адреса CPU-стека не перебирались. Прерывания и аппаратные шинные циклы не моделировались.

Для обычных корабельных записей база 9803 соответствует Price, база 9802 Capacity. Это уже подтверждённые поля [торговых таблиц](StationTransportTradeTables.md). Произвольный индекс по-прежнему не ограничивается числом записей, а общий ReadAtBase принимает иную базу. Поэтому назначение всех возможных адресов общей процедуры не сводится к этим двум полям.


## Полный перебор баз и чтение изменённой стековой рамки

Ещё 262144 случая исполняют два общих ReadAtBase для всех 65536 баз при индексах 0 и 255. Сверены вычисленный адрес по модулю 65536, значение, полные флаги, R, единственная пара записей и сохранность возврата. Старший байт входного индекса задаётся A5 и действительно заменяется нулём. Перебор всех баз при двух индексах не равен полному произведению всех баз и индексов.

В двух случаях словный читатель начинает по FFFF, старший байт берёт по 0000 и возвращает HL=0000. В 18 случаях источник пересекает снятое слово индекса либо слово возврата. PUSH выполняется до чтения источника, поэтому при совпадении читается уже изменённая RAM. Например, при исходном SP=7FFA и чтении слова по 7FFA возвращается 0000 для индекса 0 и 00FF для индекса 255. По 7FFB возвращается FF00, младший байт уже нулевой, старший берётся из сохранённого возврата 3FFF по 7FFC..7FFD.

Для обычных баз торговых полей таблица находится отдельно от выбранного CPU-стека модели. Общий вход принимает произвольный DE, поэтому обещание неизменности любой входной таблицы было слишком широким. Точный контракт ограничивает запись снятым словом индекса. Защиты от такого совпадения в исходном коде нет, она не добавляется. Произвольные положения SP, банковая память и IRQ этим дополнительным проходом не доказаны.


## Переход корабельного индекса в соседнюю таблицу

При исходной базе #9802 Entry ReadStrideFiveByte читает четыре Unknown00 CNSK на индексах 7..10, поскольку семь пятибайтовых корабельных строк непосредственно предшествуют четырём строкам скриммеров. Это конкретное следствие отсутствия проверки количества, а не доказательство допустимых индексов интерфейса. [Физическая смежность и ограничения](StationTransportTradeTables.md#условное-чтение-тоннажа-cnsk-корабельным-читателем), [проверка](../Tools/Disasm/Research/CheckShipCapacitySkimmerAlias.py), [отчёт](../Tools/Disasm/Reports/ShipCapacitySkimmerAliasVerification.json). Общий ReadAtBase с произвольной DE имеет другой диапазон и этим утверждением не ограничивается.
