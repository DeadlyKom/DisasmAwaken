# Экранные адреса и маски карты

[BuildMapScreenTables](../Source/Map/BuildMapScreenTables.asm) получает пиксельное начало элемента в DE, где E=X, D=Y. Внутреннее начало сдвигается на 8 по X и 16 по Y байтовыми сложениями. По подготовленным страницам 82,83,84 вычисляется исходный экранный адрес. Его младшие пять бит образуют исходную горизонтальную колонку, а маска E0 оставляет строковую часть младшего байта.

| Страница банка KARTA | Содержимое |
| --- | --- |
| EE00..EEFF | Старшие байты адресов последовательных строк |
| EF00..EFFF | Младшие байты адресов строк без горизонтальной колонки |
| F000..F0FF | Исходная колонка + floor(пиксельный X/8) |
| F100..F1FF | Маски 80,40,20,10,08,04,02,01 с повторением |

Первые две страницы заполняются одновременно. Для следующей пиксельной строки увеличивается D. Если его младшие три разряда обнулились, к E прибавляется 20. При переносе E старшая часть уже перешла в следующую треть экрана, иначе из D вычитается 8. Все изменения байтовые. Эта схема воспроизводит фактическую раскладку Spectrum, но отсутствие ограничения длины означает, что часть из 256 построенных строк может лежать за видимым экраном. Потребители обязаны ограничивать высоту отдельно.

Последние две страницы строятся по восемь позиций на колонку. EX AF,AF альтернативного набора разделяет номер колонки и маску. После восьми RRCA маска снова равна 80, номер колонки увеличивается. Оба адресных индекса L оборачиваются в пределах своих страниц. Функция пишет ровно 1024 байта и сохраняет соседние области.

На выходе HL=F000, DE содержит адрес строки после всех 256 переходов, B=0, C сохранён. A равен исходной колонке+32, F=42. AF альтернативного набора равен 80A3, прочие альтернативные и индексные регистры сохранены. Функция не сохраняет прежний AF альтернативного набора, это важно для вызывающего кода.

[Модель](../Tools/Disasm/Research/CheckMapScreenTables.py) проверяет 3286 вариантов, охватывая все входные байты каждой координаты и крайние отступы. С независимым проходом адреса сравниваются все 1024 байта, регистры, флаги, стек и границы записи. Для входов за экраном используются фактические байты исходных lookup-страниц, это не объявляется корректным нативным отображением. Сборка и IRQ не исполнялись.

Банковый вызов из [станционного обновления 6D58](../Source/Station/DrawMapPanelContents.asm) теперь ссылается на доказанное имя этого построителя. Полный станционный вызывающий путь описан в [MapPanel](MapPanel.md), его модель отдельно проверяет три запроса, размеры и банковый рисунок с явными ограничениями сцены.


## Точные 5261 M1 и R

BuildMapScreenTables требует 5261 M1, в функции нет префиксов и вызовов.
Подготовка до StoreRow даёт 20 M1. Запись 256 строк имеет базу
256×10 M1. В 256 увеличениях D ровно 32 раза обнуляются младшие
три бита, независимо от начального D. Тогда E увеличивается на 32.
За 32 таких прибавления ровно четыре дают перенос, поэтому только
28 раз исполняется трёхинструкционная коррекция D. Добавка равна
32×4+28×3 M1.

Подготовка двух следующих страниц требует ещё четыре M1. Каждая
из 32 колонок содержит LD B,8, восемь итераций по девять M1
и четыре завершающих инструкции проверки L. Последний RET даёт один
M1. Итог `20+256×10+32×4+28×3+4+32×(1+8×9+4)+1=5261`.
Младшие семь битов R увеличиваются на 5261 по модулю 128, это
приращение 13, старший бит сохраняется. Оно не означает стоимость 13 M1.

[CheckMapScreenTables.py](../Tools/Disasm/Research/CheckMapScreenTables.py)
проверяет конечный R во всех прежних 3286 координатных профилях.
16 профилей с X=0/1/247/255 и Y=0/7/191/255 дополнительно проверяют
R после каждой инструкции, абсолютные M1, 32 перехода групп и 28
коррекций. Начальный R=(X+Y) AND FF охватывает все 256 кодов без
независимого произведения R и координат. I принимает начальный R,
IM=(X XOR Y) modulo 3, IFF младший бит X XOR Y, они сохраняются.

До запуска сверены оригинальный TRD, секторы KARTA/STATION и все
56 статических инструкций C49B..C4E4. Прежние выходные данные
[отчёта](../Tools/Disasm/Reports/MapScreenTablesVerification.json) сохранены,
добавлен refresh_verification. Таблицы-результаты записываются в те же
четыре страницы, собственного PUSH/CALL и записи стека нет.
Геометрическая допустимость всех неэкранных входов, IRQ, сборка
и нативная игра не объявляются доказанными.
