# Условный обход атрибутов в хвосте вступления

Исходный LDIR из вступления переносит 54 байта AWAKEN.B по файловым смещениям #2C97..#2CCC из RAM #8F97..#8FCC в #7497..#74CC. По #7497 начинается последовательность с замкнутой рамкой из четырёх слов и выходом RET. Прямой вызов этого входа в разобранных путях вступления отсутствует. [Исходник](../Source/IntroUnpack/ScanAttributeCountTail.asm) · [Перенос экранного потока](IntroScreenResources.md)

Первый байт по входному HL получает L. Затем LDIR копирует семь байтов из входного HL во входной DE. Если DE=HL+1, только что записанный байт становится источником следующей итерации, поэтому по всем восьми адресам распространяется один исходный L.

Цикл читает 255 атрибутов #5800..#58FE. Три сдвига и маска 7 извлекают биты PAPER. Каждый результат записывается по #8157 в первоначальный bitmap. При исполнении перенесённой копии смещение INC (IX+0) по #74B3 не меняется. Поэтому все 255 инкрементов приходятся на первый байт счётчиков, независимо от прочитанных PAPER. После последней итерации по #8157 остаётся PAPER из #58FE.

Далее начальный байт по входному HL сравнивается с семью байтами от входного DE. Адрес заменяется только при строго большем значении, поэтому равные максимумы сохраняют первого кандидата. Из выбранного адреса вычитается входной HL по модулю 65536. Результат возвращается в HL. Его младший байт попадает в A, на шину данных и в старшие восемь битов адреса порта, младший байт адреса порта равен #FE.

В 1024 профилях [модель](../Tools/Disasm/Research/CheckIntroAttributeCountTail.py) сверила всю RAM, исходные записи в стеке, все записи PAPER, итоговые регистры и точную операцию OUT. Она исполнила исходный перенос и затем явно задала условный вход по #7497.

В 256 дополнительных профилях запуск сделан с трёх непосредственно
предшествующих байтов 11 01 FF по #7494.
[SetAttributeScanDest](../Source/IntroUnpack/SetAttributeScanDest.asm) задаёт DE=#FF01,
затем управление последовательно переходит на #7497. Входной DE
в опытах был #2468, HL проверен с восемью базами, включая #FF00
и обе стороны от #FF01. При HL=#FF00 получается описанное выше
копирование с перекрытием. Цели #7494 в прямых переходах вступления
нет. Остальные байты предшествующего диапазона сохраняют исходную
[физическую разметку](IntroScreenResources.md).

## Проверка возможных входов перед `#7494`

Диапазон `#746B..#7493` начинается с `#80` и 28 нулевых байтов.
По `#7488` начинается последовательность `EF BB BB B0 00 00 FF C1 FF 87 FE FF`.
Весь диапазон и отдельно его последние 12 байтов встречаются в исходном
TRD только в этом секторном хвосте AWAKEN.B.
В зарегистрированных ветвях вступления нет прямой цели внутри диапазона
ни по адресу переноса, ни по исходному адресу `#8F6B..#8F93`.

Принудительный вход по `#7488` исполняет `RST #28`. Обе проверенные ROM,
48K и 128K ROM 1, после входа по `#336A` читают следующие байты как
команды калькулятора. Чтения по `#33D0`, `#33D7` и `#33E8` включают
`FE FF 11 01 FF` по `#7492..#7496`, то есть и три байта `LD DE,#FF01`.
Во всех восьми подготовленных профилях с 0, 1, 2 или 8 числами на стеке
калькулятора этот путь через 8083 инструкции достигает `RST #08`
по `#31AD` с байтом ошибки `#05` по `#31AE`.

При принудительном входе по `#748E`, `#748F`, `#7490` или `#7493`
те же ROM возвращают управление к последовательности, которая достигает
`#7494`. Первые два входа исполняют `POP BC` по `#748F` и прибавляют
два к CPU-SP. При входе по `#7493` байт `#FF` исполняется как `RST #38`,
а при входе по `#7492` он служит операндом `CP #FF`.

В 512 сценариях с входами `#7491` и `#7492` последующий обход атрибутов
дал тот же результат, что запуск с `#7494` при тех же счётчиках и атрибутах.
Цикл загружает A из атрибута и маской `#07` исключает внесённый сдвигами
входной Carry. Эти условные входы не устанавливают назначение диапазона
в игре. [Результаты проверки](../Tools/Disasm/Reports/IntroAttributeCountTailVerification.json)

## Совпадение адреса записи с операндом

Смещение байта `d` инструкции `DD 34 d` от начала фрагмента равно 28.
Поэтому только при модельном размещении фрагмента с `#813B` запись
`LD (#8157), A` меняет этот операнд. В 24 опытах с такой копией и
`DE=HL+1` на выровненной базе исходный цикл действительно построил
восемь счётчиков PAPER. Сумма счётчиков равна 255. При равенстве
максимумов в порт ушёл младший индекс. Модель проверила все восемь
цветов и случаи с одним, двумя и тремя цветами.

По `#813B` исходный снимок содержит байты bitmap. Установленный перенос
помещает код по `#7497`. Модельное совпадение объясняет, какой результат
может дать изменяемое смещение, прежняя фактическая база и вызов этого
варианта остаются открытыми.

Ещё в 24 профилях перед телом по #813B сохранена исходная команда
выбора приёмника. Исполнение начиналось с #8138 при HL=#FF00 и
входном DE=#2468. Команда заменяет DE на #FF01, что позволяет
очистить и затем заполнить все восемь счётчиков #FF00..#FF07.
Сверены гистограмма, последовательность 255 записей PAPER и индекс
первого максимума. Размещение #8138 относится к этой модели.
[Отчёт](../Tools/Disasm/Reports/IntroAttributeCountTailVerification.json)


## Счёт R исходного размещения

Для условного входа #7497 исходная команда INC (IX+0) остаётся неизменной, байт PAPER по #8157 не меняет её смещение. Счёт M1 равен 24+255*10+3+7*5+8+2*k=2620+2*k. Начальные 24 M1 включают семь повторений LDIR и POP IX, цикл PAPER даёт по десять M1 на атрибут. В сравнении каждый из семи кандидатов требует пять M1. Только строго большее значение исполняет дополнительные LD E,L и LD D,H, число этих замен обозначено k. Равенство сохраняет прежний адрес. Младшие семь битов R увеличиваются на число M1 modulo 128, старший сохраняется.

Префикс #7494 добавляет один M1. Принудительные входы #7491 и #7492 добавляют соответственно три и два с учётом префикса. Обновлённая модель проверяет эту формулу в 1024 случаях тела, 256 случаях префикса и 512 случаях двух принудительных входов, всего 1792. I, IM и IFF варьируются и сохраняются. Подготовленные счётчики и приёмник исключают пересечение с атрибутами, #8157, кодом и временной рамкой CPU-стека, но могут перекрываться друг с другом как в исходных сценариях LDIR.

Формула не перенесена на модельные копии #813B/#8138, где #8157 изменяет смещение INC. Эти прежние проверки гистограммы и отдельные ROM-пути воспроизведены с прежними границами. Штатный вызов хвоста, точные такты и нативное поведение по-прежнему не доказаны.
