# Создание записи ракеты по коду цели

[CreateMissileForTarget](../Source/Action/CreateMissileForTarget.asm) занимает
60AE..6144 перенесённого ядра банка 5, смещения 02EB..0381 записи 17 ACTION.
Входной C задаёт код цели. Процедура проверяет существование цели, получает
три компоненты, ищет слот, инициализирует новую запись и связывает её с целью.
Само движение и последующее списание запаса сюда не входят.

## Три пути

Цель адресуется через [RecordIndexToAddress](ActionRecordIndex.md).
Проверяется только Component0.High. Значение 80 означает потерянную запись,
другие значения принимаются. Числового ограничения C здесь нет, для пути
создания требуется действительный адрес допустимой записи.

При потерянной цели в операнд CursorA по ECA9 банка 0 записывается EDA8.
Потребитель ECA8 позднее выводит поток через AY-регистры 0, 1, 7 и 8,
то есть канал A. Это отдельный контекст от Controls банка 1.
Затем через настоящую банковую обёртку передаётся текст F248 «Цель потеряна.».
Очередь может молча отказать. Результат HL=EDA8, DE и BC сохранены,
AF=8090, Carry=0, IY и альтернативные регистры сохранены.
OUT 7FFD получает 11 и 10, итоговая конфигурация 10.

При существующей цели альтернативный вектор заменяется на 0, 0, 400,
исполняется [TransformVectorTransposed](ActionVectorWrapper.md).
Входные альтернативные компоненты при этом не сохраняются, на выходе
они содержат три рассчитанных слова. Для этого конкретного исходного
вектора переполнение невозможно, каждая компонента лежит в -395..396.
Она зависит от исходного третьего ряда матрицы, с усечением произведения
и прибавлением единицы для отрицательного ненулевого результата.

[SelectMissileStock](ActionMissileStock.md) выбирает поле запаса, но не
уменьшает его и не проверяет ненулевое значение. Выбор Fallback задаёт
Unknown13=0A, выбор Preferred задаёт Unknown13=32. Операнд записи 612E
изменяется до поиска свободного слота. B получает 1A для будущего Unknown0D.

[FindReusableRecord](ActionRecordSearch.md) обнуляет ReuseByte проверяемых
доступных строк. При отсутствии слота возвращаются HL=9C12 либо 9C13,
DE=0040, B=1A, C исходный код цели, AF=8042, IY указывает на маркер.
В альтернативном A остаётся 01, F' соответствует вычислителю вектора.
Уже выполненные изменения геометрии и операнда 612E сохраняются.
Новый текст и звук по этому отказу сама процедура не ставит.

## Инициализация и связь

Физическая раскладка [FActionRecord](ActionObjectRecords.md) содержит
реальные вложенные компоненты и явные Unknown. В новый слот записываются
три рассчитанных слова по 00..05, 90 по 06, нули по 07..09, 08 по 0A,
нуль LinkedIndex и LinkFlags по 0B/0C, 1A по 0D, код цели по 0F,
01 по 11, класс 11 по 12, выбранный параметр 0A/32 по 13 и 02 по 25.
ReuseByte по 18 уже обнулён поиском. Прочие байты не трогаются.
Неизвестным значениям не приписываются скорость, углы или другие роли
до разбора потребителей.

Затем у исходной цели устанавливается бит 1 LinkFlags по 0C.
Предыдущее поле LinkedIndex по 0B получает код нового слота,
полученный [RecordIYToIndex](ActionRecordIndex.md).
Новая запись сама здесь получает LinkedIndex=0, её TargetIndex хранит
код исходной цели. Типы двух запасов по одному параметру не угадываются.

При успехе HL=0040, DE указывает на LinkedIndex цели, B=1A, C исходная
цель, A новый код, F=45 OR (A AND 28), IY новый слот. AF'=0044.
Таким образом, и успех, и отказ по слотам возвращают установленный Z,
а Carry различает их, 1 при создании, 0 при отказе.
IX, I, IM и IFF сохраняются, SP=входной SP+2. На путях существующей цели
OUT нет. Максимальная дополнительная рамка 10 байтов на пути расчёта,
18 байтов на пути банкового сообщения о потерянной цели.

## Проверка

[Модель существующей цели](../Tools/Disasm/Research/CheckActionMissileCreation.py)
прошла 12263 сценария, 12063 создания и 200 отказов по слотам.
Проверены все различные пары 25 начальных слотов, оба поля выбора запаса,
пропуски FF, все 255 байтов состояния цели кроме 80 и все 256 коэффициентов
каждой из девяти позиций. Ни один счётчик запаса не изменяется.

[Модель потерянной цели](../Tools/Disasm/Research/CheckActionLostMissileTarget.py)
прошла 36864 сценария, все 256 кодов цели, четыре незаблокированные
конфигурации банка 0 и очереди с приёмом, отказом и маркером.
Текст независимо прочитан из Controls банка 1 как CP866.
Приняты 20480 сообщений, отклонены 16384. Запись ECA9 проверена именно
в банке 0, её нельзя переносить в текстовый контекст банка 1.

Исполнялись настоящие дети без подмен. Проверены все регистры, F, R, SP,
каждый байт RAM и кратности записей. На потерянной цели проверены все
восемь физических банков и настоящие OUT. Эталон родителя композиционный,
полного независимого эталона детей здесь нет. 25 слотов и маркер A740
подтверждают исходную раскладку, не все динамические пределы.
Сборка, IRQ, фактическое звучание и игровой полёт модели не проверяют.
