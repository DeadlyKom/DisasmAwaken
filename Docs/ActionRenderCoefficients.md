# Девять коэффициентов по байтовым фазам

[BuildRenderCoefficients](../Source/Action/BuildRenderCoefficients.asm) занимает C99B..CB22 ACTION банка 0, 392 исходных байта. Процедура читает [физический экземпляр FRenderPhases](../Source/Action/Data/RenderPhases.asm), три байтовые фазы 9B12..9B14 и заполняет девять раздельных операндов последующего вычислителя CB23. Сам потребитель отдельно проверен как [ComposeRenderMatrix](ActionRenderMatrix.md), последующее преобразование вершин ещё не доказано. Сторонняя версия исходников не используется как доказательство.

Ниже `s0=S(Phase0)`, `c0=S((Phase0+64) mod 256)`, аналогично s1/c1 и s2/c2. S является фактической [исходной синусоидой ACTION](ActionSineTable.md). Один полный период равен 256. Страница 98 содержит [симметричные квадраты](ActionProjectionClip.md), её точная функция `T(i)=floor(min(i,255-i)^2/127)` проверена по всем байтам.

Для байтов a и b произведение P определено точно:

1. `d=(floor(signed8(a)/2)-floor(signed8(b)/2)) mod 256`.
2. `u=(d+b) mod 256`.
3. `P(a,b)=(T(u)-T(d)) mod 256`.

Нельзя заменять P обычным умножением с делением на 127 либо 128. Арифметические половины отрицательных чисел округляются вниз, а индексы и разность таблицы оборачиваются. Даже нулевой множитель не гарантирует математического нуля при любой второй байтовой величине.

## Режимы и формулы

Бит 0 младшего байта HeaderWord0 по 9B8D выбирает короткий режим. Разряды 7..0 имеют схему `? ? ? ? ? ? ? S`, маска S=01. S=0 допускает общий расчёт, S=1 использует только Phase1. Другие семь битов этой процедурой не интерпретируются, смысл всего нулевого HeaderWord0 вне этого потребителя не утверждается. Условие нулевых Phase0 и Phase2 внутри процедуры не проверяется.

В коротком режиме коэффициенты имеют значения `(c1, 0, -s1, s1, 0, c1, 0, 127, 0)` в порядке таблицы ниже. Общий режим использует следующие точные выражения. CAdd и CSub означают байтовое сложение либо вычитание с исходной коррекцией Overflow.

| Коэффициент | Операнд | Формула общего режима |
|---|---|---|
| Coeff11 | CB38 | P(c2,c1) |
| Coeff21 | CB3A | CAdd(P(P(c1,c0),s2), P(s1,s0)) |
| Coeff31 | CB3C | CSub(P(P(c1,s0),s2), P(s1,c0)) |
| Coeff12 | CC25 | P(s1,c2) |
| Coeff22 | CC27 | CSub(P(P(s1,c0),s2), P(c1,s0)) |
| Coeff32 | CC29 | CAdd(P(P(s1,s0),s2), P(c1,c0)) |
| Coeff13 | CD22 | -s2 mod 256 |
| Coeff23 | CD24 | P(c2,c0) |
| Coeff33 | CD26 | P(c2,s0) |

После CAdd или CSub при отсутствии знакового переполнения сохраняется обёрнутый байт. При Overflow выполняется NEG этого байта. Если и NEG переполняется, то есть его аргумент равен 80, выполняется DEC и результатом становится 7F. Это отражение обёрнутого результата, а не насыщение математической суммы. Все три вида каждого из четырёх корректоров достигнуты в модели.

Индексы Coeff обозначают строку и столбец матрицы для потребителя CB23. Последовательные операнды CB38, CB3A, CB3C являются первым столбцом, CC25, CC27, CC29 вторым, CD22, CD24, CD26 третьим.

Это девять отдельных непосредственных байтов, новая непрерывная область матрицы и фиктивный STRUCT поверх промежутков кода не добавляются. В общем режиме они записываются в порядке Coeff13, Coeff11, Coeff12, Coeff21, Coeff23, Coeff22, Coeff31, Coeff33, Coeff32. В коротком режиме порядок другой, но набор исходных физических целей тот же. Все 18 прямых писателей зарегистрированы.

## Регистры и банки

В коротком режиме HL=9900 OR Phase1, B=Phase1, AF=7F44, C, DE, IX и IY сохраняются. В общем режиме BC содержит s0/c0, IX содержит P(c1,c0)/s1, IY содержит c2/c1. HL содержит страницу 98 и последний u для P(P(s1,s0),s2), D=s2, E=T(d) этого произведения. A содержит Coeff32, F относится к последнему сложению либо его коррекции. Альтернативные пары, I, IM и IFF сохраняются. RET потребляет только внешний возврат, дополнительных стековых рамок и портовых операций нет.

[Кадровые записи банка 4](ActionBank4Writes.md) по совпадающим адресам не меняют этот код. Полная конфигурация 14 выбирает OBJECT3D, а процедура C99B здесь проверена в банке 0. Совпадающий код в файле 3DPART и его иной банковый контекст автоматически этим доказательством не покрываются.

В проекте уже есть [матрица предварительного просмотра](PreviewModelMatrix.md) с теми же числовыми примитивами. Исследовательская проверка повторно использует её чистые формулы произведения и коррекции. При этом собственные байты ACTION, обе таблицы, адреса операндов, регистры, R и все записи проверяются отдельно. Процедуры отличаются организацией инструкций и стековых вызовов, их стоимость не переносится между модулями.

## Проверка

[CheckActionRenderCoefficients.py](../Tools/Disasm/Research/CheckActionRenderCoefficients.py) содержит 353280 сценариев, 32768 коротких и 320512 общих. Проверены все байты режима и все вторые фазы в выбранных сочетаниях, все пары Phase0/Phase1 при четырёх четверть-периодных Phase2, все Phase2 при выбранных окрестностях экстремумов и смены знака. [Отчёт](../Tools/Disasm/Reports/ActionRenderCoefficientsVerification.json) разделяет три пути каждого корректора.

Проверяются оба регистровых набора, флаги, R, SP, вся физическая RAM и кратность каждой записи. Полный перебор всех трёх фаз и всех байтовых аргументов каждого изолированного корректора не заявляется. Композиция CB23 проверена отдельной моделью, весь кадр, преобразование вершин, IRQ, нативный вывод и сборка этой моделью не подтверждаются.

FRenderPhases занимает ровно три байта, поля Phase0, Phase1 и Phase2 имеют смещения 0, 1, 2. Исходные значения равны 0, 0, 0, они сохранены физическими инициализаторами. Runtime-узел содержит ту же вложенную структуру по смещениям 5, 6, 7, размер FActionRenderNode остаётся 14. Чтение пары первых фаз словом и отдельного третьего байта не меняет их физический порядок.
