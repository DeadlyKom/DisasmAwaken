# Арифметика исходной игры

Проверки исполняют оригинальные байты в изолированной модели Z80.
Объём перебора указан отдельно для каждого алгоритма, время не измеряется.
Машинный код игры не исправлялся.

Табличные квадраты и корень разности квадратов карты разобраны отдельно
в [MapMath](MapMath.md), включая входной Carry и полный перебор байтовых аргументов.

Торговый интерпретатор получает левый операнд в DE, правый в BC. Сравнения
возвращают в DE ноль или единицу. Сложение ограничивает результат сверху
`#FFFF`, вычитание ограничивает снизу нулём. AND и OR работают над словами.

Для каждой из десяти процедур проверено 121 сочетание из набора:

```text
0, 1, 2, 127, 128, 255, 256, 257, 32767, 32768, 65535
```

Девять процедур совпали с формулами на этих входах.

## Особенность умножения

`#C3DF` проверяет перенос после удвоения промежуточного результата.
Перенос после предшествующего `ADD HL,DE` может быть перезаписан следующей
инструкцией `ADD HL,HL`. Это не корректное насыщающее умножение для всех входов.

При `DE=32767`, `BC=32767` получено **1**, а не `65535`. В выбранном наборе
четыре отличия от математического произведения с насыщением. Входы и результаты
сохранены в `Reports/MathVerification.json`. Имя `MultiplyWithChecks`
не обещает более сильного контракта. Поведение оригинала сохранено.

## 3D-модуль

Вход `#D12C` использует знаковый коэффициент A и множитель DE. Для
подтверждённого диапазона коэффициентов `-127..127` проверенные результаты:

```text
HL = trunc_toward_zero(signed(A) * signed(DE) / 128)
```

Выход выполняется через `JP (IX)`. Проверены 208 сочетаний, включая
`DE=-32768`. Коэффициент `-128` в подтверждённый контракт не включён.
