# Противоракетная команда 722E

[Исполняемый исходник ActivateAntimissileSystem](../Source/Action/ActivateAntimissileSystem.asm).
[Факты и договор](../Tools/Disasm/Research/ActionAntimissileCommandFacts.py).
[Независимая композиционная модель](../Tools/Disasm/Research/ReferenceActionAntimissileCommand.py).
[Проверка](../Tools/Disasm/Research/CheckActionAntimissileCommand.py).

Физический указатель клавиатурной таблицы ведёт в перенесённое ядро банка 5 по `722E`. Исходные 144 байта сохранены. Название действия подтверждается передаваемым сообщением «Противоракетная система активирована». Наличие PS1/PS2 непосредственно команда не проверяет.

При ненулевом CommandDelay возвращается исходное состояние с A и флагами от задержки. При нулевом значении задержка становится 5. Сообщение передаётся в очередь, затем CursorA получает `EDC1`. Эти действия происходят и при отсутствии подходящей ракеты, отказ очереди поиск не отменяет.

Поиск идёт с `A100` шагом 64. High первой компоненты `80` обозначает свободную запись, пара `8080` завершает список. Выбирается первая активная запись с ClassCode `11` и TargetIndex `1A`, проверки StateCode нет. Команда не перебирает остальные подходящие ракеты после обработки первой.

У выбранной записи последовательно устанавливаются биты 0 и 3 LinkFlags. Бит 0 означает уже установленный признак обратной связи. Бит 3 выбирает в [CheckRecordEffectThreshold](../Source/Action/CheckRecordEffectThreshold.asm) порог PS1/PS2 при LinkedIndex `1A`. Наличие PS1 выбирает `1E`, иначе наличие PS2 выбирает `3C`, отсутствие обоих выбирает `14`. Сброшенный бит 3 выбирает изменяемый Link1ABaseLimit. TargetIndex и LinkedIndex остаются отдельными полями. Биты устанавливаются до проверки ViewPosition.X.High и перед проекцией, ни один последующий отказ не восстанавливает старое значение.

Если ViewPosition.X.High равен `80`, команда только восстанавливает IX и возвращается с Carry. Иначе слова X, Y и Depth из ViewPosition переходят в альтернативные BC/HL/DE. Главные пары получают `BC=0003`, `HL=00B0`, `DE=FFFF`. Одновременно изменяются шесть существующих операндов.

| Операнд | Инструкция-владелец | Значение |
| --- | --- | --- |
| Output0 `D9B6` | ProjectRenderVertex, `LD BC,nn` по D9B5 | 0003 |
| Input0 `AF48` | ComputePatchedVector, `LD DE,nn` по AF47 | 0003 |
| Input1 `AF56` | ComputePatchedVector, `LD DE,nn` по AF55 | 0003 |
| Input2 `AF69` | ComputePatchedVector, `LD DE,nn` по AF68 | 0003 |
| Output1 `D7C4` | ProjectRenderVertex, `LD BC,nn` по D7C3 | 00B0 |
| Output2 `D7A2` | ProjectRenderVertex, `LD DE,nn` по D7A1 | FFFF |

Вызывается внутренний [CheckAndToggleLinkedOverlay.CheckDepthSigns](../Source/Action/CheckAndToggleLinkedOverlay.asm) по `E835`. Поиск связанной записи и случайное создание обратной ссылки из полного входа `E804` пропускаются. Этот вход выполняет EXX, отбрасывает пару отрицательных глубин, затем проверяет signed overflow трёх разностей. При допуске исполняет настоящий ToggleTargetOverlay с проекцией, клиппингом и XOR-растеризацией. Carry после успешного допуска сбрасывается независимо от того, вывел ли дочерний алгоритм пиксели. Подготовленные операнды и LinkFlags сохраняются даже при раннем отказе.

IX восстанавливается командой. Прочие регистры и побочные эффекты полного сегмента определены его договором. Стек, очередь, экран, проекционные таблицы и код банков должны быть доступны, IRQ и повторный вход исключены в модели. Команда сама DI не выполняет.

Проверка содержит 197716 сценариев. Все байты задержки, класса, цели и начальных LinkFlags проверены отдельно, каждое из трёх векторных слов проходит все 65536 значений при фиксированных остальных. Проверяются пропуски свободных и неподходящих записей, состояние очереди, настоящий внутренний вход и дети. Сверяются регистры кроме R и тактов, все восемь банков RAM и кратность записей вне 32 временных байтов обычного стека. Полное совместное произведение входов не перебиралось. Сборка, IRQ и нативная игра этим исследованием не подтверждаются.
