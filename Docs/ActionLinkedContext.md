# Подготовка связанной записи и компонентных операндов

[PrepareLinkedRecordContext](../Source/Action/PrepareLinkedRecordContext.asm)
занимает E761..E793 ACTION банка 0. LinkedIndex записи IX проверяется через
INC A. Для 00..FE выполняется обратный DEC и
[RecordIndexToAddress](ActionRecordIndex.md). Для FF выбирается A780,
а не обычный адрес индекса 255 E0C0. Адрес A780 сохраняется по оригиналу,
это не выделение новой памяти. Другой обычный индекс 1A также даёт A780.

Выбранный адрес всегда записывается в существующий операнд будущего
LD IY,nn по E796. Живой IY в данной процедуре не меняется.
Затем читается полный старший байт Component0 выбранной записи.
При значении 80 выполняется RET, прежние три компонентных операнда
сохраняются. Младший байт кода доступности либо маркера не читается.

В остальных случаях три **текущие** компоненты записи IX записываются
в операнды F1ED, F1F0 и F1FE. Они принадлежат соответственно LD DE,nn
по F1EC, LD BC,nn по F1EF и LD BC,nn по F1FD после EXX. Последующие
потребители ещё исследуются, их полное поведение не подменяется этим
подготовителем. Четыре писателя зарегистрированы с физическими целями
в [реестре самомодификации](ModifiedCode.md), исходные адреса сохранены.

A содержит прочитанный старший байт, F соответствует CP с 80.
Z означает недоступность выбранной записи, а не результат сравнения
координат. При отказе HL равен выбранному адресу плюс один, при успехе
HL равен третьему слову Components текущего IX. DE, BC, альтернативные
регистры, IX, IY, I, IM, IFF и paging сохраняются. SP после RET увеличен
на два. Обычный индекс использует два дополнительных байта CPU-стека,
специальный FF не использует их. R добавляет 11 M1 для FF либо 23 для
обычного индекса до отказа, ещё 16 M1 при подготовке компонент.

[Независимая проверка](../Tools/Disasm/Research/CheckActionLinkedContext.py)
исполнила 197120 сценариев, все 65536 значений каждой компоненты
и все 256 байтов LinkedIndex. За исходным массивом исходные байты,
включая исполняемый код, не подменяются тестовыми записями. Реальное
преобразование индекса исполняется. Точно сравниваются регистры,
флаги, R, SP, восемь банков и все записи. Подготовленные потребители,
полное произведение входов, IRQ, сборка и нативный запуск не проверялись.
