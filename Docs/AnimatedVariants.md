# Анимация вариантов вокруг исходной позиции

Корень C677 подтверждён исходным станционным CALL по 7939 после LD A,11 и SelectRamBank. Станционные процедуры выделены и описаны в [PeriodicVariants](PeriodicVariants.md). Статическое основание не выдано за наблюдавшийся игровой вызов.

Поток содержит подготовку общего начала, шесть последовательных обёрток, выбор мигающего ресурса и трёхстрочный XOR. Все исходные адреса сохранены, дополнительной памяти не выделено.

- [Map.DrawVariantCluster](../Source/Map/DrawVariantCluster.asm) по C677.
- [Map.AnimateVariant0](../Source/Map/AnimateVariant0.asm) по C6C0.
- [Map.AnimateVariant1](../Source/Map/AnimateVariant1.asm) по C6DD.
- [Map.AnimateVariant2](../Source/Map/AnimateVariant2.asm) по C6FA.
- [Map.AnimateVariant3](../Source/Map/AnimateVariant3.asm) по C717.
- [Map.AnimateVariant4](../Source/Map/AnimateVariant4.asm) по C734.
- [Map.AnimateVariant5](../Source/Map/AnimateVariant5.asm) по C751.
- [Map.SelectBlinkingVariant](../Source/Map/SelectBlinkingVariant.asm) по C76E.
- [Map.XorVariantPhase](../Source/Map/XorVariantPhase.asm) по C827.

Модель CheckAnimatedVariants исполняет настоящие вызовы, сравнивает bitmap, все байты счётчика и маски мигания, курсоры и стек. Это не нативный игровой запуск.

## Начало и центральная метка

C677 сохраняет входной A в Count и обменивает AF с альтернативным набором. Поэтому количество и входной Carry становятся исходным состоянием альтернативного счётчика. Начало поступает в DE, E задаёт X, D задаёт Y. К каждому байту отдельно прибавляется 4 по модулю 256, затем собранное слово умножается на восемь целиком. Это отличается от раздельного умножения двух координат — большой E переносит биты в старший байт.

По станционным таблицам 8200..84FF находится экранный адрес. Четыре INC H смещают начало центральной метки, затем пять строк получают XOR масками 1C, 3E, 3E, 3E, 1C. Переход последней строки через знакоместо сохранён точно. Обычная интерпретация как пяти соседних экранных строк требует согласованной исходной фазы Y. Код не добавляет проверки произвольного начала.

После восстановления масштабированного слова к нему прибавляется 0603 целым словом. BC получает результат, B становится BaseY, C становится BaseX. Далее идёт последовательное исполнение первой обёртки без CALL. Корректность порядка INCLUDE обязательна для префикса и шести обёрток.

## Счётчик и потребление потоков

Каждая обёртка сначала читает ресурс из своего изменяемого операнда, обрабатывает мигание и записывает общий SpriteSource. Затем читается собственный курсор. Если первый байт равен ровно 80, курсор возвращается к Point00 соответствующей траектории. Другие отрицательные байты являются допустимыми смещениями, общий тест знака здесь не применяется.

XorVariantPhase получает OffsetX в A и указатель пары в HL. Он сначала читает OffsetY и продвигает HL на два. К OffsetX прибавляется BaseX по модулю 256, затем AF обменивается с альтернативным набором. DEC уменьшает счётчик, а RET M проверяет бит 7 результата.

| Входной счётчик A′ | Результат отдельного шага |
| --- | --- |
| 0 | Пара потреблена, рисунка нет, основной A=FF |
| 1..128 | Пара потреблена, выбранная фаза нарисована, A′ уменьшен на один |
| 129..255 | Пара потреблена, рисунка нет, основной A лежит в 80..FE |

Это числовой счётчик, независимыми флагами его разряды не являются. На раннем выходе основной AF содержит уменьшенный счётчик и флаги DEC с сохранённым Carry, альтернативный AF получает исходный OffsetY и флаги сложения OffsetX+BaseX. На рисующем выходе основной AF принудительно равен 0044, альтернативный AF содержит уменьшенный счётчик и флаги DEC. После этого обёртка всегда сохраняет новый HL в свой Cursor.

Поэтому при количестве от 1 до 5 полная цепочка C677 рисует указанное число вариантов, затем потребляет ещё одну пару следующего варианта и возвращает по RET M. Курсор этого ненарисованного варианта тоже сдвинут. При количестве 0 первая пара также потребляется без рисунка. При количестве 6..128 рисуются все шесть, дальнейшего седьмого шага нет. Значения 129..255 прекращают цепочку на первой обёртке. Этот алгоритм отличается от PrepareVariantResources, где нулевое количество приводит к подготовке шести указателей.

## Траектории и исходные фазы

Физические записи FMapPathPoint содержат OffsetX и OffsetY, по одному байту в пиксельных единицах. Для сложения с общим началом используется байтовое оборачивание. В описании формы байты интерпретируются как знаковые смещения. Все шесть наборов имеют поворотную симметрию на 90 градусов, различные соседние пары и максимальный координатный шаг два. Название RadiusN обозначает условный радиус по первой точке (N,0), равенство X²+Y²=N² для всех точек не утверждается.

| Вариант | Траектория | Пар | Исходный курсор |
| --- | --- | --- | --- |
| 0 | [Radius13](../Source/Map/Data/VariantPath13.asm) | 52 | Point20 |
| 1 | [Radius10](../Source/Map/Data/VariantPath10.asm) | 40 | Point14 |
| 2 | [Radius7](../Source/Map/Data/VariantPath7.asm) | 28 | Point06 |
| 3 | [Radius16](../Source/Map/Data/VariantPath16.asm) | 64 | Point30 |
| 4 | [Radius19](../Source/Map/Data/VariantPath19.asm) | 76 | Point50 |
| 5 | [Radius22](../Source/Map/Data/VariantPath22.asm) | 88 | Point00 |

Каждый поток заканчивается отдельным однобайтовым End=80, он не является экземпляром двухбайтовой структуры. Никакого второго байта ограничителю не добавлено. Начальные курсоры находятся внутри тех же исходных массивов.

FMapVariantPhase содержит три пары Row0Left/Right, Row1Left/Right и Row2Left/Right. Восемь записей по шесть байтов занимают ровно 48 байтов ресурса. Каждое двухбайтовое слово читается в порядке старший байт слева, каждая последующая фаза равна исходному слову, сдвинутому вправо на номер фазы.

| Ресурс | Рисунок нулевой фазы | Назначение выбора |
| --- | --- | --- |
| [Default](../Source/Map/Resources/VariantDefault.asm) | 000 / 010 / 000 | Обычный вариант |
| [Current](../Source/Map/Resources/VariantCurrent.asm) | 101 / 010 / 101 | Текущий ключ и вариант |
| [Stored](../Source/Map/Resources/VariantStored.asm) | 111 / 101 / 111 | Совпадение во втором сохранённом списке |
| [Selected](../Source/Map/Resources/VariantSelected.asm) | 010 / 111 / 010 | Выбранный порядковый вариант |

Приоритет выбора описан в [VariantResources](VariantResources.md). Для рисуемого шага X=(OffsetX+BaseX)&FF, Y=(OffsetY+BaseY)&FF. Ресурс выбирается по смещению 6*(X AND 7). Строки читаются по станционным RowHigh/RowLow/ColumnByte, в отличие от карты C000 с собственными страницами EE..F1. Рисуются три строки по два соседних байта, отдельного отсечения нет. После восстановления указателя потока AF сбрасывается через XOR A, этим обеспечено продолжение после RET M.

## Маска мигания

BlinkMask находится в исходном операнде C777 и первоначально равна CC. Схема разрядов 7..0 — 1 1 0 0 1 1 0 0. Это циклическая временная последовательность, каждый следующий шаг берёт прежний бит 0 и выполняет RRCA. Единица сохраняет Selected, ноль заменяет его на Default. При нулевом байте выбранный вариант всегда получает Default. При FF он всегда получает Selected. Начальный рисунок CC повторяется через четыре поворота, произвольный байт имеет период, делящий восемь.

Маска поворачивается только при полном равенстве входного указателя Selected. Остальные указатели не изменяют её. Несколько Selected в одном вызове дают несколько поворотов, отдельного таймера в этом помощнике нет. DE возвращает адрес Selected. Для несовпавшего HL флаги учитывают вычитание и восстанавливающее ADD, при совпадении Carry возвращает прежний бит 0. Все альтернативные регистры помощник сохраняет.

## Проверки и остающиеся границы

[CheckAnimatedVariants.py](../Tools/Disasm/Research/CheckAnimatedVariants.py) исполнил 8192 отдельных вызова XorVariantPhase, все 256 альтернативных счётчиков, восемь фаз и четыре ресурса. Ещё 1536 проверок покрыли все байты BlinkMask и шесть разных указателей с точными AF. Полный исходный C677 прошёл 2048 сцен с четырьмя началами и двумя исходными рисунками экрана. Проверены полный bitmap и атрибуты, все курсоры, 1008 возвратов по End, изменяемые операнды, оба набора AF, сохранённые регистры и стек. Вызовы не подменялись.

[CheckAnimatedVariantTables.py](../Tools/Disasm/Research/CheckAnimatedVariantTables.py) отдельно проверил 348 пар, шесть однобайтовых ограничителей, 32 фазы и 96 двухбайтовых строк. Статическая проверка исходников сравнивает все 894 физических байта этих данных с оригиналом.

Игровое значение вариантов сверх доказанных ключей, селектора и графического поведения здесь не выдумывается. Банковый вызов станции найден статически, его периодический вызывающий путь описан в [PeriodicVariants](PeriodicVariants.md), весь игровой цикл ещё не доказан. Не проверены произвольные адреса за пределами допустимого bitmap, аппаратные IRQ, нативный игровой цикл и сборка. Эти ограничения не изменяют исходный алгоритм.
