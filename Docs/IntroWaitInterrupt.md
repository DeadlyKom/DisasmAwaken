# Ожидание прерывания во вступлении

[WaitInterrupt](../Source/Intro/WaitInterrupt.asm), вход `6A13`, выполняет
`EI / HALT / DI / RET`. Собственные инструкции не меняют регистры данных,
но полный договор зависит от реально выбранного обработчика IRQ.

Проверенный профиль использует IM 1, IY=5C3A, локальную 48K ROM, отсутствие
нажатых клавиш и неактивные записи KSTATE, первые байты `5C00` и `5C04`
равны FF. Входной IFF может быть любым, поскольку EI его разрешает.

Обработчик по 0038 сохраняет AF, HL, BC и DE, увеличивает младшее слово
FRAMES по `5C78`. При переполнении слова увеличивается байт `(IY+40)`,
в данном профиле это `5C7A`. После сканирования восьми строк клавиатуры
сохранённые регистры восстанавливаются, EI и RET возвращают управление
на DI по `6A15`. Затем WaitInterrupt выполняет внешний RET.

При отсутствии клавиш и KSTATE=FF других системных записей нет.
FRAMES увеличивается на один modulo 2²⁴, все регистры данных сохраняются,
выходной IFF=0, SP увеличен на два внешним RET.

Временный стек требует **14 байтов ниже входного SP**.
Аппаратный возврат занимает два байта, четыре PUSH занимают восемь,
вложенные CALL клавиатурной части достигают ещё четырёх.
Два последовательных CALL повторно используют нижнее слово.
Если вызывающий код сам использовал CALL WaitInterrupt, его два байта
нужно учитывать дополнительно к этим четырнадцати.

[Независимый эталон](../Tools/Disasm/Research/ReferenceIntroIRQ.py) численно
вычисляет FRAMES, кадры аппаратного возврата, четыре сохранённых регистра
и три CALL. Он не исполняет ROM.
[Проверка](../Tools/Disasm/Research/CheckIntroWaitInterrupt.py) исполняет
реальные EI/HALT/DI, штатный планировщик прерываний и настоящий ROM-код.
IRQ не заменяется снятием HALT, RET или заглушкой.

3072 сценария покрывают все F, FRAMES=0, FFFF, FFFFFE и FFFFFF,
три начальные фазы времени при периоде 69888 и три CPU-стека.
[Отчёт](../Tools/Disasm/Reports/IntroWaitInterruptVerification.json)
подтверждает все регистры кроме R, всю логическую RAM, временные
записи стека с кратностью и точные адреса чтения клавиатуры.

Другие ROM, нажатые клавиши, активные KSTATE, IM 0/2, NMI и отдельная
модель всех физических банков не проверялись. Точное время при ожиданиях
памяти и нативный показ вступления также не доказаны.
