# Преобразование записи по изменяемому указателю

[ApplyPendingRecordLink](../Source/Action/ApplyPendingRecordLink.asm) занимает 635B..637F перенесённого ядра ACTION. PendingRecord находится в слове непосредственного операнда по 635C. В оригинальных дисковых байтах он нулевой. Локальная процедура сама только обнуляет его. [CaptureProjectedRecord](ActionProjectedCapture.md) записывает сюда альтернативный HL по E366 после двух координатных проверок. **Допустимость этого указателя из полного обхода и игровой смысл события ещё не доказаны.**

Если PendingRecord равен нулю, процедура возвращает HL=0, AF=0044, сохраняет DE и BC и ничего не записывает. Для ненулевого указателя договор требует базу доступной [FActionRecord](ActionObjectRecords.md) с исходным выравниванием на 64. Проверки допустимости или границ указателя исходный код не содержит.

## Последовательность изменений

1. По смещению 0C устанавливается бит 0 LinkFlags, остальные разряды сохраняются.
2. Прежний LinkedIndex по смещению 0B читается в C, поле получает код 1A.
3. В B читается ClassCode по смещению 12. Разность смещений равна 7, прибавление выполняется только к L, выравнивание исключает перенос в H.
4. PendingRecord обнуляется, CursorA получает EF3B, начало [потока RecordRow00](ActionAyStreams.md).
5. Если прежний LinkedIndex равен 1A, выполняется RET Z, дополнительная поправка не применяется. Все четыре предыдущих шага уже выполнены.
6. При другом прежнем LinkedIndex исполнение продолжается прямо в [ApplyIndexedDelta](../Source/Action/ApplyIndexedDelta.asm) по соседнему include. B содержит класс этой записи. Классы 00..0F меняют State по [договору табличной поправки](ActionTypeDelta.md), классы 10..FF его сохраняют.

Код 1A не объявляется отсутствующим объектом или специальным типом связи без доказательства потребителя. Этот вход устанавливает бит 0 LinkFlags перед записью LinkedIndex=1A. В другом подтверждённом контексте CheckAndToggleLinkedOverlay тот же бит ставится вместе с обратной ссылкой на текущую запись. Это не делает само событие ApplyPendingRecordLink тождественным любому случаю обратной связи.

Текущая схема LinkFlags по разрядам `7 6 5 4 3 2 1 0` равна `? ? ? ? P H R B`. Бит 1 с маской 02 обозначает ракетную атаку, бит 2 с маской 04 — ракетное поражение в State08, бит 3 с маской 08 используется противоракетным режимом и выбором порога PS1/PS2. Писатели, потребители, авторские определения и ограничения собраны в [разборе четырёх младших разрядов](ActionObjectRecords.md#разряды-linkflags) и [реестре писателей](ActionLinkFlagWrites.md). Неустановленными остаются отдельные назначения старших битов 7..4, они всё же влияют на проверку всего байта через AND A.

Нулевой бит 0 означает отсутствие именно этого установленного признака, но не отсутствие всех событий в других подсистемах. Нулевой целый LinkFlags в UpdateObjects сразу выбирает CallHandler, то есть обходится ветка связи и проверки эффекта. Это установленное местное поведение, а не общий код жизненного состояния объекта.

## Возврат и ограничения

После ветви прежнего кода 1A возвращаются HL=EF3B, B=ClassCode, C=1A, AF=1A42. При продолжении результаты соответствуют ApplyIndexedDelta, а исходный адрес записи в HL уже не сохраняется. DE, альтернативные регистры, IX, IY, I, IM и IFF сохраняются. SP увеличивается на два из-за внешнего RET, дополнительных рамок CALL, записей CPU-стека и OUT нет. Назначение CursorA не означает фактического воспроизведения, поток прочитает [UpdateAyEffects](ActionAyEffects.md) позднее.

Порядок include с ApplyIndexedDelta обязателен, условный RET допускает проход в соседний файл. Комментарий продолжения не заменён настоящим JP, байты не добавляются. Два исходных писателя изменяемых слов, 6373→635C и 6379→ECA9, зарегистрированы в [ModifiedCode](ModifiedCode.md).

[CheckActionRecordLinkEvent.py](../Tools/Disasm/Research/CheckActionRecordLinkEvent.py) исполняет оригинальные инструкции и настоящий дочерний хвост. [Отчёт](../Tools/Disasm/Reports/ActionRecordLinkEventVerification.json) содержит 80384 сценария, все сочетания прежнего LinkedIndex и ClassCode, каждый исходный байт State с обоими режимами для табличных классов и все байты LinkFlags у 25 начальных слотов. Сравниваются договорные регистры, флаги, R, SP, вся RAM и кратность записей. Родительская модель использует ранее проверенную формулу поправки, полный независимый эталон ребёнка и полный декартов перебор входов не заявляются. Эта модель не включает производителя указателя, он проверен отдельно в локальных границах CaptureProjectedRecord. Полный обход, смысл события, прерывания и нативное поведение остаются непроверенными.
