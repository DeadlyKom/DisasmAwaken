# Приближение слова и накопитель остатка

[ApproachWordAndAccumulate](../Source/Action/ApproachWordAndAccumulate.asm)
занимает исходные адреса 6311..634A ACTION. HL содержит текущее слово,
BC базу, C' байтовый накопитель. Процедура не пишет память и использует
только внешний адрес возврата, дополнительные стековые слова не нужны.

## Выбор шага

Сначала с очищенным Carry вычисляется `delta=wrap16(HL−BC)`. Знак
определяется исключительно битом 15 этой обёрнутой разности. JP P
после SBC не означает сравнение математических величин без переполнения.
При отрицательной delta DE получает `wrap16(−delta)`, иначе саму delta.
Особый код 8000 при таком отрицании остаётся 8000.

Для модуля меньше 256 шаг равен `floor(magnitude/8)`. Два RRA с нулевым
Carry и заключительный SRL дают три деления на два. При модуле не меньше
256 выбирается 180. Отрицательной delta соответствует положительный шаг,
неотрицательной отрицательный. Итоговое HL равно исходному HL плюс этот
знаковый шаг с оборачиванием слова. DE возвращает знаковый шаг, BC
сохраняется. При модуле меньше восьми шаг нулевой, процедура дальше
не приближает значение к базе. Особенность не исправляется.

## Остаток и C'

До восстановления абсолютного HL сохраняется старший байт остатка
`residual=wrap16(delta+signedStep)`. Если его старший разряд установлен,
байт инвертируется, единица не прибавляется. Получается folded.
Это не точный модуль остатка. folded объединяется с исходным C' через
OR, результат возвращается одновременно в A и C'.

Все разряды 7..0 C' участвуют в накопительном OR, независимые игровые
флаги им не назначаются. Нулевой C' начинает накопление без прежних
разрядов. Флаг Z возвращает ноль накопленного байта, а не точное
равенство HL и BC. Например, ненулевой малый остаток также может дать
нулевой folded. F содержит обычные логические флаги OR результата,
Carry, Half Carry и N сброшены, PV отражает чётность байта.

HL', DE', B', AF', IX, IY, I, IM, IFF и paging сохраняются. SP после RET
увеличен на два. Число M1 равно 25 плюс 7 для отрицательной delta,
плюс 9 для модуля меньше 256, плюс 7 для неотрицательной delta,
плюс 1 для отрицательного residual. Бит 7 R сохраняется, младшие семь
разрядов увеличиваются с оборачиванием. Точные такты T не объявляются
проверенными этой формулой M1.

[Независимая модель](../Tools/Disasm/Research/CheckActionApproachWord.py)
сверила 196608 исполнений, все 65536 обёрнутых разностей при трёх базах
0000, 7FFF и FFFF. Сравниваются точные регистры, включая альтернативные,
флаги, R, SP и вся память. Любая попытка записи памяти немедленно
отвергается тестовой фикстурой. Полное произведение двух слов и всех
независимых значений C' не исчерпано. Ассемблер, IRQ и нативный
запуск не выполнялись.

## Подтверждённый вызывающий код

[Обработчик State08](ActionArrivalState.md) вызывает процедуру трижды,
для Components.Component0, Component1 и Component2. Перед первым вызовом C'
обнуляется, затем общий накопитель определяет дальний или ближний путь.
Первые два результата записываются сразу, третий только на дальнем пути.

[CreateLinkedMissileRecord](../Source/Action/CreateLinkedMissileRecord.asm)
записывает StateCode=#08 и ClassCode=#11. На входе Entry диспетчер
[DispatchObjectState](../Source/Action/DispatchObjectState.asm) сохраняет
состояние класса #11 через ветвь ClassCode>=#10, исключение #12 к нему
не относится. В [физической таблице](../Source/Action/Data/ObjectStateHandlers.asm)
State08 указывает ApproachTargetRecordAndResolve. Это установленная по
исходникам связь создателя записи, диспетчера и потребителя, а не
подтверждение её нативного прохождения во время игры.

[Модель State08](../Tools/Disasm/Research/CheckActionArrivalState.py)
отдельно проверяет реальный код трёх вызовов в составе 70256 сценариев
обработчика. Её синтетический ROM и исключение IRQ сохраняют ограничения
модельной проверки, полный игровой запуск этим не доказывается.
