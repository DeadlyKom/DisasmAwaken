# Копирование подстановки в запись ACTION

[CopyRecordLinkOverride](../Source/Action/CopyRecordLinkOverride.asm)
занимает исходные 662B..6638 перенесённого ACTION. Общий помощник
обработчиков [диспетчера классов](ActionClassDispatch.md) читает LinkOverride
по IX+15. FF означает отсутствие подстановки. Любое другое значение,
включая ноль, записывается в LinkedIndex по IX+0B, затем StateCode получает
02. Конкретная игровая роль связи и состояния для всех классов пока
не установлены, поля не переименованы по предположению.

Запрет проверяется через INC A и RET Z. При FF возвращаются A=0,
F=50 OR входной Carry, RAM не изменяется. На разрешённом пути DEC A
восстанавливает прочитанный байт. A равен исходному LinkOverride, F содержит
S, Z, Y, X от A, H при младшей тетраде A=F, P/V при A=7F, N=1,
Carry остаётся входным. Это исходный результат DEC от (A+1) AND FF.

Разрешённый ноль записывается и возвращает Z. Следовательно, нельзя
без дополнительного условия трактовать любой Z как запрет изменения.
Порядок двух записей сохранён, сначала LinkedIndex, затем StateCode.
HL, DE, BC, альтернативные и индексные регистры сохранены. SP после RET
равен входному SP+2, CPU-стек не записывается. I, IM, IFF и страница
сохраняются. R получает 4 M1 при запрете и 10 при копировании, бит 7 сохранён.

[Модель](../Tools/Disasm/Research/CheckActionLinkOverride.py) прошла
72192 сценария, все 65536 пар исходного байта и входного F, затем все
256 байтов на каждой из 26 физических записей. Сопоставлены все регистры,
включая R, восемь банков RAM, точный порядок двух байтовых записей и
отсутствие записи стека. Единицы и игровые роли полей, точные T, IRQ,
сборка и нативный запуск этой проверкой не устанавливаются.

Поле структуры теперь называется LinkOverride, его адрес и размер не изменены. Известные писатели по 7921, 7A73, 7DF0, E908 и F479 записывают FF, по F58C записывается Unknown0D родителя до проверки активности цели. Это имя описывает доказанный механизм подстановки, а не принадлежность объекта к игровому классу.
