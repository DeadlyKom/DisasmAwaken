# Создание связанной ракеты

[CreateLinkedMissileRecord](../Source/Action/CreateLinkedMissileRecord.asm) занимает исходные 60E8..6144 в перенесённом коде банка 5. Физическое смещение в ACTION отличается на 23D, ни новый адрес, ни новая память не выделяются.

## Вход и выделение

Альтернативные HL/DE/BC задают три Components ребёнка, альтернативный A задаёт Unknown11. Основной B копируется в Phase0OrLink, C является обычным индексом цели, A становится начальным EffectReserve. Назначение этих неизвестных полей в других состояниях данным договором не переопределяется.

A записывается в операнд InitialParam по 612E ещё до поиска. [FindReusableRecord](../Source/Action/FindReusableRecord.asm) может очистить ReuseByte=FF и пропустить такую запись один раз. При отсутствии слота возвращаются A=80/F=42, IY указывает маркер, BC и альтернативные пары сохранены. Параметр уже изменён, его запись не отменяется.

## Поля ребёнка

| Поле | Исходное значение |
| --- | --- |
| Components | альтернативные HL, DE, BC |
| ModelOffset | 90 |
| OffsetPhase0/1/2 | 0 |
| StateCode | 08 |
| LinkedIndex, LinkFlags | 0 |
| Phase0OrLink | входной B |
| Phase2OrTarget | входной C |
| Unknown11 | входной альтернативный A |
| ClassCode | 11, десятичный класс 17 |
| EffectReserve | входной A |
| TargetCodeStep | 2 |

Все остальные поля сохраняются после побочных действий поиска. Дополнительного обнуления OffsetScaleLow или оставшегося хвоста нет.

## Обратная связь и результат

Цель вычисляется обычной формулой A100+64*C. FF здесь не является специальной ссылкой A780. У цели устанавливается бит 1 LinkFlags, затем LinkedIndex получает индекс созданной записи IY. Целевая запись не проверяется на активность и класс, эту исходную особенность нельзя исправлять при дизассемблировании.

При успехе HL=0040, DE указывает LinkedIndex цели, BC сохранён, A содержит индекс ребёнка, Carry установлен. F=#45 OR (A AND #28) для всех выделенных записей, выровненных на 64 байта. Преобразование IY умножает младший байт адреса на четыре и получает ноль, поэтому Z и PV установлены для любого такого слота. SCF задаёт Carry=1, успех не определяется Z. Альтернативный AF равен 0044, остальные альтернативные пары, IX, I, IM, IFF и paging сохраняются. IY указывает ребёнка. Внешний RET увеличивает SP на два, требуется до шести дополнительных байтов стека. R добавляет стоимость поиска и 88 M1 при успехе либо 5 при отказе.

## Проверка

[Независимая модель](../Tools/Disasm/Research/ReferenceActionClass17Spawn.py) сопоставлена с настоящими командами и поисковыми детьми [проверкой](../Tools/Disasm/Research/CheckActionClass17Spawn.py). Прошли 66560 сценариев, все пары B/C, все начальные A, разные позиции слота, FF-пропуск и отказ выделения. Сверены точные регистры, флаги, R, все восемь банков, кратность RAM-записей и остатки стека. [Результат](../Tools/Disasm/Reports/ActionClass17SpawnVerification.json).

Полное произведение входов, аппаратные прерывания, точные T, сборка и нативная игра не проверялись.

Происхождение ракеты в Unknown11 подтверждено авторским LZS: ноль задаёт ракету персонажа, неноль ракету игрока. Текущие создатели передают соответственно 0 и 1 через A′, [проверка и контекстные роли](ActionObjectRecords.md#авторское-поле-lzs-у-ракеты).

В ракетном контексте Phase0OrLink хранит индекс стрелявшего, Phase2OrTarget индекс цели. Это соответствует авторским RAND и MSPD, а текущие записи по #611D и #6120 сохраняют именно B и C. Для ракеты игрока стрелявший равен `ActionMissileCreateConst.PlayerIndex=#1A`, его расчётный адрес #A780 совпадает с авторским PLAYER. Для ракеты персонажа B вычисляется из текущего IX. Это описание класса #11, имена и значения тех же полей в других классах не переопределяются.

Авторский `T_ROKET=#11` означает ракету. Текущий создатель записывает этот класс и смещение модели `#90`, указатель `#9E90` выбирает `ROKET=#D864`. Весь файл OBJECT3D, 10580 байтов, совпадает с авторским архивом. Связь подтверждена [проверкой оригинальных байтов](../Tools/Disasm/Research/CheckActionMissileIdentity.py) и [отчётом](../Tools/Disasm/Reports/ActionMissileIdentityVerification.json). Вход общий для ракеты игрока через последовательное продолжение CreateMissileForTarget и ракеты персонажа через JP из CreateMissileFromCurrentLink. Это уточняет назначение создателя, но не доказывает полный игровой цикл ракеты.


## Совпадение цели и выделенной записи

Таблица исходных значений описывает инициализацию до обратной связи.
Общий создатель не проверяет активность целевой записи и допускает
совпадение обычного адреса A100+64*C с выделенным IY. Тогда последующий
SET бита 1 и запись обратного индекса выполняются в самом ребёнке.
Его окончательный LinkFlags=#02, LinkedIndex равен собственному индексу.
Эти поля не остаются нулевыми, кроме собственного индекса ноль.
При разных записях LinkFlags и LinkedIndex ребёнка остаются нулевыми.

В модели 66560 исполнений отдельно проверены 275 таких совпадений,
окончательные поля, полный AF успеха и полное число M1 каждого исполнения,
не только итоговый R по модулю 128. Прежние сравнения всех регистров,
восьми банков и кратности записей сохранены. Для
[CreateMissileFromCurrentLink](ActionSpawnCurrentLink.md#окончательные-регистры-и-совпадение-цели)
подтверждены ещё 257 совпадений в его собственной серии.
Это прямые сценарии модели, штатная постановка ракеты на саму себя
и полный игровой цикл ими не доказываются.

## Контекст Unknown11

В ракете класса #11 поле Unknown11 соответствует авторскому LZS,
полный ноль означает ракету персонажа, неноль ракету игрока.
[Архивное определение и текущие байты обоих производителей](ActionObjectRecords.md#авторское-поле-lzs-у-ракеты).
CreateMissileFromCurrentLink передаёт ноль, CreateMissileForTarget единицу.
Это контекстная роль байта, неизвестные и другие подтверждённые роли
того же смещения у других классов не заменяются общим флагом.
